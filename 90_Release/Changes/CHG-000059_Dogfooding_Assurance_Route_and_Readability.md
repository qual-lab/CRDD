# 変更トレース: Dogfoodingからの保証コスト・変更経路・可読性改善

変更ID: `CHG-000059`
- 状態: `In Progress`
- 決定権限者: Qual-Lab
- 判断日: 2026-09-02
- 対象: v0.18～v0.18.1のDogfoodingと外部レビューから確認した、保証活動、変更経路および人間可読性の横断改善
- 対象リリース: `v0.19.0`
- 変更分類: `normative` / `additive`候補
- `migration_required`: `false`候補。既存CHGの遡及更新、新しい監査、専用データベースまたは固定Profileを要求しない
- リリースレベル: `MINOR`候補

正本: [変更トレース](../../12_Change.md)、[品質保証](../../16_Quality_Assurance.md)、[文書化](../../03_Documentation.md)、[文書監査](../../51_Document_Audit.md)

## 1. 契機と変更意図

v0.18～v0.18.1では、Runtimeの安全性と完成品質を高める一方、レビュー・監査・再確認の反復、当初計画からの経路変更、および規範文書を初見で理解する負荷が発生した。人間の決定権限者は、規範や保証活動を一律に軽くするのではなく、既存の仕組みが実際にどう機能したかを観測し、その根拠から後で最適化できるようにする方針を採用した。

本変更は次を一つの横断改善として扱う。

1. 採用可能な結果までに使った保証活動のコストを観測する。
2. 計画した変更経路と実際の変更経路、その差と有効だった検証を観測可能にする。
3. 人間可読性を既存の文書監査の責務として具体化する。
4. 内容の正しさと文書の所有先を分け、共通規則、Toolの設計、反復手順、実装規約、検証および履歴が責務を越えて第二の正本になっていないか確認する。

## 2. 目指さないこと

- Light／Heavy等のProfileへCRDD規範を分割しない。
- 新しい自動経路決定機構、経路専用データベースまたは登録簿を作らない。
- 人間可読性専用の監査、Checkerまたは文字数による合否判定を作らない。
- 監査数、根拠量または保証活動の削減自体を成功指標にしない。
- 既存CHGを機械的に遡及更新しない。
- Project Runtimeの実装またはRuntime Security／Authority／Effect境界を変更しない。

## 3. 変更経路の計画

- 計画した主な経路: [変更トレース](../../12_Change.md) → [エージェント](../../10_Agent.md)／[概要](../../00_Overview.md) → [品質保証](../../16_Quality_Assurance.md)／[進捗管理](../../15_Progress.md) → [文書化](../../03_Documentation.md)／[文書監査](../../51_Document_Audit.md) → [準拠監査](../../52_Conformance_Audit.md)／[不足・影響監査](../../53_Gap_Impact_Audit.md) → 利用側ひな型・Project Runtimeの有用性評価
- 選択理由: 変更経路は変更トレース、保証コストは品質保証、可読性は文書化と文書監査がそれぞれ正本責務を持ち、AI入口、ひな型、準拠およびProject Runtime評価へ直接伝播するため。
- 予定する検証: 全体Checker、品質保証・変更工程の専門レビュー、文書監査、準拠監査、不足／影響監査。
- 重要な非選択経路: [セキュリティ原則](../../01_Principles.md)に基づくセキュリティレビューと[RuntimeのE2E検証](../../07_Quality/03_Verification_Design.md)は、実装、Authority、Effect、Recovery、Providerまたは外部送信境界を変更しないため非選択。新しい可読性専用監査は、既存の[文書監査](../../51_Document_Audit.md)と責務が重複するため非選択。

## 4. 適用境界と代表例

| 区分 | 代表例 | 期待する処置 |
|---|---|---|
| 発火 | 非自明な変更で、複数の工程・監査候補から経路を選び、実行中に別工程や検証を追加した | 計画した主な経路、実際の経路、差の理由、追加処置、有効だった検証を既存CHGまたは根拠へ残す |
| 非発火 | 誤字修正、一意な変換、既存判断を変えない機械更新 | 経路記録を増やさず、必要な通常確認だけを行う |
| 境界 | 計画と実績は異なるが、新しい影響を処置し、差の理由を説明できる | 差を失敗にせず、工程改善の観測として保持する |
| 判定情報不足 | 影響工程、決定権限または必要な検証を安全に限定できない | 経路を捏造せず、不足情報と確認先を示して停止または再整理する |

可読性では、表示名の直感性、一言説明、用語依存、文の複雑さおよび情報構造を確認する。文字数や用語数だけで不合格にせず、読み違いが判断、義務、例外、実装、検証または引き渡しへ影響し得る場合に指摘事項とする。

## 5. 保証コストの観測

既存の運用上の有用性指標へ、レビュー回数、独立レビュー回数、監査回数、再レビュー／再監査回数、検証実行時間、完了までの検証反復数、根拠生成量、指摘事項数および是正回数を候補として追加する。すべての対象へ全項目を要求せず、比較目的、観測可能性および判断を変える可能性に応じて選ぶ。未測定値を0へ補正しない。

評価単位は実装時間ではなく、品質条件を満たす採用可能な結果までの総コストである。保証活動が少ないことだけを成功とせず、後工程指摘、残存リスク、人間負荷および有効だった検証と合わせて評価する。

## 7. 検証と完了条件

- 全体CheckerがError 0、Warning 0である。
- 独立した品質保証・変更工程レビューが、保証コストの所有、合否との分離および過剰適用の防止を確認する。
- 文書監査が、表示名、一言説明、用語依存、文の複雑さ、情報構造および文字数Gate非採用を確認する。
- 文書監査が、各項目が対象文書の目的、対象、決定権限および成果物種別に属し、別文書の第二の正本を作っていないことを確認する。
- 準拠監査と不足／影響監査が、正本、AI入口、ひな型、Project Runtime評価および既存監査への伝播を確認する。
- 指摘是正後の固定改訂版で再確認し、計画した経路と実際の経路、その差、有効だった検証を本CHGへ戻す。

## 8. 実際の経路・影響・逸脱

当初計画した正本・AI入口・ひな型・監査への伝播後、CRDD自身の文書監査を追加した。文書監査は、入口文書の条件過密、READMEの利用手順と移行案内の圧縮、英語CHANGELOGの伝播漏れに加え、`19_Maintenance.md`がTool固有の実装・Security・検証契約を所有していた責務混在を検出した。

実際の経路は、文書化／文書監査から保守、内部ツール・コーディング規約、Coordinator／Windowsプラットフォームアクセスのアーキテクチャ、Workflowおよび検証設計へ拡大した。この差は新しいRuntime変更ではなく、新しい所有先確認をCRDD自身へ適用した結果である。移管では既存のBCP 14強度、TCB、Provider Home、Mount Grant、Process、Fakeと実環境、Build／Runtimeの意味を保持した。既存Runtimeの挙動、移行結果および公開済みv0.18.1履歴は変更していない。

機械Checkerはリンク・アンカー・構造の成立に有効だったが、文章の過密さ、英日差分および正しい内容の誤配置は検出しなかった。文書監査は可読性と所有先の不整合、準拠／不足・影響監査は英語CHANGELOGと利用側・変更トレースへの伝播不足、専門レビューはSecurity／Runtime契約の意味保持を確認する役割として有効だった。

3つの固定改訂版を3系統で確認し、2回是正した。最終固定改訂版`008c583`では、CheckerがMarkdown 396件、local link 2,778件、anchor 949件、Error 0、Warning 0で終了し、全独立確認が`Pass`、残る指摘事項0となった。指摘、共通原因、未測定値および非該当範囲は[検証結果](../../07_Quality/Verification_Results/2026-09-02_Dogfooding_Assurance_Route_Readability_Verification.md)に記録する。

## 9. 既知の制限と後続評価

本変更は観測契約を整えるものであり、現時点で最適な変更経路、最小保証コストまたは可読性の単一尺度を確定しない。一定量の実績が蓄積した後、経路不足の共通パターン、保証コストと品質の関係、および文書監査で繰り返す可読性指摘を、追加変更の根拠として再評価する。
