## 1. 変更理由

v0.13.0は、複数箇所へ及ぶ是正について、処置の適用と解消を分け、契約母集団、新しい根拠、独立再レビューを要求した。導入先の試行では、修正漏れを発見する効果は確認できた一方、同じ根本原因が別の利用側で再発し、次の境界が不足していることが分かった。

- 元の指摘事項が途中で別の意味へ置き換わる
- 契約の組合せを確認しても、その契約を使う利用側が漏れる
- 合否判定方法が正しいことを、プロダクトや各利用側の実行結果へ流用する
- 宣言した固定版と、実際に観測・実行した対象の同一性を十分に分けない
- 現在記録への追記を監査対象へ追加し続け、根拠確認が終了しない
- 同じ原因の再発に局所修正を継ぎ足し、構造原因へ戻れない

## 2. 人間による判断

Qual-Labの人間の決定権限者は、次をv0.14.0候補として採用した。

1. 指摘事項の意味保存、訂正、置換および是正との対応関係
2. 契約母集団と利用側母集団の二段階網羅
3. 合否判定方法、参照用実行環境、プロダクト実装、利用側実行結果の証明境界
4. Git中心の宣言対象、実観測対象、実行対象の同一性
5. 再発時の構造是正と、現在記録／根拠確認の終了境界

次は追加しない。

- 必須の解消パッケージファイルまたは専用ID
- 通常のcleanなGit Commitに対する独自Manifest
- 新しい監査、承認段階、プロファイル、フォルダまたは安定コンテキストID
- 外部QA／テスト管理ツールへの依存
- 完了済みの履歴指摘事項または根拠の一括書き換え

## 4. 移行

既存基準版からの採用では、基準版採用評価と移行完了の条件を適用する。

- AIが指摘事項を是正する、またはエージェント型提供を表明する場合は、AI入口または同等手順を確認し、AD-21を再評価する
- CRDD品質保証を使う場合は、固定後根拠、現在記録、契約／利用側網羅、判定方法／利用側結果の分離を確認し、PL-16を再評価する
- 進行中のひな型または手順が新しい境界を保持できない場合だけ更新する
- 完了済み履歴は、形式合わせだけを理由に書き換えない
- 復旧: 移行完了の条件と人間による有効化が終わるまで、現在有効なv0.13.0基準版と運用手順を維持する。部分適用を戻す場合はv0.13.0のAI入口と根拠手順へ戻し、v0.14.0候補で作成した履歴は削除せず候補記録として保持する
- 延期時の既知リスク: 指摘事項の意味変更、利用側漏れ、合否判定方法の結果を利用側実行結果へ流用すること、宣言対象と実行対象の取り違え、現在記録の確認連鎖が終了しないことが残り得る

## 6. 既知の制限

- 未知の利用側を規則だけで必ず発見できるわけではない
- 合否判定方法の形式的整合だけでは、その判定方法自体の正しさを保証できない
- 実運用での再監査往復回数とAI処理コストの改善量は、リリース後の新しい運用データがなければ測定できない

これらはv0.14.0の規範境界を不成立にする未完了作業ではない。新しい運用データが得られ、規則変更が必要と判断された場合は、別の変更契機として扱う。
