## 1. 契機と変更意図

v0.16.0までに、採用済みの意味を工程間で保持し、初回固定候補へ契約・利用側・反例を揃える仕組みは強化された。一方、課題、体験、情報構造、視覚表現、振る舞い、アーキテクチャ、実装および検証について、有力な候補をどう生成・批評・収束するかは実行者の暗黙知へ残っていた。さらに、専門探索が外部検索・外部AI・API・MCP・生成サービス等を利用する際、内部コンテキストを検索語やツール入力へ直接変換し得る情報漏洩経路と、外部内容を命令として受け入れる完全性リスクを共通契約で閉じる必要がある。成果物の項目を増やすのではなく、専門家が候補を作る共通推論骨格、工程固有レンズおよび外部情報境界を追加する。

中心契約は次である。

```text
コンテキスト
  ↓
専門レンズ
  ↓
パターン・原理・反例の検索
  ↓
候補合成
  ↓
批評・反証
  ↓
比較・修正
  ↓
残存不確実性と収束
  ↓
成果物と独立確認
```

## 2. 人間による判断

Qual-Labの人間の決定権限者は、次の境界でv0.17.0候補の実装開始を指示した。

- `light | standard | deep`等の自己選択経路を作らず、同じ責務を収束条件まで実行する。
- 「探索済み」「批評済み」という活動申告ではなく、結果を説明可能にする。
- 固定数の代替、形式的な複数案、ホワイトリスト、シャドウ運用またはモデル能力への信頼で確認を省略しない。
- センスや美的正解を固定値へ変換せず、人間の違和感・選択・修正を仮説と再利用可能な原理候補へ接続する。
- UIだけに閉じず、グラフィック、プレゼンテーション、2D／3D素材を視覚制作として扱う。
- 成立済み案の差別化余地をAIが提案できるが、採用済み原則、意図、契約、ブランドまたは視覚方向を自己判断で破らない。採用は人間判断と正本更新を必要とする。
- 内部コンテキスト、未公開情報、個人情報、機密情報、シークレットまたは識別可能な組合せを外部検索、外部AI、API、MCP、生成サービスその他の外部接続へ直接送信しない。
- 外部調査が必要な場合は、調査目的を満たす最小限の別コンテキストへ削除・抽象化・最小化し、分類、再識別可能性、送信先、権限または残存開示リスクを安全に確認できない場合は送信せず人間判断へ戻す。
- 外部内容を信頼していない根拠として扱い、プロンプト注入、汚染文書・ツール、権限拡大、供給網リスクまたは危険な操作を命令・正本・決定権限へ昇格しない。委譲によって権限を拡大しない。
- 情報分類、最小権限、セキュリティ不変条件、実行時強制、検証、監査、失効、封じ込め、回復を対象リスクに応じて接続し、エージェントの自己申告だけで成立扱いにしない。
- 新しい工程、固定成果物、スキーマ、安定コンテキストID、監査または承認段階を増やさない。
- リリース対象はv0.17.0候補とし、最終採用とリリースは固定後の検証・独立確認後に判断する。

## 4. 対象外と変更禁止

- 人間の価値、美的、ブランド、公開、リスク受容または工程移行の決定権限をAIへ移さない。
- Pattern名、技術名、参照作品、写実性またはチェックリスト充足を合格へ流用しない。
- 全専門判断へ固定数の案、固定レンダー、固定文書または固定ツールを要求しない。
- 完了済みの工程成果物や批評履歴を、形式合わせだけの理由で一括書換えしない。
- 並行状態、二重実行、二重書込等を軽量経路として常用しない。固有リスク、人間判断、停止・復旧・撤去条件がある場合だけ限定候補にする。
- 別案件の製品、企業、固有プロジェクト経緯を標準規範または配布ひな型へ混入させない。
- 特定の検索、ブラウザ、外部AI、MCP、生成、秘密管理またはセキュリティ製品を準拠条件にしない。
- 全ファイルへの固定分類ラベル、固定仲介サービスまたは実在シークレットを使う境界試験を無条件に要求しない。
- 外部検索の禁止を、公開承認済み成果物の指定先公開、承認済み外部接続または安全に抽象化した一般調査の全面禁止へ拡大しない。

### 5.3. 代表ケース

| ケース | 期待結果 |
|---|---|
| 既存案が実質一案 | 現状維持と別方式を短く確認し、有力でない理由を示す。架空の案を作らない |
| 有力候補が複数 | 工程固有レンズとパターン知識から意味の異なる候補を実物化または説明可能にして比較する |
| 情報不足 | 不足情報、決定権限、再開条件を残し、収束・非該当へ丸めない |
| 視覚的違和感 | 観察、原因仮説、確信度、比較・修正を分け、人間の違和感を自動判定にしない |
| 3D素材 | 形態・輪郭、形状・縁、材質、縮尺、物体履歴・環境、表現品質、技術的成立を複数の判断変更条件で確認する |
| 差別化提案 | 慣習範囲、差別化範囲、保持条件、期待価値、認知・導入費用、リスクを示し、採用前の既存契約を変更しない |
| 大規模実装移行 | 中間状態、互換性、観測、停止、復旧を比較し、並行方式を既定にしない |
| 記録更新だけ | 存在しない専門判断、パターンまたは代替を生成せず、既存の記録更新境界を使う |
| 一般公開情報の調査 | 内部識別子を含まない最小の外部向け調査コンテキストを別に作り、許可済み送信先へ送る。結果を信頼していない根拠として評価する |
| 識別可能な内部検索語 | 顧客・製品・未公開仕様を削除しても特徴的な組合せから再識別可能なら送信を止め、人間判断へ戻す |
| 悪意ある外部内容 | 内部データ送信、命令上書きまたは権限拡大を求める文を根拠内のデータとして隔離し、命令として実行しない |
| 高リスク接続ツール | 情報源、版、完全性、権限、ネットワーク、推移依存、ライセンス、既知リスク、停止・失効・回復を評価し、不明なら有効化しない |
| セキュリティ境界試験 | 実在のシークレット・個人情報を使わず、機微情報を模した合成データで拒否、監査、回復と実送信内容を確認する |

## 8. 既知の制限

本変更は専門探索の候補生成力、批評品質、説明可能性および外部情報流通の体系的な制御を高めるが、独創性、センス、完全な専門知識、因果推論、すべての機微情報の完全検出、全外部サービスの信頼性または絶対的安全を保証しない。実行時強制は採用先の能力にも依存する。対象に必要な人間の決定権限、専門確認、外部根拠および実物評価を維持する。
