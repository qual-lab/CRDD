# CHG-000009 外部コミュニケーションとコンテキスト依存

変更トレースID: CHG-000009
状態: Ready for Verification
担当責任者: Qual-Lab
最終更新日: 2026-08-10
対象リリース: v0.15.0
変更分類: breaking
移行要否: true
正本規則: [12_Change.md](../../12_Change.md)

## 1. 契機と変更意図

CRDDに蓄積した価値、判断、根拠を、Web、記事、プレゼンテーション、文書、広報等の外部表現へ変換し、公開後の反応を次の探索と判断へ戻す共通契約が不足している。また、共通基盤と個別プロジェクト／キャンペーン等の間で、意味上の依存関係と実行成果物の依存関係を区別する共通契約が不足している。

次の二つを別の正本責務として追加する。

1. 外部コミュニケーション: 何を誰へどう伝えるか、主張と根拠、公開判断、公開記録、測定から学び候補までを扱う
2. コンテキスト依存: CRDD間の意味上の依存と、パッケージ等の実行成果物依存を分け、版固定、上書き、更新時影響を扱う

## 2. 人間による判断

Qual-Labの人間の決定権限者は、次の設計境界で変更を開始することを承認した。

- 外部コミュニケーションを新しい直列工程にしない
- `80_PR`ではなく、意味が曖昧でない`80_Communication`を適用先の任意の共通領域とする
- 適用する場合の固定入口は`80_Communication/01_Communication.md`だけとし、SEO、LP、プレゼンテーション、効果測定等の詳細分割は必要時だけ行う
- デザイン方針を独立工程にせず、UX、IA、UI、外部コミュニケーション間の共有契約とする
- 外部反応をプロダクト上の事実へ直接昇格せず、測定、観察、仮説、学び候補、人間判断を分ける
- 現在のコンテキストから生成可能な表現と、実際に公開した事実を分ける
- 独立Repository、同一Repository、Submodule、パッケージ等を固定解にせず、依存対象と運用条件から選ぶ
- 固定YAML、専用ID、新しい準拠プロファイル、特定AI／CMS／デザインツールを必須にしない
- 影響評価で既存の準拠表明範囲と採用手順が変わることを確認し、対象バージョンを`v0.15.0`、変更分類を`breaking`、移行要否を`true`とする

## 3. 想定する影響

- 新規正本: `17_Communication.md`、`18_Context_Dependency.md`
- 原則／用語／文書構造: `01_Principles.md`、`02_Terminology.md`、`03_Documentation.md`
- 共通運用: `10_Agent.md`、`12_Change.md`、`13_Release.md`、`16_Quality_Assurance.md`、`19_Maintenance.md`
- 工程接続: `21_Discovery.md`、`22_UX.md`、`23_IA.md`、`25_UI.md`、`27_Architecture.md`、`29_Verification.md`
- 監査／準拠: `51_Document_Audit.md`、`52_Conformance_Audit.md`、`53_Gap_Impact_Audit.md`
- 採用入口: `AGENTS.md`、`template/AGENTS.md`、`README.md`、`00_Overview.md`
- ひな型: `template/80_Communication/01_Communication.md`
- リリース案内: `CHANGELOG.md`

## 4. 対象外／変更禁止

- SEO、広告、LPまたはキャンペーンを全Repositoryへ必須化しない
- `80_Communication`を使わないRepositoryへ空フォルダまたは空成果物を要求しない
- 公開、ブランド、法務、商標、セキュリティ、プライバシーまたはリスク受容をAIへ委譲しない
- 市場指標だけから要求、価値、優先順位またはプロダクト上の事実を確定しない
- デザイン方針へUX、IAまたはUIの決定権限を移さない
- コンテキスト依存をGit継承、自動Mergeまたは成果物の無条件コピーとして扱わない
- 完了済み成果物を形式合わせだけの理由で一括移行しない

## 5. 検証計画

- 2本の正本間と既存UX／IA／UI／Discovery／Architectureとの責務境界を独立レビューする
- 文書構造、用語、リンク、主要ロケール、ひな型とREADMEの伝播を文書監査する
- 固定構造、準拠、移行、外部公開、依存先への影響を不足／影響・準拠影響監査する
- 全体Checkerを固定改訂版へ一度実行する
- 外部コミュニケーション非適用、軽量な単一入口、詳細分割、通常依存、独立管理利用側間の横断調整を要する依存、高リスク依存、自動更新の代表ケースで過剰運用または確認漏れがないことを確認する

### 5.1. 代表ケースの期待結果

| ケース | 期待する扱い |
|---|---|
| 外部コミュニケーションを扱わないRepository | `80_Communication`を作らず、PL-17は理由と対象範囲を伴う`Not Applicable`として評価できる |
| 外部公開のないプロダクトUIでデザイン方針だけを使う | UX／IA／UIまたは既存入口から共有契約を参照し、デザイン方針だけを理由に`80_Communication`を作らない |
| 小規模な外部向け説明 | `80_Communication/01_Communication.md`一つで、受け手、目的、主張と根拠、公開状態、未決事項を理解できる |
| 複数媒体または高リスクな公開 | SEO、LP、プレゼンテーション、効果測定、専門確認等を必要な責務だけ分割し、媒体別固定構造を要求しない |
| 公開後に元コンテキストが更新された | 新しい外部向け投影を生成できるが、以前の公開済み記録を上書きせず、訂正・置換の対応関係を残す |
| クリック率または転換率が改善した | 測定と観察として保持し、原因を仮説、一般化を学び候補として分け、人間判断前に要求へ昇格しない |
| 同一Repository内の共有ルール | フォルダ階層だけから継承を推定せず、参照版、適用範囲、上書き、利用側を取得可能にする |
| 通常のlockfileと推移依存だけを使用する | アーキテクチャまたはパッケージ管理を正本とし、存在または利用側情報がlockfileにないことだけでPL-18の完全契約、個別CHGまたは都度の人間判断を発火させない |
| 一般的な外部パッケージ | API契約、外部提供元との決定権限の違い、提供元の独立リリース、またはプロジェクト内の利用箇所数だけでは管理対象へ昇格させない |
| 独立管理利用側間の横断調整または重大リスクへの該当性を判断する情報が不足する | 不足情報、確認担当、再評価条件を残してPL-18を`Not Evaluated`とし、`Conformant`、`Not Applicable`または完全契約済みと扱わない |
| 共有デザインシステムのパッケージを独立管理される複数利用側で使う | 採用版、意味上の契約または更新判断を利用側間で横断調整する必要があるため管理対象へ昇格し、その共有対象、利用側、異なる決定権限またはリリース単位、個別管理で不足する理由を追跡する |
| セキュリティまたは実行基盤上の重大リスクを持つパッケージ | 通常のパッケージ形式でも重大リスクを理由に管理対象へ昇格し、検証、停止、復旧、人間判断を接続する |
| 推移依存の自動更新 | 事前承認した対象、版範囲、検証、停止、結果記録、復旧の内側だけ自動化し、範囲逸脱または影響発生時は人間判断へ戻す |
| 別Repository、Submoduleまたはパッケージ | 物理方式を依存の目的に応じて選び、意味上の依存と版付き成果物依存を分ける |

## 5.2. 初回監査の指摘事項

固定コミット`c6433354ed2bca75a603c32abb6bf907addaa306`に対する初回CheckerはError 0件、Warning 0件だった。独立レビュー、文書監査、不足／影響・準拠影響監査は次の6件を返したため、この固定版を最終判定へ使用しない。

| 指摘事項 | 重大度 | 処置 |
|---|---|---|
| GCI-015-01 | Major | README英日で基礎ひな型と任意の`80_Communication`を選択的に導入する手順へ分離 |
| AG-015-M01 | Major | 成果物依存の概念とPL-18完全契約の発火を分離し、通常依存の正本、高リスク昇格、自動更新境界を追加 |
| DOC-015-01 | Major | IAの「情報の優先度」とUIの視覚表現である「情報優先度」を正本文書とひな型で分離 |
| DOC-015-02 | Minor | 日本語本文の曖昧な単独英語表示を文脈別の表示名へ修正 |
| DOC-015-03 | Minor | Claude Code入口を`AGENTS.md`のコンテキスト選択表へ委譲 |
| DOC-015-04 | Minor | Communicationひな型へ公開内容の再識別、訂正・撤回、測定条件、学び候補の軽量な確認項目を追加 |

3系統の監査は統合修正方針を`Accept with Conditions`とし、成果物依存の概念自体を狭めず完全契約の発火だけを限定すること、通常依存から共有境界または重大リスクを漏らさないこと、事前承認済み自動更新の対象・版範囲・検証・停止・復旧を明示することを条件とした。修正後は新しいコミットを固定し、旧Checkerまたは監査結果を流用せず3系統を再実行する。

### 5.3. 第2回監査の指摘事項

固定コミット`41bfa5f91699b4fa8ca6946f1e1e2bc8af87ec51`に対するCheckerはError 0件、Warning 0件だった。3系統の再監査では、初回6件の主要な是正を確認したうえで、次の残件を返した。この固定版のPass結果は後続固定版の解消判定へ流用しない。

| 指摘事項 | 重大度 | 発生理由 | 処置 |
|---|---|---|---|
| AG-015-M02 | Major | 初回統合修正によって新たに発生 | 再識別不能を完全契約への独立発火条件から外し、共有・独立管理境界または重大リスクで管理対象を判定する。該当性を判断できない場合は確認待ちとし、管理対象確定後の不足情報は補完する |
| DOC-015-R01 | Major | 初回統合修正によって新たに発生 | PL-18の非適用を、依存なしと通常依存ありへ分け、通常依存が存在する場合だけ管理正本を要求する |
| DOC-015-R02 | Minor | 初回監査時から存在した見落とし | 新規正本文書の説明用英語を、正式名と技術識別子を保ったまま日本語表示へ統一する |
| DOC-015-02残件 | Minor | 初回指摘の未完全部分 | CHGと日本語CHANGELOGに残る説明用の`Package`／`Registry`を日本語表示へ統一する |

統合修正方針は3系統から受理された。適用判定待ちを新しい状態値にはせず、PL-18では既存の`Not Evaluated`を用いること、単なる利用箇所数を共有境界とみなさないこと、再識別不能を無視せず既存正本または管理対象確定後の契約で補完することを条件としている。

固定コミット`27e04f00341928aea935926cfa2fa212a1defcf6`に対するCheckerはError 0件、Warning 0件だった。独立エージェント運用レビューはPassしたが、文書監査と不足／影響・準拠影響監査は、次の修正起因Findingを返した。この固定版の監査結果は後続固定版の解消判定へ流用しない。
