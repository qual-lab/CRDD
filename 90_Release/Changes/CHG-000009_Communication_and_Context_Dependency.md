# CHG-000009 外部コミュニケーションとコンテキスト依存

変更トレースID: CHG-000009
状態: Ready for Verification
担当責任者: Qual-Lab
最終更新日: 2026-08-10
対象リリース: v0.15.0
変更分類: breaking
移行要否: true
正本規則: [12_Change.md](../../12_Change.md)

## 1. 契機と変更意図

CRDDに蓄積した価値、判断、根拠を、Web、記事、プレゼンテーション、文書、広報等の外部表現へ変換し、公開後の反応を次の探索と判断へ戻す共通契約が不足している。また、共通基盤と個別プロジェクト／キャンペーン等の間で、意味上の依存関係と実行成果物の依存関係を区別する共通契約が不足している。

次の二つを別の正本責務として追加する。

1. 外部コミュニケーション: 何を誰へどう伝えるか、主張と根拠、公開判断、公開記録、測定から学び候補までを扱う
2. コンテキスト依存: CRDD間の意味上の依存と、パッケージ等の実行成果物依存を分け、版固定、上書き、更新時影響を扱う

## 2. 人間による判断

Qual-Labの人間の決定権限者は、次の設計境界で変更を開始することを承認した。

- 外部コミュニケーションを新しい直列工程にしない
- `80_PR`ではなく、意味が曖昧でない`80_Communication`を適用先の任意の共通領域とする
- 適用する場合の固定入口は`80_Communication/01_Communication.md`だけとし、SEO、LP、プレゼンテーション、効果測定等の詳細分割は必要時だけ行う
- デザイン方針を独立工程にせず、UX、IA、UI、外部コミュニケーション間の共有契約とする
- 外部反応をプロダクト上の事実へ直接昇格せず、測定、観察、仮説、学び候補、人間判断を分ける
- 現在のコンテキストから生成可能な表現と、実際に公開した事実を分ける
- 独立Repository、同一Repository、Submodule、Package等を固定解にせず、依存対象と運用条件から選ぶ
- 固定YAML、専用ID、新しい準拠プロファイル、特定AI／CMS／デザインツールを必須にしない
- 影響評価で既存の準拠表明範囲と採用手順が変わることを確認し、対象バージョンを`v0.15.0`、変更分類を`breaking`、移行要否を`true`とする

## 3. 想定する影響

- 新規正本: `17_Communication.md`、`18_Context_Dependency.md`
- 原則／用語／文書構造: `01_Principles.md`、`02_Terminology.md`、`03_Documentation.md`
- 共通運用: `10_Agent.md`、`12_Change.md`、`13_Release.md`、`16_Quality_Assurance.md`、`19_Maintenance.md`
- 工程接続: `21_Discovery.md`、`22_UX.md`、`23_IA.md`、`25_UI.md`、`27_Architecture.md`、`29_Verification.md`
- 監査／準拠: `51_Document_Audit.md`、`52_Conformance_Audit.md`、`53_Gap_Impact_Audit.md`
- 採用入口: `AGENTS.md`、`template/AGENTS.md`、`README.md`、`00_Overview.md`
- ひな型: `template/80_Communication/01_Communication.md`
- リリース案内: `CHANGELOG.md`

## 4. 対象外／変更禁止

- SEO、広告、LPまたはCampaignを全Repositoryへ必須化しない
- `80_Communication`を使わないRepositoryへ空フォルダまたは空成果物を要求しない
- 公開、ブランド、法務、商標、セキュリティ、プライバシーまたはリスク受容をAIへ委譲しない
- 市場指標だけから要求、価値、優先順位またはプロダクト上の事実を確定しない
- デザイン方針へUX、IAまたはUIの決定権限を移さない
- Context DependencyをGit継承、自動Mergeまたは成果物の無条件コピーとして扱わない
- 完了済み成果物を形式合わせだけの理由で一括移行しない

## 5. 検証計画

- 2本の正本間と既存UX／IA／UI／Discovery／Architectureとの責務境界を独立レビューする
- 文書構造、用語、リンク、主要ロケール、ひな型とREADMEの伝播を文書監査する
- 固定構造、準拠、移行、外部公開、依存先への影響を不足／影響・準拠影響監査する
- 全体Checkerを固定改訂版へ一度実行する
- 外部コミュニケーション非適用、軽量な単一入口、詳細分割、別Repository依存の代表ケースで過剰運用がないことを確認する

### 5.1. 代表ケースの期待結果

| ケース | 期待する扱い |
|---|---|
| 外部コミュニケーションを扱わないRepository | `80_Communication`を作らず、PL-17は理由と対象範囲を伴う`Not Applicable`として評価できる |
| 外部公開のないプロダクトUIでデザイン方針だけを使う | UX／IA／UIまたは既存入口から共有契約を参照し、デザイン方針だけを理由に`80_Communication`を作らない |
| 小規模な外部向け説明 | `80_Communication/01_Communication.md`一つで、受け手、目的、主張と根拠、公開状態、未決事項を理解できる |
| 複数媒体または高リスクな公開 | SEO、LP、プレゼンテーション、効果測定、専門確認等を必要な責務だけ分割し、媒体別固定構造を要求しない |
| 公開後に元コンテキストが更新された | 新しい外部向け投影を生成できるが、以前の公開済み記録を上書きせず、訂正・置換の対応関係を残す |
| クリック率または転換率が改善した | 測定と観察として保持し、原因を仮説、一般化を学び候補として分け、人間判断前に要求へ昇格しない |
| 同一Repository内の共有ルール | フォルダ階層だけから継承を推定せず、参照版、適用範囲、上書き、利用側を取得可能にする |
| 別Repository、SubmoduleまたはPackage | 物理方式を依存の目的に応じて選び、意味上の依存と版付き成果物依存を分ける |
| 依存先の新しい版が利用可能になった | 自動適用せず、差分、上書き、利用側、過去根拠、移行、復旧、延期時リスクを確認して人間判断へ渡す |

## 6. 現在の処置

2本の共通契約、任意の単一入口、工程接続、AI入口、監査、条件付き準拠基準PL-17／PL-18、英日公開案内と移行注記を`v0.15.0`候補へ反映した。現在の処置は`Ready for Verification`であり、固定改訂版に対する機械確認、独立レビュー、文書監査、不足／影響と準拠影響監査を待つ。統合と公開識別子は未確定。
