# REQ-000024の利用者体験分析

成果物種別: UX分析

状態: UX再統合済み・独立再レビュー待ち
分析対象: [REQ-000024 境界を越えるタスク結果の帰還](../../../01_Discovery/Definitions/REQ-000024/requirement.md)

## 1. 要求の一次分析

```text
Agent結果を探し、元の相談へ貼り戻す／別タスクの結果混入を人間が見分ける
        ↓
解決策を先に固定せず、人の仕事として読み替える
        ↓
利用者に必要なこと
境界を越えた結果を同じタスクへ受け取る
```

この要求で解くのは機能の有無だけではない。仕事を委ねた人が「根拠と未確認範囲を保って採否を判断できる」状態へ進めないことを問題として扱う。具体的な画面、データ構造、API、構成要素または数値閾値はここで確定しない。

| 観点 | 内容 |
|---|---|
| 解決する問題 | Agent結果を探し、元の相談へ貼り戻す／別タスクの結果混入を人間が見分ける |
| 利用者に必要なこと | 境界を越えた結果を同じタスクへ受け取る |
| 対象範囲 | タスクを委ねる人、結果を受け取る人が、「Agent結果を探し、元の相談へ貼り戻す」状態から「同じタスクに結果、根拠、未解決事項が戻る」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

        ▼

## 3. 利用者に起きる変化

```text
変更前
────────────────
- Agent結果を探し、元の相談へ貼り戻す
- 別タスクの結果混入を人間が見分ける
        │
        │ 境界を越えるタスク結果の帰還が変える体験
        ▼
変更後
────────────────
- 同じタスクに結果、根拠、未解決事項が戻る
- タスクの識別情報と情報源との結び付けから帰還先を確認する
```

コーディングAIが結果を作っても、元の対話やプロジェクト判断へ戻らなければ、人間が再び転記・照合しなければならない。結果だけでなく、どのタスクと情報から生まれたかを保つ必要がある。

この変化で守るのは操作手順ではない。仕事を委ねた人が境界を越えた結果を同じタスクへ受け取ることで、根拠と未確認範囲を保って採否を判断できるようになることを守る。

## 5. 重要な体験

### この要求での利用の流れ

```text
Agentや実行基盤から結果が戻る時
        ↓
タスクの識別情報・結果・根拠・帰還状態を照合する
        │
        ├─ ★ 重要場面: 結果を候補として受け入れる場面
        ├─ ⚠ 失敗:  別タスクや改訂版の結果を混入し自動採用する
        └─ ✓ 守る品質:  相関識別情報と完全性を保持する
        ↓
根拠と未確認範囲を保って採否を判断できる
```

### サービス提供の流れの処置

処置: `作成`

```text
【利用者・責任者】仕事を委ねた人（プロジェクト運営者／PM）
        │ 利用者行動: 境界を越えた結果を同じタスクへ受け取る
        ▼
【利用者接点】Agentや実行基盤から結果が戻る時
        │
        ├─ 時間差: 外部実行完了と結果帰還は別時点で成立し、搬送だけが途切れ得る
        ├─ 完了時: タスクの識別情報、結果、根拠、未確認範囲、帰還状態
        └─ 失敗時: 不完全または相関不能な帰還結果を仕事を委ねた人へ返す
                     │
                     ▼
             【回復・判断する人】プロジェクト運営者／正本責任者（結果採否の判断役割）
                     │ 返却された事実と判断不能範囲を確認
                     └─ 次の行動: 同じタスクの結果再取得、追加確認、回復または採否判断を選ぶ

---------------- 可視境界 ----------------
                     │ 時間関係: 外部実行完了と結果帰還は別時点で成立し、搬送だけが途切れ得る
                     ▼
【提供側】Agent／実行基盤
        └─ 提供責務: 結果・根拠・未確認範囲・帰還状態を同じタスクへ返す
```

この図は、利用者行動、利用者が観測する接点、提供責務および失敗時の引き渡しを示す。内部構成要素の構造やプロトコルは下流工程で具体化する。

### 製品全体の整理への接続

- 利用の流れの統合先: [外部情報を送受信する](../../03_Experience_Map.md#外部情報を送受信する)
- サービス提供の流れの統合先: [共同のサービス提供の流れ](../../04_Service_Blueprint.md#1-共同のサービス提供の流れ)
- 横断成果物はこの個別分析から共通パターンを合成する。この要求での利用の流れ、責任境界または品質の代替にはしない。

### この要求での責任境界

| 担い手 | この要求で担うこと | 越えてはならない境界 |
|---|---|---|
| 仕事を委ねた人 | タスクと帰還先を確認し、戻った結果の採否を判断する | 別タスクや改訂版の結果を同一視しない |
| Agent／実行基盤 | 結果・根拠・未確認範囲・帰還状態を同じタスクへ返す | Agent完了を成果物採用として表示しない |
| プロジェクト運営者／正本責任者 | 候補を採用・却下・再作業へ振り分ける | 所有しない正本へ結果を自動反映しない |

### 補足する品質

- 結果または状態を最初に受け取る時: 結果、根拠、未確認範囲、残存リスクを同じタスクへ結ぶ。（避ける失敗: Agent結果を探し、元の相談へ貼り戻す）
- 結果を判断または引き継ぐ時: 別プロジェクト、別改訂版、別タスクの結果を混ぜない。（避ける失敗: 必要条件を満たしていないのに完了・正常と理解する）
- 結果を判断または引き継ぐ時: Agent完了を成果物採用や外部作用（Effect）成功と表示しない。（避ける失敗: 必要条件を満たしていないのに完了・正常と理解する）
- 失敗・不足から次の行動を選ぶ時: 帰還失敗時も生成済み結果の所在と再取得方法を保持する。（避ける失敗: 成立不能の理由や回復先が分からないまま作業が止まる）

### 妥当性確認と未確認事項

| 確認する仮説 | 観測方法 | 現在未確認の範囲 |
|---|---|---|
| 同じタスクに結果、根拠、未解決事項が戻る／タスクの識別情報と情報源との結び付けから帰還先を確認することで、Agent結果を探し、元の相談へ貼り戻すという負担または誤認を減らせる。 | 代表シナリオの利用者確認、利用者体験の専門レビュー、および品質期待を破る反例による下流検証 | プロジェクト運営者／PMが「境界を越えた結果を同じタスクへ受け取る」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |

### 工程別の引き渡し

| 引き渡し先 | 具体化する義務 |
|---|---|
| 下流工程 | IAはタスク、受け渡す情報一式、結果、根拠、判断および引き渡しを関係付ける。SPEC／Architectureは相関識別情報を通信方式境界で保持し、Verificationは誤配送と欠落を反証する。 |

Discoveryへ戻す条件は、想定した利用者、問題または「境界を越えた結果を同じタスクへ受け取る」という必要性が誤っていると分かった場合である。下流は実現方式を具体化してよいが、「根拠と未確認範囲を保って採否を判断できる」という成果を無断で弱めない。
