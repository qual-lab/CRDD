# REQ-000028の利用者体験分析

成果物種別: UX分析

状態: UX再統合済み・独立再レビュー待ち
分析対象: [REQ-000028 AI入口と共通正本の分離](../../../01_Discovery/Definitions/REQ-000028/requirement.md)

## 1. 要求の一次分析

```text
入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる
        ↓
解決策を先に固定せず、人の仕事として読み替える
        ↓
利用者に必要なこと
入口が違っても同じCRDD正本と判断境界を使う
```

この要求で解くのは入口ファイルの有無だけではない。異なるAIを利用する人が、入口ごとに別の規範や判断を覚えず、同じCRDD正本と判断境界へ到達できる状態へ進めないことを問題として扱う。具体的な入口形式、Prompt構造またはAgent実装はここで確定しない。

| 観点 | 内容 |
|---|---|
| 解決する問題 | 入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる |
| 利用者に必要なこと | 入口が違っても同じCRDD正本と判断境界を使う |
| 対象範囲 | 対話AI・コーディングAIを使う人が、「入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる」状態から「どのAI入口からでも同じ正本と境界へ案内され、入口固有差だけを理解すればよい」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

## 2. 利用者・目標・成果

```text
異なるAI入口を利用する開発者
        │
        │ 望んでいる
        ▼
入口が違っても同じCRDD正本と判断境界を使う
        │
        │ その結果として
        ▼
入口固有差だけを理解し、同じ基準で仕事を続けられる
```

| 項目 | 内容 |
|---|---|
| 主な想定利用者 | [製品全体の利用者像](../../02_Personas.md)の「開発者」 |
| 利用場面 | Codex、Claude、Copilot等から作業入口を選ぶ時 |
| 目的 | 入口が違っても同じCRDD正本と判断境界を使う |
| 得られる結果 | 入口固有差だけを理解し、同じ基準で仕事を続けられる |
| この要求に固有の差 | AI固有入口を案内と固有制約に限定し、共通規範を複製しないことが成立条件になる |
| 根拠・確信度 | 採用要求から導いた仮説。複数AI入口で同じ代表作業を行った際に、参照正本と判断境界が一致するかは未確認。 |

## 3. 利用者に起きる変化

```text
変更前
────────────────
- 入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる
        │
        │ AI入口と共通正本の分離が変える体験
        ▼
変更後
────────────────
- どのAI入口からでも同じ正本と境界へ案内され、入口固有差だけを理解すればよい
```

AI入口と共通正本の分離は、単に内部方式を成立させる要求ではない。「入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる」状態から、「どのAI入口からでも同じ正本と境界へ案内され、入口固有差だけを理解すればよい」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

この変化で守るのは一つの入口形式ではない。異なるAI入口を利用する人が、入口が違っても同じCRDD正本と判断境界を使い、入口固有差だけを理解して同じ基準で仕事を続けられることを守る。

## 4. 利用者成果への統合

```text
REQ-000028
   │
   └─ Same → UX-000012 入口を変えても同じ仕事を続ける
```

| 利用者成果 | 処置 | 判断理由 | この要求が補う内容 |
|---|---|---|---|
| 入口を変えても同じ仕事を続ける | `Same → UX-000012` | 4軸比較で同じ利用者成果と判断した。詳細は次の比較を参照。 | AI固有入口を第二のCRDD標準にせず、複数AIから同じ正本と判断境界へ到達する |

### Same判断の比較

#### 入口を変えても同じ仕事を続ける

比較対象: `UX-000012`

比較元: `REQ-000006`でこのUXを最初に`New`とした固有記載。得られる結果は同分析のUX固有行、他の軸は同分析と初版Definitionの一致を確認して固定した。

| 比較軸 | 既存UX | 現在の要求 | 差と統合判断 |
|---|---|---|---|
| 担い手 | 開発者 | 異なるAI入口を利用する開発者 | 現在の要求は同じ利用者をAI入口の違いが現れる場面へ限定している。 |
| 利用のきっかけ | 利用する接続方式を選ぶ時 | Codex、Claude、Copilot等から作業入口を選ぶ時 | 現在の要求はAI入口を具体化するが、入口を選んで同じ仕事を始める契機は同じである。 |
| 得られる結果 | stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる | 入口固有差だけを理解し、同じ基準で仕事を続けられる | 現在要求は通信方式間の同値性を複数AI入口へ広げるが、入口差を読み替えず同じ仕事を続ける中心成果は同じである |
| 避ける失敗 | 接続方式ごとに状態や結果が変わる | 入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる | 最初のNew分析で確認された失敗に対し、現在要求は「入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる」へ具体化するが、中心成果を妨げる同じ失敗として扱える |

統合理由: AI固有入口を案内と固有制約へ限定することは、入口を変えても同じ仕事を続ける成果の成立条件であり、別の利用者成果ではない。

`Same`／`New`は技術用語の近さや件数目標では決めない。「利用者は、どの状況で、何をするためにシステムと関わり、何ができるようになるか」が同じかを比較する。提供能力、必要情報、品質、妥当性確認または下流の実現要素は、独立UXへ分割せず対応する成果の成立条件として保持する。

## 5. 重要な体験

### この要求での利用の流れ

```text
異なるAI入口から代表作業を始める時
        ↓
参照する共通規範・工程正本・AI固有制約を確認する
        │
        ├─ ★ 重要場面: 入口が適用規則と正本を選ぶ場面
        ├─ ⚠ 失敗:  入口文書が第二正本になり同じ作業の判断が分岐する
        └─ ✓ 守る品質:  同じ正本・適用規則・判断境界と差分理由を追跡できる
        ↓
入口固有差だけを理解し、同じ基準で仕事を続けられる
```

### サービス提供の流れの処置

処置: `作成`

```text
【利用者・責任者】異なるAI入口を利用する開発者
        │ 利用者行動: 入口が違っても同じCRDD正本と判断境界を使う
        ▼
【利用者接点】Codex、Claude、Copilot等から作業入口を選ぶ時
        │
        ├─ 時間差: 入口は別々に更新されても共通正本は一つの現在値を持つ
        ├─ 完了時: 参照正本、適用規則、判断境界、AI固有制約、差分理由
        └─ 失敗時: 正本へ到達不能または入口間判断差を開発者へ返す
                     │
                     ▼
             【回復・判断する人】異なるAI入口を利用する開発者
                     │ 返却された事実と判断不能範囲を確認
                     └─ 次の行動: 正本接続を直すか、差分理由を確認して入口を選び直す

---------------- 可視境界 ----------------
                     │ 時間関係: AI固有入口は共通正本の更新と独立して案内だけを更新する
                     ▼
【提供側】AI固有入口／Agent
        └─ 提供責務: 共通正本へ案内し、固有制約だけを追加する
```

この図は、利用者行動、利用者が観測する接点、提供責務および失敗時の引き渡しを示す。内部構成要素の構造やプロトコルは下流工程で具体化する。

### 製品全体の整理への接続

- 利用の流れの統合先: [リポジトリで日常作業を進める](../../03_Experience_Map.md#リポジトリで日常作業を進める)
- サービス提供の流れの統合先: [共同のサービス提供の流れ](../../04_Service_Blueprint.md#1-共同のサービス提供の流れ)
- 横断成果物はこの個別分析から共通パターンを合成する。この要求での利用の流れ、責任境界または品質の代替にはしない。

### この要求での責任境界

| 担い手 | この要求で担うこと | 越えてはならない境界 |
|---|---|---|
| 開発者 | 仕事に合うAI入口を選び、提示された正本と固有制約を確認する | 入口固有の説明を共通規範そのものとみなさない |
| AI固有入口 | 共通正本へ案内し固有制約を明示する | 共通規範や工程判断を複製・再定義しない |
| 共通CRDD正本 | 入口に依存しない規範と工程判断を所有する | AI固有文法や制約まで一形式へ強制しない |

### 補足する品質

- 作業を開始する時: 入口文書を第二の正本にしない。（避ける失敗: 入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になる）
- 入口を切り替える時: 適用規則と判断境界が同じで、固有差の理由を追跡できる。
- 正本へ到達できない時: 入口が規則を推測補完せず、接続不能として返す。


## 6. 下流への引き渡し

```text
この要求で確定した利用者成果
        │
        ├─→ IA: 必要な情報・関係・見つけ方
        ├─→ UI: 誤認させない表示・操作意図
        ├─→ SPEC: 振る舞い・失敗・体験品質の条件
        └─→ Verification: 仮説を破る反例と観測
```

### 妥当性確認と未確認事項

| 確認する仮説 | 観測方法 | 現在未確認の範囲 |
|---|---|---|
| どのAI入口からでも同じ正本と境界へ案内され、入口固有差だけを理解すればよいことで、入口ごとに複製された規則が食い違い、同じリポジトリで異なる判断になるという負担または誤認を減らせる。 | 代表シナリオの利用者確認、利用者体験の専門レビュー、および品質期待を破る反例による下流検証 | 開発者が「入口が違っても同じCRDD正本と判断境界を使う」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |

### 工程別の引き渡し

| 引き渡し先 | 具体化する義務 |
|---|---|
| 下流工程 | DocumentationとAgent設計は案内と正本を分け、Verificationは複数入口で同じ基準が選ばれることを確認する。 |

Discoveryへ戻す条件は、想定した利用者、問題または「入口が違っても同じCRDD正本と判断境界を使う」という必要性が誤っていると分かった場合である。下流は実現方式を具体化してよいが、「入口固有差だけを理解し、同じ基準で仕事を続けられる」という成果を無断で弱めない。
