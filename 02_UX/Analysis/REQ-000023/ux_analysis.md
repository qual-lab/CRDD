分析対象: [REQ-000023 異なるAI実行環境の違いに応じた接続部分離](../../../01_Discovery/Definitions/REQ-000023/requirement.md)

## 1. 要求の一次分析

```text
名前やCLI形状が似ているだけで既存接続部へ設定し、認証・取消・回復が壊れる
        ↓
解決策を先に固定せず、人の仕事として読み替える
        ↓
利用者に必要なこと
AI提供元固有の一連の状態変化を接続部越しに正確に扱う
```

この要求で解くのは機能の有無だけではない。実行基盤保守者・運用者が「AI提供元差を隠さず共通実行基盤から安全に利用できる」状態へ進めないことを問題として扱う。具体的な画面、データ構造、API、構成要素または数値閾値はここで確定しない。

| 観点 | 内容 |
|---|---|
| 解決する問題 | 名前やCLI形状が似ているだけで既存接続部へ設定し、認証・取消・回復が壊れる |
| 利用者に必要なこと | AI提供元固有の一連の状態変化を接続部越しに正確に扱う |
| 対象範囲 | AI実行基盤を追加・利用する人が、「名前やCLI形状が似ているだけで既存接続部へ設定し、認証・取消・回復が壊れる」状態から「現在実行基盤が対応する一連の状態変化と未対応範囲を理解し、適切な接続部経由で利用できる」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

## 3. 利用者に起きる変化

```text
変更前
────────────────
- 名前やCLI形状が似ているだけで既存接続部へ設定し、認証・取消・回復が壊れる
        │
        │ 異なるAI実行環境の違いに応じた接続部分離が変える体験
        ▼
変更後
────────────────
- 現在実行基盤が対応する一連の状態変化と未対応範囲を理解し、適切な接続部経由で利用できる
```

AI実行環境の違いに応じて接続方法を分けることは、単に内部方式を成立させる要求ではない。「名前やCLI形状が似ているだけで既存接続部へ設定し、認証・取消・回復が壊れる」状態から、「現在実行基盤が対応する一連の状態変化と未対応範囲を理解し、適切な接続部経由で利用できる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

この変化で守るのは操作手順ではない。実行基盤保守者・運用者がAI提供元固有の一連の状態変化を接続部越しに正確に扱うことで、AI提供元差を隠さず共通実行基盤から安全に利用できるようになることを守る。

`Same`／`New`は技術用語の近さや件数目標では決めない。「利用者は、どの状況で、何をするためにシステムと関わり、何ができるようになるか」が同じかを比較する。提供能力、必要情報、品質、妥当性確認または下流の実現要素は、独立UXへ分割せず対応する成果の成立条件として保持する。

## 5. 重要な体験

### この要求での利用の流れ

```text
AI提供元を選択・取消・回復する時
        ↓
現在機能と開始から終了・回復までの意味を確認する
        │
        ├─ ★ 重要場面: AI提供元へ変更を依頼すると完了観測の境界
        ├─ ⚠ 失敗:  設定可能を実行可能とみなし同じ取消挙動を仮定する
        └─ ✓ 守る品質:  開始・完了・取消・回復差を外在化する
        ↓
AI提供元差を隠さず共通実行基盤から安全に利用できる
```

### サービス提供の流れの処置

処置: `作成`

```text
【利用者・責任者】実行環境の導入・運用者
        │ 利用者行動: AI提供元差と現在状態を理解して開始・取消・回復を選ぶ
        ▼
【利用者接点】AI提供元を選択・取消・回復する時
        │
        ├─ 時間差: AI提供元ごとに開始・取消・終了・回復の通知時点が異なる
        ├─ 完了時: AI提供元固有状態、発生済み外部作用（Effect）、取消結果、回復要否
        └─ 失敗時: 観測できない状態をAI提供元との境界から実行環境の導入・運用者へ返す
                     │
                     ▼
             【回復・判断する人】実行環境の導入・運用者
                     │ 返却された事実と判断不能範囲を確認
                     └─ 次の行動: 待機、取消継続、状態確認、回復または別AI提供元を選ぶ

---------------- 可視境界 ----------------
                     │ 時間関係: AI提供元ごとに開始・取消・終了・回復の通知時点が異なる
                     ▼
【提供側】提供システム
        └─ 提供責務: AI提供元固有の一連の状態変化を失わず共通の判断材料として返す
```

この図は、利用者行動、利用者が観測する接点、提供責務および失敗時の引き渡しを示す。内部構成要素の構造やプロトコルは下流工程で具体化する。

### 製品全体の整理への接続

- 利用の流れの統合先: [実行基盤を導入・更新・回復する](../../03_Experience_Map.md#実行基盤を導入更新回復する)
- サービス提供の流れの統合先: [共同のサービス提供の流れ](../../04_Service_Blueprint.md#1-共同のサービス提供の流れ)
- 横断成果物はこの個別分析から共通パターンを合成する。この要求での利用の流れ、責任境界または品質の代替にはしない。

### この要求での責任境界

| 担い手 | この要求で担うこと | 越えてはならない境界 |
|---|---|---|
| 実行環境の導入・運用者 | AI提供元差と現在状態を理解して開始・取消・回復を選ぶ | 設定可能を実行可能とみなさない |
| 提供システム | AI提供元固有の一連の状態変化を失わず共通の判断材料として返す | 異なる取消・回復を同一挙動と仮定しない |
| AI提供元 | 実際の受理・開始・完了・残存状態を通知する | 要求受理を外部作用（Effect）完了として報告しない |

### 補足する品質

- 結果または状態を最初に受け取る時: 設定可能を実行可能と見せない。（避ける失敗: 名前やCLI形状が似ているだけで既存接続部へ設定し、認証・取消・回復が壊れる）
- 結果を判断または引き継ぐ時: AI提供元固有の停止・回復差を隠さない。（避ける失敗: 必要条件を満たしていないのに完了・正常と理解する）
- 失敗・不足から次の行動を選ぶ時: 未対応実行基盤は外部変更の前に停止する。（避ける失敗: 成立不能の理由や回復先が分からないまま作業が止まる）
