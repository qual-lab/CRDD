# REQ-000032の利用者体験分析

成果物種別: UX分析

状態: UX再統合済み・独立再レビュー待ち
分析対象: [REQ-000032 工程固有の基本図と意図引き渡し](../../../01_Discovery/Definitions/REQ-000032/requirement.md)

## 1. 要求の一次分析

```text
文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられない
        ↓
解決策を先に固定せず、人の仕事として読み替える
        ↓
利用者に必要なこと
工程固有の図から状態・関係・未接続を理解する
```

この要求で解くのは機能の有無だけではない。設計・実装・検証を引き継ぐ人が「後工程で意図を再発明せず漏れを発見できる」状態へ進めないことを問題として扱う。具体的な画面、データ構造、API、構成要素または数値閾値はここで確定しない。

| 観点 | 内容 |
|---|---|
| 解決する問題 | 文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられない |
| 利用者に必要なこと | 工程固有の図から状態・関係・未接続を理解する |
| 対象範囲 | 設計者、実装者、検証者が、「文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられない」状態から「工程固有の基本図から全体像と未接続箇所を理解し、次工程の確認対象へ進める」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

## 3. 利用者に起きる変化

```text
変更前
────────────────
- 文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられない
        │
        │ 工程固有の基本図と意図引き渡しが変える体験
        ▼
変更後
────────────────
- 工程固有の基本図から全体像と未接続箇所を理解し、次工程の確認対象へ進める
```

工程固有の基本図と意図引き渡しは、単に内部方式を成立させる要求ではない。「文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられない」状態から、「工程固有の基本図から全体像と未接続箇所を理解し、次工程の確認対象へ進める」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

この変化で守るのは操作手順ではない。設計・実装・検証を引き継ぐ人が工程固有の図から状態・関係・未接続を理解することで、後工程で意図を再発明せず漏れを発見できるようになることを守る。

## 4. 利用者成果への統合

```text
REQ-000032
   │
   └─ New  → UX-000028 工程固有の図から意図を引き継ぐ
```

| 利用者成果 | 処置 | 判断理由 | この要求が補う内容 |
|---|---|---|---|
| 工程固有の図から意図を引き継ぐ | `New → UX-000028` | 本要求が「工程固有の図から全体像・関係・状態差・未接続を理解し、後工程で意図を再発明せずに引き継げる」という独立した利用者成果を最初に定義する。 | 基本図と理由付き処置から全体像を確認することが、この要求固有の成立条件になる |

`Same`／`New`は技術用語の近さや件数目標では決めない。「利用者は、どの状況で、何をするためにシステムと関わり、何ができるようになるか」が同じかを比較する。提供能力、必要情報、品質、妥当性確認または下流の実現要素は、独立UXへ分割せず対応する成果の成立条件として保持する。

## 5. 重要な体験

### この要求での利用の流れ

```text
工程の入口・出口で成果物を渡す時
        ↓
基本図と理由付き処置から全体像を確認する
        │
        ├─ ★ 重要場面: 下流義務へ変換する場面
        ├─ ⚠ 失敗:  必要な図を黙って省略しAIごとに記法が変わる
        └─ ✓ 守る品質:  図の意味・凡例・正本関係を固定する
        ↓
後工程で意図を再発明せず漏れを発見できる
```

### サービス提供の流れの処置

処置: `作成`

```text
【利用者・責任者】設計・実装・検証を引き継ぐ人（CRDD閲覧者）
        │ 利用者行動: 工程固有の図から状態・関係・未接続を理解する
        ▼
【利用者接点】工程の入口・出口で成果物を渡す時
        │
        ├─ 時間差: 上流工程の確定後に下流が受け取り、欠落時は工程間で差し戻す
        ├─ 完了時: 工程固有図、入力意味、未接続、下流義務、非該当理由
        └─ 失敗時: 図と正本の不一致または未接続義務を品質確認者から上流責任者へ返す
                     │
                     ▼
             【回復・判断する人】上流工程の成果物責任者（CRDD作成者・保守者）
                     │ 返却された事実と判断不能範囲を確認
                     └─ 次の行動: 上流成果物を補完するか、下流で扱う義務を明示する

---------------- 可視境界 ----------------
                     │ 時間関係: 上流工程の確定後に下流が受け取り、欠落時は工程間で差し戻す
                     ▼
【提供側】上流工程の成果物責任者
        └─ 提供責務: 工程固有の基本図と非該当理由を残す
```

この図は、利用者行動、利用者が観測する接点、提供責務および失敗時の引き渡しを示す。内部構成要素の構造やプロトコルは下流工程で具体化する。

### 製品全体の整理への接続

- 利用の流れの統合先: [標準を変更・検証・公開する](../../03_Experience_Map.md#標準を変更検証公開する)
- サービス提供の流れの統合先: [共同のサービス提供の流れ](../../04_Service_Blueprint.md#1-共同のサービス提供の流れ)
- 横断成果物はこの個別分析から共通パターンを合成する。この要求での利用の流れ、責任境界または品質の代替にはしない。

### この要求での責任境界

| 担い手 | この要求で担うこと | 越えてはならない境界 |
|---|---|---|
| 上流工程の成果物責任者 | 工程固有の基本図と非該当理由を残す | 必要な図を黙って省略しない |
| 下流工程の担当者 | 図から保持する意図と具体化対象を受け取る | 不足を独自解釈で再発明しない |
| 品質確認者 | 図・設計要素・試験観点の接続を確認する | 図の存在だけで意味伝達をPassにしない |

### 補足する品質

- 結果または状態を最初に受け取る時: 図がない場合も理由を明示する。（避ける失敗: 文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられない）
- 結果を判断または引き継ぐ時: 機械的な記法で可読性を失わない。（避ける失敗: 必要条件を満たしていないのに完了・正常と理解する）
- 失敗・不足から次の行動を選ぶ時: 図の要素を実装・試験へ接続する。（避ける失敗: 成立不能の理由や回復先が分からないまま作業が止まる）


## 6. 下流への引き渡し

```text
この要求で確定した利用者成果
        │
        ├─→ IA: 必要な情報・関係・見つけ方
        ├─→ UI: 誤認させない表示・操作意図
        ├─→ SPEC: 振る舞い・失敗・体験品質の条件
        └─→ Verification: 仮説を破る反例と観測
```

### 妥当性確認と未確認事項

| 確認する仮説 | 観測方法 | 現在未確認の範囲 |
|---|---|---|
| 工程固有の基本図から全体像と未接続箇所を理解し、次工程の確認対象へ進めることで、文章だけでは状態・Block・順序・Data責務の抜けを後工程まで見つけられないという負担または誤認を減らせる。 | 代表シナリオの利用者確認、利用者体験の専門レビュー、および品質期待を破る反例による下流検証 | CRDD作成者・保守者が「工程固有の図から状態・関係・未接続を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |

### 工程別の引き渡し

| 引き渡し先 | 具体化する義務 |
|---|---|
| 下流工程 | 各工程は図の意味と処置を所有し、Checkerは欠落を、レビューは意味の正しさを確認する。 |

Discoveryへ戻す条件は、想定した利用者、問題または「工程固有の図から状態・関係・未接続を理解する」という必要性が誤っていると分かった場合である。下流は実現方式を具体化してよいが、「後工程で意図を再発明せず漏れを発見できる」という成果を無断で弱めない。
