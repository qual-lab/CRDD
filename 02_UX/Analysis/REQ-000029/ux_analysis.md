# REQ-000029の利用者体験分析

成果物種別: UX分析

状態: UX再統合済み・独立再レビュー待ち
分析対象: [REQ-000029 推論に使った情報の履歴・現行性・選択](../../../01_Discovery/Definitions/REQ-000029/requirement.md)

## 1. 要求の一次分析

```text
古い仮説や判断を現在値として読み、理由を推測で補完する
        ↓
解決策を先に固定せず、人の仕事として読み替える
        ↓
利用者に必要なこと
当時の仮説と現在有効な意図を区別する
```

設計者・AI協働者が「判断理由を追跡しつつ古い前提を現在値にしない」状態へ進めないことを問題として扱う。

| 観点 | 内容 |
|---|---|
| 解決する問題 | 古い仮説や判断を現在値として読み、理由を推測で補完する |
| 利用者に必要なこと | 当時の仮説と現在有効な意図を区別する |
| 対象範囲 | 成果物を変更・再評価する人、AIが、「古い仮説や判断を現在値として読み、理由を推測で補完する」状態から「当時の根拠・判断・学びと現在有効な意図を区別し、変更に必要な情報だけを辿れる」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

## 3. 利用者に起きる変化

```text
変更前
────────────────
- 古い仮説や判断を現在値として読み、理由を推測で補完する
        │
        │ 推論に使った情報の履歴・現行性・選択が変える体験
        ▼
変更後
────────────────
- 当時の根拠・判断・学びと現在有効な意図を区別し、変更に必要な情報だけを辿れる
```

推論に使った情報の履歴・現行性・選択は、単に内部方式を成立させる要求ではない。「古い仮説や判断を現在値として読み、理由を推測で補完する」状態から、「当時の根拠・判断・学びと現在有効な意図を区別し、変更に必要な情報だけを辿れる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

設計者・AI協働者が当時の仮説と現在有効な意図を区別することで、判断理由を追跡しつつ古い前提を現在値にしないようになることを守る。

## 4. 利用者成果への統合

```text
REQ-000029
   │
   └─ New  → UX-000025 過去の推論情報と現在値を区別する
```

| 利用者成果 | 処置 | 判断理由 | この要求が補う内容 |
|---|---|---|---|
| 過去の推論情報と現在値を区別する | `New → UX-000025` | 本要求が「当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる」という独立した利用者成果を最初に定義する。 | 根拠・仮説・判断・学びの時点を確認することが、この要求固有の成立条件になる |

`Same`／`New`は技術用語の近さや件数目標では決めない。「利用者は、どの状況で、何をするためにシステムと関わり、何ができるようになるか」が同じかを比較する。提供能力、必要情報、品質、妥当性確認または下流の実現要素は、独立UXへ分割せず対応する成果の成立条件として保持する。

## 5. 重要な体験

### この要求での利用の流れ

```text
過去判断を再利用または更新する時
        ↓
根拠・仮説・判断・学びの時点を確認する
        │
        ├─ ★ 重要場面: 判断理由をAIへ渡す場面
        ├─ ⚠ 失敗:  履歴を上書きし競合する理由を勝手に統合する
        └─ ✓ 守る品質:  現行性・選択範囲・使用改訂版を追跡する
        ↓
判断理由を追跡しつつ古い前提を現在値にしない
```

### サービス提供の流れの処置

処置: `作成`

```text
【利用者・責任者】CRDD作成者・保守者
        │ 利用者行動: 履歴と現在値を区別して再利用候補を提示する
        ▼
【利用者接点】過去判断を再利用または更新する時
        │
        ├─ 時間差: 過去記録の作成時点と現在の再利用判断には時間差がある
        ├─ 完了時: 当時の仮説・根拠・確信度・観測時点と現在意図
        └─ 失敗時: 競合または現行性不明の情報を人間の決定権限者へ返す
                     │
                     ▼
             【回復・判断する人】人間の決定権限者
                     │ 返却された事実と判断不能範囲を確認
                     └─ 次の行動: 過去値として参照するか、新しい判断で置換する

---------------- 可視境界 ----------------
                     │ 時間関係: 過去記録の作成時点と現在の再利用判断には時間差がある
                     ▼
【提供側】過去の判断・仮説の作成者
        └─ 提供責務: 当時の根拠・確信度・観測時点を残す
```

- 利用の流れの統合先: [対話と構築を往復する](../../03_Experience_Map.md#対話と構築を往復する)
- サービス提供の流れの統合先: [共同のサービス提供の流れ](../../04_Service_Blueprint.md#1-共同のサービス提供の流れ)

### この要求での責任境界

| 担い手 | この要求で担うこと | 越えてはならない境界 |
|---|---|---|
| 過去の判断・仮説の作成者 | 当時の根拠・確信度・観測時点を残す | 後日の知識で過去根拠を上書きしない |
| CRDD作成者・保守者 | 履歴と現在値を区別して再利用候補を提示する | 競合する理由を勝手に統合しない |
| 人間の決定権限者 | 継続・訂正・置換と現在有効な意図を決める | 古い仮説を黙示的に現行化しない |

### 補足する品質

- 結果または状態を最初に受け取る時: 過去を遡及上書きしない。（避ける失敗: 古い仮説や判断を現在値として読み、理由を推測で補完する）
- 結果を判断または引き継ぐ時: 古い仮説を現在値として渡さない。（避ける失敗: 必要条件を満たしていないのに完了・正常と理解する）
- 失敗・不足から次の行動を選ぶ時: 不足する理由をAIが生成しない。（避ける失敗: 成立不能の理由や回復先が分からないまま作業が止まる）

## 6. 下流への引き渡し

本節では、IAへの直後工程の引き渡し、UX工程に伴走する品質分析、およびIA完了後にUI／SPECが保持する契約を区別する。UXの完了だけを根拠にIAを飛び越えてUIまたはSPECを開始しない。

| 接続先 | この要求から保持する意味 |
|---|---|
| IA（直後工程への正式な引き渡し） | 必要な情報、理解すべき差、関係、現行性および利用者成果 |
| Quality Analysis / UX（伴走） | 得られる結果、重要場面、失敗、品質期待および検証意図 |
| UI（後続Contract Relation） | IA完了後にUX定義とIA定義の双方から分析する認識・操作・判断の意図 |
| SPEC（後続Contract Relation） | IA完了後にUX定義とIA定義の双方から分析する成立条件・失敗・利用者成果 |

```text
この要求で確定した利用者成果
├─→ IA                         直後工程への正式な引き渡し
├─→ Quality Analysis / UX      UX工程に伴走する検証義務分析
└─→ UI / SPEC                  IA完了後に保持するContract Relation
```

### 妥当性確認と未確認事項

| 確認する仮説 | 観測方法 | 現在未確認の範囲 |
|---|---|---|
| 当時の根拠・判断・学びと現在有効な意図を区別し、変更に必要な情報だけを辿れることで、古い仮説や判断を現在値として読み、理由を推測で補完するという負担または誤認を減らせる。 | 代表シナリオの利用者確認、利用者体験の専門レビュー、および品質期待を破る反例による下流検証 | CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |

人間への確認:
- 現在判定: 後続の実利用確認が必要。UX工程の構造整理を止める判断事項ではない。
- 確認事項: CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: [製品全体の利用者像](../../02_Personas.md)の「CRDD作成者・保守者」を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果と品質期待は仮説として保持し、負担、閾値、UIまたは実装方式を確定しない。

Discoveryへ戻す条件は、想定した利用者、問題または「当時の仮説と現在有効な意図を区別する」という必要性が誤っていると分かった場合である。IA以降は実現方式を具体化してよいが、利用者成果を無断で弱めない。
