# UX-000032 実行事実を安全に記録して結果を確かめる

成果物種別: UX定義
UX ID: `UX-000032`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

実行基盤またはアプリの組込み担当者が、観測した実行事実を一度の依頼で安全に記録し、記録済み・未記録・結果不明を取り違えず次の処置を選べる。

```text
実行基盤・アプリの組込み担当者
        │ 観測した実行事実を共有可能にする時
        ▼
同じ実行を重複させず記録を依頼する
        │
        ├─ 記録済み   → 後の取得・比較へ進む
        ├─ 未記録     → 原因を直して再依頼する
        └─ 結果不明   → 同じ実行と試行を再観測する
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | 実行基盤・TypeScriptアプリへ実行記録を組み込む担当者 |
| 利用のきっかけ／場面 | AIまたはToolの観測可能な実行段階が確定し、事実を後から比較できる形で残す時 |
| 目的 | 実行主体が違っても同じ意味で取得できる記録を、安全に一度だけ公開する |
| 得られる結果 | 記録の成否と不明状態を見分け、重複記録や別実行の上書きを起こさず次の処置を選べる |

## 利用者に起きる変化

```text
変更前
────────────────
- 記録要求を出したことやコマンドが終了したことだけで、実行事実が保存されたとみなす
        │
        │ 実行事実を安全に記録できる体験
        ▼
変更後
────────────────
- 記録要求の受理、保存完了および結果不明を区別し、同じ実行の重複記録や別実行への上書きを起こさずに記録できる
```

この変化が扱うのは、観測した実行事実を記録する側の体験である。組込み担当者が、記録要求の受理と保存完了を取り違えず、結果不明を保持して同じ試行を再観測し、重複・上書きを避けられることを守る。記録済み事実を比較・判断へ使う体験は`UX-000006`が所有する。

## 成立条件

- 同じ実行、情報源、観測時点、観測状態および記録試行を対応付けて依頼できる。
- 複数の作成側、再送、並行書込みまたは途中失敗でも、別の実行や完成記録へ誤統合しない。
- 保存結果を観測できない場合は未記録と決めつけず、同じ実行と記録試行を再観測できる。
- 生出力、秘密情報または不要な個人情報を、記録や診断へ無条件に含めない。

## 重要な体験・失敗・品質期待

```text
記録を依頼する
        ↓
実行・情報源・観測・試行を確認する
        │
        ├─ ★ 重要場面: 保存要求後に結果確認が途切れる
        ├─ ⚠ 失敗:  未記録と推定して再発行し、重複または上書きを起こす
        └─ ✓ 守る品質: 同じ識別情報で再観測し、結果不明を保つ
        ↓
記録済み／未記録／結果不明に応じて次へ進む
```

### 重要な失敗

- 未記録と推定して再発行し、重複または上書きを起こす

### 体験品質への期待

- 同じ識別情報で再観測し、結果不明を保つ

## 必要な情報

実行、情報源、観測値または未観測理由、観測時点、記録試行、記録状態、衝突した完成記録および回復先を区別する。

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 記録Authorityを、Task実行、評価採用または別情報源の変更Authorityへ広げない。
- 記録方式、保存製品、Process配置または特定画面を利用者成果そのものにしない。
- 記録する体験と、記録を後から振り返る`UX-000006`を同じ責務へ畳まない。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000004: 実行環境の導入・運用者が「実行事実を出所と観測時点付きで比較する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000004: 実行環境の導入・運用者が「実行事実を出所と観測時点付きで比較する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: 実行基盤・TypeScriptアプリへ実行記録を組み込む担当者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

異なる作成側、同一再送、並行書込み、途中失敗、結果搬送失敗および許可外情報を与え、結果状態、重複0、別実行不変、再観測先、終了後資源および許可外Effect 0を確認する。
