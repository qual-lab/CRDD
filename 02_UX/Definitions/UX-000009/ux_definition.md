# UX-000009 プロジェクトの現在地を根拠と不完全性付きで理解する

UX ID: `UX-000009`
状態: Canonical
維持責任者: Qual-Lab

物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる

## 利用者に起きる変化

```text
変更前
────────────────
- 複数文書とログを辿り、現在地を自分で合成する
- 要約が完全かどうかを推測する
        │
        │ 出典と不完全性を保つプロジェクト全体の表示が変える体験
        ▼
変更後
────────────────
- プロジェクト全体の表示から現在地、根拠、観測時点および不足を同時に理解する
- `missing`、`restricted`、`stale`、`conflicting`を識別する
```

プロジェクトの要約が短くても、どの情報源をいつ読んだ結果か分からなければ判断には使えない。欠測や古い観測を隠した見やすさは、利用者を誤った確信へ導く。

プロジェクト運営者／PMがプロジェクトの現在地を根拠と不完全性付きで理解することで、不足・競合・古さを踏まえて次の判断を選べるようになることを守る。

## 成立条件

- 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる
- 不足、競合、古さを確認したうえで、次の判断へ進める。
- 重要場面「現在の表示を信じる直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
プロジェクト状況を確認する時
        ↓
プロジェクトの現在地を根拠と不完全性付きで理解する
        │
        ├─ ★ 重要場面: 現在の表示を信じる直前
        ├─ ⚠ 失敗:  欠測や古い値を完全な現在値と誤認する
        └─ ✓ 守る品質:  根拠、不完全性、観測時点を同時に示す
        ↓
物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる
```

### 重要な失敗

- 欠測や古い値を完全な現在値と誤認する

### 体験品質への期待

- 根拠、不完全性、観測時点を同時に示す

## 必要な情報

プロジェクト、項目、情報源、改訂版、観測時点、網羅範囲および次の判断を関連付ける

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

- REQ-000020: プロジェクト運営者／PMが「複数リポジトリを不完全性付きで一つのプロジェクトとして見る」を行う際の判断基準、許容負担、利用環境および失敗後の選択

- 確認事項: REQ-000007: プロジェクト運営者／PMが「プロジェクトの現在地を根拠と不完全性付きで理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000020: プロジェクト運営者／PMが「複数リポジトリを不完全性付きで一つのプロジェクトとして見る」を行う際の判断基準、許容負担、利用環境および失敗後の選択

- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

partial、stale、restricted、conflictingおよび未観測値の誤認を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
