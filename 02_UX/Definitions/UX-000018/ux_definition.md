# UX-000018 AIモデル構成を安全に更新・選択する

成果物種別: UX定義
UX ID: `UX-000018`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

新しいモデルへ追随するとき、コード改修を待たず検証済み構成を更新し、実効選択と再選定理由を理解できる

```text
実行環境の導入・運用者
        │ 利用モデルやAI提供元条件を変更する時
        ▼
AIモデル選択を検証可能な構成として更新する
        │
        ▼
新モデルへ追随してもコード改修を繰り返さずに済む
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「実行環境の導入・運用者」 |
| 利用のきっかけ／場面 | 利用モデルやAI提供元条件を変更する時 |
| 目的 | AIモデル選択を検証可能な構成として更新する |
| 得られる結果 | 新モデルへ追随してもコード改修を繰り返さずに済む |

## 利用者に起きる変化

```text
変更前
────────────────
- 新モデルやCLI配置の変更ごとに中核改修を待ち、何が選ばれたか分からない
        │
        │ AIモデル設定内容の検証可能な外部構成が変える体験
        ▼
変更後
────────────────
- 互換範囲の変更は検証済み設定で反映でき、実際に選ばれた設定内容と理由を確認できる
```

AIモデル設定内容の検証可能な外部構成は、単に内部方式を成立させる要求ではない。「新モデルやCLI配置の変更ごとに中核改修を待ち、何が選ばれたか分からない」状態から、「互換範囲の変更は検証済み設定で反映でき、実際に選ばれた設定内容と理由を確認できる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

実行基盤構成管理者がAIモデル選択を検証可能な構成として更新することで、新モデルへ追随してもコード改修を繰り返さずに済むようになることを守る。

## 成立条件

- 新しいモデルへ追随するとき、コード改修を待たず検証済み構成を更新し、実効選択と再選定理由を理解できる
- 重要場面「AI提供元で実行する前のモデル確定」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
利用モデルやAI提供元条件を変更する時
        ↓
AIモデル選択を検証可能な構成として更新する
        │
        ├─ ★ 重要場面: AI提供元で実行する前のモデル確定
        ├─ ⚠ 失敗:  未知または非対応のモデルを実行可能と表示する
        └─ ✓ 守る品質:  構成変更を検証し実効選択を観測可能にする
        ↓
新モデルへ追随してもコード改修を繰り返さずに済む
```

### 重要な失敗

- 未知または非対応のモデルを実行可能と表示する

### 体験品質への期待

- 構成変更を検証し実効選択を観測可能にする

## 必要な情報

Model 設定内容、利用可否、Selection、理由、Fallback Conditionを結ぶ

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000016: 実行環境の導入・運用者が「AIモデル選択を検証可能な構成として更新する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000016: 実行環境の導入・運用者が「AIモデル選択を検証可能な構成として更新する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: 実行環境の導入・運用者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

未知設定の黙示代替、非対応モデルの実行可能表示および無説明選択を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
