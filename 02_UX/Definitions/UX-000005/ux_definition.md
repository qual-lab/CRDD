# UX-000005 目的と受入条件で節目を委ねる

成果物種別: UX定義
UX ID: `UX-000005`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる

```text
プロジェクト運営者／PM
        │ プロジェクトの成果をまとめて任せる時
        ▼
目的と受入条件で節目を委ねる
        │
        ▼
内部タスクを追わず統合済みの完成を判断できる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「プロジェクト運営者／PM」 |
| 利用のきっかけ／場面 | プロジェクトの成果をまとめて任せる時 |

| 得られる結果 | 内部タスクを追わず統合済みの完成を判断できる |

## 利用者に起きる変化

```text
変更前
────────────────
- タスク数、Agent log、個別結果から進捗を組み立て直す
- 内部処理の節目ごとに再指示する
        │
        │ 目的から統合までのプロジェクトの開始から完了・再開までの状態が変える体験
        ▼
変更後
────────────────
- 節目の成立状態、判断待ち、統合結果をプロジェクトの仕事として理解する
- 許可済みの目標範囲では進行を委ね、判断が必要な時だけ戻される
```

人間が内部タスクを一つずつ起動・監視しても、プロジェクトの目的が成立したかは分からない。利用者が委ねたいのはタスク実行ではなく、目的を受け入れ可能な結果へ進める一連の仕事である。

プロジェクト運営者／PMが目的と受入条件で節目を委ねることで、内部タスクを追わず統合済みの完成を判断できるようになることを守る。

## 成立条件

- 内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる
- 節目が停止した場合も、受入条件と現在状態を失わず、同じ目的・節目・判断点へ再開するかを判断できる。
- 重要場面「タスク成功と節目完成を区別する」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
プロジェクトの成果をまとめて任せる時
        ↓
目的と受入条件で節目を委ねる
        │
        ├─ ★ 重要場面: タスク成功と節目完成を区別する
        ├─ ⚠ 失敗:  タスク件数を完成と誤認する
        └─ ✓ 守る品質:  統合・品質・判断待ちを分けて示す
        ↓
内部タスクを追わず統合済みの完成を判断できる
```

### 重要な失敗

- タスク件数を完成と誤認する

### 体験品質への期待

- 統合・品質・判断待ちを分けて示す

## 必要な情報

目的、受入条件、節目、タスク、統合状態、品質、および同じ節目へ戻るための再開条件を関連付ける

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000003: プロジェクト運営者／PMが「目的と受入条件で節目を委ねる」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000003: プロジェクト運営者／PMが「目的と受入条件で節目を委ねる」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: プロジェクト運営者／PMを代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

タスク数や部分成功を完成へ畳む表示と、停止後に目的・受入条件・判断点を失った別の節目として再開する挙動を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
