# UX-000005 目的と受入条件で節目を委ねる

成果物種別: UX定義
UX ID: `UX-000005`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる

```text
プロジェクト運営者／PM
        │ プロジェクトの成果をまとめて任せる時
        ▼
目的と受入条件で節目を委ねる
        │
        ▼
内部タスクを追わず統合済みの完成を判断できる
```

## 利用者・状況・目的

| 項目 | 内容 |

| 得られる結果 | 内部タスクを追わず統合済みの完成を判断できる |

## 成立条件

- 内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる
- 節目が停止した場合も、受入条件と現在状態を失わず、同じ目的・節目・判断点へ再開するかを判断できる。
- 重要場面「タスク成功と節目完成を区別する」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
プロジェクトの成果をまとめて任せる時
        ↓
目的と受入条件で節目を委ねる
        │
        ├─ ★ 重要場面: タスク成功と節目完成を区別する
        ├─ ⚠ 失敗:  タスク件数を完成と誤認する
        └─ ✓ 守る品質:  統合・品質・判断待ちを分けて示す
        ↓
内部タスクを追わず統合済みの完成を判断できる
```

## 必要な情報

目的、受入条件、節目、タスク、統合状態、品質、および同じ節目へ戻るための再開条件を関連付ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

タスク数や部分成功を完成へ畳む表示と、停止後に目的・受入条件・判断点を失った別の節目として再開する挙動を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAは目的、節目、タスク、統合状態、品質および判断の関係を分ける。SPECとArchitectureは同じ目的・節目・判断点へ戻る再開契約を具体化し、Verificationはタスク数でなく一連の委任体験を確認する。
