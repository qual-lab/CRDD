# UX-000010 リポジトリ単独で日常作業を続ける

成果物種別: UX定義
UX ID: `UX-000010`
状態: 現行正本
維持責任者: Qual-Lab

## 利用者成果

横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる

```text
開発者
        │ リポジトリで作業を始める時
        ▼
現在リポジトリだけで日常作業を完結する
        │
        ▼
必要な時だけCROSへ移り普段の作業を複雑にしない
```

## 利用者・状況・目的

| 項目 | 内容 |

| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「開発者」 |
| 利用のきっかけ／場面 | リポジトリで作業を始める時 |

| 得られる結果 | 必要な時だけCROSへ移り普段の作業を複雑にしない |

## 成立条件

- 横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる
- 重要場面「横断利用へ切り替える判断」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
リポジトリで作業を始める時
        ↓
現在リポジトリだけで日常作業を完結する
        │
        ├─ ★ 重要場面: 横断利用へ切り替える判断
        ├─ ⚠ 失敗:  CROS未設定で手元作業まで止まる
        └─ ✓ 守る品質:  手元を既定にし横断を任意に保つ
        ↓
必要な時だけCROSへ移り普段の作業を複雑にしない
```

## 必要な情報

手元の情報、日常作業、履歴管理 機能を分ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

CROS未設定、未Commitまたは履歴管理の接続部障害による無関係な作業停止を反証する

具体的な試験段階、試験場面、期待結果は品質保証工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAは手元の情報源を既定とし、横断情報源を別状態にする。Architectureは手元経路をCROS Serverの可用性へ依存させず、回帰試験はCROSなしの開始と完了を守る。
