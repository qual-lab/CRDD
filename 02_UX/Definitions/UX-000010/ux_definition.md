# UX-000010 リポジトリ単独で日常作業を続ける

成果物種別: UX定義
UX ID: `UX-000010`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる

```text
開発者
        │ リポジトリで作業を始める時
        ▼
現在リポジトリだけで日常作業を完結する
        │
        ▼
横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる
```

## 利用者に起きる変化

```text
変更前
────────────────
- 横断機能の設定有無が作業開始を左右する
- 別リポジトリの存在を意識して情報を選ぶ
        │
        │ CROSなしで成立するリポジトリ作業が変える体験
        ▼
変更後
────────────────
- 対象リポジトリだけで開発を開始・完了できる
- 必要になった時だけプロジェクト横断入口へ進む
```

横断機能が便利でも、一つのリポジトリで完結する日常作業へServer、作業領域または横断統合の理解を要求すると、基礎体験が悪化する。

開発者が現在リポジトリだけで日常作業を完結することで、必要な時だけCROSへ移り普段の作業を複雑にしないようになることを守る。

## 成立条件

- 横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる
- 重要場面「横断利用へ切り替える判断」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
リポジトリで作業を始める時
        ↓
現在リポジトリだけで日常作業を完結する
        │
        ├─ ★ 重要場面: 横断利用へ切り替える判断
        ├─ ⚠ 失敗:  CROS未設定で手元作業まで止まる
        └─ ✓ 守る品質:  手元を既定にし横断を任意に保つ
        ↓
横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる
```

### 重要な失敗

- CROS未設定で手元作業まで止まる

### 体験品質への期待

- 手元を既定にし横断を任意に保つ

## 必要な情報

手元の情報、日常作業、履歴管理 機能を分ける

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000008: 開発者が「現在リポジトリだけで日常作業を完結する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- REQ-000036: 開発者が「日常作業をCommit SHAや特定Git実装から切り離す」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000008: 開発者が「現在リポジトリだけで日常作業を完結する」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000036: 開発者が「日常作業をCommit SHAや特定Git実装から切り離す」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: 開発者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

CROS未設定、未Commitまたは履歴管理の接続部障害による無関係な作業停止を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

| 接続先 | 保持する意味 |
|---|---|
| IA（直後工程への正式な引き渡し） | 必要な情報、理解すべき差、関係、現行性および利用者成果 |
| Quality Analysis / UX（伴走） | 得られる結果、成立条件、重要場面、失敗、品質期待および検証意図 |
| UI（後続Contract Relation） | IA完了後にUX定義とIA定義の双方から分析する認識・操作・判断の意図 |
| SPEC（後続Contract Relation） | IA完了後にUX定義とIA定義の双方から分析する成立条件・失敗・利用者成果 |

## 統合後に追加された要求固有条件

この体験の中心成果はREQ-000008が定める、横断機能や特定の履歴実装を前提にせず現在のリポジトリで日常作業を続けることである。REQ-000036は、未Commit状態や履歴管理接続部の障害だけで無関係な日常作業を停止しない条件を追加する。中心成果は置き換えない。
