# UX-000025 過去の推論情報と現在値を区別する

成果物種別: UX定義
UX ID: `UX-000025`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる

```text
CRDD作成者・保守者
        │ 過去判断を再利用または更新する時
        ▼
当時の仮説と現在有効な意図を区別する
        │
        ▼
判断理由を追跡しつつ古い前提を現在値にしない
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「CRDD作成者・保守者」 |
| 利用のきっかけ／場面 | 過去判断を再利用または更新する時 |
| 目的 | 当時の仮説と現在有効な意図を区別する |
| 得られる結果 | 判断理由を追跡しつつ古い前提を現在値にしない |

## 成立条件

- 当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる
- 重要場面「判断理由をAIへ渡す場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
過去判断を再利用または更新する時
        ↓
当時の仮説と現在有効な意図を区別する
        │
        ├─ ★ 重要場面: 判断理由をAIへ渡す場面
        ├─ ⚠ 失敗:  履歴を上書きし競合する理由を勝手に統合する
        └─ ✓ 守る品質:  現行性・選択範囲・使用改訂版を追跡する
        ↓
判断理由を追跡しつつ古い前提を現在値にしない
```

## 必要な情報

過去の情報、現在の意図、選択根拠を分ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

遡及上書き、古い仮説の現在値化および履歴全量の無選択投入を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAは判断理由の履歴と現在有効な内容を分け、各工程とAIが使う情報は選択根拠を追跡する。
