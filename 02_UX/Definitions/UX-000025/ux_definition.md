# UX-000025 過去の推論情報と現在値を区別する

成果物種別: UX定義
UX ID: `UX-000025`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる

```text
CRDD作成者・保守者
        │ 過去判断を再利用または更新する時
        ▼
当時の仮説と現在有効な意図を区別する
        │
        ▼
判断理由を追跡しつつ古い前提を現在値にしない
```

| 項目 | 内容 |

| 利用のきっかけ／場面 | 過去判断を再利用または更新する時 |

| 得られる結果 | 判断理由を追跡しつつ古い前提を現在値にしない |

## 利用者に起きる変化

```text
変更前
────────────────
- 古い仮説や判断を現在値として読み、理由を推測で補完する
        │
        │ 推論に使った情報の履歴・現行性・選択が変える体験
        ▼
変更後
────────────────
- 当時の根拠・判断・学びと現在有効な意図を区別し、変更に必要な情報だけを辿れる
```

推論に使った情報の履歴・現行性・選択は、単に内部方式を成立させる要求ではない。「古い仮説や判断を現在値として読み、理由を推測で補完する」状態から、「当時の根拠・判断・学びと現在有効な意図を区別し、変更に必要な情報だけを辿れる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

設計者・AI協働者が当時の仮説と現在有効な意図を区別することで、判断理由を追跡しつつ古い前提を現在値にしないようになることを守る。

## 成立条件

- 当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる
- 重要場面「判断理由をAIへ渡す場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
過去判断を再利用または更新する時
        ↓
当時の仮説と現在有効な意図を区別する
        │
        ├─ ★ 重要場面: 判断理由をAIへ渡す場面
        ├─ ⚠ 失敗:  履歴を上書きし競合する理由を勝手に統合する
        └─ ✓ 守る品質:  現行性・選択範囲・使用改訂版を追跡する
        ↓
判断理由を追跡しつつ古い前提を現在値にしない
```

### 重要な失敗

- 履歴を上書きし競合する理由を勝手に統合する

### 体験品質への期待

- 現行性・選択範囲・使用改訂版を追跡する

## 必要な情報

過去の情報、現在の意図、選択根拠を分ける

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000029: CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000029: CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: CRDD作成者・保守者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

遡及上書き、古い仮説の現在値化および履歴全量の無選択投入を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
