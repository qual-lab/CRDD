# UX-000028 工程固有の図から意図を引き継ぐ

成果物種別: UX定義
UX ID: `UX-000028`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

工程固有の図から全体像・関係・状態差・未接続を理解し、後工程で意図を再発明せずに引き継げる

```text
CRDD閲覧者（後工程担当者）
        │ 工程の入口・出口で成果物を渡す時
        ▼
工程固有の図から状態・関係・未接続を理解する
        │
        ▼
後工程で意図を再発明せず漏れを発見できる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「CRDD閲覧者」。設計・実装・検証を引き継ぐ後工程担当者を含む |
| 利用のきっかけ／場面 | 工程の入口・出口で成果物を渡す時 |
| 目的 | 工程固有の図から状態・関係・未接続を理解する |
| 得られる結果 | 後工程で意図を再発明せず漏れを発見できる |

## 成立条件

- 工程固有の図から全体像・関係・状態差・未接続を理解し、後工程で意図を再発明せずに引き継げる
- 重要場面「下流義務へ変換する場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
工程の入口・出口で成果物を渡す時
        ↓
工程固有の図から状態・関係・未接続を理解する
        │
        ├─ ★ 重要場面: 下流義務へ変換する場面
        ├─ ⚠ 失敗:  必要な図を黙って省略しAIごとに記法が変わる
        └─ ✓ 守る品質:  図の意味・凡例・正本関係を固定する
        ↓
後工程で意図を再発明せず漏れを発見できる
```

## 必要な情報

Diagram Element、情報源が持つ意味、引き渡す義務を結ぶ

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

図の黙示省略、機械的で読めない記法および図と試験の断絶を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

各工程は図の意味と処置を所有し、Checkerは欠落を、レビューは意味の正しさを確認する。
