# UX-000017 実行時データを安全に保持・清掃する

保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる

```text
保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる
```

## 利用者に起きる変化

```text
変更前
────────────────
- `.crdd`やOS領域に用途不明のFileが増え、消してよいか判断できない
        │
        │ 実行時データの基点フォルダの所有と用途が変える体験
        ▼
変更後
────────────────
- リポジトリ固有データと横断実行基盤データを区別し、責任者、保持、Git管理、清掃条件を確認できる
```

実行時データの基点フォルダの所有と用途は、単に内部方式を成立させる要求ではない。「`.crdd`やOS領域に用途不明のFileが増え、消してよいか判断できない」状態から、「リポジトリ固有データと横断実行基盤データを区別し、責任者、保持、Git管理、清掃条件を確認できる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

実行基盤運用者・保守者が実行時データの所有場所と一連の状態変化を理解することで、残存・清掃・回復を別リポジトリへ波及させず扱えるようになることを守る。

## 成立条件

- 保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる
- 重要場面「永続化または削除の直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
実行時データを作成または清掃する時
        ↓
実行時データの所有場所と一連の状態変化を理解する
        │
        ├─ ★ 重要場面: 永続化または削除の直前
        ├─ ⚠ 失敗:  subdirectoryや別基点フォルダへ同名データを作る
        └─ ✓ 守る品質:  用途別領域とcleanup条件を明示する
        ↓
保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる
```

### 重要な失敗

- subdirectoryや別基点フォルダへ同名データを作る

### 体験品質への期待

- 用途別領域とcleanup条件を明示する

## 必要な情報

データの責任者、基点フォルダ、Durability、保持期間、清掃を関連付ける

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

- REQ-000022: 実行環境の導入・運用者が「残存資源の由来・保持・清掃・回復を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択

- 確認事項: REQ-000015: 実行環境の導入・運用者が「実行時データの所有場所と一連の状態変化を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000022: 実行環境の導入・運用者が「残存資源の由来・保持・清掃・回復を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
