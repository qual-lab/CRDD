## 利用者に起きる変化

```text
変更前
────────────────
- 次のAgentへ必要そうな情報を手で貼り直す
- Agentが何を参照したか推測する
        │
        │ 出所付き受け渡す情報一式の解決が変える体験
        ▼
変更後
────────────────
- 対象タスクに必要な情報が情報源と改訂版付きで解決される
- 利用した情報集合と不足範囲を後から追跡する
```

対話AIとコーディングAIの間で人間が文書や会話を転記すると、出所、改訂版、選択理由が失われる。全情報の投入は過剰共有と認知負荷を増やす。

対話AI／コーディングAIの利用者が必要な情報だけを出所付きで渡すことで、何を使って判断・生成したか後から追跡できるようになることを守る。

## 成立条件

- 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
- 重要場面「外部境界へ情報を出す直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
別Agentやツールへ仕事を渡す時
        ↓
必要な情報だけを出所付きで渡す
        │
        ├─ ★ 重要場面: 外部境界へ情報を出す直前
        ├─ ⚠ 失敗:  全量投入・秘密情報混入・古い仮説の現在値化
        └─ ✓ 守る品質:  情報源・改訂版・選択理由を保持する
        ↓
必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
```

### 重要な失敗

- 全量投入・秘密情報混入・古い仮説の現在値化

### 体験品質への期待

- 情報源・改訂版・選択理由を保持する

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

全量投入、秘密情報混入、情報捏造、別タスク結果混入およびAgent完了の自動採用を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
