UX ID: `UX-000019`
状態: Canonical
維持責任者: Qual-Lab

```text

        │ 別Agentやツールへ仕事を渡す時、または結果を受け取る時
        ▼
必要な情報だけを出所付きで渡す
        │
        ▼
必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「外部へ渡す情報の所有者」／「プロジェクト運営者／PM」 |
| 利用のきっかけ／場面 | 別Agentやツールへ仕事を渡す時、または結果を受け取る時 |
| 目的 | 必要な情報だけを出所付きで渡す |
| 得られる結果 | 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる |

## 成立条件

- 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
- 重要場面「外部境界へ情報を出す直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
別Agentやツールへ仕事を渡す時
        ↓
必要な情報だけを出所付きで渡す
        │
        ├─ ★ 重要場面: 外部境界へ情報を出す直前
        ├─ ⚠ 失敗:  全量投入・秘密情報混入・古い仮説の現在値化
        └─ ✓ 守る品質:  情報源・改訂版・選択理由を保持する
        ↓
必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
```

## 必要な情報

受け渡す情報一式、情報源、タスク、結果、根拠、引き渡し、判断を関連付ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

全量投入、秘密情報混入、情報捏造、別タスク結果混入およびAgent完了の自動採用を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAは受け渡す情報一式、情報源、改訂版、選択理由およびタスク Relationを分ける。ArchitectureはResolverと通信方式を分離し、Verificationは出所喪失と過剰投入を反証する。

## 統合後に追加された要求固有条件

この体験の中心成果はREQ-000017が定める、必要最小限の情報を許可付きで渡し、相関・完全性付きの結果を同じ仕事へ戻すことである。後続要求は次の差分を追加するが、中心成果を置き換えない。

| 追加元 | 追加される場面・条件 | 追加される失敗・検証意図 |
|---|---|---|
| REQ-000024 | 境界を越えた結果・根拠・未確認範囲を元タスクへ戻し、人間が採否を判断する | 一部欠落、別タスク結果の混入、自動採用を反証する |
| REQ-000027 | 外部AIやAPIへ送る前に送信先・目的・分類・最小情報を確認する | 秘密情報や不要な正本を送信し、外部結果を指示や権限へ昇格する失敗を反証する |
