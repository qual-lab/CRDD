# UX-000029 作業・変更・根拠・品質を迷わず辿る

成果物種別: UX定義
UX ID: `UX-000029`
状態: 現行正本
維持責任者: Qual-Lab

## 利用者成果

未完了、変更理由、全影響パス、成立根拠および現在品質を役割の違いとともに辿れる

```text
CRDD作成者・保守者
        │ 変更の現在地や根拠を調べる時
        ▼
作業・変更・根拠・品質を役割別に辿る
        │
        ▼
変更理由と全影響パスを重複なく確認できる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「CRDD作成者・保守者」 |
| 利用のきっかけ／場面 | 変更の現在地や根拠を調べる時 |
| 目的 | 作業・変更・根拠・品質を役割別に辿る |
| 得られる結果 | 変更理由と全影響パスを重複なく確認できる |

## 成立条件

- 未完了、変更理由、全影響パス、成立根拠および現在品質を役割の違いとともに辿れる
- 重要場面「変更の影響漏れを確認する場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
変更の現在地や根拠を調べる時
        ↓
作業・変更・根拠・品質を役割別に辿る
        │
        ├─ ★ 重要場面: 変更の影響漏れを確認する場面
        ├─ ⚠ 失敗:  同じ説明を複製し代表ファイルだけで済ませる
        └─ ✓ 守る品質:  正本を分け全影響ファイルを列挙する
        ↓
変更理由と全影響パスを重複なく確認できる
```

## 必要な情報

Work、Change、変更対象ファイル、根拠、観測した改訂版、品質を分ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

責任者の混同、代表パスだけの表示、根拠の遡及上書きおよびGit差分への丸投げを反証する

具体的な試験段階、試験場面、期待結果は品質保証工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAは作業の一連の流れのNavigationとEntity関係を分け、リリース・品質・Checkerは各責任者境界を維持する。
