# UX-000023 監査・是正・判断を一つの改訂版で閉じる

成果物種別: UX定義
UX ID: `UX-000023`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる

```text
CRDD作成者・保守者
        │ 複数指摘を是正する時
        ▼
監査合意から是正・反証までを一つの改訂版で閉じる
        │
        ▼
小出しの指摘と局所PatchのLoopを減らせる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「CRDD作成者・保守者」 |
| 利用のきっかけ／場面 | 複数指摘を是正する時 |
| 目的 | 監査合意から是正・反証までを一つの改訂版で閉じる |
| 得られる結果 | 小出しの指摘と局所PatchのLoopを減らせる |

## 利用者に起きる変化

```text
変更前
────────────────
- 指摘が小出しになり、何が合意済みで何が未処置か分からない
        │
        │ 判断・監査・是正の収束可能な閉包が変える体験
        ▼
変更後
────────────────
- 対象範囲、全指摘、是正対応、反証結果、今決める事項を一つの閉包として把握できる
```

判断・監査・是正の収束可能な閉包は、単に内部方式を成立させる要求ではない。「指摘が小出しになり、何が合意済みで何が未処置か分からない」状態から、「対象範囲、全指摘、是正対応、反証結果、今決める事項を一つの閉包として把握できる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

CRDD保守者・判断する人が監査合意から是正・反証までを一つの改訂版で閉じることで、小出しの指摘と局所PatchのLoopを減らせるようになることを守る。

## 成立条件

- 合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる
- 重要場面「再レビューへ固定候補を渡す直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
複数指摘を是正する時
        ↓
監査合意から是正・反証までを一つの改訂版で閉じる
        │
        ├─ ★ 重要場面: 再レビューへ固定候補を渡す直前
        ├─ ⚠ 失敗:  一部是正や監査回数を完成と誤認する
        └─ ✓ 守る品質:  合意事項と試験を全数対応させる
        ↓
小出しの指摘と局所PatchのLoopを減らせる
```

### 重要な失敗

- 一部是正や監査回数を完成と誤認する

### 体験品質への期待

- 合意事項と試験を全数対応させる

## 必要な情報

指摘、是正、Verification、判断要求、現在の改訂版を結ぶ

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000026: CRDD作成者・保守者が「監査合意から是正・反証までを一つの改訂版で閉じる」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000026: CRDD作成者・保守者が「監査合意から是正・反証までを一つの改訂版で閉じる」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: CRDD作成者・保守者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

指摘の小出し適用、解消済み判断の再要求および一部是正の完成表示を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
