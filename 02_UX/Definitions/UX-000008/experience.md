# UX-000008 故障した境界と影響範囲を理解する

成果物種別: UX定義
UX ID: `UX-000008`
状態: 現行正本
維持責任者: Qual-Lab

## 利用者成果

接続・認証・実行・結果搬送またはAI提供元境界のどこで止まり、何が利用可能かを理解できる

```text
実行環境の導入・運用者
        │ 外部接続または実行基盤実行が止まった時
        ▼
故障した境界と影響する能力を特定する
        │
        ▼
使える能力を保ち正しい診断・回復先を選べる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「実行環境の導入・運用者」 |
| 利用のきっかけ／場面 | 外部接続または実行基盤実行が止まった時 |
| 目的 | 故障した境界と影響する能力を特定する |
| 得られる結果 | 使える能力を保ち正しい診断・回復先を選べる |

## 成立条件

- 接続・認証・実行・結果搬送またはAI提供元境界のどこで止まり、何が利用可能かを理解できる
- 重要場面「一つの失敗を全体障害と判断する直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
外部接続または実行基盤実行が止まった時
        ↓
故障した境界と影響する能力を特定する
        │
        ├─ ★ 重要場面: 一つの失敗を全体障害と判断する直前
        ├─ ⚠ 失敗:  一律の失敗表示で無関係な能力まで停止する
        └─ ✓ 守る品質:  失敗した場所・影響範囲・利用可能性を分ける
        ↓
使える能力を保ち正しい診断・回復先を選べる
```

## 必要な情報

失敗した場所、境界、影響を受ける機能、結果の受け渡しを関連付ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

一律の失敗表示、無関係な能力停止および全体成功表示を反証する

具体的な試験段階、試験場面、期待結果は品質保証工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

Architectureは責務と依存方向を、Verificationは各公開機能の保存を具体化する。
