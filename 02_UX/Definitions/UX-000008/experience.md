# UX-000008 故障した境界と影響範囲を理解する

成果物種別: UX定義
UX ID: `UX-000008`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる

```text
実行環境の導入・運用者
        │ AI実行環境の導入または利用が止まった時
        ▼
故障した境界と影響する能力を特定する
        │
        ▼
AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる
```

## 成立条件

- AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる
- 重要場面「一つの失敗を全体障害と判断する直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
AI実行環境の導入または利用が止まった時
        ↓
故障した境界と影響する能力を特定する
        │
        ├─ ★ 重要場面: 一つの失敗を全体障害と判断する直前
        ├─ ⚠ 失敗:  一律の失敗表示で無関係な能力まで停止する
        └─ ✓ 守る品質:  失敗した場所・影響範囲・利用可能性を分ける
        ↓
AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる
```

## 必要な情報

AI実行環境ごとの認証、起動、取消、結果取得、回復、利用可能な機能を関連付ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

認証・起動・取消・結果取得・回復の違いを同じ失敗へ畳む表示と、利用可能な機能まで停止する判断を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAはAI実行環境、状態変化、利用可能な機能、故障時の判断材料を関連付ける。Architectureは専用接続部と共通中核の境界を、Verificationは開始から終了後清掃までの段階的な確認を具体化する。

## 統合後に追加された要求固有条件

この体験の中心成果はREQ-000023が定める、新しいAI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、どの能力が利用できるかを理解することである。後続の`Same`要求はまだなく、中心成果を別要求の意味で補完しない。
