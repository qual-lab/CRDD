# UX-000027 物語と構造から文書の意味を理解する

成果物種別: UX定義
UX ID: `UX-000027`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

課題と判断の物語を理解してから、表・図で条件と関係を確認し、次の行動へ進める

```text
CRDD閲覧者（初めて読む人・後工程担当者）
        │ 工程成果物を初めて読む時
        ▼
課題と判断の物語から構造化詳細へ進む
        │
        ▼
情報量を失わず短時間で意味と次の行動を理解できる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「CRDD閲覧者」。初めて読む人と後工程担当者を含む |
| 利用のきっかけ／場面 | 工程成果物を初めて読む時 |
| 目的 | 課題と判断の物語から構造化詳細へ進む |
| 得られる結果 | 情報量を失わず短時間で意味と次の行動を理解できる |

## 利用者に起きる変化

```text
変更前
────────────────
- 確認項目順の表と専門語を解読しないと、問題・目的・判断が分からない
        │
        │ 人の理解順と構造を両立する成果物が変える体験
        ▼
変更後
────────────────
- 物語から問題と目的を理解し、構造化情報で条件・責務・根拠を確認できる
```

人の理解順と構造を両立する成果物は、単に内部方式を成立させる要求ではない。「確認項目順の表と専門語を解読しないと、問題・目的・判断が分からない」状態から、「物語から問題と目的を理解し、構造化情報で条件・責務・根拠を確認できる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

CRDD成果物を読む人・書く人が課題と判断の物語から構造化詳細へ進むことで、情報量を失わず短時間で意味と次の行動を理解できるようになることを守る。

## 成立条件

- 課題と判断の物語を理解してから、表・図で条件と関係を確認し、次の行動へ進める
- 重要場面「判断理由と条件を結び付ける場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
工程成果物を初めて読む時
        ↓
課題と判断の物語から構造化詳細へ進む
        │
        ├─ ★ 重要場面: 判断理由と条件を結び付ける場面
        ├─ ⚠ 失敗:  確認項目順と専門語だけで文書を埋める
        └─ ✓ 守る品質:  物語と構造化した情報を両立する
        ↓
情報量を失わず短時間で意味と次の行動を理解できる
```

### 重要な失敗

- 確認項目順と専門語だけで文書を埋める

### 体験品質への期待

- 物語と構造化した情報を両立する

## 必要な情報

物語、構造化した詳細、判断、根拠を結ぶ

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000031: CRDD作成者・保守者が「課題と判断の物語から構造化詳細へ進む」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000031: CRDD作成者・保守者が「課題と判断の物語から構造化詳細へ進む」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: CRDD閲覧者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

確認項目順、専門語だけの説明および情報削減による見せかけの可読性を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
