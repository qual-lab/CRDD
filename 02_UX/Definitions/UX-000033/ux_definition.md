# UX-000033 論点と会議記録を安全に維持する

成果物種別: UX定義
UX ID: `UX-000033`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

入口を変えても同じ論点と会議記録を扱い、正当な経緯を失わず誤登録だけを安全に除ける。

```text
Project運営者／Meeting参加者／Topic責任者
        │ 論点や会議記録を後の仕事へつなぐ時
        ▼
論点と会議記録を経緯ごと維持する
        │
        ▼
正当な履歴を保ち、誤登録だけを影響確認後に除ける
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | Project運営者／PM、Meeting参加者、Topic責任者が論点や会議記録を日常的に扱う状況 |
| 利用のきっかけ／場面 | 論点や会議記録を登録・確認・更新する時、誤登録を見つけた時 |
| 目的 | Topicの現在状態とMeetingの時点記録を、経緯と関係を保って維持する |
| 得られる結果 | 入口を変えても同じ記録へ到達し、正当な履歴を残して誤登録だけを安全に除ける |

## 利用者に起きる変化

```text
変更前
入口ごとにファイル、書式、関係、削除方法を解釈する
        ↓
変更後
同じ記録を一通り扱い、終了・訂正と誤登録削除を使い分ける
```

利用者は記録方式の調停ではなく、論点、会議の意味、関係および次の判断へ集中できる。

## 成立条件

- TopicとMeetingを作成・発見・取得・更新でき、Topicの継続状態とMeetingの時点記録を区別できる。
- 正当な履歴は終了・撤回・訂正として保持し、誤登録の物理削除と区別できる。
- 物理削除前に対象、失われる内容、参照元・参照先、関係への処置および復旧可能性を理解できる。
- 人間の明示確認なしに削除せず、削除対象外の成果物を連鎖削除せず、無効な関係を残さない。
- 競合、権限不足、観測不能または部分失敗を正常完了として表示しない。

## 重要な体験・失敗・品質期待

```text
論点または会議記録を扱う
        ↓
継続・終了・訂正または誤登録削除を選ぶ
        │
        ├─ ★ 重要場面: 物理削除を確定する直前
        ├─ ⚠ 失敗: 正当な履歴や関連対象まで失う
        └─ ✓ 守る品質: 影響と復旧可能性を示し明示確認する
        ↓
経緯を保って次の判断・Actionへ進む
```

### 重要な失敗

- Meetingの当時記録を現在状態で無言に上書きする。
- 正当な履歴または削除対象外の成果物を失う。
- 対象だけ、または関係だけを変更した部分成功を完了と表示する。

### 体験品質への期待

- 入口を変えてもIdentity、状態、関係および結果が一致する。
- 削除確認は損失と関係への処置を判断できる具体性を持つ。
- 失敗後に残る状態と選べる回復が分かる。

## 必要な情報

Topic、Meeting、現在状態、記録時点、参加主体、Source、Relation、候補、Decision／Action、終了・訂正理由、削除影響、Authority、競合、復旧可能性。

## 責任境界・制約・対象外

- UXが定義すること: 論点と会議記録を安全に維持する利用者成果、削除時の重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、操作、状態遷移、保存、競合処理、削除適用および回復方式。
- 制約: 読取り可能性を編集・削除Authorityとみなさず、Git Commitを業務Identityにしない。
- 対象外: 具体的な画面、Tool名、保存形式およびTransaction方式。

## 未確認事項と戻り条件

- 未確認事項: 登録必須項目、一覧粒度、削除確認の理解しやすさと許容負担。
- 現在判定: 後続確認が必要。現在のUX定義を止める事項ではない。
- 確認事項: 実際のTopic／Meeting作業で、直接編集より負担を増やさず安全性が上がるか。
- 判断者: Project運営者、Meeting参加者、Topic責任者およびQual-Lab。
- 未確認時の影響: 具体的な入力、表示、確認回数および実装方式を確定しない。
- Discoveryへ戻す条件: 共通操作で負担や誤削除が増える、またはTopicとMeetingの意味を一貫して保てない場合。
- UX分析へ戻す条件: 維持と削除が独立した利用者成果へ分かれる、または主な利用者成果が変わる場合。

## 検証意図

異なる入口から同じTopic／Meetingを扱って同じ結果へ到達できること、正当な履歴と誤登録を区別できること、削除前に影響を理解できること、失敗時に関係不整合や部分成功を隠さないことを観測する。

## 下流への引き渡し

| 接続先 | 保持する意味 |
|---|---|
| IA（直後工程への正式な引き渡し） | Topic、Meeting、時点、状態、関係、候補、削除影響、復旧可能性およびOwner |
| Quality Analysis / UX（伴走） | 入口一貫性、履歴保持、削除前確認、非連鎖削除、関係整合、部分失敗および回復 |
| UI（後続Contract Relation） | 発見・編集・終了・訂正・削除確認に必要な認識と判断 |
| SPEC（後続Contract Relation） | 操作結果、競合、Authority、削除、部分成功および回復の成立条件 |
