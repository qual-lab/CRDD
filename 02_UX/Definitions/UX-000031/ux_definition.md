# UX-000031 公式の識別と保証を混同せず見分ける

成果物種別: UX定義
UX ID: `UX-000031`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

CRDDの公式入口や素材を視覚的に見分けながら、その表示だけを署名・準拠・品質または発行元への信頼の証明と誤認せず利用できる

```text
CRDDの文書・ツール・公開案内を閲覧する人
        │ 公式らしい入口や素材を見つけた時
        ▼
識別表示と保証の根拠を分けて確認する
        │
        ▼
見た目だけを信頼根拠にせず適切な入口を選べる
```

## 利用者・状況・目的

| 項目 | 内容 |

| 利用のきっかけ／場面 | 公式らしい入口や視覚素材を見つけた時 |

| 得られる結果 | 見た目だけを信頼根拠にせず適切な入口を選べる |

## 利用者に起きる変化

```text
変更前
────────────────
- 閲覧者が公式らしい見た目を、品質、安全性または発行元への信頼の証明として受け取る
        │
        │ 公式入口を誤認せず選べる体験
        ▼
変更後
────────────────
- 閲覧者が公式の識別表示と、品質・安全性・発行元を確認できる根拠を分けて理解し、適切な入口を選べる
```

この変化が扱うのは、公式らしい入口を選ぶ閲覧者の体験である。識別表示が示す「公式であること」と、品質、安全性または発行元への信頼を支える根拠を分けて理解し、見た目だけで保証を推定しないことを守る。保守者が素材の権利と用途を確認する体験は`UX-000030`が所有する。

## 成立条件

- 公式入口や素材を識別でき、同時に署名・準拠・品質・発行元への信頼の根拠は別に確認できる。
- 重要場面「公式表示を信頼判断へ用いる直前」で、視覚的な公式らしさを保証の証明と誤認しない。
- 表示媒体や入口が変わっても、識別用途と保証根拠の境界を維持する。

## 重要な体験・失敗・品質期待

```text
公式らしい入口や視覚素材を見つけた時
        ↓
識別表示と保証の根拠を分けて確認する
        │
        ├─ ★ 重要場面: 公式表示を信頼判断へ用いる直前
        ├─ ⚠ 失敗:  アイコンや見た目を署名・準拠・品質保証と誤認する
        └─ ✓ 守る品質:  識別表示と検証可能な信頼根拠を別に示す
        ↓
見た目だけを信頼根拠にせず適切な入口を選べる
```

### 重要な失敗

- アイコンや見た目を署名・準拠・品質保証と誤認する

### 体験品質への期待

- 識別表示と検証可能な信頼根拠を別に示す

## 必要な情報

公式識別、配布者、署名、準拠状況、品質上の主張を分ける

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 視覚素材を実行環境の信頼、公式署名、準拠または品質の証明にしない。
- 非公式入口の存在や利用可能性を、公式表示がないことだけで否定しない。
- 下流工程は識別表示と保証根拠を一つの状態へ畳まない。

## 未確認事項と戻り条件

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000035: 識別表示が入口発見を助けながら信頼誤認を増やさないか、権利情報の許容確認負担
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000035: 識別表示が入口発見を助けながら信頼誤認を増やさないか、権利情報の許容確認負担
- 判断者: CRDD閲覧者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

## 検証意図

公式／非公式表示、保証根拠の欠落、見た目だけの信頼推定および識別不能な入口を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
