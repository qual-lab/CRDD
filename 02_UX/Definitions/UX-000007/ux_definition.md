# UX-000007 内部変更後も成立済み能力を安全に使う

成果物種別: UX定義
UX ID: `UX-000007`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる

```text
CRDD作成者・保守者／実行環境の導入・運用者
        │ 責務・契約・接続部または実行環境の構成を変更する時
        ▼
維持・変更・廃止された能力と利用側を確認する
        │
        ▼
責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる
```

## 利用者に起きる変化

```text
変更前
────────────────
- 一つの構成要素変更が無関係な入口や操作を壊し、原因を利用者が切り分ける
        │
        │ 実行基盤責務と依存方向の分離が変える体験
        ▼
変更後
────────────────
- 責務の違いを意識せず同じ入口を使え、故障時は影響する範囲を正確に知れる
```

実行基盤責務と依存方向の分離は、単に内部方式を成立させる要求ではない。「一つの構成要素変更が無関係な入口や操作を壊し、原因を利用者が切り分ける」状態から、「責務の違いを意識せず同じ入口を使え、故障時は影響する範囲を正確に知れる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

実行基盤保守者・利用者が責務分離後も成立済み機能を使うことで、内部変更の影響範囲を限定して更新できるようになることを守る。

## 成立条件

- 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる
- 重要場面「変更を完了・公開可能と判断する直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
責務・契約・接続部を変更して公開する時
        ↓
維持・変更・廃止された能力と利用側を確認する
        │
        ├─ ★ 重要場面: 変更を完了・公開可能と判断する直前
        ├─ ⚠ 失敗:  主経路だけ移行し副次利用側を取り残す
        └─ ✓ 守る品質:  旧能力・全利用側・置換根拠を閉じる
        ↓
責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる
```

### 重要な失敗

- 主経路だけ移行し副次利用側を取り残す

### 体験品質への期待

- 旧能力・全利用側・置換根拠を閉じる

## 責任境界・制約・対象外

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。
