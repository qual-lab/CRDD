# UX-000015 複数プロジェクトを根拠付きで比較する

成果物種別: UX定義
UX ID: `UX-000015`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

許可されたプロジェクトの重要差を比較し、網羅範囲と根拠を保ったまま必要なプロジェクトだけを掘り下げられる

```text
経営・管理層
        │ 複数プロジェクトの一覧の優先度を判断する時
        ▼
複数プロジェクトを根拠付きで比較する
        │
        ▼
重要差分から必要なプロジェクトだけを掘り下げられる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「経営・管理層」 |
| 利用のきっかけ／場面 | 複数プロジェクトの一覧の優先度を判断する時 |
| 目的 | 複数プロジェクトを根拠付きで比較する |
| 得られる結果 | 重要差分から必要なプロジェクトだけを掘り下げられる |

## 成立条件

- 許可されたプロジェクトの重要差を比較し、網羅範囲と根拠を保ったまま必要なプロジェクトだけを掘り下げられる
- 重要場面「要約から優先判断へ進む直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
複数プロジェクトの一覧の優先度を判断する時
        ↓
複数プロジェクトを根拠付きで比較する
        │
        ├─ ★ 重要場面: 要約から優先判断へ進む直前
        ├─ ⚠ 失敗:  単一Scoreや欠測した集計で健全性を断定する
        └─ ✓ 守る品質:  比較値から根拠・古さ・不足へ戻れる
        ↓
重要差分から必要なプロジェクトだけを掘り下げられる
```

## 必要な情報

プロジェクト Summary、網羅範囲、観測時点、開示範囲を分ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

非開示プロジェクトの存在漏えい、単一Score断定および網羅範囲差の消去を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAはプロジェクト比較軸、情報源の網羅範囲、情報の新しさおよび根拠導線をモデル化する。Verificationは不完全なプロジェクト集合を完全複数プロジェクトの一覧として表示しないことを確認する。
