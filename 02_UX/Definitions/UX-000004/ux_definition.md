## 利用者に起きる変化

```text
変更前
────────────────
- 失敗後に外部作用や残存状態を推測し、新規実行、回復または清掃のどれを選ぶか判断できない
        │
        │ 失敗後の継続方法を安全に選べる体験
        ▼
変更後
────────────────
- 同じ依頼の外部作用、残存、回復義務および終了条件を確認し、再試行、回復または清掃を選べる
```

この変化が扱うのは失敗・取消・切断後の安全な継続である。仕事を委ねた人が、外部作用、残存、回復義務および終了条件を確認し、新規実行で上書きせず再試行・回復・清掃を選べることを守る。委任前の範囲選択や通常実行中の状態確認は兄弟UXの成果であり、本定義の成果へ含めない。

## 成立条件

- 失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる
- 重要場面「同じ外部作用（Effect）を再発行する直前」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

```text
        └─ ✓ 守る品質:  外部作用（Effect）状態・回復対象の識別情報・終了条件を示す

```

### 重要な失敗

- 結果不明の処理を新規実行して外部作用（Effect）の二重実行を起こす

### 体験品質への期待

- 外部作用（Effect）状態・回復対象の識別情報・終了条件を示す

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

無条件Retry、古い決定権限、AI提供元差の隠蔽および外部作用（Effect）の二重実行を反証する
