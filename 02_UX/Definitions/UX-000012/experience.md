# UX-000012 入口を変えても同じ仕事を続ける

成果物種別: UX定義
UX ID: `UX-000012`
状態: 現行正本
維持責任者: Qual-Lab

## 利用者成果

Workbench、MCP、CLIまたはAIの入口を変えても、同じ入力・権限・状態・結果を用いて仕事を続けられる

```text
開発者
        │ Workbench・MCP・CLI・AIの入口を選ぶ時
        ▼
入口差にかかわらず同じ正本・入力・権限で操作する
        │
        ▼
入口を変えても判断と結果を読み替えず仕事を続けられる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「開発者」 |
| 利用のきっかけ／場面 | Workbench・MCP・CLI・AIの入口を選ぶ時 |

| 得られる結果 | 入口を変えても判断と結果を読み替えず仕事を続けられる |

## 成立条件

- Workbench、MCP、CLIまたはAIの入口を変えても、同じ入力・権限・状態・結果を用いて仕事を続けられる
- 重要場面「入口を切り替えて同じ仕事を開始・継続する場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
Workbench・MCP・CLI・AIの入口を選ぶ時
        ↓
入口差にかかわらず同じ正本・入力・権限で操作する
        │
        ├─ ★ 重要場面: 入口を切り替えて同じ仕事を開始・継続する場面
        ├─ ⚠ 失敗:  入口固有の第二正本や判断が同じ仕事の意味を変える
        └─ ✓ 守る品質:  正本・適用規則・入力・認可・結果の意味を共通化する
        ↓
入口を変えても判断と結果を読み替えず仕事を続けられる
```

## 必要な情報

処理結果、公開契約、通信入口向けの表示を分ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

入口固有の第二正本、適用規則、業務状態、決定権限判断または結果差を反証する

具体的な試験段階、試験場面、期待結果は品質保証工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

SPECは公開結果と通信方式 errorを分け、ArchitectureとVerificationは両入口の意味同値性を保証する。
