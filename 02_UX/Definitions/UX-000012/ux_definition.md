# UX-000012 入口を変えても同じ仕事を続ける

成果物種別: UX定義
UX ID: `UX-000012`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる

```text
開発者
        │ ローカルMCPの通信方式を選ぶ時
        ▼
通信方式を変えても同じ公開契約・入力・権限判断で操作する
        │
        ▼
stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる
```

## 利用者に起きる変化

```text
変更前
────────────────
- 通信方式ごとに結果、状態、エラー、許可の意味が変わる
        │
        │ ローカルMCP 通信方式間の意味統一が変える体験
        ▼
変更後
────────────────
- 利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す
```

ローカルMCP 通信方式間の意味統一は、単に内部方式を成立させる要求ではない。「通信方式ごとに結果、状態、エラー、許可の意味が変わる」状態から、「利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

MCP／ツール利用者・統合者がstdioとHTTPで同じ意味の操作を行うことで、通信方式を変えても結果を読み替えなくてよいようになることを守る。

## 成立条件

- stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる
- 失敗時は、失敗した通信方式と外部作用（Effect）が発行されたかを区別して、入口変更や再処置を判断できる。
- 重要場面「入口を切り替えて同じ仕事を開始・継続する場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験・失敗・品質期待

```text
ローカルMCPの通信方式を選ぶ時
        ↓
通信方式を変えても同じ公開契約・入力・権限判断で操作する
        │
        ├─ ★ 重要場面: 入口を切り替えて同じ仕事を開始・継続する場面
        ├─ ⚠ 失敗:  通信方式によって入力・権限判断・状態・結果の意味が変わる
        └─ ✓ 守る品質:  公開契約・入力・権限判断・状態・結果を通信方式間で一致させる
        ↓
stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる
```

### 重要な失敗

- 通信方式によって入力・権限判断・状態・結果の意味が変わる

### 体験品質への期待

- 公開契約・入力・権限判断・状態・結果を通信方式間で一致させる

## 必要な情報

- UXが定義すること: 利用者、状況、目的、得られる結果、重要場面、失敗および品質期待。
- 下流工程へ残すこと: 情報構造、表示、操作、振る舞いおよび実現方式。
- 対象外: 特定画面、通信方式、内部構成、試験段階または実装方式の決定。

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

stdio MCPとlocalhost HTTPで入力・権限判断・状態・結果が変わること、および失敗した通信方式と外部作用の発行有無を識別できない表示を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。
