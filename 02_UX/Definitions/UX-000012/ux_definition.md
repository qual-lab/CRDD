# UX-000012 入口を変えても同じ仕事を続ける

成果物種別: UX定義
UX ID: `UX-000012`
状態: Canonical
維持責任者: Qual-Lab

## 利用者成果

stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる

```text
開発者
        │ ローカルMCPの通信方式を選ぶ時
        ▼
通信方式を変えても同じ公開契約・入力・権限判断で操作する
        │
        ▼
stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる
```

## 利用者・状況・目的

| 項目 | 内容 |
|---|---|
| 主な想定利用者／利用状況 | [製品全体の利用者像](../../02_Personas.md)の「開発者」 |
| 利用のきっかけ／場面 | ローカルMCPの通信方式を選ぶ時 |

| 得られる結果 | stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる |

## 成立条件

- stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる
- 失敗時は、失敗した通信方式と外部作用（Effect）が発行されたかを区別して、入口変更や再処置を判断できる。
- 重要場面「入口を切り替えて同じ仕事を開始・継続する場面」で、避ける失敗を利用者が正常状態や完了として誤認しない。
- 入口、実装または利用主体が変わっても、この利用者成果の意味を維持する。

## 重要な体験と品質期待

```text
ローカルMCPの通信方式を選ぶ時
        ↓
通信方式を変えても同じ公開契約・入力・権限判断で操作する
        │
        ├─ ★ 重要場面: 入口を切り替えて同じ仕事を開始・継続する場面
        ├─ ⚠ 失敗:  通信方式によって入力・権限判断・状態・結果の意味が変わる
        └─ ✓ 守る品質:  公開契約・入力・権限判断・状態・結果を通信方式間で一致させる
        ↓
stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる
```

## 必要な情報

処理結果、公開契約、通信方式、外部作用の発行有無を分ける

## 制約

- 画面、通信方式、内部構成要素または特定の実装方式をUX成果そのものにしない。
- 下流工程は利用者成果を弱めず、情報構造、操作、振る舞いおよび実現方式へ具体化する。
- 想定した利用者、状況または目的が誤っていると判明した場合は、元の要求分析とDiscoveryへ戻す。

## 検証意図

stdio MCPとlocalhost HTTPで入力・権限判断・状態・結果が変わること、および失敗した通信方式と外部作用の発行有無を識別できない表示を反証する

具体的な試験段階、試験場面、期待結果は検証（Verification）工程で設計し、この体験定義には実行結果を書き込まない。

## 下流への引き渡し

IAは通信方式、外部作用の発行有無、結果および次の処置を関連付ける。SPECは公開結果と通信方式 errorを分け、ArchitectureとVerificationは両入口の意味同値性と、外部作用の発行前後を取り違えないことを保証する。

## 統合後に追加された要求固有条件

この体験の中心成果はREQ-000006が定めるローカルMCPの通信方式間の同値性である。後続要求は次の条件を追加するが、中心成果を置き換えない。

| 追加元 | 追加される場面・条件 | 追加される失敗・検証意図 |
|---|---|---|
| REQ-000010 | プロジェクト運営者／PMがWorkbench・MCP・CLIを選ぶ場面で、共通の公開アプリケーション契約へ要求する | 入口ごとの業務ロジックや結果契約の差を反証する |
| REQ-000028 | 開発者が複数のAI入口を選ぶ場面で、AI固有入口を第二のCRDD標準にしない | 入口ごとに複製した規則と判断境界の不一致を反証する |
