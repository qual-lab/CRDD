# CRDD／CROSの体験品質期待

状態: 候補（v0.21.0、公開済みの基準版: v0.20.1）
担当責任者: Qual-Lab
最終更新日: 2026-09-14
工程規則: [UX](../22_UX.md)

本書は、利用者や運用者へ現れる品質を製品全体で統合する。数値閾値、状態Schema、プロトコルおよび実現方式は下流工程が具体化する。

## 1. 品質期待の全体像

```text
理解できる ─────────┐
根拠へ戻れる ───────┤
不足を誤認しない ───┼→ 安心して次の判断と仕事へ進める
止まった理由が分かる ┤
同じ仕事へ戻れる ───┤
不要に待たされない ─┘
```

速く応答するだけでは成立しない。利用者が、現在状態、根拠、不完全性、必要な判断および次の安全な行動を理解できることを優先する。

## 2. 品質期待台帳

| 品質期待 | 利用者に現れる状態 | 重要場面 | 避ける失敗 | 下流で具体化すること |
|---|---|---|---|---|
| 分かりやすさ | 状態、結果、失敗理由、次の行動を専門的な内部ログなしで理解できる | 初回結果、判断待ち、停止 | 一律に「失敗」とだけ示す、専門語だけで説明する、根拠なく完了と示す | 表示する状態、説明、エラー時の振る舞い |
| 根拠へたどれること | 結論から情報源、改訂版、観測時点、判断へ戻れる | プロジェクト表示、複数プロジェクトの比較、外部情報の利用結果 | 出典のない要約、別の仕事の結果混入 | 識別情報、関係、たどり方 |
| 不完全さに気づけること | 欠測、制限、古さ、競合、未観測を正常・0・完全と区別できる | 複数リポジトリの統合、状態の表示、実行記録の分析 | 一部成功を全体完了として扱う | 網羅範囲、情報の新しさ、競合状態 |
| 自分で制御できること | 何を誰へどこまで任せ、どこで人間が判断するか分かる | 委任前、外部送信、候補採用 | 接続済みであることから包括的な許可を推定する | 決定権限、同意、判断の取り決め |
| 回復できること | 再試行、再取得、回復、清掃を取り違えず同じ仕事へ戻れる | 応答喪失、取消、残存検出 | 処理の二重実行、回復先不明、要求を出しただけで完了とする | 一連の状態変化、回復対象の識別、終了条件 |
| 待っている状況が分かること | 状態不明のまま長く待たされず、待機中も現在地と次の選択を理解できる | 外部実行、横断取得、長時間処理 | 無反応、偽の進捗、不要な反復承認 | 観測頻度、時間切れ、進捗の取り決め |
| 入口を変えても意味が変わらないこと | Workbench、MCP、CLI、対話AIで、同じ入力と決定権限から同じ意味の結果へ届く | 入口の切替、再接続 | 入口ごとに別の正本や状態を持つ | 公開する取り決め、表示結果の同値性 |
| 誰でも必要な情報へ届けること | 能力、端末、知識の差が不必要な成果格差にならない | 初回利用、エラー、複雑な比較 | 色や専門語だけで状態を表す | キーボード操作、読み上げ、言語、代替表現 |
| 事実と判断材料を取り違えないこと | 事実、仮説、評価、候補、公式表示、発行元への信頼を取り違えない | AI結果、実行環境の導入、公開判断 | 推測を事実にする、異なる信頼要素を一つの表示へまとめる | 出所、表示分類、利用環境の信頼方針 |

## 3. 利用の流れの中の重要場面

```text
結果を受け取る
      │
      ├─ ★ 状態と網羅範囲を最初に理解できる
      ├─ ⚠ Missing／Stale／Restrictedを隠さない
      └─ ✓ 情報源と次の行動へ進める
      ↓
判断する
      │
      ├─ ★ 人間へ残る判断が分かる
      ├─ ⚠ 決定権限を暗黙に拡張しない
      └─ ✓ 保留・拒否・訂正・再開を選べる
      ↓
継続または回復
      │
      ├─ ★ 同じ識別情報へ戻る
      ├─ ⚠ 結果不明の外部作用（Effect）を再実行しない
      └─ ✓ 終了後状態を確認できる
```

## 4. 両立が難しい点と優先順位

| 両立が難しい点 | 現在の優先判断 |
|---|---|
| 短い要約と、不完全さの表示 | 要約を短くしても網羅範囲、制限、根拠への道筋を失わない |
| 自動継続と、人間の制御 | 既に許可した範囲は繰り返し確認しないが、新しい決定権限やリスクは人間へ戻す |
| 速さと、確実な終了確認 | 要求を出したことや処理番号を得たことだけで完了とせず、必要な結果を確認する |
| 柔軟な環境と、安全な停止 | バージョン文字列を過剰固定せず、意味や危険な変化を検出した時に止まる |
| 一つのプロジェクト表示と、リポジトリ境界 | 日常表示はプロジェクト中心にするが、情報源、欠測、開示境界を隠さない |

## 5. 妥当性確認と下流への引き渡し

- IAは情報源、網羅範囲、情報の新しさ、Conflict、判断および回復の関係を定義する。
- UIは状態、不完全性、判断待ちおよび根拠を誤認させない表示と操作を設計する。
- SPECは失敗、Timeout、再取得、取消、回復および完了条件を観測可能な契約にする。
- Architectureは外部境界、決定権限、外部作用（Effect）、診断および資源の一連の状態変化を閉じる。
- Verificationは成功例だけでなく、品質期待を破る反例を試す。
- Prototypeと代表利用者確認では、到達時間だけでなく、誤認、再探索、迷い、判断Confidenceおよび回復可否を観測する。
