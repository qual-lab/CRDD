# REQ-000006の利用者体験分析

状態: UX成果統合済み・独立レビュー待ち
要求: `REQ-000006` Local MCP Transport間の意味統一
探索元: [EXP-000015](../../../01_Discovery/Explorations/EXP-000015_Local_MCP_HTTP_Access/exploration.md)

## 1. 要求から起こしたい利用者変化

```text
Before
────────────────
- Transportごとに結果、状態、エラー、許可の意味が変わる
        │
        │ Local MCP Transport間の意味統一が変える体験
        ▼
After
────────────────
- 利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す
```

Local MCP Transport間の意味統一は、単に内部方式を成立させる要求ではない。「Transportごとに結果、状態、エラー、許可の意味が変わる」状態から、「利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

## 2. REQの一次分析

| 観点 | 内容 |
|---|---|
| 課題 | Transportごとに結果、状態、エラー、許可の意味が変わる |
| 対象範囲 | Local MCPをstdioまたはHTTPで使う人・Toolが、「Transportごとに結果、状態、エラー、許可の意味が変わる」状態から「利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す」状態へ移る場面 |

| 主な利用者 | 利用場面 | 目標・困りごと | 根拠・確信度 |

| Local MCPをstdioまたはHTTPで使う人・Tool | Transportごとに結果、状態、エラー、許可の意味が変わる | 利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す | 探索元の課題と採用要求から導いた設計上の想定。個人属性、利用頻度および許容負担は未実測。 |

## 6. サービス提供上の責任境界

| 担い手 | 担うこと | 越えてはならない境界 |
|---|---|---|
| 人間 | 対象、目的、許可範囲を確認し、提示された根拠から採否または次の行動を判断する。 | 内部状態や不足情報を推測で補って判断することを要求されない。 |
| System／AI | 利用者が「利用する接続方法を変えても同じ依頼が同じ意味の結果と停止理由を返す」状態へ進めるよう、必要な状態、根拠および選択肢を示し、許可された処理だけを行う。 | 不明状態を成功へ畳まず、権限・対象・意味を無断で拡張しない。 |
| 運用・確認者 | 期待品質を検証し、成立不能時は根拠を保ったまま責任所有者または回復経路へ移送する。 | 人間の判断、観測事実または正本を便宜的に上書きしない。 |

## 7. 重要場面、失敗、品質期待

| 重要場面 | 避ける失敗 | 品質期待 |
|---|---|---|
| 結果または状態を最初に受け取る時 | Transportごとに結果、状態、エラー、許可の意味が変わる | Transport差を業務状態として見せない。 |
| 結果を判断または引き継ぐ時 | 必要条件を満たしていないのに完了・正常と理解する | 同じ入力・権限なら同じ意味になる。 |
| 失敗・不足から次の行動を選ぶ時 | 成立不能の理由や回復先が分からないまま作業が止まる | 接続失敗とRuntime失敗を区別できる。 |
