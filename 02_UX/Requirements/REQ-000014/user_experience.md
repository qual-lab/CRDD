# REQ-000014の利用者体験分析

状態: UX成果統合済み・独立レビュー待ち
要求: `REQ-000014` Repository Tool能力の明示Registry
探索元: [EXP-000025](../../../01_Discovery/Explorations/EXP-000025_Repository_Capability_Discovery/exploration.md)

## 1. 要求から起こしたい利用者変化

```text
Before
────────────────
- 存在するファイルや名前から能力と実行許可を推測する
        │
        │ Repository Tool能力の明示Registryが変える体験
        ▼
After
────────────────
- 登録済み能力、現在利用可能な能力、許可された操作を区別して選べる
```

Repository Tool能力の明示Registryは、単に内部方式を成立させる要求ではない。「存在するファイルや名前から能力と実行許可を推測する」状態から、「登録済み能力、現在利用可能な能力、許可された操作を区別して選べる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

## 2. REQの一次分析

| 観点 | 内容 |
|---|---|
| 課題 | 存在するファイルや名前から能力と実行許可を推測する |
| 対象範囲 | Repositoryで作業する人、AI、外部Toolが、「存在するファイルや名前から能力と実行許可を推測する」状態から「登録済み能力、現在利用可能な能力、許可された操作を区別して選べる」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

## 3. 利用者の想定とペルソナ

| 主な利用者 | 利用場面 | 目標・困りごと | 根拠・確信度 |
|---|---|---|---|
| Repositoryで作業する人、AI、外部Tool | 存在するファイルや名前から能力と実行許可を推測する | 登録済み能力、現在利用可能な能力、許可された操作を区別して選べる | 探索元の課題と採用要求から導いた設計上の想定。個人属性、利用頻度および許容負担は未実測。 |

ここでのペルソナは架空の人物像ではなく、判断や体験差へ必要な役割と利用状況である。

## 4. 体験区間とSupporting Model

| 項目 | 内容 |
|---|---|
| 起点 | 存在するファイルや名前から能力と実行許可を推測する |
| 行動・判断 | 利用者は提示された状態と根拠から、続行、確認、修正または回復を選ぶ。 |
| 接点・期待支援 | 未登録能力を推測表示しない。／利用不能理由を登録欠落と権限拒否で分ける。 |
| 完了または回復 | 登録済み能力、現在利用可能な能力、許可された操作を区別して選べる。成立不能時は不明を成功へ畳まず、理由と次の行動を確認できる。 |

| Supporting Model | 処置 | 理由・参照先 |
|---|---|---|
| Experience Change | `作成` | 本文冒頭で、この要求が変える利用前後の仕事・認知・判断を示した。 |
| Experience Flow／Journey | `既存参照` | 本要求が関わる時間軸は[非AI外部ToolのJourney](../../03_Experience_Map.md#repositoryで日常作業を進める)を参照し、要求固有の区間は上表で示す。 |
| Service Blueprint | `非該当` | 本要求では複数主体の協調そのものを新しい体験成立条件にせず、必要な責任境界は次節で示す。 |
| User／Task Flow／Storyboard | `非該当` | 具体的な操作、画面遷移または利用環境の描写はIA／UIで具体化し、この要求分析では先取りしない。 |

## 6. サービス提供上の責任境界

| 担い手 | 担うこと | 越えてはならない境界 |
|---|---|---|
| 人間 | 対象、目的、許可範囲を確認し、提示された根拠から採否または次の行動を判断する。 | 内部状態や不足情報を推測で補って判断することを要求されない。 |
| System／AI | 利用者が「登録済み能力、現在利用可能な能力、許可された操作を区別して選べる」状態へ進めるよう、必要な状態、根拠および選択肢を示し、許可された処理だけを行う。 | 不明状態を成功へ畳まず、権限・対象・意味を無断で拡張しない。 |
| 運用・確認者 | 期待品質を検証し、成立不能時は根拠を保ったまま責任所有者または回復経路へ移送する。 | 人間の判断、観測事実または正本を便宜的に上書きしない。 |

## 7. 重要場面、失敗、品質期待

| 重要場面 | 避ける失敗 | 品質期待 |
|---|---|---|
| 結果または状態を最初に受け取る時 | 存在するファイルや名前から能力と実行許可を推測する | 未登録能力を推測表示しない。 |
| 結果を判断または引き継ぐ時 | 必要条件を満たしていないのに完了・正常と理解する | 利用不能理由を登録欠落と権限拒否で分ける。 |
| 失敗・不足から次の行動を選ぶ時 | 成立不能の理由や回復先が分からないまま作業が止まる | 一覧表示だけでEffect Authorityを与えない。 |
