## 1. REQの一次分析

```text
残存物を消してよいか分からず蓄積するか、名前だけで削除して回復情報を失う
        ↓
解決策を先に固定せず、人の仕事として読み替える
        ↓
UXとして必要
残存資源の由来・保持・清掃・回復を理解する
```

この要求で解くのは機能の有無だけではない。Runtime運用者が「必要なEvidenceを残し不要物を安全に片付けられる」状態へ進めないことを問題として扱う。具体的な画面、データ構造、API、Componentまたは数値閾値はここで確定しない。

| 観点 | 内容 |
|---|---|
| 解決する問題 | 残存物を消してよいか分からず蓄積するか、名前だけで削除して回復情報を失う |
| UX Need | 残存資源の由来・保持・清掃・回復を理解する |
| 対象範囲 | Runtime運用者、Repository所有者が、「残存物を消してよいか分からず蓄積するか、名前だけで削除して回復情報を失う」状態から「保持理由、Recovery要否、清掃可能条件、終了後状態を確認して安全に処置できる」状態へ移る場面 |
| 対象外 | 具体的な画面、データ構造、実装方式および数値閾値の確定 |

## 3. 利用者に起きる変化

```text
Before
────────────────
- 残存物を消してよいか分からず蓄積するか、名前だけで削除して回復情報を失う
        │
        │ Runtime Dataの保持・清掃・回復が変える体験
        ▼
After
────────────────
- 保持理由、Recovery要否、清掃可能条件、終了後状態を確認して安全に処置できる
```

Runtime Dataの保持・清掃・回復は、単に内部方式を成立させる要求ではない。「残存物を消してよいか分からず蓄積するか、名前だけで削除して回復情報を失う」状態から、「保持理由、Recovery要否、清掃可能条件、終了後状態を確認して安全に処置できる」状態へ変わり、利用者が次の判断へ進めることまでを体験として扱う。

この変化で守るのは操作手順ではない。Runtime運用者が残存資源の由来・保持・清掃・回復を理解することで、必要なEvidenceを残し不要物を安全に片付けられるようになることを守る。

## 5. 重要な体験

```text
失敗後または保守時に残存を見つけた時
        ↓
exact Identity・参照中か・cleanup条件を確認する
        │
        ├─ ★ Critical: 削除または回復を選ぶ場面
        ├─ ⚠ Failure:  名前や経過時間だけで由来不明物を削除する
        └─ ✓ Quality:  残存・観測不能・不存在を区別する
        ↓
必要なEvidenceを残し不要物を安全に片付けられる
```

### 責任境界

| 担い手 | この要求で担うこと | 越えてはならない境界 |
|---|---|---|
| 利用者（Runtime運用者） | 残存資源の由来・保持・清掃・回復を理解するために、提示された状態と根拠から次の行動を判断する | 不足情報や内部状態を推測で補うことを要求されない |
| 提供System／AI | exact Identity・参照中か・cleanup条件を確認するための状態、根拠および選択肢を示す | 名前や経過時間だけで由来不明物を削除する状態を成功・完了として表示しない |
| 運用・確認者 | 「残存・観測不能・不存在を区別する」ことと、必要なEvidenceを残し不要物を安全に片付けられる状態へ到達できることを反証する | 未確認範囲や人間の判断を便宜的に上書きしない |

### 重要場面・失敗・品質期待の対応

| 重要場面 | 避ける失敗 | 品質期待 |
|---|---|---|
| 削除または回復を選ぶ場面 | 名前や経過時間だけで由来不明物を削除する | 残存・観測不能・不存在を区別する |

要求から得た追加の品質期待は次のとおりである。主Flowの品質を置き換えず、下流で具体化する観測点として保持する。

| 重要場面 | 避ける失敗 | 品質期待 |
|---|---|---|
| 結果または状態を最初に受け取る時 | 残存物を消してよいか分からず蓄積するか、名前だけで削除して回復情報を失う | 由来不明と不要を同一視しない。 |
| 結果を判断または引き継ぐ時 | 必要条件を満たしていないのに完了・正常と理解する | 清掃不能時にexactな再入場情報を示す。 |
| 失敗・不足から次の行動を選ぶ時 | 成立不能の理由や回復先が分からないまま作業が止まる | 成功後は物理残存がないことを確認できる。 |
