## 3. 観測可能にする契機・結果・失敗

```text
プロジェクト運営者／PM
        │ 複数AIへ仕事を委ねる時
        ▼
複数AIへ任せる範囲と権限を理解する
        │
        ├─ 成立   → 実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる
        ├─ 不成立 → 暗黙の範囲拡張や回復不能
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 外部作用（Effect）の前の委任境界
- 成功は処理の開始ではなく、「委任状態・停止理由・回復先を行動可能に示す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる
- 境界: 「外部作用（Effect）の前の委任境界」で、成立・不成立・判断不能を分け、「暗黙の範囲拡張や回復不能」へ至る状態を正常へ畳まない
- 失敗: 暗黙の範囲拡張や回復不能
- 品質: 委任状態・停止理由・回復先を行動可能に示す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
