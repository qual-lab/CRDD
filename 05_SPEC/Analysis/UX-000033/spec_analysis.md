## 1. 正式入力

- UX定義: [UX-000033 論点と会議記録を安全に維持する](../../../02_UX/Definitions/UX-000033/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。

## 2. 振る舞いへ引き継ぐ利用者成果

正当な履歴を保ちながらTopicとMeetingを一通り扱い、誤登録だけを影響確認後に除ける。

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | Project運営者、Meeting参加者、Topic責任者が記録を維持する |
| 利用のきっかけ | 登録、確認、更新、終了、訂正、誤登録削除 |
| 目的 | Topicの継続状態とMeetingの時点記録を経緯ごと維持する |
| 利用者成果 | 正当な履歴を残して誤登録だけを安全に除ける |
| 必要な情報 | Topic、Meeting、状態、時点、関係、削除影響、Authority、操作結果 |
| 重要場面 | 物理削除を確定する直前 |
| 避ける失敗 | 正当な履歴、関連対象または関係整合性を失う |
| 守る品質 | 影響、復旧可能性、終了後状態を保持する |
| 検証意図 | 入口一貫性、履歴保持、非連鎖削除、関係整合、部分失敗を観測する |

## 3. 観測可能にする契機・結果・失敗

```text
Topic／Meetingを処置する
        ├─ 成立   → 対象・関係・処置・終了後状態が一致する
        ├─ 不成立 → 競合・部分成功・残存関係・回復先を返す
        └─ 不明   → 影響またはAuthorityを再確認しEffect 0
```

## 4. 受入条件と適用範囲

- 正常: 作成、取得、更新、終了、訂正、削除の結果を同じIdentityで返す。
- 境界: 正当な履歴処置と誤登録の物理削除を分ける。
- 失敗: 削除対象外を連鎖削除せず、部分成功を完了としない。
- 判断不能: 影響、Authorityまたは復旧可能性が不明なら変更しない。
- 下流へ失わず渡す意味: 操作、Authority、Relation整合、終了後状態、回復。
