## 1. 正式入力

- UX定義: [UX-000009 プロジェクトの現在地を根拠と不完全性付きで理解する](../../../02_UX/Definitions/UX-000009/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

| 必要な情報 | プロジェクト、項目、情報源、改訂版、観測時点、網羅範囲および次の判断を関連付ける |
| 重要場面 | 現在の表示を信じる直前 |
| 避ける失敗 | 欠測や古い値を完全な現在値と誤認する |

| 検証意図 | partial、stale、restricted、conflictingおよび未観測値の誤認を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
プロジェクト運営者／PM
        │ プロジェクト状況を確認する時
        ▼
プロジェクトの現在地を根拠と不完全性付きで理解する
        │
        ├─ 成立   → 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる
        ├─ 不成立 → 欠測や古い値を完全な現在値と誤認する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 現在の表示を信じる直前
- 成功は処理の開始ではなく、「根拠、不完全性、観測時点を同時に示す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる
- 境界: 「現在の表示を信じる直前」で、成立・不成立・判断不能を分け、「欠測や古い値を完全な現在値と誤認する」へ至る状態を正常へ畳まない
- 失敗: 欠測や古い値を完全な現在値と誤認する
- 品質: 根拠、不完全性、観測時点を同時に示す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
