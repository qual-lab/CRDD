## 3. 観測可能にする契機・結果・失敗

```text
CRDD閲覧者。設計・実装・検証を引き継ぐ後工程担当者を含む
        │ 工程の入口・出口で成果物を渡す時
        ▼
工程固有の図から状態・関係・未接続を理解する
        │
        ├─ 成立   → 工程固有の図から全体像・関係・状態差・未接続を理解し、後工程で意図を再発明せずに引き継げる
        ├─ 不成立 → 必要な図を黙って省略しAIごとに記法が変わる
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 下流義務へ変換する場面
- 成功は処理の開始ではなく、「図の意味・凡例・正本関係を固定する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 工程固有の図から全体像・関係・状態差・未接続を理解し、後工程で意図を再発明せずに引き継げる
- 境界: 「下流義務へ変換する場面」で、成立・不成立・判断不能を分け、「必要な図を黙って省略しAIごとに記法が変わる」へ至る状態を正常へ畳まない
- 失敗: 必要な図を黙って省略しAIごとに記法が変わる
- 品質: 図の意味・凡例・正本関係を固定する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
