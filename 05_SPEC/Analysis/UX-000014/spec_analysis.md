# UX-000014のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000014`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000014 Meeting内容を候補化し採否を判断する](../../../02_UX/Definitions/UX-000014/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

会話・観察・仮説・候補・決定を区別し、既存Topicとの関係を根拠付きで判断して所有正本へ戻せる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」 |
| 利用のきっかけ | Meeting後に決定・Topic・Actionを整理する時 |
| 目的 | 会議の内容を候補として整理し正本へつなぐ |
| 利用者成果 | 会話・観察・仮説・候補・決定を区別し、既存Topicとの関係を根拠付きで判断して所有正本へ戻せる |
| 必要な情報 | Meeting Item、候補、Topic Relation、判断、責任者を結ぶ |
| 重要場面 | 候補を採用または却下する場面 |
| 避ける失敗 | 会議記録が自動的に正本へ昇格する |
| 守る品質 | 候補・判断・反映結果を区別する |
| 検証意図 | 会話の自動採用と文字列一致だけの統合・分割を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」
        │ Meeting後に決定・Topic・Actionを整理する時
        ▼
会議の内容を候補として整理し正本へつなぐ
        │
        ├─ 成立   → 会話・観察・仮説・候補・決定を区別し、既存Topicとの関係を根拠付きで判断して所有正本へ戻せる
        ├─ 不成立 → 会議記録が自動的に正本へ昇格する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 候補を採用または却下する場面
- 成功は処理の開始ではなく、「候補・判断・反映結果を区別する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 会話・観察・仮説・候補・決定を区別し、既存Topicとの関係を根拠付きで判断して所有正本へ戻せる
- 失敗: 会議記録が自動的に正本へ昇格する
- 品質: 候補・判断・反映結果を区別する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAはMeeting、Topic、候補、判断および情報源同士の関係を分ける。Communicationは外部表現への昇格を別判断とし、UI／SPECは候補比較と採用を別操作にする。」を失わず渡す。
