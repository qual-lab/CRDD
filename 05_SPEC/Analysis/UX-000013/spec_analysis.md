# UX-000013のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000013`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000013 許可された作業領域だけをリモート利用する](../../../02_UX/Definitions/UX-000013/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

接続元や接続資格情報が変わっても、現在許可された作業領域だけを利用し、利用不能理由と管理能力を内容閲覧から区別できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | プロジェクト運営者／PM |
| 利用のきっかけ | リモート接続を開始・再接続する時 |
| 目的 | 許可された作業領域だけへ接続する |
| 利用者成果 | 接続元や接続資格情報が変わっても、現在許可された作業領域だけを利用し、利用不能理由と管理能力を内容閲覧から区別できる |
| 必要な情報 | 接続資格情報、接続単位、作業領域の利用許可範囲、システム管理能力、開示範囲を分ける |
| 重要場面 | 利用可能情報を表示する時 |
| 避ける失敗 | 利用不能なリポジトリの存在や内容を推測表示する |
| 守る品質 | 現在の利用許可範囲（Grant）だけを開示し不足を補完しない |
| 検証意図 | 存在漏えい、一律の追加許可による解錠、古い利用許可範囲および管理能力からの閲覧権限推定を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
プロジェクト運営者／PM
        │ リモート接続を開始・再接続する時
        ▼
許可された作業領域だけへ接続する
        │
        ├─ 成立   → 接続元や接続資格情報が変わっても、現在許可された作業領域だけを利用し、利用不能理由と管理能力を内容閲覧から区別できる
        ├─ 不成立 → 利用不能なリポジトリの存在や内容を推測表示する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 利用可能情報を表示する時
- 成功は処理の開始ではなく、「現在の利用許可範囲（Grant）だけを開示し不足を補完しない」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 接続元や接続資格情報が変わっても、現在許可された作業領域だけを利用し、利用不能理由と管理能力を内容閲覧から区別できる
- 境界: 「利用可能情報を表示する時」で、成立・不成立・判断不能を分け、「利用不能なリポジトリの存在や内容を推測表示する」へ至る状態を正常へ畳まない
- 失敗: 利用不能なリポジトリの存在や内容を推測表示する
- 品質: 現在の利用許可範囲（Grant）だけを開示し不足を補完しない
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
