## 3. 観測可能な契機・結果

Remote接続／再接続で資格からユーザーを識別し、現行Role詳細権限、公開対象、実アクセスを別々に成立させた範囲だけ返す。名前を認証・認可の根拠にせず、Role変更は次の認可へ反映する。

認証済み利用者の自身表示、非認証入口へのユーザー情報0、非管理者への他ユーザー一覧・存在・件数0を別々に保持する。Repository非開示対象の存在・名前・件数も漏らさない。

利用可能／資格要求／制限／利用不能／不明を区別する。複数対象の「一部だけ利用可能」は別の部分成立として示し、全体利用可能や単なる制限へ畳まない。リセット成功から開始済み操作の取消完了を推定しない。

userIdは正式入力の採用済みUUID制約を継承する。版・Schema・生成方式をここで決めない。
