# UX-000017のSPEC分析

成果物種別: SPEC分析（UX観点）

## 1. 正式入力

- UX定義: [UX-000017 実行時データを安全に保持・清掃する](../../../02_UX/Definitions/UX-000017/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「実行環境の導入・運用者」 |
| 利用のきっかけ | 実行時データを作成または清掃する時 |
| 目的 | 実行時データの所有場所と一連の状態変化を理解する |
| 利用者成果 | 保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる |
| 必要な情報 | データの責任者、基点フォルダ、Durability、保持期間、清掃を関連付ける |
| 重要場面 | 永続化または削除の直前 |
| 避ける失敗 | subdirectoryや別基点フォルダへ同名データを作る |
| 守る品質 | 用途別領域とcleanup条件を明示する |
| 検証意図 | 用途不明の書込み、名前や時間だけの削除および別リポジトリへの波及を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「実行環境の導入・運用者」
        │ 実行時データを作成または清掃する時
        ▼
実行時データの所有場所と一連の状態変化を理解する
        │

        ├─ 不成立 → subdirectoryや別基点フォルダへ同名データを作る
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 永続化または削除の直前
- 成功は処理の開始ではなく、「用途別領域とcleanup条件を明示する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる
- 失敗: subdirectoryや別基点フォルダへ同名データを作る
- 品質: 用途別領域とcleanup条件を明示する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAは基点フォルダ、用途、責任者、一連の状態変化を分け、ArchitectureとMaintenanceはパス契約と清掃を定める。」を失わず渡す。
