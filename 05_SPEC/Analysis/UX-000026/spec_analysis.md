成果物種別: SPEC分析（UX観点）

## 1. 正式入力

- UX定義: [UX-000026 試験層と現在の保証範囲を理解して選ぶ](../../../02_UX/Definitions/UX-000026/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

各試験層が確認したこと・未確認範囲・時間や費用を理解し、必要な検証と高負荷試験の実行有無を選べる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | CRDD作成者・保守者 |
| 利用のきっかけ | 変更の検証計画を作る時 |
| 目的 | 試験層ごとの保証と未確認範囲を理解する |
| 利用者成果 | 各試験層が確認したこと・未確認範囲・時間や費用を理解し、必要な検証と高負荷試験の実行有無を選べる |
| 必要な情報 | Test Layer、対象範囲、一連の状態変化 根拠、決定権限、Not Executed Stateを結ぶ |
| 重要場面 | 外部境界を結合する各段階 |
| 避ける失敗 | 単発成功や試験件数から一連の状態変化全体を保証する |
| 守る品質 | 開始から清掃まで段階的に反証する |
| 検証意図 | 一部Passからの全体品質推定、単発成功だけの一連の状態変化保証および未指示の高負荷実行を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
CRDD作成者・保守者
        │ 変更の検証計画を作る時
        ▼
試験層ごとの保証と未確認範囲を理解する
        │
        ├─ 成立   → 各試験層が確認したこと・未確認範囲・時間や費用を理解し、必要な検証と高負荷試験の実行有無を選べる
        ├─ 不成立 → 単発成功や試験件数から一連の状態変化全体を保証する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 外部境界を結合する各段階
- 成功は処理の開始ではなく、「開始から清掃まで段階的に反証する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 各試験層が確認したこと・未確認範囲・時間や費用を理解し、必要な検証と高負荷試験の実行有無を選べる
- 境界: 「外部境界を結合する各段階」で、成立・不成立・判断不能を分け、「単発成功や試験件数から一連の状態変化全体を保証する」へ至る状態を正常へ畳まない
- 失敗: 単発成功や試験件数から一連の状態変化全体を保証する
- 品質: 開始から清掃まで段階的に反証する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。

### UX-000026から継承する確認事項

正式入力: [UX-000026](../../../02_UX/Definitions/UX-000026/ux_definition.md)

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000030: CRDD作成者・保守者が「試験層ごとの保証と未確認範囲を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000030: CRDD作成者・保守者が「試験層ごとの保証と未確認範囲を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: CRDD作成者・保守者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

再評価契機: 対象利用者による実利用確認、前提変更、または後続工程でこの未確認事項が成立条件へ影響すると判明した時。
