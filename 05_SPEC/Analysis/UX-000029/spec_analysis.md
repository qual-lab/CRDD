# UX-000029のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000029`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000029 作業・変更・根拠・品質を迷わず辿る](../../../02_UX/Definitions/UX-000029/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

未完了、変更理由、全影響パス、成立根拠および現在品質を役割の違いとともに辿れる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | CRDD作成者・保守者 |
| 利用のきっかけ | 変更の現在地や根拠を調べる時 |
| 目的 | 作業・変更・根拠・品質を役割別に辿る |
| 利用者成果 | 未完了、変更理由、全影響パス、成立根拠および現在品質を役割の違いとともに辿れる |
| 必要な情報 | Work、Change、変更対象ファイル、根拠、観測した改訂版、品質を分ける |
| 重要場面 | 変更の影響漏れを確認する場面 |
| 避ける失敗 | 同じ説明を複製し代表ファイルだけで済ませる |
| 守る品質 | 正本を分け全影響ファイルを列挙する |
| 検証意図 | 責任者の混同、代表パスだけの表示、根拠の遡及上書きおよびGit差分への丸投げを反証する |

## 3. 観測可能にする契機・結果・失敗

```text
CRDD作成者・保守者
        │ 変更の現在地や根拠を調べる時
        ▼
作業・変更・根拠・品質を役割別に辿る
        │
        ├─ 成立   → 未完了、変更理由、全影響パス、成立根拠および現在品質を役割の違いとともに辿れる
        ├─ 不成立 → 同じ説明を複製し代表ファイルだけで済ませる
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 変更の影響漏れを確認する場面
- 成功は処理の開始ではなく、「正本を分け全影響ファイルを列挙する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 未完了、変更理由、全影響パス、成立根拠および現在品質を役割の違いとともに辿れる
- 境界: 「変更の影響漏れを確認する場面」で、成立・不成立・判断不能を分け、「同じ説明を複製し代表ファイルだけで済ませる」へ至る状態を正常へ畳まない
- 失敗: 同じ説明を複製し代表ファイルだけで済ませる
- 品質: 正本を分け全影響ファイルを列挙する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。

### UX-000029から継承する確認事項

正式入力: [UX-000029](../../../02_UX/Definitions/UX-000029/ux_definition.md)

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000033: CRDD作成者・保守者が「作業・変更・根拠・品質を役割別に辿る」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000033: CRDD作成者・保守者が「作業・変更・根拠・品質を役割別に辿る」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: CRDD作成者・保守者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

再評価契機: 対象利用者による実利用確認、前提変更、または後続工程でこの未確認事項が成立条件へ影響すると判明した時。
