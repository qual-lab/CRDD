## 2. 振る舞いへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | 実行基盤・TypeScriptアプリの組込み担当者／観測した実行事実を共有可能にする時 |
| 利用のきっかけ | AIまたはToolの観測可能な実行段階が確定した時 |
| 目的 | 同じ意味で取得できる記録を安全に一度だけ公開する |
| 利用者成果 | 記録済み・未記録・結果不明を見分け、重複や上書きなく次の処置を選べる |
| 必要な情報 | 実行、情報源、観測、記録試行、記録状態、完成記録または回復先 |
| 重要場面 | 保存要求後に結果確認が途切れる時 |
| 避ける失敗 | 未記録と推定して再発行し、重複または別実行の上書きを起こす |
| 守る品質 | 同じ識別情報で再観測し、結果不明を保つ |
| 検証意図 | 異なる作成側、再送、並行書込み、途中失敗、結果搬送失敗、許可外情報を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
観測可能な実行段階が確定
        ↓
記録を一度依頼
        │
        ├─ 成立   → 完成記録を確認
        ├─ 不成立 → Effect 0と理由を確認
        └─ 不明   → 同じExecution／Attemptで再観測
```

## 4. 受入条件と適用範囲

- 正常: 異なる作成側が同じ意味契約で記録し、完成記録を同じExecutionとAttemptへ対応付けられる。
- 境界: 同一再送、複数作成側、並行書込みを重複事実または別実行の上書きにしない。
- 失敗: 途中失敗や許可外情報を完成記録として公開しない。
- 判断不能: Effect成立を推定せず、同じIdentityで再観測できる結果を返す。
- SPEC定義で保持する意味: 記録Authority、記録Effect、結果状態、情報最小化、終了後資源。
