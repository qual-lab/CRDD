## 1. 正式入力

- UX定義: [UX-000003 委任中の状態と判断要否を理解する](../../../02_UX/Definitions/UX-000003/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」 |
| 利用のきっかけ | 委任した仕事の応答を待つ時 |
| 目的 | 現在の実行状態と必要な判断を確認する |
| 利用者成果 | 内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる |
| 必要な情報 | タスク State、AI提供元 State、判断、入力、取消、および再試行・回復・再開を区別した次の行動を関連付ける |
| 重要場面 | 応答がなく待機か停止かを判断する場面 |
| 避ける失敗 | 古い観測や一律表示を進捗・完了と誤認する |
| 守る品質 | 観測時点・停止理由・必要な判断を行動可能に示す |
| 検証意図 | 無反応、偽の進捗、AI提供元差の誤表示、停止中の実行表示、および再試行・回復・再開を取り違える案内を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」
        │ 委任した仕事の応答を待つ時
        ▼
現在の実行状態と必要な判断を確認する
        │
        ├─ 成立   → 内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる
        ├─ 不成立 → 古い観測や一律表示を進捗・完了と誤認する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 応答がなく待機か停止かを判断する場面
- 成功は処理の開始ではなく、「観測時点・停止理由・必要な判断を行動可能に示す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる
- 失敗: 古い観測や一律表示を進捗・完了と誤認する
- 品質: 観測時点・停止理由・必要な判断を行動可能に示す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAはタスク、担い手、決定権限、結果、入力、取消、および再試行・回復・再開の関係を分け、SPECとArchitectureは各行動を選べる状態と一連の状態変化全体の成立条件を定める。」を失わず渡す。

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。
