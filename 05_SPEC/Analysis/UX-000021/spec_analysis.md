# UX-000021のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000021`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000021 切断後も同じ依頼へ戻る](../../../02_UX/Definitions/UX-000021/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」 |
| 利用のきっかけ | 応答喪失後に再接続する時 |
| 目的 | 切断後に同じ依頼へ戻る |
| 利用者成果 | 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる |
| 必要な情報 | 依頼の識別情報、接続単位、現在の利用権限、結果、回復を結ぶ |
| 重要場面 | 再実行するか判断する直前 |
| 避ける失敗 | Timeoutを未実行とみなし新規外部作用（Effect）を起こす |
| 守る品質 | 同一識別情報の照会を再実行より先に示す |
| 検証意図 | 再接続時の外部作用（Effect）の二重実行、古いセッションの決定権限および別依頼への誤結合を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」
        │ 応答喪失後に再接続する時
        ▼
切断後に同じ依頼へ戻る
        │
        ├─ 成立   → 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる
        ├─ 不成立 → Timeoutを未実行とみなし新規外部作用（Effect）を起こす
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 再実行するか判断する直前
- 成功は処理の開始ではなく、「同一識別情報の照会を再実行より先に示す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる
- 失敗: Timeoutを未実行とみなし新規外部作用（Effect）を起こす
- 品質: 同一識別情報の照会を再実行より先に示す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAは依頼、試行、結果、結果の受け渡しおよび回復を関連付ける。SPEC／Architectureは冪等な照会と再入場を分け、総合試験は切断を含む一連の状態変化全体を確認する。」を失わず渡す。

## 6. IA観点との統合時に確認すること

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。
