## 3. 観測可能にする契機・結果・失敗

```text
外部へ渡す情報の所有者
        │ 外部AI・検索・公開Communication・管理対象依存を利用する時
        ▼
送信範囲と内部へ戻す際の昇格条件を理解する
        │
        ├─ 成立   → 外部作用（Effect）の前に送信先・目的・操作・情報分類・許可範囲を理解し、外部情報・反応・依存新版を出典付き候補として扱える
        ├─ 不成立 → 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 外部作用（Effect）の前と結果昇格時
- 成功は処理の開始ではなく、「同意・投影・採用を分離する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 外部作用（Effect）の前に送信先・目的・操作・情報分類・許可範囲を理解し、外部情報・反応・依存新版を出典付き候補として扱える
- 境界: 「外部作用（Effect）の前と結果昇格時」で、成立・不成立・判断不能を分け、「接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する」へ至る状態を正常へ畳まない
- 失敗: 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する
- 品質: 同意・投影・採用を分離する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
