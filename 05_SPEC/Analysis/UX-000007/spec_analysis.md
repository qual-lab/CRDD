## 2. 振る舞いへ引き継ぐ利用者成果

責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「CRDD作成者・保守者」／「実行環境の導入・運用者」 |
| 利用のきっかけ | 責務・契約・接続部または実行環境の構成を変更する時 |
| 目的 | 維持・変更・廃止された能力と利用側を確認する |
| 利用者成果 | 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる |
| 必要な情報 | 変更前の機能、公開契約、利用側、置換後の実装、根拠を結ぶ |
| 重要場面 | 変更を完了・公開可能と判断する直前 |
| 避ける失敗 | 主経路だけ移行し副次利用側を取り残す |
| 守る品質 | 旧能力・全利用側・置換根拠を閉じる |
| 検証意図 | 主経路だけの移行、旧契約残存および根拠のない旧処理削除を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「CRDD作成者・保守者」／「実行環境の導入・運用者」
        │ 責務・契約・接続部または実行環境の構成を変更する時
        ▼
維持・変更・廃止された能力と利用側を確認する
        │
        ├─ 成立   → 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる
        ├─ 不成立 → 主経路だけ移行し副次利用側を取り残す
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 変更を完了・公開可能と判断する直前
- 成功は処理の開始ではなく、「旧能力・全利用側・置換根拠を閉じる」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる
- 失敗: 主経路だけ移行し副次利用側を取り残す
- 品質: 旧能力・全利用側・置換根拠を閉じる
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
