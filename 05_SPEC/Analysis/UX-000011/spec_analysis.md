# UX-000011のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000011`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000011 プロジェクト・リポジトリ・基点フォルダを区別して対象を選ぶ](../../../02_UX/Definitions/UX-000011/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」 |
| 利用のきっかけ | 参照または操作対象を選ぶ時 |
| 目的 | プロジェクト・リポジトリ・基点フォルダを区別して対象を確認する |
| 利用者成果 | 論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる |
| 必要な情報 | プロジェクト、リポジトリ、基点フォルダ、Bindingを分ける |
| 重要場面 | 外部作用（Effect）対象を確定する直前 |
| 避ける失敗 | 同名や近いパスを同じ対象と誤認する |
| 守る品質 | 各識別情報と物理基点フォルダの結合を明示する |
| 検証意図 | 名前やパスの類似だけから対象識別情報を推定する操作を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」
        │ 参照または操作対象を選ぶ時
        ▼
プロジェクト・リポジトリ・基点フォルダを区別して対象を確認する
        │
        ├─ 成立   → 論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる
        ├─ 不成立 → 同名や近いパスを同じ対象と誤認する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 外部作用（Effect）対象を確定する直前
- 成功は処理の開始ではなく、「各識別情報と物理基点フォルダの結合を明示する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる
- 失敗: 同名や近いパスを同じ対象と誤認する
- 品質: 各識別情報と物理基点フォルダの結合を明示する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAはプロジェクト、リポジトリ、基点フォルダおよびBindingを別Entityとして関連付ける。UIは通常表示と情報源詳細を分け、Architectureは検証済み識別情報を公開結果まで保持する。」を失わず渡す。

## 6. IA観点との統合時に確認すること

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。
