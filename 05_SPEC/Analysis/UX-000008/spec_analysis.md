## 1. 正式入力

## 2. 振る舞いへ引き継ぐ利用者成果

AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | 実行環境の導入・運用者 |
| 利用のきっかけ | AI実行環境の導入または利用が止まった時 |
| 目的 | 故障した境界と影響する能力を特定する |
| 利用者成果 | AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる |
| 必要な情報 | AI実行環境ごとの認証、起動、取消、結果取得、回復、利用可能な機能を関連付ける |
| 重要場面 | 一つの失敗を全体障害と判断する直前 |
| 避ける失敗 | 一律の失敗表示で無関係な能力まで停止する |
| 守る品質 | 失敗した場所・影響範囲・利用可能性を分ける |
| 検証意図 | 認証・起動・取消・結果取得・回復の違いを同じ失敗へ畳む表示と、利用可能な機能まで停止する判断を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
実行環境の導入・運用者
        │ AI実行環境の導入または利用が止まった時
        ▼
故障した境界と影響する能力を特定する
        │
        ├─ 成立   → AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる
        ├─ 不成立 → 一律の失敗表示で無関係な能力まで停止する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 一つの失敗を全体障害と判断する直前
- 成功は処理の開始ではなく、「失敗した場所・影響範囲・利用可能性を分ける」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる
- 境界: 「一つの失敗を全体障害と判断する直前」で、成立・不成立・判断不能を分け、「一律の失敗表示で無関係な能力まで停止する」へ至る状態を正常へ畳まない
- 失敗: 一律の失敗表示で無関係な能力まで停止する
- 品質: 失敗した場所・影響範囲・利用可能性を分ける
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
