| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「実行環境の導入・運用者」 |
| 利用のきっかけ | 利用モデルやAI提供元条件を変更する時 |
| 目的 | AIモデル選択を検証可能な構成として更新する |
| 利用者成果 | 新しいモデルへ追随するとき、コード改修を待たず検証済み構成を更新し、実効選択と再選定理由を理解できる |
| 必要な情報 | Model 設定内容、利用可否、Selection、理由、Fallback Conditionを結ぶ |
| 重要場面 | AI提供元で実行する前のモデル確定 |
| 避ける失敗 | 未知または非対応のモデルを実行可能と表示する |

| 検証意図 | 未知設定の黙示代替、非対応モデルの実行可能表示および無説明選択を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「実行環境の導入・運用者」
        │ 利用モデルやAI提供元条件を変更する時
        ▼
AIモデル選択を検証可能な構成として更新する
        │
        ├─ 成立   → 新しいモデルへ追随するとき、コード改修を待たず検証済み構成を更新し、実効選択と再選定理由を理解できる
        ├─ 不成立 → 未知または非対応のモデルを実行可能と表示する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: AI提供元で実行する前のモデル確定
- 成功は処理の開始ではなく、「構成変更を検証し実効選択を観測可能にする」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 新しいモデルへ追随するとき、コード改修を待たず検証済み構成を更新し、実効選択と再選定理由を理解できる
- 失敗: 未知または非対応のモデルを実行可能と表示する
- 品質: 構成変更を検証し実効選択を観測可能にする
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
