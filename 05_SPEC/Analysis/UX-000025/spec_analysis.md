## 1. 正式入力

- UX定義: [UX-000025 過去の推論情報と現在値を区別する](../../../02_UX/Definitions/UX-000025/ux_definition.md)

## 2. 振る舞いへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |

| 利用者成果 | 当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる |
| 必要な情報 | 過去の情報、現在の意図、選択根拠を分ける |
| 重要場面 | 判断理由をAIへ渡す場面 |
| 避ける失敗 | 履歴を上書きし競合する理由を勝手に統合する |
| 守る品質 | 現行性・選択範囲・使用改訂版を追跡する |
| 検証意図 | 遡及上書き、古い仮説の現在値化および履歴全量の無選択投入を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
CRDD作成者・保守者
        │ 過去判断を再利用または更新する時
        ▼
当時の仮説と現在有効な意図を区別する
        │
        ├─ 成立   → 当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる
        ├─ 不成立 → 履歴を上書きし競合する理由を勝手に統合する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 判断理由をAIへ渡す場面
- 成功は処理の開始ではなく、「現行性・選択範囲・使用改訂版を追跡する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 当時の仮説・判断・学びと現在有効な意図を区別し、必要な情報を選べる
- 境界: 「判断理由をAIへ渡す場面」で、成立・不成立・判断不能を分け、「履歴を上書きし競合する理由を勝手に統合する」へ至る状態を正常へ畳まない
- 失敗: 履歴を上書きし競合する理由を勝手に統合する
- 品質: 現行性・選択範囲・使用改訂版を追跡する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。

## 未確認事項・人間判断・戻り条件

正式入力に残る未確認事項を、解消済みとみなさず次のとおり継承する。

### UX-000025から継承する確認事項

正式入力: [UX-000025](../../../02_UX/Definitions/UX-000025/ux_definition.md)

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000029: CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000029: CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: CRDD作成者・保守者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

再評価契機: 対象利用者による実利用確認、前提変更、または後続工程でこの未確認事項が成立条件へ影響すると判明した時。
