# UX-000015のSPEC分析

成果物種別: SPEC分析（UX観点）

## 1. 正式入力

- UX定義: [UX-000015 複数プロジェクトを根拠付きで比較する](../../../02_UX/Definitions/UX-000015/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

許可されたプロジェクトの重要差を比較し、網羅範囲と根拠を保ったまま必要なプロジェクトだけを掘り下げられる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | 経営・管理層 |
| 利用のきっかけ | 複数プロジェクトの一覧の優先度を判断する時 |
| 目的 | 複数プロジェクトを根拠付きで比較する |
| 利用者成果 | 許可されたプロジェクトの重要差を比較し、網羅範囲と根拠を保ったまま必要なプロジェクトだけを掘り下げられる |
| 必要な情報 | プロジェクト Summary、網羅範囲、観測時点、開示範囲を分ける |
| 重要場面 | 要約から優先判断へ進む直前 |
| 避ける失敗 | 単一Scoreや欠測した集計で健全性を断定する |
| 守る品質 | 比較値から根拠・古さ・不足へ戻れる |
| 検証意図 | 非開示プロジェクトの存在漏えい、単一Score断定および網羅範囲差の消去を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
経営・管理層
        │ 複数プロジェクトの一覧の優先度を判断する時
        ▼
複数プロジェクトを根拠付きで比較する
        │
        ├─ 成立   → 許可されたプロジェクトの重要差を比較し、網羅範囲と根拠を保ったまま必要なプロジェクトだけを掘り下げられる
        ├─ 不成立 → 単一Scoreや欠測した集計で健全性を断定する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 要約から優先判断へ進む直前
- 成功は処理の開始ではなく、「比較値から根拠・古さ・不足へ戻れる」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 許可されたプロジェクトの重要差を比較し、網羅範囲と根拠を保ったまま必要なプロジェクトだけを掘り下げられる
- 境界: 「要約から優先判断へ進む直前」で、成立・不成立・判断不能を分け、「単一Scoreや欠測した集計で健全性を断定する」へ至る状態を正常へ畳まない
- 失敗: 単一Scoreや欠測した集計で健全性を断定する
- 品質: 比較値から根拠・古さ・不足へ戻れる
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
