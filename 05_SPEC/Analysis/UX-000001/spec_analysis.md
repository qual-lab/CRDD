# UX-000001のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000001`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000001 意味レビューへ集中できる事前確認](../../../02_UX/Definitions/UX-000001/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

同じ対象と条件なら機械的不備と修正箇所を先に理解し、意味レビューへ集中できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「CRDD作成者・保守者」 |
| 利用のきっかけ | 成果物をレビューへ渡す前 |
| 目的 | 意味レビュー前に機械判定できる不備を落とす |
| 利用者成果 | 同じ対象と条件なら機械的不備と修正箇所を先に理解し、意味レビューへ集中できる |
| 必要な情報 | 対象、検査条件、指摘、Location、Responsibilityを関連付ける |
| 重要場面 | 機械指摘と意味判断を分ける |
| 避ける失敗 | 検査範囲や理由が分からない |
| 守る品質 | 同じ入力へ同じ指摘と修正可能な場所を返す |
| 検証意図 | 結果の決定性、対象箇所、理由および意味判断との境界を確認する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「CRDD作成者・保守者」
        │ 成果物をレビューへ渡す前
        ▼
意味レビュー前に機械判定できる不備を落とす
        │
        ├─ 成立   → 同じ対象と条件なら機械的不備と修正箇所を先に理解し、意味レビューへ集中できる
        ├─ 不成立 → 検査範囲や理由が分からない
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 機械指摘と意味判断を分ける
- 成功は処理の開始ではなく、「同じ入力へ同じ指摘と修正可能な場所を返す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 同じ対象と条件なら機械的不備と修正箇所を先に理解し、意味レビューへ集中できる
- 失敗: 検査範囲や理由が分からない
- 品質: 同じ入力へ同じ指摘と修正可能な場所を返す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「品質は決定論性と誤検知を、文書化規則は人が理解できる指摘を、Verificationは意味監査との境界を具体化する。」を失わず渡す。

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。
