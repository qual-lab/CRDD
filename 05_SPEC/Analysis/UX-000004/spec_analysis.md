# UX-000004のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000004`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000004 失敗後の再試行・回復を選ぶ](../../../02_UX/Definitions/UX-000004/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」 |
| 利用のきっかけ | 失敗・取消・切断後に仕事を続ける時 |
| 目的 | 再試行・回復・清掃の違いを理解する |
| 利用者成果 | 失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる |
| 必要な情報 | 失敗、外部変更の状態、回復、Retryを分ける |
| 重要場面 | 同じ外部作用（Effect）を再発行する直前 |
| 避ける失敗 | 結果不明の処理を新規実行して外部作用（Effect）の二重実行を起こす |
| 守る品質 | 外部作用（Effect）状態・回復対象の識別情報・終了条件を示す |
| 検証意図 | 無条件Retry、古い決定権限、AI提供元差の隠蔽および外部作用（Effect）の二重実行を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「プロジェクト運営者／PM」
        │ 失敗・取消・切断後に仕事を続ける時
        ▼
再試行・回復・清掃の違いを理解する
        │
        ├─ 成立   → 失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる
        ├─ 不成立 → 結果不明の処理を新規実行して外部作用（Effect）の二重実行を起こす
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 同じ外部作用（Effect）を再発行する直前
- 成功は処理の開始ではなく、「外部作用（Effect）状態・回復対象の識別情報・終了条件を示す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる
- 失敗: 結果不明の処理を新規実行して外部作用（Effect）の二重実行を起こす
- 品質: 外部作用（Effect）状態・回復対象の識別情報・終了条件を示す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAはタスク、担い手、決定権限、結果、回復の関係を分け、SPECとArchitectureは一連の状態変化全体の成立条件を定める。」を失わず渡す。

## 6. IA観点との統合時に確認すること

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。
