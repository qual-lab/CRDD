|---|---|---|

## 4. 状態・可視性・時間的意味

入力UXで必要とされた状態は次のとおりである。状態実値を採用する場合は、下流工程で対応関係を定義し、この利用者向け区分を上書きしない。

- `UX-000025`: 現在有効（current）／履歴（historical）／置換済み（superseded）／不明（unknown）

重要な状態、不足、判断要否は次の行動と同じ文脈で示す。観測不能を不存在や正常へ丸めない。

欠測、不明、非開示、競合、古い情報を同じ空値へ丸めない。一時的情報と永続的情報、表示可否と実行権限を別に扱う。

## 5. 導線・責任・失敗時の保持

- CRDD作成者・保守者: 過去判断を再利用または更新する時に「当時の仮説と現在有効な意図を区別する」ために必要な判断を行う。システムは「履歴を上書きし競合する理由を勝手に統合する」を避けられるよう、現行性・選択範囲・使用改訂版を追跡する。

各利用場面の導線は「利用場面」の対応表を正とする。結果なし、判断待ち、失敗、状態不明の場合も、根拠または安全な戻り先へ接続する。

### 制約

Git Commitだけを情報の有効性や現在性の成立条件にしない。履歴管理手段が変わっても、情報源、改訂版、置換関係、選択理由を追跡できる意味を維持する。

入力不足、権限不足、観測不能または関係不整合では、既知の状態・識別情報・未解消義務を保持し、安全な拒否または再確認先を返す。IAが定義していない状態値や保存方式はここで創作しない。

### SPEC定義で保持する意味

SPEC定義では、前節までに示した対象、識別、関係、状態、可視性、責任および失敗時に保持する意味を、観測可能な契機・条件・結果へ変換する。実現方式、UI表現または試験手順は本分析で確定しない。
