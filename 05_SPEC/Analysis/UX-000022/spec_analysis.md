# UX-000022のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000022`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000022 残存資源を安全に回復・清掃する](../../../02_UX/Definitions/UX-000022/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

失敗後に残存の由来・影響・再入場先を理解し、必要な回復を行って不存在まで確認できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | 実行環境の導入・運用者 |
| 利用のきっかけ | 失敗後または保守時に残存を見つけた時 |
| 目的 | 残存資源の由来・保持・清掃・回復を理解する |
| 利用者成果 | 失敗後に残存の由来・影響・再入場先を理解し、必要な回復を行って不存在まで確認できる |
| 必要な情報 | 残存物、回復対象の識別情報、処置、不存在の根拠を結ぶ |
| 重要場面 | 削除または回復を選ぶ場面 |
| 避ける失敗 | 名前や経過時間だけで由来不明物を削除する |
| 守る品質 | 残存・観測不能・不存在を区別する |
| 検証意図 | 清掃要求だけの完了表示、別処理の巻込みおよび不明状態での削除を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
実行環境の導入・運用者
        │ 失敗後または保守時に残存を見つけた時
        ▼
残存資源の由来・保持・清掃・回復を理解する
        │
        ├─ 成立   → 失敗後に残存の由来・影響・再入場先を理解し、必要な回復を行って不存在まで確認できる
        ├─ 不成立 → 名前や経過時間だけで由来不明物を削除する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 削除または回復を選ぶ場面
- 成功は処理の開始ではなく、「残存・観測不能・不存在を区別する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 失敗後に残存の由来・影響・再入場先を理解し、必要な回復を行って不存在まで確認できる
- 境界: 「削除または回復を選ぶ場面」で、成立・不成立・判断不能を分け、「名前や経過時間だけで由来不明物を削除する」へ至る状態を正常へ畳まない
- 失敗: 名前や経過時間だけで由来不明物を削除する
- 品質: 残存・観測不能・不存在を区別する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。

## 未確認事項・人間判断・戻り条件

### UX-000022から継承する確認事項

正式入力: [UX-000022](../../../02_UX/Definitions/UX-000022/ux_definition.md)

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000022: 実行環境の導入・運用者が「残存資源の由来・保持・清掃・回復を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000022: 実行環境の導入・運用者が「残存資源の由来・保持・清掃・回復を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: 実行環境の導入・運用者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

再評価契機: 対象利用者による実利用確認、前提変更、または後続工程でこの未確認事項が成立条件へ影響すると判明した時。
