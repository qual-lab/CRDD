## 1. 正式入力

- UX定義: [UX-000005 目的と受入条件で節目を委ねる](../../../02_UX/Definitions/UX-000005/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | プロジェクト運営者／PM |
| 利用のきっかけ | プロジェクトの成果をまとめて任せる時 |
| 目的 | 目的と受入条件で節目を委ねる |
| 利用者成果 | 内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる |
| 必要な情報 | 目的、受入条件、節目、タスク、統合状態、品質、および同じ節目へ戻るための再開条件を関連付ける |
| 重要場面 | タスク成功と節目完成を区別する |
| 避ける失敗 | タスク件数を完成と誤認する |
| 守る品質 | 統合・品質・判断待ちを分けて示す |
| 検証意図 | タスク数や部分成功を完成へ畳む表示と、停止後に目的・受入条件・判断点を失った別の節目として再開する挙動を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
プロジェクト運営者／PM
        │ プロジェクトの成果をまとめて任せる時
        ▼
目的と受入条件で節目を委ねる
        │
        ├─ 成立   → 内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる
        ├─ 不成立 → タスク件数を完成と誤認する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: タスク成功と節目完成を区別する
- 成功は処理の開始ではなく、「統合・品質・判断待ちを分けて示す」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる
- 境界: 「タスク成功と節目完成を区別する」で、成立・不成立・判断不能を分け、「タスク件数を完成と誤認する」へ至る状態を正常へ畳まない
- 失敗: タスク件数を完成と誤認する
- 品質: 統合・品質・判断待ちを分けて示す
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。

## 6. IA観点との統合時に確認すること

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。

## 未確認事項・人間判断・戻り条件

正式入力に残る未確認事項を、解消済みとみなさず次のとおり継承する。

### UX-000005から継承する確認事項

正式入力: [UX-000005](../../../02_UX/Definitions/UX-000005/ux_definition.md)

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000003: プロジェクト運営者／PMが「目的と受入条件で節目を委ねる」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000003: プロジェクト運営者／PMが「目的と受入条件で節目を委ねる」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: プロジェクト運営者／PMを代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

再評価契機: 対象利用者による実利用確認、前提変更、または後続工程でこの未確認事項が成立条件へ影響すると判明した時。
