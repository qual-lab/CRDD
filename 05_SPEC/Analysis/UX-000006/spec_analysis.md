# UX-000006のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000006`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000006 実行事実を根拠付きで振り返る](../../../02_UX/Definitions/UX-000006/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

実行主体が異なっても、観測事実・未観測・評価・改善候補を出所と時点付きで区別して振り返れる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | 実行環境の導入・運用者 |
| 利用のきっかけ | 実行結果を振り返る時 |
| 目的 | 実行事実を出所と観測時点付きで比較する |
| 利用者成果 | 実行主体が異なっても、観測事実・未観測・評価・改善候補を出所と時点付きで区別して振り返れる |
| 必要な情報 | 実行記録（Execution）、観測状態（Observation State）、情報源、評価（Assessment）、候補を分ける |
| 重要場面 | 未観測値を含む実行事実の取得 |
| 避ける失敗 | 未観測を0や正常へ畳む |
| 守る品質 | 出所・時点・観測状態を保持する |
| 検証意図 | 空値の正常化、評価の事実化および出所のない比較を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
実行環境の導入・運用者
        │ 実行結果を振り返る時
        ▼
実行事実を出所と観測時点付きで比較する
        │
        ├─ 成立   → 実行主体が異なっても、観測事実・未観測・評価・改善候補を出所と時点付きで区別して振り返れる
        ├─ 不成立 → 未観測を0や正常へ畳む
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 未観測値を含む実行事実の取得
- 成功は処理の開始ではなく、「出所・時点・観測状態を保持する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 実行主体が異なっても、観測事実・未観測・評価・改善候補を出所と時点付きで区別して振り返れる
- 境界: 「未観測値を含む実行事実の取得」で、成立・不成立・判断不能を分け、「未観測を0や正常へ畳む」へ至る状態を正常へ畳まない
- 失敗: 未観測を0や正常へ畳む
- 品質: 出所・時点・観測状態を保持する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。

### UX-000006から継承する確認事項

正式入力: [UX-000006](../../../02_UX/Definitions/UX-000006/ux_definition.md)

未確認事項は、統合元の要求ごとに次を保持する。

- REQ-000004: 実行環境の導入・運用者が「実行事実を出所と観測時点付きで比較する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 現在判定: 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。
- 確認事項: REQ-000004: 実行環境の導入・運用者が「実行事実を出所と観測時点付きで比較する」を行う際の判断基準、許容負担、利用環境および失敗後の選択
- 判断者: 実行環境の導入・運用者を代表する利用者とQual-Lab。
- 未確認時の影響: 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。
- Discoveryへ戻す条件: 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。
- UX分析へ戻す条件: 利用場面、目的、得られる結果、重要場面、失敗または品質期待の統合判断が変わる場合。

再評価契機: 対象利用者による実利用確認、前提変更、または後続工程でこの未確認事項が成立条件へ影響すると判明した時。
