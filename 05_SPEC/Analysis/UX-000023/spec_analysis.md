# UX-000023のSPEC分析

成果物種別: SPEC分析（UX観点）
分析単位: `UX-000023`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000023 監査・是正・判断を一つの改訂版で閉じる](../../../02_UX/Definitions/UX-000023/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「CRDD作成者・保守者」 |
| 利用のきっかけ | 複数指摘を是正する時 |
| 目的 | 監査合意から是正・反証までを一つの改訂版で閉じる |
| 利用者成果 | 合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる |
| 必要な情報 | 指摘、是正、Verification、判断要求、現在の改訂版を結ぶ |
| 重要場面 | 再レビューへ固定候補を渡す直前 |
| 避ける失敗 | 一部是正や監査回数を完成と誤認する |
| 守る品質 | 合意事項と試験を全数対応させる |
| 検証意図 | 指摘の小出し適用、解消済み判断の再要求および一部是正の完成表示を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「CRDD作成者・保守者」
        │ 複数指摘を是正する時
        ▼
監査合意から是正・反証までを一つの改訂版で閉じる
        │
        ├─ 成立   → 合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる
        ├─ 不成立 → 一部是正や監査回数を完成と誤認する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 再レビューへ固定候補を渡す直前
- 成功は処理の開始ではなく、「合意事項と試験を全数対応させる」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる
- 失敗: 一部是正や監査回数を完成と誤認する
- 品質: 合意事項と試験を全数対応させる
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAは指摘、判断、是正、根拠を分け、WorkflowとVerificationは収束完了条件を具体化する。」を失わず渡す。

IA観点が与える対象、関係、状態、可視性、保存・開示条件と組み合わせても、利用者成果、失敗、検証意図を弱めない。具体的なAPI、Process、保存方式または画面はここで決めない。
