## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「外部へ渡す情報の所有者」／「プロジェクト運営者／PM」

        ▼
必要な情報だけを出所付きで渡す
        │
        ├─ 成立   → 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
        ├─ 不成立 → 全量投入・秘密情報混入・古い仮説の現在値化
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 外部境界へ情報を出す直前
- 成功は処理の開始ではなく、「情報源・改訂版・選択理由を保持する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
- 失敗: 全量投入・秘密情報混入・古い仮説の現在値化
- 品質: 情報源・改訂版・選択理由を保持する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAは受け渡す情報一式、情報源、改訂版、選択理由およびタスク Relationを分ける。ArchitectureはResolverと通信方式を分離し、Verificationは出所喪失と過剰投入を反証する。」を失わず渡す。
