## 2. 振る舞いへ引き継ぐ利用者成果

必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる

| 観点 | UX定義から受け取る内容 |

| 利用者／状況 | 外部へ渡す情報の所有者／「プロジェクト運営者／PM」 |
| 利用のきっかけ | 別Agentやツールへ仕事を渡す時、または結果を受け取る時 |
| 目的 | 必要な情報だけを出所付きで渡す |
| 利用者成果 | 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる |
| 必要な情報 | 受け渡す情報一式、情報源、タスク、結果、根拠、引き渡し、判断を関連付ける |
| 重要場面 | 外部境界へ情報を出す直前 |
| 避ける失敗 | 全量投入・秘密情報混入・古い仮説の現在値化 |

| 検証意図 | 全量投入、秘密情報混入、情報捏造、別タスク結果混入およびAgent完了の自動採用を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
外部へ渡す情報の所有者／「プロジェクト運営者／PM」
        │ 別Agentやツールへ仕事を渡す時、または結果を受け取る時
        ▼
必要な情報だけを出所付きで渡す
        │
        ├─ 成立   → 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
        ├─ 不成立 → 全量投入・秘密情報混入・古い仮説の現在値化
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 外部境界へ情報を出す直前
- 成功は処理の開始ではなく、「情報源・改訂版・選択理由を保持する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
- 境界: 「外部境界へ情報を出す直前」で、成立・不成立・判断不能を分け、「全量投入・秘密情報混入・古い仮説の現在値化」へ至る状態を正常へ畳まない
- 失敗: 全量投入・秘密情報混入・古い仮説の現在値化
- 品質: 情報源・改訂版・選択理由を保持する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- SPEC定義では、上記の利用者成果、成立条件、失敗条件および判断不能を失わず保持する。
