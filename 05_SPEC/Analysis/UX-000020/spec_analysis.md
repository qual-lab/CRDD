# UX-000020のSPEC分析

## 1. 正式入力

- UX定義: [UX-000020 利用環境の信頼方針で実行基盤を選ぶ](../../../02_UX/Definitions/UX-000020/ux_definition.md)

IA、UIまたはREQを直接読んで不足を補完しない。この分析はUX定義から、利用者に観測できる振る舞いと失敗だけを導く。

## 2. 振る舞いへ引き継ぐ利用者成果

準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／状況 | [製品全体の利用者像](../../../02_UX/02_Personas.md)の「実行環境の導入・運用者」 |
| 利用のきっかけ | 実行基盤を導入または更新する時 |
| 目的 | 実行環境の信頼の各要素を別々に評価する |
| 利用者成果 | 準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる |
| 必要な情報 | 準拠状況、改ざん有無、配布者、方針、導入先を分ける |
| 重要場面 | 実行を信頼すると判断する場面 |
| 避ける失敗 | 一つの署名表示を全保証と誤認する |
| 守る品質 | 保証要素と決定権限を分離表示する |
| 検証意図 | 一つの署名やブランド表示への全保証集約とQual-Lab署名だけの実行資格化を反証する |

## 3. 観測可能にする契機・結果・失敗

```text
[製品全体の利用者像](../../../02_UX/02_Personas.md)の「実行環境の導入・運用者」
        │ 実行基盤を導入または更新する時
        ▼
実行環境の信頼の各要素を別々に評価する
        │
        ├─ 成立   → 準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる
        ├─ 不成立 → 一つの署名表示を全保証と誤認する
        └─ 不明   → 推測せず不足情報または再確認先
```

- ★ 判断点: 実行を信頼すると判断する場面
- 成功は処理の開始ではなく、「保証要素と決定権限を分離表示する」を守って利用者成果を観測できる結果で判定する。
- UXが要求しない取消、回復、Authorityまたは外部Effectをひな型だけから追加しない。

## 4. 受入条件と適用範囲

- 正常: 準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる
- 失敗: 一つの署名表示を全保証と誤認する
- 品質: 保証要素と決定権限を分離表示する
- 判断不能: 不足を補完せず、何を再確認すべきかを返す。
- 下流へは「IAは準拠状況、改ざん有無、配布者、配布物を分け、UI／SPECは根拠別の状態を提示する。」を失わず渡す。
