# 利用場面と振る舞いFlow

## 1. 主要な利用場面

| 利用場面 | 主なSPEC | Actor | 完了の意味 |
|---|---|---|---|
| Repositoryで作業を始める | SPEC-000001、000010、000014 | 開発者／保守者 | 正しい対象と利用可能なToolを確認できる |
| 仕事を委任し状態を確認する | SPEC-000002、000003、000017 | Project運営者／PM | 範囲を固定し、同じTaskの状態・結果へ戻れる |
| 失敗後に継続する | SPEC-000004、000005、000009、000016 | 運用者 | Effectを重複させず義務を解消する |
| Projectを理解・比較する | SPEC-000006、000007 | PM／Management | 根拠・欠測・時点付きで判断できる |
| 実行事実を振り返る | SPEC-000008 | 実行環境の導入・運用者 | 事実・未観測・評価を根拠付きで比較できる |
| 外部・横断入口を使う | SPEC-000011、000012、000021、000026、000027 | 接続利用者／管理者 | 現在Grantと同意範囲内で結果を得る |
| 標準を保守・公開する | SPEC-000018、000019、000020、000023、000024 | Qual-Lab／決定権限者 | 信頼・変更・品質・権利を混同せず閉じる |

## 2. Flow

```text
目的を選ぶ
   │
   ├─ 対象を読む ─→ 状態・根拠・不足を返す
   ├─ 仕事を依頼 ─→ 範囲固定 ─→ 実行 ─→ 結果／判断待ち
   ├─ 外部へ送る ─→ 同意確認 ─→ 送信 ─→ 結果帰還 ─→ 候補の採否
   └─ 失敗を直す ─→ Effect確認 ─→ 回復／清掃 ─→ 終了後確認

どの経路でも、接続・閲覧・候補・採用・Effectは別の成立条件とする。
```
