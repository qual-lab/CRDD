# サービス提供の流れ（Service Blueprint）

本書は要求別UX分析にある利用者接点と責任境界を、製品全体で比較・統合する。人間、利用者接点、システム／AI、運用および根拠の責任を接続するが、個別要求固有のサービス提供の流れを置き換えない。

## 製品全体のサービス提供の流れ

```text
利用者        [目的を示す] ───→ [状態を理解] ───→ [判断する]
                         │                 │
----------------------- 可視境界 -----------------------
                         ▼                 ▼
接点           [入力を受ける] ───→ [結果を示す] ───→ [次の行動]
                         │                 │
システム／AI     [許可を確認] ───→ [処理・表示] ───→ [記録・回復]
                         │                 │
運用・根拠       [正本／根拠] ───→ [確認・支援] ───→ [改善へ戻す]
```

## 補足（必要な場合）

上の節へ無理に入れると、製品全体の責任や受け渡しが分かりにくくなる補足だけを書く。個別要求固有の流れや責任境界を移さず、作業日誌や未分類のメモにも使わない。同じ種類の補足が繰り返される場合は標準項目への昇格を見直す。補足がなければ、この節は削除する。

## Checklist

ひな型では`[ ]`を未評価として残す。完成時は、処置済みを`[x]`、未完了を`OPEN: 理由 — 項目`、不適合を`FAIL: 理由 — 項目`、非該当を`N/A: 理由 — 項目`として評価する。

- [ ] 個別UX分析の利用者接点、提供責務、失敗および回復を横断合成した
- [ ] 全UX IDについてサービス提供の流れの適用を処置した
- [ ] 利用者成果とサービス側の責任の対応を追跡できる
- [ ] 利用者、接点、提供側、運用・根拠の責任と可視境界を区別した
- [ ] 人間、AIおよびシステムの責任を必要な範囲で区別した
- [ ] 完了時と失敗時に誰へ何が返るかを示した
- [ ] 返却後に誰が何を判断できるかを示した
- [ ] Architecture Componentへ提供責務を固定していない
- [ ] UI部品、Protocol、Class等の下流方式を先取りしていない
- [ ] 未確認の責任境界を確定した提供責務へ混ぜていない
- [ ] 補足へ主要な責任境界を退避していない
