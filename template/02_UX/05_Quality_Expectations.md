# 体験品質として守ること

本書は各要求で見つかった体験品質への期待を製品全体で統合する。数値条件や実現方式を定めず、人または運用者にどう現れる必要があるかを所有する。

## 品質期待の全体像

```text
理解できる ─┐
辿れる ─────┼→ 安心して次の判断へ進める
回復できる ─┤
待たされない ┘
```

## 競合・優先順位・未確認事項

速度と根拠確認、簡潔さと不完全性表示等の両立が難しい点、現在の優先判断、未確認の許容範囲を示す。

## 補足（必要な場合）

上の節へ無理に入れると、製品全体の品質期待や優先判断が分かりにくくなる補足だけを書く。個別要求固有の品質を移さず、作業日誌や未分類のメモにも使わない。同じ種類の補足が繰り返される場合は標準項目への昇格を見直す。補足がなければ、この節は削除する。

## Checklist

ひな型では`[ ]`を未評価として残す。完成時は、処置済みを`[x]`、未完了を`OPEN: 理由 — 項目`、不適合を`FAIL: 理由 — 項目`として評価する。非該当は`N/A: 理由 — 項目`として評価する。

- [ ] 個別UX分析で見つかった品質期待を製品全体で横断合成した
- [ ] 全UX IDの品質期待を処置した
- [ ] 品質を内部特性でなく利用者や運用者に現れる状態として示した
- [ ] 各品質が利用者成果の成立に必要な理由を説明できる
- [ ] 重要場面、避ける失敗および関係REQ／UXを接続した
- [ ] Quality Analysis / UXへ渡す検証義務を識別した
- [ ] 両立が難しい品質と現在の優先判断を隠していない
- [ ] 数値条件、状態Schema、Protocolまたは実現方式を先取りしていない
- [ ] 未確認範囲を確認済みの品質期待へ混ぜていない
- [ ] 補足へ主要な品質期待を退避していない
