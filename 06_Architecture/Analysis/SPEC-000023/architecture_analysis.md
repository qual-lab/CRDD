# SPEC-000023のArchitecture分析

成果物種別: Architecture分析（SPEC観点）
分析単位: `SPEC-000023`
状態: Canonical

## 1. 正式入力

- SPEC定義: [SPEC-000023 文書の物語・構造・図と工程引継ぎを検査する](../../../05_SPEC/Definitions/SPEC-000023/spec_definition.md)

このSPEC定義だけを正式入力とする。反対観点、上流工程、現行Architectureまたは実装から不足する意味を補わない。

## 2. Architectureへ引き継ぐSPEC契約

### 振る舞いの目的

文書の物語・構造・図と工程引継ぎを検査する。

### 契機・事前条件・Authority

| 項目 | 契約 |
|---|---|
| 契機 | 工程成果物を作成・更新・引き渡す時 |
| 事前条件 | 対象工程、正式入力、必要図、引き渡し条件を特定できる |
| Authority | 工程成果物の作成者と確認者。Checker結果は意味採用Authorityを持たない |
| 判定不能 | 不足を既定値で補完せず、対象を変更せず理由と再確認先を返す |

### 振る舞い・状態・結果

```text
[工程成果物] -> [物語／構造／図／凡例／関係を検査]
 -> [成立／不足／作成不能理由]
```

- 振る舞い: 工程固有の物語、構造、必要図、凡例、入力・出力関係、作成不能理由を検査する。
- 成功条件: 人間が理解する順序と機械的な関係閉包を両立する。
- ここにない取消、再試行、回復または状態値を架空に追加しない。

### 失敗・回復・副作用

- 失敗: Checklistの並びを章構成へ強制せず、必要図の無言欠落を許さない。
- 副作用: 読取り検査だけを行い、文書内容や工程状態を自動変更しない。
- 本SPEC固有の回復経路は設けず、失敗理由と安全な戻り先を返す。

### 受入条件と検証義務

| 観点 | 受入条件 |
|---|---|
| 正常 | 人間が理解する順序と機械的な関係閉包を両立する |
| 境界 | 必要図あり／作成不能、正式構造／説明例を分け、説明例を正本関係として検出しない |
| 失敗 | Checklistの並びを章構成へ強制せず、必要図の無言欠落を許さない |
| 観測不能 | 不明を正常・不存在・完了へ丸めず、実際の副作用「読取り検査だけを行い、文書内容や工程状態を自動変更しない」と矛盾する結果を返さない |
| 対応UI | [UI-000018](../../../04_UI/Definitions/UI-000018/ui_definition.md)の操作・Feedbackと契機・結果・失敗が一致する |

### 制約

API、Process、保存方式、画面、部品または実装技術を本定義で確定しない。現行実装は独立した照合対象であり、望ましい振る舞いの根拠として自動採用しない。
