### 両観点の統合判断

情報を外部へ送る時、送信先、目的、情報分類、対象範囲、同意状態を検証し、許可された最小情報だけを送る。

### 契機・事前条件・Authority

| 項目 | 契約 |
|---|---|
| 契機 | 情報を外部へ送る時 |
| 事前条件 | 送信先、目的、情報分類、対象範囲、同意の有効性を確認できる |
| Authority | 送信同意は許可範囲内の送信Effectだけを認め、結果受領や候補採用へ流用しない |
| 回復Owner | 元の送信依頼識別情報と状態照会Capabilityを保持する送信側の機能責任が再観測を所有する。具体的なComponentまたは人物はArchitectureで割り当てる |
| 再観測Authority | 元の送信依頼の状態照会だけを許し、新しい送信Effect、結果採用または同意範囲の拡張を許さない。照会不能または未解消なら、同じ依頼識別情報と未解消義務を保持して人間の決定権限者へ移送する |
| 判定不能 | 不足を既定値で補完せず、新しいEffectを発行せず現在状態と未解消義務を保持する |

### 振る舞い・状態・結果

```text
[送信候補] -> [同意検証]
  ├ invalid／unknown --------------------------> [Effect 0]
  └ valid -> [送信要求発行] -> [要求受理]
                                  │
                                  ├ Effect成立を観測不能
                                  │      -> [Effect不明]
                                  │
                                  └ [外部Effect成立] -> [結果搬送]
                                                           ├ 搬送失敗 -> [Effect成立・結果不明]
                                                           └ 結果受領 -> [送信済み]
```

- 振る舞い: 送信先、目的、情報分類、対象範囲、同意状態を検証し、許可された最小情報だけを送る。
- 成功条件: 送信前検査、要求発行、要求受理、外部Effect成立、結果観測および結果搬送を区別し、利用した同意範囲と同一の送信依頼識別情報を結果へ結合する。
- 要求受理後に外部Effect成立を観測できない場合は、未送信または成立済みへ丸めず、`Effect不明`として同一の送信依頼識別情報を保持する。
- 外部Effect成立後に結果搬送を完了できない場合は、`Effect成立・結果不明`として同一の送信依頼識別情報を保持する。
- 結果不明を理由に同じ外部Effectを自動再発行しない。再観測または回復は同じ送信依頼識別情報へ結合する。
- 取消、再試行または回復方式はArchitectureで具体化するが、二重送信防止と結果不明の保持という振る舞い契約を弱めない。

### 失敗・回復・副作用

- 失敗: 期限切れ・範囲変更・不明な同意ではEffect 0で停止する。
- 副作用: 許可範囲の外部送信Effectを発行し、送信時の依頼識別情報と同意範囲を要求、Effectおよび結果へ結合する。
- 同意がinvalid／unknownの場合は要求発行前にEffect 0で停止する。要求受理後に切断した場合はEffect成立の有無を推測せず、同じ依頼識別情報による再観測を要求する。
- 回復Ownerは、同じ依頼識別情報を保持してEffectと結果を再観測し、`送信済み`、Effect未成立を確認した安全な終了、または人間判断を要する`Effect不明`／`Effect成立・結果不明`へ閉じる。再観測Authorityは状態照会に限定し、回復不能時は二重送信を避けたまま未解消義務を人間の決定権限者へ移送する。

### 受入条件と検証義務

| 観点 | 受入条件 |
|---|---|
| 正常 | 送信前検査、要求発行、受理、外部Effect成立、結果観測および結果搬送を区別し、利用した同意範囲と同一依頼識別情報を結果へ結合する |
| 境界 | 同意範囲内／範囲外、有効／期限切れ／不明を分け、範囲外では送信Effectを発行しない |
