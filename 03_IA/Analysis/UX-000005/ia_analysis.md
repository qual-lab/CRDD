# IA分析: 目的と受入条件で節目を委ねる

成果物種別: IA分析
分析対象: [UX-000005](../../../02_UX/Definitions/UX-000005/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | プロジェクトの成果をまとめて任せる時 |
| 目的 | 目的と受入条件で節目を委ねる |
| 得たい結果 | 内部タスクを追わず統合済みの完成を判断できる |
| 重要場面 | タスク成功と節目完成を区別する |
| 避ける失敗 | タスク件数を完成と誤認する |
| 守る品質 | 統合・品質・判断待ちを分けて示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | プロジェクト（Project）、節目（Milestone）、目的（Objective）、作業（Task）、受入条件、統合状態、品質 | 対象を同一視せず、「Milestone→目的と受入条件→Task根拠→受入判断」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | Milestone→目的と受入条件→Task根拠→受入判断 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: プロジェクト（Project）]
[O: プロジェクト（Project）] --根拠と次の行動を辿る--> [O: 内部タスクを追わず統合済みの完成を判断できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | Task完了／Objective受入／Milestone受入を別にする |
| 可視性 | タスク成功と節目完成を区別するでは、統合・品質・判断待ちを分けて示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | Milestone→目的と受入条件→Task根拠→受入判断。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「目的と受入条件で節目を委ねる」ために必要な判断を行う。システムは「内部タスクを追わず統合済みの完成を判断できる」を支える対象・状態・根拠を示し、「タスク件数を完成と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト実行状態の管理（Project Runtime）は階層を持つ。作業（Task）件数を上位完成へ丸めない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

[IA-000002](../../Definitions/IA-000002/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
