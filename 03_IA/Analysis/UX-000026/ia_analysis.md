# IA分析: 試験層と現在の保証範囲を理解して選ぶ

成果物種別: IA分析
分析対象: [UX-000026](../../../02_UX/Definitions/UX-000026/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 変更の検証計画を作る時 |
| 目的 | 試験層ごとの保証と未確認範囲を理解する |
| 得たい結果 | 最終E2E前に外部境界の問題を局所化できる |
| 重要場面 | 外部境界を結合する各段階 |
| 避ける失敗 | 単発成功や試験件数から一連の状態変化全体を保証する |
| 守る品質 | 開始から清掃まで段階的に反証する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 試験層 | 確認の粒度 | UT／IT／ST／UAT／RT／PT-LT |
| 対象範囲 | 試験層ごとの保証と未確認範囲を理解する際に、「対象範囲」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 対象、判定時点、情報源で識別し、不明を正常へ丸めない |
| 一連の状態変化の根拠 | 試験層ごとの保証と未確認範囲を理解する際に、「一連の状態変化の根拠」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 対象、判定時点、情報源で識別し、不明を正常へ丸めない |
| 決定権限 | 試験層ごとの保証と未確認範囲を理解する際に、「決定権限」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 主体、対象範囲、有効時点で識別する |
| 未実行状態 | 試験層ごとの保証と未確認範囲を理解する際に、「未実行状態」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 対象、判定時点、情報源で識別し、不明を正常へ丸めない |


```text
                              [O: 決定権限]
                                    │ 実行可否を決める
                                    ▼
[O: 一連の状態変化の根拠] ──成立根拠を与える──▶ [O: 対象範囲] ◀──確認範囲を定める── [O: 試験層]
                                                                                │
                                                                                └── 未実行を明示する ──▶ [O: 未実行状態]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000016 | 試験層 | 試験層 | Same | UT／IT／ST／UAT等の検証段階を保持する |
| ― | 対象範囲 | ― | Not Applicable | IA-000016の「状態・可視性・時間的な意味」節へ、対象範囲を独立Objectではなく状態・可視条件として保持する |
| ― | 一連の状態変化の根拠 | ― | Not Applicable | IA-000016の「状態・可視性・時間的な意味」節へ、一連の状態変化の根拠を独立Objectではなく状態・可視条件として保持する |
| ― | 決定権限 | ― | Not Applicable | IA-000016の「責任と判断権限」表へ、決定権限を独立Objectではなく機能責任・権限として保持する |
| ― | 未実行状態 | ― | Not Applicable | 品質状態の状態値として保持し、独立Objectへ変換しない |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 計画済み（planned）／未実行（not_executed）／合格（passed）／失敗（failed）／停止（blocked）／非該当（not_applicable） |
| 可視性 | 「外部境界を結合する各段階」では、開始から清掃まで段階的に反証するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 試験層→対象範囲→一連の状態変化の根拠→決定権限→未実行状態。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 検証責任者が試験層・対象範囲・状態変化の根拠・未実行状態を記録する。 |
| 時間的な意味 | 計画済み（planned）／未実行（not_executed）／合格（passed）／失敗（failed）／停止（blocked）／非該当（not_applicable）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「試験層ごとの保証と未確認範囲を理解する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD作成者・保守者が「変更の検証計画を作る時」に「最終E2E前に外部境界の問題を局所化できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 検証責任者が必要な試験層を選び、公開可否を決める主体が残存未実行の受容を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 単発成功や試験件数から一連の状態変化全体を保証する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD作成者・保守者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「外部境界を結合する各段階」に、単発成功や試験件数から一連の状態変化全体を保証することを避け、開始から清掃まで段階的に反証することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000030: CRDD作成者・保守者が「試験層ごとの保証と未確認範囲を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | CRDD作成者・保守者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 品質状態の統合（Quality Center）と試験一覧（Test Catalog）がある。未実行の負荷試験（PT／LT）を失敗や合格へ丸めない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000016](../../Definitions/IA-000016/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「最終E2E前に外部境界の問題を局所化できる」の成立条件、「単発成功や試験件数から一連の状態変化全体を保証する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
