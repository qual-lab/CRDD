# IA分析: 試験層と現在の保証範囲を理解して選ぶ

成果物種別: IA分析
分析対象: [UX-000026](../../../02_UX/Definitions/UX-000026/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 変更の検証計画を作る時 |
| 目的 | 試験層ごとの保証と未確認範囲を理解する |
| 得たい結果 | 最終E2E前に外部境界の問題を局所化できる |
| 重要場面 | 外部境界を結合する各段階 |
| 避ける失敗 | 単発成功や試験件数から一連の状態変化全体を保証する |
| 守る品質 | 開始から清掃まで段階的に反証する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 試験層（Test Layer）、確認対象範囲（Target Scope）、一連の開始から終了までの根拠（Lifecycle Evidence）、実行状態（Execution State）、実行権限（Authority）、対象範囲（Coverage） | 対象を同一視せず、「変更→不確実性→試験層→実行結果→現在保証」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 変更→不確実性→試験層→実行結果→現在保証 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: CRDD作成者・保守者の判断] --確認する--> [O: 試験層（Test Layer）]
[O: 試験層（Test Layer）] --根拠と次の行動を辿る--> [O: 最終E2E前に外部境界の問題を局所化できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 計画済み（planned）／未実行（not_executed）／合格（passed）／失敗（failed）／停止（blocked）／非該当（not_applicable） |
| 可視性 | 外部境界を結合する各段階では、開始から清掃まで段階的に反証するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 変更→不確実性→試験層→実行結果→現在保証。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | CRDD作成者・保守者は「試験層ごとの保証と未確認範囲を理解する」ために必要な判断を行う。システムは「最終E2E前に外部境界の問題を局所化できる」を支える対象・状態・根拠を示し、「単発成功や試験件数から一連の状態変化全体を保証する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 品質状態の統合（Quality Center）と試験一覧（Test Catalog）がある。未実行の負荷試験（PT／LT）を失敗や合格へ丸めない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000016](../../Definitions/IA-000016/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
