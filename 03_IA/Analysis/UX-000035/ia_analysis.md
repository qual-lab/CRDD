# IA分析: 軽量なユーザー管理でRemote Accessを維持・回復する

成果物種別: IA分析
分析対象: [UX-000035](../../../02_UX/Definitions/UX-000035/ux_definition.md)
状態: 初回Host設定の旧限定レビュー結果は履歴。今回の鍵提示方式はIAまで候補伝播・限定独立再レビューPass・残指摘0。UI／SPEC以降の今回差分は未適用。旧Pass非流用

## 1. UXから受け取る意味

初回にはHost操作者が未初期化CROSの最初のadministratorと鍵を成立させて通常管理へ入る。その後の業務管理・鍵維持・喪失後回復と同じ利用者成果を扱い、初回設定と既存ユーザーのHost回復を別場面にする。

鍵の発行・独立失効・交換はadministrator専用固定で、Role詳細権限のON／OFF設定を設けない。通常入口は同一Process Workbench backendだけとし、MCPには秘密値の有無を問わず鍵操作の一覧・Schema・登録・dispatchを公開しない。通常Host回復はログイン済みローカル操作者を信頼する対話CLIで、鍵交換2操作だけを扱う。追加認証・専用資格・承認コード・OS管理者昇格を要求せず、既存の管理Root／Path検証は維持する。manager／administratorはユーザー登録・表示名変更、developer／managerの割当て・詳細権限、Repository登録・登録解除・公開範囲を管理する。administratorの付与・解除・降格を含むRole変更、administrator詳細権限と鍵3操作はadministratorだけが管理する。developerへ管理操作、managerへ管理者専用操作を設定で委譲しない。

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 業務管理のmanager／administrator、鍵・管理者Role管理のadministrator、Server Host運用者 |
| 場面 | 未初期化CROSの初回利用開始、ユーザー登録、表示名／Role変更、Repository登録・登録解除・公開範囲変更、鍵発行・独立失効・交換、漏洩、既存administratorの有効Credential全喪失 |
| 目的 | 最初の管理者と鍵から利用可能にし、対象を見分け、最小管理でRemote利用範囲を維持し、安全に通常管理へ戻る |
| 得たい結果 | 未初期化CROSから通常管理へ入り、業務の利用範囲を維持し、鍵が必要な時だけadministratorへ引き継ぎ、必要な再設定だけを案内できる |
| 重要場面 | 未初期化状態の確認と最初の鍵の一度提示と同鍵の最初の接続成功による受領・接続確認、administrator Roleのユーザー資格をすべて失った時 |
| 避ける失敗 | 別ユーザー処置、名前のAuthority化、Secret保存、管理能力からの内容権限推定、未確定元処理への別Recovery重複、Product Data削除 |
| 守る品質 | 2操作の対象範囲と通常／Hostの入口・Authorityを別軸で示し、保持範囲と安全な再入場を確認できる |

userIdのUUID制約は正式UXから継承する。IAは安定した同一性を扱い、UUID版・Schema・生成方式を決定しない。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| ユーザー | 資格の対象。表示名は管理者の対象識別と自身表示に限る | 安定userId。表示名は属性であり、同名・改名でIdentityや権限を変えない。一つの現行Roleへ結ぶ |
| Role | 利用する権限の分類 | `administrator`／`manager`／`developer`。Repository RoleやTask Roleと別 |
| Role詳細権限 | Roleが所有する情報・操作の許可範囲 | Role IDに結ぶ。ユーザーやCredentialへ個別追加権限を持たせない |
| 接続資格Metadata | ユーザーへ紐づく資格の識別・状態・期限なしの扱い | Credential IDとuserId。生Secretや同等値を含めず、古いRole権限を固定しない。元発行Identity（Credential IDとは別の非秘密Operation／Attempt相関情報）と発行・結果記録・提示結果を別属性として保持し、通常の対象本人への製品外引渡し・受領は観測外とする |
| 一度表示するSecret | 発行または鍵交換後に一度渡す秘密 | 発行Attempt内だけ。永続情報へ含めない |
| 接続資格状態 | 有効・失効・不明の差 | Credential IDと現行状態。鍵交換は旧資格失効と新資格発行の関係であり、新しい永続状態を作らない |
| 管理能力 | 最小ユーザー情報・Role権限・Credential等を管理する能力 | 業務管理はmanager／administrator、管理者Role・詳細権限と鍵はadministrator専用固定。内容閲覧を自動的に得ない。初回には対象Host管理状態の由来・確認結果、初期化状態、確認済み初回試行の非秘密相関を属性として持ち、成立したユーザー・資格へ結ぶ |
| Access Recovery | 通常管理またはHostから鍵だけを交換して接続へ戻る回復 | Recovery IDを最初の失敗から再入場まで保つ。操作種別（指定ユーザー交換／全員交換）と入口・Authorityは別属性 |
| Recovery対象 | 鍵交換の対象ユーザー・失効資格集合・新資格発行先 | Recovery ID、対象userId、失効対象Credential集合、発行先userId。指定交換は同じユーザー、全員交換は指定既存administrator |
| 保持対象 | 変更しないユーザーID・表示名・Role・詳細権限・Repository登録・Product Data | Recovery IDとユーザーID・表示名・Role・詳細権限・Repository登録・Product Dataの保持区分 |
| Recovery結果 | 現在地、終了後状態、次の安全な行動 | Recovery IDと結果改訂版。失効確定範囲と新資格発行結果を分離し、不明を保持する。元発行事実と新しい明示交換の結果・Identityを区別 |

```text
[O: 接続資格Metadata] ──紐づく──▶ [O: ユーザー]
        │                            │ 一つの現行Role
        │                            ▼
        │                        [O: Role]
        │                            └─持つ──▶ [O: Role詳細権限]
        ├─発行時だけ──▶ [補足: 一度表示するSecret]
        └─現在値を持つ▶ [O: 接続資格状態]

[O: Role] ──採用済み担当Roleの固定管理操作（下表）──▶ [O: 管理能力]

[O: Access Recovery]
      ├─処置する──▶ [O: Recovery対象]
      ├─変更しない▶ [O: 保持対象]
      └─記録する──▶ [O: Recovery結果]
```

図中の`[O:]`は情報Objectだけを表す。表示名はユーザーの属性であり独立Identityを発行しない。両入口で既存userIdへ新資格を結び、ユーザー情報・Role・詳細権限を保持する。表示名は対象Identityではない。

### 操作対象と担当Role

| 操作対象・内容 | manager | administrator | developer |
|---|---|---|---|
| ユーザー登録・表示名変更 | 許可 | 許可 | 不許可 |
| developer／managerの割当て・変更 | 許可 | 許可 | 不許可 |
| administratorの付与・解除・降格を含む変更 | 不許可 | 許可 | 不許可 |
| developer／managerの詳細権限 | 許可 | 許可 | 不許可 |
| administratorの詳細権限 | 不許可 | 許可 | 不許可 |
| 鍵の発行・独立失効・交換 | 不許可 | 許可 | 不許可 |
| Repository登録・登録解除 | 許可 | 許可 | 不許可 |
| Repository公開範囲 | 許可 | 許可 | 不許可 |

管理能力の固定割当と内容範囲を別に扱う。managerは変更前の現在管理権限による認可を経て、自身のRole内容範囲・公開範囲も明示更新できる。次要求から現行Role権限・Exposure・実アクセスを再評価する。管理能力だけから内容取得を許可しない。ユーザーの表示名はadministratorのものもmanagerが変更できるが、userId・Role・Credential・Authorityの変更とは別である。

Repository登録状態は登録関係の属性、公開範囲はExposureの属性、内容の存在はRepositoryの情報として区別する。登録だけで公開・アクセス可能とせず、登録解除は登録と対応する公開設定を同時に解除し、CROSから対象へ以後アクセスできなくする。他対象の登録・公開設定と対象Repository／Product Dataは保持する。既存対象の属性・関係として扱い、新Objectや安定IDを追加しない。

### 鍵操作と情報結果の関係

| 操作 | 旧資格への作用 | 新資格・Secret | 交換専用の回復条件 |
|---|---|---|---|
| 通常発行 | 既存資格は失効しない | 新資格を発行し、新Secretを一度だけ表示する | 適用しない。交換の失効・再入場条件を転用しない |
| 独立失効 | 指定したCredentialを失効する | 新資格もSecretも発行しない | 適用しない。交換の発行・再入場条件を転用しない |
| 交換 | 指定ユーザーまたは全員の旧有効資格を定義済み範囲で失効する | 指定交換は同じ既存userId、全員交換は指定既存administratorへ発行し、新Secretを一度だけ表示する | 同じRecoveryへ失効確定／発行不明を結び、現在状態の再観測後に再入場する |

接続資格・資格状態・Secret表示境界の情報関係として区別し、Access Recoveryへ結ぶのは定義済みの交換条件だけとする。通常発行・独立失効について未定義の失敗・回復契約や回復状態の不存在保証を新設しない。

両入口でユーザーID・表示名・Role・詳細権限・Repository登録・Product Dataを保持する。表示名を対象Identityにせず、特別ユーザー・追加権限・回復専用Bootstrapを作らない。初回設定は下記の独立した開始場面として扱い、既存ユーザーの回復用Bootstrapへ転用しない。

交換の発行自体または結果記録が未確定となる発行失敗・応答喪失・Process喪失では、失効確定範囲と発行結果の不明を非秘密の耐久的な事実として同じRecovery IDへ結ぶ。再入場は現在状態の再観測後に判断し、再観測なしに完了・rollback・旧資格未失効・開始済み操作取消済みへ畳まない。Secretを再表示せず、元処理の発行・記録が未確定のまま新しいRecoveryを重ねない。対象ユーザー、全員交換の既存administrator、必要な資格集合・現行権限を安全に確認できない場合や認可設定が破損している場合は処置前停止する。鍵交換は認可設定を修復しない。

### 登録解除と鍵の受け渡しに関する情報関係

最新UX-000035の追加判断を既存Objectの属性・関係へ統合する。新Object・安定ID・回復機構を追加せず、通常発行をAccess Recoveryへ結ばない。

| 既存の情報対象 | 保持する属性・関係 | 次の行動と時間的な意味 |
|---|---|---|
| Repository登録状態・Repository Exposure・リポジトリ | 同じRepositoryに結ぶ登録関係と対応公開設定を同時に解除する。他対象の登録・公開設定と対象Repository本体・Product Dataは保持する | CROSから対象へ以後アクセスできない。別の先行公開解除を必須にせず、登録解除から開始済み操作の取消完了や本体削除を推定しない |
| 接続資格Metadata／接続資格 | 元発行Identity（Credential IDとは別の非秘密Operation／Attempt相関情報）、資格ID・userId、発行事実と結果記録の確認、提示結果を保持し、通常の対象本人への製品外引渡し・受領は観測外とする。Secretは保存しない | 発行と記録が確定し受け渡しだけ未確認なら「発行済み・受け渡し未確認」。確実な未受領や未発行へ畳まず、現在認可されたadministratorが既存交換を明示して新しく実行できる。発行自体または結果記録が不明なら、元発行Identityと既知事実で現在再観測する。交換由来だけ元のexact Recoveryを保持する。新交換を開始しない。通常発行へ交換Recoveryを新設せず、未確定の元処理を別交換で置換しない |
| 接続資格状態 | 発行時の事実と現在の有効／失効等を区別し、旧応答の由来となる資格へ相関する | 遅延した旧応答から失効済み鍵を利用可能と案内しない。新交換の成功で旧Secret受領・rollback・取消を証明しない |
| Access Recovery・Recovery対象・Recovery結果 | 各交換内は同じexact Recovery。確定発行後の新交換は別Operation／別Recoveryで、旧発行事実を保持し旧資格を新交換の失効対象へ結ぶ | 指定ユーザー交換は当該ユーザーの発行済み資格を含む旧有効資格すべてを失効し同じ既存ユーザーへ発行。全員交換は全旧有効資格を失効し指定既存administratorへ発行する。他ユーザーは通常の再発行・再配布まで利用できない |
| 管理能力・入口とAuthority | 現在administrator認証とログイン済みHost操作者を別に扱う | 現在の管理者認証が使えなければ既存Host交換入口へ。通常Workbench認可を迂回せず、追加認証・新Authorityを作らない |

情報導線は、資格の発行・記録の確認→提示結果と観測外引渡しの区別（初回だけ同鍵の接続確認）→現在の資格・権限→次の行動とする。発行・記録確定／受け渡し未確認は明示新交換、発行・記録不明は元Identity再観測、管理者認証喪失は既存Host入口へ分岐する。Secret再表示・自動再発行は案内しない。新交換も2操作の対象・既存発行先・保持範囲、4組の事前表示・3組の明示確認を保持する。

### 初回設定の情報関係と導線

初回設定は既存の管理能力を利用可能にする開始場面として扱う。新しいIA ID・情報Object・安定IDは追加しない。初回設定対象となるHost管理状態の由来・確認結果、未初期化／既存／途中／観測不能、確認できた初回試行の非秘密相関は、ユーザー・資格が未作成でも存在し得る管理能力側の属性である。資格の属性だけに閉じず、作成・発行が成立した後に既存ユーザー・接続資格・資格状態・Secret表示境界へ結ぶ。初回試行をAccess Recoveryへ統合しない。

| 情報のまとまり | 保持する属性・関係 | 次の行動・時間関係 |
|---|---|---|
| 管理能力の開始条件 | 既存Host管理状態の由来・確認結果。管理状態と初回途中記録の双方が未初期化と確定しているか | ログイン済みHost操作者の明示開始だけ。単一File不存在や別Rootから未初期化を推定しない。Remote Credential、追加認証、専用資格、承認コード、OS管理者昇格を前提にしない |
| 管理能力の既存状態 | 既存ユーザー・管理状態、初回試行の有無と確認可能性を区別 | 既存状態では初期化を拒否する。鍵喪失は既存Host交換2操作へ。管理者不存在・Role／認可設定破損を初期化で修復しない |
| 管理能力の観測不能 | 読取不能・破損・対象不明・Lock競合・回収待ちと再確認先 | 未初期化や元試行の存在を推定せず、新ユーザー・鍵作成0。判定不能理由を示して確認へ戻る |
| 確認済み初回試行と成立した対象 | 同じ初回試行の非秘密相関と作成済みuserId、発行・結果記録・Host提示結果・同鍵の最初の接続成功による受領・接続確認の各事実への関係 | 確認済み途中試行だけ同じ相関で現在再観測する。作成後・発行後を未初期化へ戻さず、別UUID作成・自動再初期化・Secret再表示0 |
| ユーザー・Role | 管理用表示名、最初のadministrator UUID、同じユーザーに結ぶ初資格 | 表示名は非Authority。UUID版や構文はここで決めない。Repository登録・公開・内容アクセスを暗黙付与せず、Product Dataを変更しない |
| 接続資格・Secret表示境界 | 作成済みuserId、資格ID、発行・記録の確認、Host端末への一度提示と同鍵の最初の接続成功による受領・接続確認 | 発行・記録確定／受け渡し未確認だけ、作成済みadministratorを指定する明示的な既存Host交換へ。発行・記録不明は元初回試行再観測で新交換0 |

初回設定の情報優先度は、まず対象管理状態と初回設定可否・停止理由、次に管理用表示名・作成済みUUIDと発行／記録／Host提示／同鍵初回接続確認の事実、必要時に非秘密の元試行相関と確認根拠とする。初回設定の文脈と通常管理・鍵回復を別にまとめ、取得不能なユーザーや資格のIDを空値で作成済みと表示しない。情報の永続・短命の別は、ユーザーと資格Metadataの成立事実、元試行の既知事実、一度だけのSecret表示を分離する。具体保存形式・保持・物理Pathは下流で設計する。

```text
[N: Hostの明示初回設定]
          │ 対象管理状態の由来と確認結果
          ▼
[O: 管理能力]（初回状態・確認済み元試行相関のOwner）
          │ 対象状態を判定。成立後のユーザー・資格へ関係を結ぶ
          ▼
[状態: 未初期化を確定できるか]
    ├─ 既存 ──→ [N: 通常管理／鍵喪失時は既存Host交換]
    ├─ 観測不能 ─→ [N: 判定理由と再確認先]（新作成0・試行推定0）
    ├─ 確認済み途中 ─→ [N: 同じ初回試行の現在再観測]
    └─ 未初期化確定
          ▼
[N: 管理用表示名] ──→ [O: ユーザー]（最初のadministrator UUID）
                              │ 同じuserIdへの発行
                              ▼
                       [O: 接続資格] ──→ [O: Secret表示境界]
                              │ 端末への一度提示→同鍵の最初の接続成功を受領・接続確認
                              ▼
                         [N: 通常管理]
```

この図は情報の到達関係であり、API実行順や保存Schemaを固定しない。発行・記録・受け渡しの一部成立を初回設定全体の完了にしない。ログイン済みHost操作者が開始・表示名入力・提示された鍵による最初の接続を行い、管理機能は確認可能な状態と成立事実を区別して提供する。MCP・自動起動から初期化せず、Hostの信頼からRemoteの管理認可や内容閲覧を導出しない。
