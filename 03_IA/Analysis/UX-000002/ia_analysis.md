# IA分析: 委任範囲と権限を理解して任せる

成果物種別: IA分析
分析対象: [UX-000002](../../../02_UX/Definitions/UX-000002/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 複数AIへ仕事を委ねる時 |
| 目的 | 複数AIへ任せる範囲と権限を理解する |
| 得たい結果 | 実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる |
| 重要場面 | 外部作用（Effect）の前の委任境界 |
| 避ける失敗 | 暗黙の範囲拡張や回復不能 |
| 守る品質 | 委任状態・停止理由・回復先を行動可能に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 目的、対象範囲、担い手、決定権限、入力、候補、取消、回復 | 対象を同一視せず、「目的→範囲と担い手→許可→実行」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 目的→範囲と担い手→許可→実行 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: 目的]
[O: 目的] --根拠と次の行動を辿る--> [O: 実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 準備中／許可待ち／実行中／停止。権限発行前後を分ける |
| 可視性 | 外部作用（Effect）の前の委任境界では、委任状態・停止理由・回復先を行動可能に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 目的→範囲と担い手→許可→実行。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「複数AIへ任せる範囲と権限を理解する」ために必要な判断を行う。システムは「実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる」を支える対象・状態・根拠を示し、「暗黙の範囲拡張や回復不能」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト実行状態の管理（Project Runtime）は目的と実行を分ける。AI提供元（Provider）名や作業（Task）作成を権限成立とみなさない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000002](../../Definitions/IA-000002/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
