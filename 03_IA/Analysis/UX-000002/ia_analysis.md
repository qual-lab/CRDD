# IA分析: 委任範囲と権限を理解して任せる

成果物種別: IA分析
分析対象: [UX-000002](../../../02_UX/Definitions/UX-000002/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 複数AIへ仕事を委ねる時 |
| 目的 | 複数AIへ任せる範囲と権限を理解する |
| 得たい結果 | 実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる |
| 重要場面 | 外部作用（Effect）の前の委任境界 |
| 避ける失敗 | 暗黙の範囲拡張や回復不能 |
| 守る品質 | 委任状態・停止理由・回復先を行動可能に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| プロジェクト | 同じ目的・対象範囲・受入条件を共有する仕事のまとまり | Project IDで識別する |
| 目的 | Milestoneを成立させる目的 | Milestoneに属する安定ID |
| 対象範囲 | 複数AIへ任せる範囲と権限を理解する際に、「対象範囲」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 対象、判定時点、情報源で識別し、不明を正常へ丸めない |
| 担い手 | 複数AIへ任せる範囲と権限を理解する際に、「担い手」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 主体、対象範囲、有効時点で識別する |
| 決定権限 | 誰が何を決められるか | 対象・主体・時点へ結合 |
| 候補結果 | 複数AIへ任せる範囲と権限を理解する際に、「候補結果」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 元の依頼・対象・改訂版へ結び、別の結果と混同しない |
| 受入条件 | 候補結果を採用できるか判断する条件 | プロジェクトと目的へ結ぶ安定ID |
| 入力 | 複数AIへ任せる範囲と権限を理解する際に、「入力」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 取消 | 複数AIへ任せる範囲と権限を理解する際に、「取消」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 回復 | 複数AIへ任せる範囲と権限を理解する際に、「回復」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |


```text
                         [O: 決定権限]
                                │ 実行を許す
                                ▼
[O: プロジェクト] ──持つ──▶ [O: 目的] ──適用範囲を定める──▶ [O: 対象範囲] ──担い手を限定する──▶ [O: 担い手]
                                   ▲       ▲                              │
                                   │       │                              │ 返す
                    停止対象を示す │       │ 回復対象を示す               ▼
                              [O: 取消] [O: 回復]                  [O: 候補結果]
                                                                          ▲
                                                                          │ 渡される
                                                                      [O: 入力]

[O: 受入条件] ──判定する──▶ [O: 候補結果]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 準備中／許可待ち／実行中／停止。権限発行前後を分ける |
| 可視性 | 「外部作用（Effect）の前の委任境界」では、委任状態・停止理由・回復先を行動可能に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 目的→対象範囲→担い手→決定権限→候補結果→入力→取消→回復。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMが目的・節目・作業・受入条件を更新し、実行担当が作業状態を提供する。 |
| 時間的な意味 | 準備中／許可待ち／実行中／停止。権限発行前後を分けるの区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「複数AIへ任せる範囲と権限を理解する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | プロジェクト運営者／PMが「複数AIへ仕事を委ねる時」に「実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 人間の決定権限者が委任範囲・受入・採否を確定し、実行担当はその権限を代行しない。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 暗黙の範囲拡張や回復不能 |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はプロジェクト運営者／PMを代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「外部作用（Effect）の前の委任境界」に、暗黙の範囲拡張や回復不能ことを避け、委任状態・停止理由・回復先を行動可能に示すことを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000002: プロジェクト運営者／PMが「複数AIへ任せる範囲と権限を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000003: プロジェクト運営者／PMが「目的と受入条件で節目を委ねる」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | プロジェクト運営者／PMを代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト実行状態の管理（Project Runtime）は目的と実行を分ける。AI提供元（Provider）名や作業（Task）作成を権限成立とみなさない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000002](../../Definitions/IA-000002/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「実行前に誰へ何をどこまで任せるかを理解し、暗黙の範囲拡張なく仕事を委ねられる」の成立条件、「暗黙の範囲拡張や回復不能」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
