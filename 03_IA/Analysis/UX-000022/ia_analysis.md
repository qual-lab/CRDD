# IA分析: 残存資源を安全に回復・清掃する

成果物種別: IA分析
分析対象: [UX-000022](../../../02_UX/Definitions/UX-000022/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 失敗後または保守時に残存を見つけた時 |
| 目的 | 残存資源の由来・保持・清掃・回復を理解する |
| 得たい結果 | 必要な根拠を残し不要物を安全に片付けられる |
| 重要場面 | 削除または回復を選ぶ場面 |
| 避ける失敗 | 名前や経過時間だけで由来不明物を削除する |
| 守る品質 | 残存・観測不能・不存在を区別する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 残存物（Residue）、回復対象の識別子（Recovery Identity）、作用状態（Effect State）、回復義務（Recovery Obligation）、回復処置（Recovery Action）、処置（Disposition）、清掃根拠（Cleanup Evidence） | 対象を同一視せず、「停止→残存観測→同一の回復対象識別子→回復処置・清掃→不存在確認→義務解消」の順に関係付ける。回復処置の終了だけで義務解消とみなさない。 |
| 根拠と次の行動 | 停止→残存観測→同一の回復対象識別子→回復処置・清掃→不存在確認→義務解消 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 実行環境の導入・運用者の判断] --確認する--> [O: 残存物（Residue）]
[O: 残存物（Residue）] --根拠と次の行動を辿る--> [O: 必要な根拠を残し不要物を安全に片付けられる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 存在（present）／不存在（absent）／不明（unknown）、回復可能（recoverable）／清掃可能（cleanup_eligible） |
| 可視性 | 削除または回復を選ぶ場面では、残存・観測不能・不存在を区別するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 停止→残存観測→同一の回復対象識別子→回復処置・清掃→不存在確認→義務解消。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行環境の導入・運用者は「残存資源の由来・保持・清掃・回復を理解する」ために必要な判断を行う。システムは「必要な根拠を残し不要物を安全に片付けられる」を支える対象・状態・根拠を示し、「名前や経過時間だけで由来不明物を削除する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行時データ（runtime-data）と実行編成（Coordinator）の回復経路を利用する。観測不能を不存在にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000003](../../Definitions/IA-000003/ia_definition.md)および[IA-000012](../../Definitions/IA-000012/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
