# IA分析: 残存資源を安全に回復・清掃する

成果物種別: IA分析
分析対象: [UX-000022](../../../02_UX/Definitions/UX-000022/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 失敗後または保守時に残存を見つけた時 |
| 目的 | 残存資源の由来・保持・清掃・回復を理解する |
| 得たい結果 | 必要な根拠を残し不要物を安全に片付けられる |
| 重要場面 | 削除または回復を選ぶ場面 |
| 避ける失敗 | 名前や経過時間だけで由来不明物を削除する |
| 守る品質 | 残存・観測不能・不存在を区別する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 残存物 | 残存資源の由来・保持・清掃・回復を理解する際に、「残存物」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 回復対象の識別情報 | 残存資源の由来・保持・清掃・回復を理解する際に、「回復対象の識別情報」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 回復・清掃処置 | 残存資源の由来・保持・清掃・回復を理解する際に、「回復・清掃処置」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 不存在の根拠 | 残存資源の由来・保持・清掃・回復を理解する際に、「不存在の根拠」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 支える対象、情報源、改訂版または観測時点へ結ぶ |
| 回復義務 | 清掃前に閉じるべき義務 | 回復対象識別子（Recovery Identity） |
| 実行データ | 残存し得る実行時のData Item | Data Identity＋Ownerで識別する |
| 実行データの基点 | 実行データを識別・回復する基点 | 検証済みRepository Root＋用途で識別する |
| 回復処置 | 回復義務を解消する操作 | Recovery Identity＋処置識別子で識別する |
| 終了確認 | 作用と残存が閉じたことの観測 | Recovery Identity＋確認時点で識別する |
| 清掃根拠 | 削除許可と終了後不存在の根拠 | Data Identity＋確認時点へ結ぶ |


```text
[O: 残存物]
      │ 同じ回復対象へ結ぶ
      ▼
[O: 回復対象の識別情報]
      │ 処置を限定する
      ▼
[O: 回復・清掃処置]
      │ 終了を確認する
      ▼
[O: 不存在の根拠]

[O: 実行データの基点] ──含む──▶ [O: 実行データ] ──残存時に生む──▶ [O: 回復義務]
[O: 回復義務] ──解消する──▶ [O: 回復処置] ──確認する──▶ [O: 終了確認] ──根拠となる──▶ [O: 清掃根拠]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |

| ― | 回復対象の識別情報 | ― | Not Applicable | 回復義務と実行データの基点を識別する情報として保持する |
| ― | 回復・清掃処置 | ― | Not Applicable | 回復処置の利用者向け表示として保持し、別Objectへ変換しない |

| IA-000003 | 回復義務 | 回復義務 | Same | 失敗後に解消が必要な残存状態を保持する |
| IA-000012 | 回復義務 | 回復義務 | Same | 清掃前に閉じるべき義務を保持する |
| IA-000012 | 実行データ | 実行データ | Same | 通常時と失敗後の同じData Itemを保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 存在（present）／不存在（absent）／不明（unknown）、回復可能（recoverable）／清掃可能（cleanup_eligible） |
| 可視性 | 「削除または回復を選ぶ場面」では、残存・観測不能・不存在を区別するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 残存物→回復対象の識別情報→回復・清掃処置→不存在の根拠。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行データを管理する主体が残存物と回復Identityを保ち、回復・清掃を実行する主体が回復・清掃処置と不存在の根拠を更新する。 |
| 時間的な意味 | 存在（present）／不存在（absent）／不明（unknown）、回復可能（recoverable）／清掃可能（cleanup_eligible）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「残存資源の由来・保持・清掃・回復を理解する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 実行環境の導入・運用者が「失敗後または保守時に残存を見つけた時」に「必要な根拠を残し不要物を安全に片付けられる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 回復完了と削除可否を確定する主体が回復完了と削除可否を確定する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 名前や経過時間だけで由来不明物を削除する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は実行環境の導入・運用者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「削除または回復を選ぶ場面」に、名前や経過時間だけで由来不明物を削除することを避け、残存・観測不能・不存在を区別することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000022: 実行環境の導入・運用者が「残存資源の由来・保持・清掃・回復を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 実行環境の導入・運用者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行時データ（runtime-data）と実行編成（Coordinator）の回復経路を利用する。観測不能を不存在にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000003](../../Definitions/IA-000003/ia_definition.md)および[IA-000012](../../Definitions/IA-000012/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「必要な根拠を残し不要物を安全に片付けられる」の成立条件、「名前や経過時間だけで由来不明物を削除する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
