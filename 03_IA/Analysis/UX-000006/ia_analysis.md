# IA分析: 実行事実を根拠付きで振り返る

成果物種別: IA分析
分析対象: [UX-000006](../../../02_UX/Definitions/UX-000006/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 実行結果を振り返る時 |
| 目的 | 実行事実を出所と観測時点付きで比較する |
| 得たい結果 | 推測と事実を混ぜず改善候補を判断できる |
| 重要場面 | 未観測値を含む実行事実の取得 |
| 避ける失敗 | 未観測を0や正常へ畳む |
| 守る品質 | 出所・時点・観測状態を保持する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 実行記録、観測、情報源、観測時点、評価、改善候補 | 対象を同一視せず、「実行→観測→根拠→評価→改善候補」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 実行→観測→根拠→評価→改善候補 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 実行環境の導入・運用者の判断] --確認する--> [O: 実行記録]
[O: 実行記録] --根拠と次の行動を辿る--> [O: 推測と事実を混ぜず改善候補を判断できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 観測済み（observed）／未観測（not_observed）／不明（unknown）。評価は事実と別 |
| 可視性 | 未観測値を含む実行事実の取得では、出所・時点・観測状態を保持するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 実行→観測→根拠→評価→改善候補。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行環境の導入・運用者は「実行事実を出所と観測時点付きで比較する」ために必要な判断を行う。システムは「推測と事実を混ぜず改善候補を判断できる」を支える対象・状態・根拠を示し、「未観測を0や正常へ畳む」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行観測（execution-intelligence）が実装済み。空値を正常値へ変換しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000004](../../Definitions/IA-000004/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
