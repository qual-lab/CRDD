# IA分析: 実行事実を根拠付きで振り返る

成果物種別: IA分析
分析対象: [UX-000006](../../../02_UX/Definitions/UX-000006/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 実行結果を振り返る時 |
| 目的 | 実行事実を出所と観測時点付きで比較する |
| 得たい結果 | 推測と事実を混ぜず改善候補を判断できる |
| 重要場面 | 未観測値を含む実行事実の取得 |
| 避ける失敗 | 未観測を0や正常へ畳む |
| 守る品質 | 出所・時点・観測状態を保持する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 実行記録 | 一回の実行 | 実行識別子（Execution ID） |
| 観測状態 | 観測した値と観測状態 | Execution＋測定項目（Metric）＋観測時点（Observed At） |
| 情報源 | 観測元 | 情報源の識別子（Source Identity）／改訂版（Revision） |
| 評価 | 事実に対する評価 | Observation集合へ結合 |
| 改善候補 | 改善候補 | Assessmentと根拠へ結合 |


```text
[O: 実行記録]
      │ 含む
      ▼
[O: 観測状態]
      ├── 取得元へ結ぶ ──▶ [O: 情報源]
      └── 評価を支える ──▶ [O: 評価] ──生む──▶ [O: 改善候補]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000004 | 実行記録 | 実行 | Rename | 記録が指す実行主体をCanonical Objectとする |
| IA-000004 | 観測状態 | 観測 | Rename | 実行に対する観測事実として保持する |
| IA-000004 | 情報源 | 情報源 | Same | 観測の由来を保持する |
| IA-000004 | 評価 | 評価 | Same | 観測と判断を分けて保持する |
| IA-000004 | 改善候補 | 改善候補 | Same | 評価から得た候補を採用済み改善と区別する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 観測済み（observed）／未観測（not_observed）／不明（unknown）。評価は事実と別 |
| 可視性 | 「未観測値を含む実行事実の取得」では、出所・時点・観測状態を保持するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 実行記録→観測状態→情報源→評価→改善候補。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行・観測・情報源を記録する責任と、評価・改善候補を更新する責任を分ける。 |
| 時間的な意味 | 観測済み（observed）／未観測（not_observed）／不明（unknown）。評価は事実と別の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「実行事実を出所と観測時点付きで比較する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 実行環境の導入・運用者が「実行結果を振り返る時」に「推測と事実を混ぜず改善候補を判断できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 品質または運用の決定権限者が評価の採用と改善着手を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 未観測を0や正常へ畳む |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は実行環境の導入・運用者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「未観測値を含む実行事実の取得」に、未観測を0や正常へ畳むことを避け、出所・時点・観測状態を保持することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000004: 実行環境の導入・運用者が「実行事実を出所と観測時点付きで比較する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 実行環境の導入・運用者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行観測（execution-intelligence）が実装済み。空値を正常値へ変換しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000004](../../Definitions/IA-000004/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「推測と事実を混ぜず改善候補を判断できる」の成立条件、「未観測を0や正常へ畳む」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
