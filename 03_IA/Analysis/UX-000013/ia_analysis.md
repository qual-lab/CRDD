# IA分析: 許可された作業領域だけをリモート利用する

成果物種別: IA分析
分析対象: [UX-000013](../../../02_UX/Definitions/UX-000013/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | リモート接続を開始・再接続する時 |
| 目的 | 許可された作業領域だけへ接続する |
| 得たい結果 | 場所が変わっても開示範囲を理解して安全に使える |
| 重要場面 | 利用可能情報を表示する時 |
| 避ける失敗 | 利用不能なリポジトリの存在や内容を推測表示する |
| 守る品質 | 現在の利用許可範囲（Grant）だけを開示し不足を補完しない |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 接続資格、接続中の作業単位（Session）、利用可能領域（Workspace Grant）、公開関係（Exposure）、リポジトリの利用可否、管理能力（System Capability） | 対象を同一視せず、「接続→接続単位→許可された作業領域→公開されたリポジトリ→情報源」の順に関係付ける。内容を読めることと管理操作ができることを同一視しない。 |
| 根拠と次の行動 | 接続→Session→許可Workspace→公開Repository→情報源（Source） | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: 接続資格]
[O: 接続資格] --根拠と次の行動を辿る--> [O: 場所が変わっても開示範囲を理解して安全に使える]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 利用可能（available）／接続資格が必要（credential_required）／開示制限（restricted）／利用不能（unavailable）／不明（unknown） |
| 可視性 | 利用可能情報を表示する時では、現在の利用許可範囲（Grant）だけを開示し不足を補完しないために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 接続→Session→許可Workspace→公開Repository→情報源（Source）。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「許可された作業領域だけへ接続する」ために必要な判断を行う。システムは「場所が変わっても開示範囲を理解して安全に使える」を支える対象・状態・根拠を示し、「利用不能なリポジトリの存在や内容を推測表示する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | CROS Architectureに設計候補がある。システム管理能力（system administration）を内容閲覧へ流用しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000009](../../Definitions/IA-000009/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
