# IA分析: 利用環境の信頼方針で実行基盤を選ぶ

成果物種別: IA分析
分析対象: [UX-000020](../../../02_UX/Definitions/UX-000020/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 実行基盤を導入または更新する時 |
| 目的 | 実行環境の信頼の各要素を別々に評価する |
| 得たい結果 | 準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる |
| 重要場面 | 実行を信頼すると判断する場面 |
| 避ける失敗 | 一つの署名表示を全保証と誤認する |
| 守る品質 | 保証要素と決定権限を分離表示する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 準拠（Conformance）、完全性（Integrity）、配布者（Publisher）、成果物（Artifact）、信頼方針（Trust Policy）、導入（Deployment） | 対象を同一視せず、「成果物（Artifact）→各根拠→利用者方針→導入判断」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 成果物（Artifact）→各根拠→利用者方針→導入判断 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 実行環境の導入・運用者の判断] --確認する--> [O: 準拠（Conformance）]
[O: 準拠（Conformance）] --根拠と次の行動を辿る--> [O: 準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 確認済み（verified）／未確認（unverified）／信頼済み（trusted）／非信頼（not_trusted）を別軸にする |
| 可視性 | 実行を信頼すると判断する場面では、保証要素と決定権限を分離表示するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 成果物（Artifact）→各根拠→利用者方針→導入判断。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行環境の導入・運用者は「実行環境の信頼の各要素を別々に評価する」ために必要な判断を行う。システムは「準拠、改ざん有無、配布者、公式表示および実行許可を区別し、自分の環境の方針で公式版・派生版・組織版を選べる」を支える対象・状態・根拠を示し、「一つの署名表示を全保証と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 成果物署名（artifact-signing）が完全性・配布者（Publisher）の根拠を支える。Qual-Lab署名を唯一の実行資格にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |
