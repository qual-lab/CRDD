# IA分析: 論点と会議記録を安全に維持する

成果物種別: IA分析
分析対象: [UX-000033](../../../02_UX/Definitions/UX-000033/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | Project運営者／PM、Meeting参加者、Topic責任者 |
| 場面 | 論点や会議記録を扱う時、誤登録を見つけた時 |
| 目的 | Topicの現在状態とMeetingの時点記録を経緯と関係を保って維持する |
| 得たい結果 | 正当な履歴を残し、誤登録だけを安全に除ける |
| 重要場面 | 物理削除を確定する直前 |
| 避ける失敗 | 当時記録の上書き、誤削除、連鎖削除、無効な関係、部分成功 |
| 守る品質 | 影響と復旧可能性を示し、明示確認後も関係を整合させる |

正式入力はUX-000033だけとし、画面、API、保存形式または実装から意味を逆輸入しない。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 論点 | 時間を越えて追跡する現在状態と経緯 | Topic ID |
| 会議 | 特定時点の記録 | Meeting IDと記録時点 |
| 関係 | Topic、Meeting、候補、Decision／Actionの接続 | 参照元Identity＋参照先Identity＋関係種別 |
| Lifecycle処置 | 継続、終了、撤回、訂正または物理削除の区別 | 対象Identity＋処置種別＋決定時点 |
| 削除影響 | 失われる内容、参照元・参照先、関係処置、復旧可能性 | 削除候補と観測改訂版に結合 |
| 操作結果 | 完了、競合、権限不足、部分成功、状態不明 | 操作Identityと終了後観測 |

```text
    │                                      │
    └──────────── [O: 関係] ◀────────────┘
                         │

                  [O: Lifecycle処置]
                         │
                ┌────────┴────────┐
                ▼                 ▼
          [O: 削除影響]      [O: 操作結果]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果をObjectとして代用しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | Topicの継続／終了／撤回、Meetingの時点記録／訂正、削除候補／確認待ち／削除済み、操作の完了／部分成功／競合／不明を区別する |
| 可視性 | 読取り可能性と編集・削除Authorityを分け、削除判断者にだけ必要な影響と確認を示す |
| 導線 | Topic／Meeting→関係・経緯→Lifecycle処置。削除時は対象→削除影響→確認→操作結果→回復へ進む |
| 責任 | 記録Ownerが内容と関係を保ち、共通能力が入口間で同じ情報契約と終了後状態を提供する |
| 時間的な意味 | Topicのcurrentと履歴、Meetingのhistoricalな当時記録、訂正後、unknownを区別する |
| 情報の優先度 | 通常は対象・現在状態・経緯・次行動、削除時は失われる内容・関係処置・復旧可能性を先に示す |
| 情報のまとまり | TopicまたはMeetingと、その状態・関係・根拠・Lifecycle処置・結果を同じ文脈で扱う |
| 判断権限 | Ownerが終了・訂正を判断し、削除Authorityを持つ利用者が影響確認後に物理削除を決める |
| 重要な失敗 | 正当な履歴の消失、当時記録の上書き、連鎖削除、無効Relation、部分成功の完了表示 |
| 制約・対象外 | Screen、API、Schema、保存方式、Transaction、具体的状態実値は確定しない |
| 人間判断 | UXから継承する削除確認負担をDogfoodで判断する。IA固有の追加判断はない |
| IAへ戻す条件 | UI／SPECで時点、Lifecycle、関係または削除影響を一意に扱えない場合 |
| 検証意図 | 同じ対象・時点・関係を保ち、削除前後の影響と終了後状態を情報上追跡できることを確認する |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | 登録必須項目、一覧粒度、削除確認の理解しやすさと許容負担 |
| 判断者 | Project運営者、Meeting参加者、Topic責任者およびQual-Lab |
| 現在判定 | 後続確認が必要。IA定義の補強は進められる |
| 未確認時の影響 | 表示粒度、確認回数および具体的状態実値を確定しない |
| IAで追加した未確認事項 | なし |
| IA固有の追加人間判断 | なし |
| Discoveryへ戻す条件 | 共通操作で負担や誤削除が増える、またはTopicとMeetingの意味を保てない場合 |
