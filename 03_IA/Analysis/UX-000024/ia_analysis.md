# IA分析: 外部利用の送信・持帰り・昇格を制御する

成果物種別: IA分析
分析対象: [UX-000024](../../../02_UX/Definitions/UX-000024/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 外部へ渡す情報の所有者 |
| 場面 | 外部AI・検索・公開Communication・管理対象依存を利用する時 |
| 目的 | 送信範囲と内部へ戻す際の昇格条件を理解する |
| 得たい結果 | 不要情報を漏らさず人間判断を保って外部連携できる |
| 重要場面 | 外部作用（Effect）の前と結果昇格時 |
| 避ける失敗 | 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する |
| 守る品質 | 同意・投影・採用を分離する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 送信先 | 情報の送信先 | 提供先の識別子（Provider／Service Identity） |
| 目的 | 許可する操作目的 | 目的識別子（Purpose Identity） |
| 情報分類 | 送る情報の分類 | Policyに基づく値 |
| 同意 | 主体が許可した範囲 | 送信先（Destination）＋目的（Purpose）＋Scope＋Time |
| 持帰り候補 | 出所付きの戻り結果 | Task＋送信先（Destination） |
| 送信情報 | 同意範囲内で外部へ渡す最小情報 | 送信先・目的・情報分類・対象Revisionで識別する |
| 引き渡し | 情報と責任を境界の外へ移す単位 | 情報源（Source）＋送信先（Destination）＋目的（Purpose）＋対象Revision |
| 判断 | 持帰り候補を正本へ採用するか決めた記録 | 候補（Candidate）＋判断主体＋判断時点 |

```text
                              [O: 同意]
                                    │ 送信を許す
                                    ▼
[O: 情報分類] ──内容を制約する──▶ [O: 送信情報] ──必要最小限を渡す──▶ [O: 送信先]
                                    ▲                                  │
                                    │                                  │ 結果を候補として返す
                       目的を限定する│                                  ▼
                                [O: 目的]                         [O: 持帰り候補]
                                    │                                  │
                                    └────[O: 引き渡し]───────▶ [O: 判断]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000017 | 送信先 | 送信先 | Same | 外部情報境界の相手先を保持する |
| IA-000017 | 目的 | 目的 | Same | 許可する処理目的を保持する |
| IA-000017 | 情報分類 | 情報分類 | Same | 送信可否判断の分類を保持する |
| IA-000017 | 同意 | 同意 | Same | 送信範囲へのHuman Authorizationを保持する |
| IA-000017 | 持帰り候補 | 持帰り候補 | Same | 外部結果を正本へ自動昇格しないCandidateとして保持する |
| IA-000017 | 送信情報 | 送信情報 | Same | 実際に境界外へ出す最小情報を保持する |
| IA-000014 | 引き渡し | 引き渡し | Same | 境界をまたぐ情報と責任の移動単位を保持する |
| IA-000014 | 判断 | 判断 | Same | 候補の採否を元の権限へ戻す記録を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 未許可（not_authorized）／許可済み（authorized）／送信済み（sent）／返却済み（returned）／候補（candidate）／採用（adopted） |
| 可視性 | 「外部作用（Effect）の前と結果昇格時」では、同意・投影・採用を分離するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 送信先→目的→情報分類→同意→持帰り候補。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 送信元の正本から送信情報と引き渡しを作成する責任と、送信同意の範囲・送信結果を記録する責任を分ける。 |
| 時間的な意味 | 未許可（not_authorized）／許可済み（authorized）／送信済み（sent）／返却済み（returned）／候補（candidate）／採用（adopted）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「送信範囲と内部へ戻す際の昇格条件を理解する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 外部へ渡す情報の所有者が「外部AI・検索・公開Communication・管理対象依存を利用する時」に「不要情報を漏らさず人間判断を保って外部連携できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 人間の決定権限者が送信を許可し、正本Ownerが持帰り候補の採否を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は外部へ渡す情報の所有者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「外部作用（Effect）の前と結果昇格時」に、接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格することを避け、同意・投影・採用を分離することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000027: 外部へ渡す情報の所有者が「送信範囲を理解し帰還結果を候補として扱う」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 外部へ渡す情報の所有者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 外部送信方針（external-send policy）と実行編成（Coordinator）が境界を支える。接続済みを包括許可にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000014](../../Definitions/IA-000014/ia_definition.md)および[IA-000017](../../Definitions/IA-000017/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「不要情報を漏らさず人間判断を保って外部連携できる」の成立条件、「接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
