# IA分析: 外部利用の送信・持帰り・昇格を制御する

成果物種別: IA分析
分析対象: [UX-000024](../../../02_UX/Definitions/UX-000024/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 外部へ渡す情報の所有者 |
| 場面 | 外部AI・検索・公開Communication・管理対象依存を利用する時 |
| 目的 | 送信範囲と内部へ戻す際の昇格条件を理解する |
| 得たい結果 | 不要情報を漏らさず人間判断を保って外部連携できる |
| 重要場面 | 外部作用（Effect）の前と結果昇格時 |
| 避ける失敗 | 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する |
| 守る品質 | 同意・投影・採用を分離する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 送信先（Destination）、目的（Purpose）、情報分類（Information Classification）、同意（Consent）、送信する最小情報、作業（Task）、持帰り結果（Returned Result）、候補（Candidate）、判断（Decision） | 対象を同一視せず、「送信候補→境界確認→送信する最小情報→送信→出所付き結果→採否」の順に関係付ける。接続済みであることを送信許可と同一視しない。 |
| 根拠と次の行動 | 送信候補→境界確認→送信→出所付き結果→採否 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 外部へ渡す情報の所有者の判断] --確認する--> [O: 送信先（Destination）]
[O: 送信先（Destination）] --根拠と次の行動を辿る--> [O: 不要情報を漏らさず人間判断を保って外部連携できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 未許可（not_authorized）／許可済み（authorized）／送信済み（sent）／返却済み（returned）／候補（candidate）／採用（adopted） |
| 可視性 | 外部作用（Effect）の前と結果昇格時では、同意・投影・採用を分離するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 送信候補→境界確認→送信→出所付き結果→採否。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 外部へ渡す情報の所有者は「送信範囲と内部へ戻す際の昇格条件を理解する」ために必要な判断を行う。システムは「不要情報を漏らさず人間判断を保って外部連携できる」を支える対象・状態・根拠を示し、「接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 外部送信方針（external-send policy）と実行編成（Coordinator）が境界を支える。接続済みを包括許可にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000014](../../Definitions/IA-000014/ia_definition.md)および[IA-000017](../../Definitions/IA-000017/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
