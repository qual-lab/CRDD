# IA分析: 失敗後の再試行・回復を選ぶ

成果物種別: IA分析
分析対象: [UX-000004](../../../02_UX/Definitions/UX-000004/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 失敗・取消・切断後に仕事を続ける時 |
| 目的 | 再試行・回復・清掃の違いを理解する |
| 得たい結果 | 失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる |
| 重要場面 | 同じ外部作用（Effect）を再発行する直前 |
| 避ける失敗 | 結果不明の処理を新規実行して外部作用（Effect）の二重実行を起こす |
| 守る品質 | 外部作用（Effect）状態・回復対象の識別情報・終了条件を示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 失敗、試行（Attempt）、外部作用、結果、残存、回復処置（Recovery Action）、再試行 | 対象を同一視せず、「失敗→作用状態→同じ依頼の結果→回復処置または再試行」の順に関係付ける。回復処置と未解決の回復義務を同一視しない。 |
| 根拠と次の行動 | 失敗→作用状態→同じ依頼の結果→回復処置または再試行 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: 失敗]
[O: 失敗] --根拠と次の行動を辿る--> [O: 失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 失敗後の作用なし／作用済み／不明、回復要／不要 |
| 可視性 | 同じ外部作用（Effect）を再発行する直前では、外部作用（Effect）状態・回復対象の識別情報・終了条件を示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 失敗→作用状態→同じ依頼の結果→回復処置または再試行。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「再試行・回復・清掃の違いを理解する」ために必要な判断を行う。システムは「失敗後に状態確認、再試行、回復および清掃を取り違えず、外部作用（Effect）の二重実行を避けて次の行動を選べる」を支える対象・状態・根拠を示し、「結果不明の処理を新規実行して外部作用（Effect）の二重実行を起こす」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行編成（Coordinator）と実行時データ部品（runtime-data）に回復記録がある。API要求成功だけで作用完了を推定しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000003](../../Definitions/IA-000003/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
