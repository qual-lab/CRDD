# IA分析: 意味レビューへ集中できる事前確認

成果物種別: IA分析
分析対象: [UX-000001](../../../02_UX/Definitions/UX-000001/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 成果物をレビューへ渡す前 |
| 目的 | 意味レビュー前に機械判定できる不備を落とす |
| 得たい結果 | 人が意味と判断へ集中できる |
| 重要場面 | 機械指摘と意味判断を分ける |
| 避ける失敗 | 検査範囲や理由が分からない |
| 守る品質 | 同じ入力へ同じ指摘と修正可能な場所を返す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 検査対象、検査条件、指摘、場所、修正責任 | 対象を同一視せず、「対象→指摘→場所→所有成果物」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 対象→指摘→場所→所有成果物 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: CRDD作成者・保守者の判断] --確認する--> [O: 検査対象]
[O: 検査対象] --根拠と次の行動を辿る--> [O: 人が意味と判断へ集中できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 検査前／不備あり／機械確認済み。意味判断は別状態 |
| 可視性 | 機械指摘と意味判断を分けるでは、同じ入力へ同じ指摘と修正可能な場所を返すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 対象→指摘→場所→所有成果物。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | CRDD作成者・保守者は「意味レビュー前に機械判定できる不備を落とす」ために必要な判断を行う。システムは「人が意味と判断へ集中できる」を支える対象・状態・根拠を示し、「検査範囲や理由が分からない」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | Checkerは位置付きの決定論的指摘を実装済み。専門判断や監査結果を同じ合否へ丸めない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000001](../../Definitions/IA-000001/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
