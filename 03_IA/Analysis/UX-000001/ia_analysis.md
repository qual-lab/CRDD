# IA分析: 意味レビューへ集中できる事前確認

成果物種別: IA分析
分析対象: [UX-000001](../../../02_UX/Definitions/UX-000001/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 成果物をレビューへ渡す前 |
| 目的 | 意味レビュー前に機械判定できる不備を落とす |
| 得たい結果 | 人が意味と判断へ集中できる |
| 重要場面 | 機械指摘と意味判断を分ける |
| 避ける失敗 | 検査範囲や理由が分からない |
| 守る品質 | 同じ入力へ同じ指摘と修正可能な場所を返す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 検査対象 | 確認する成果物または範囲 | 改訂版（Revision）と対象範囲で識別 |
| 検査条件 | 適用した機械規則 | 適用範囲（Profile）と規則（Rule）で識別 |
| 指摘 | 条件に反した観測 | 対象と場所と理由へ結合 |
| 場所 | 意味レビュー前に機械判定できる不備を落とす際に、「場所」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 検証済みの対象と範囲へ結び、表示名だけで同一視しない |
| 修正責任 | 正すべき正本 | 指摘から所有成果物へ結合 |


```text
[O: 検査対象]
      │ 検査される
      ▼
[O: 検査条件]
      │ 条件違反として生む
      ▼
[O: 指摘]
      ├── 発生場所を示す ──▶ [O: 場所]
      └── 修正を委ねる ───▶ [O: 修正責任]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000001 | 検査対象 | 検査対象 | Same | 検査する対象をそのままCanonical化する |
| IA-000001 | 検査条件 | 検査条件 | Same | 検査の成立条件をそのまま保持する |
| IA-000001 | 指摘 | 指摘 | Same | 検出した問題をそのまま保持する |
| ― | 場所 | ― | Not Applicable | IA-000001のCanonical Object表にある対応対象の「識別・関係」へ、場所を独立Objectではなく識別条件または関係として保持する |
| IA-000001 | 修正責任 | 修正責任 | Same | 指摘後の処置責任を対象情報として保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 検査前／不備あり／機械確認済み。意味判断は別状態 |
| 可視性 | 「機械指摘と意味判断を分ける」では、同じ入力へ同じ指摘と修正可能な場所を返すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 検査対象→検査条件→指摘→場所→修正責任。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 機械検査の対象・条件・指摘を生成・記録する責任と、修正状態を更新する責任を分ける。 |
| 時間的な意味 | 検査前／不備あり／機械確認済み。意味判断は別状態の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「意味レビュー前に機械判定できる不備を落とす」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD作成者・保守者が「成果物をレビューへ渡す前」に「人が意味と判断へ集中できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | CRDD標準保守責任者が検査条件と指摘の解消判定を確定する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 検査範囲や理由が分からない |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD作成者・保守者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「機械指摘と意味判断を分ける」に、検査範囲や理由が分からないことを避け、同じ入力へ同じ指摘と修正可能な場所を返すことを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000001: CRDD作成者・保守者が「意味レビュー前に機械判定できる不備を落とす」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | CRDD作成者・保守者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | Checkerは位置付きの決定論的指摘を実装済み。専門判断や監査結果を同じ合否へ丸めない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000001](../../Definitions/IA-000001/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「人が意味と判断へ集中できる」の成立条件、「検査範囲や理由が分からない」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
