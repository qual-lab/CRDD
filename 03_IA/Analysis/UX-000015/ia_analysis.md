# IA分析: 複数プロジェクトを根拠付きで比較する

成果物種別: IA分析
分析対象: [UX-000015](../../../02_UX/Definitions/UX-000015/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 経営・管理層 |
| 場面 | 複数プロジェクトの一覧の優先度を判断する時 |
| 目的 | 複数プロジェクトを根拠付きで比較する |
| 得たい結果 | 重要差分から必要なプロジェクトだけを掘り下げられる |
| 重要場面 | 要約から優先判断へ進む直前 |
| 避ける失敗 | 単一Scoreや欠測した集計で健全性を断定する |
| 守る品質 | 比較値から根拠・古さ・不足へ戻れる |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | プロジェクト概要（Project Summary）、比較軸、対象範囲（Coverage）、観測時点（Observed At）、公開関係（Exposure）、情報源（Source） | 対象を同一視せず、「Portfolio→差→対象範囲（Coverage）→Project→情報源（Source）」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | Portfolio→差→対象範囲（Coverage）→Project→情報源（Source） | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 経営・管理層の判断] --確認する--> [O: プロジェクト概要（Project Summary）]
[O: プロジェクト概要（Project Summary）] --根拠と次の行動を辿る--> [O: 重要差分から必要なプロジェクトだけを掘り下げられる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | complete／partial／開示制限（restricted）／stale／競合あり（conflicting） |
| 可視性 | 要約から優先判断へ進む直前では、比較値から根拠・古さ・不足へ戻れるために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | Portfolio→差→対象範囲（Coverage）→Project→情報源（Source）。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 経営・管理層は「複数プロジェクトを根拠付きで比較する」ために必要な判断を行う。システムは「重要差分から必要なプロジェクトだけを掘り下げられる」を支える対象・状態・根拠を示し、「単一Scoreや欠測した集計で健全性を断定する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | CROSの横断投影候補を利用できる。単一の評価値（Score）や非開示プロジェクト（Project）の存在を推測しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000006](../../Definitions/IA-000006/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
