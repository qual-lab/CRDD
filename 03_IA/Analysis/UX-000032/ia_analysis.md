# IA分析: 実行事実を安全に記録して結果を確かめる

成果物種別: IA分析
分析対象: [UX-000032](../../../02_UX/Definitions/UX-000032/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行基盤・TypeScriptアプリへ実行記録を組み込む担当者 |
| 場面 | AIまたはToolの観測可能な実行段階が確定し、事実を後から比較できる形で残す時 |
| 目的 | 実行主体が違っても同じ意味で取得できる記録を、安全に一度だけ公開する |
| 得たい結果 | 記録の成否と不明状態を見分け、重複記録や別実行の上書きを起こさず次の処置を選べる |
| 重要場面 | 保存要求後に結果確認が途切れる |
| 避ける失敗 | 未記録と推定して再発行し、重複または上書きを起こす |
| 守る品質 | 同じ識別情報で再観測し、結果不明を保つ |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 実行 | 記録対象となる一回の実行 | 実行識別子（Execution ID） |
| 情報源 | 観測した実行基盤・アプリ | 情報源の識別子と改訂版 |
| 観測 | 値または未観測理由と時点 | Execution＋Source＋測定項目＋観測時点 |
| 観測時点 | 値または未観測理由と時点 | Execution＋Source＋測定項目＋観測時点 |
| 記録試行 | 記録依頼と再観測の単位 | Execution＋作成側＋Attempt ID |
| 記録状態 | 実行主体が違っても同じ意味で取得できる記録を、安全に一度だけ公開する際に、「記録状態」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 対象、判定時点、情報源で識別し、不明を正常へ丸めない |
| 衝突した完成記録 | 実行主体が違っても同じ意味で取得できる記録を、安全に一度だけ公開する際に、「衝突した完成記録」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 回復先 | 実行主体が違っても同じ意味で取得できる記録を、安全に一度だけ公開する際に、「回復先」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 検証済みの対象と範囲へ結び、表示名だけで同一視しない |
| 公開結果 | 記録が完成・衝突・回復必要のどれかを利用側へ返す結果 | Execution IDとRecord Attempt IDで識別する |

```text
[O: 実行]
      ├── 持つ ──────▶ [O: 観測]
      │                     ├── 取得元へ結ぶ ─▶ [O: 情報源]
      │                     └── 時点を持つ ───▶ [O: 観測時点]
      │
      └── 記録を試みる ─▶ [O: 記録試行]
                                │ 状態を返す
                                ▼
                          [O: 記録状態]
                                ├── 衝突時に結ぶ ──▶ [O: 衝突した完成記録]
                                ├── 結果不明時に結ぶ ▶ [O: 回復先]
                                └── 利用側へ返す ───▶ [O: 公開結果]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000022 | 実行 | 実行 | Same | 記録対象となるExecutionを保持する |
| IA-000022 | 情報源 | 情報源 | Same | 観測の由来を保持する |
| IA-000022 | 観測 | 観測 | Same | 値とObserved Atを持つ観測を保持する |
| ― | 観測時点 | ― | Not Applicable | 観測のIdentityを構成する時点として保持し、独立Objectへ変換しない |
| IA-000022 | 記録試行 | 記録試行 | Same | 保存要求と完成結果を区別する |
| ― | 記録状態 | ― | Not Applicable | 公開結果の状態として保持し、独立Objectへ変換しない |
| ― | 衝突した完成記録 | ― | Not Applicable | 公開結果から完成記録へ結ぶ関係として保持し、独立Objectへ変換しない |
| ― | 回復先 | ― | Not Applicable | 公開結果から回復先へ結ぶ関係として保持し、独立Objectへ変換しない |
| IA-000022 | 公開結果 | 公開結果 | Same | 利用側へ返す中心結果を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 準備中（prepared）／公開中（publishing）／記録済み（recorded）／未記録（not_recorded）／結果不明（unknown） |
| 可視性 | 「保存要求後に結果確認が途切れる」では、同じ識別情報で再観測し、結果不明を保つために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 実行→情報源→観測→観測時点→記録試行→記録状態→衝突した完成記録→回復先。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | Execution・Source・Observation・Record Attemptを記録する責任と、公開結果を返す責任を分ける。 |
| 時間的な意味 | 準備中（prepared）／公開中（publishing）／記録済み（recorded）／未記録（not_recorded）／結果不明（unknown）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「実行主体が違っても同じ意味で取得できる記録を、安全に一度だけ公開する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 実行基盤・TypeScriptアプリへ実行記録を組み込む担当者が「AIまたはToolの観測可能な実行段階が確定し、事実を後から比較できる形で残す時」に「記録の成否と不明状態を見分け、重複記録や別実行の上書きを起こさず次の処置を選べる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 検証根拠を正式採用する主体が記録の正式採用を、運用責任者が衝突時の回復を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 未記録と推定して再発行し、重複または上書きを起こす |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は実行基盤・TypeScriptアプリへ実行記録を組み込む担当者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「保存要求後に結果確認が途切れる」に、未記録と推定して再発行し、重複または上書きを起こすことを避け、同じ識別情報で再観測し、結果不明を保つことを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000004: 実行環境の導入・運用者が「実行事実を出所と観測時点付きで比較する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 実行基盤・TypeScriptアプリへ実行記録を組み込む担当者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行記録Writerと不変Storeは存在するが、Canonical設計の根拠ではなく後続Reality Auditの照合対象とする。 |
| 採用境界 | 現行名や状態値はUXから必要性を導けた範囲だけ採用し、実装都合の項目を逆流させない。 |

## 5. IA処置

[IA-000022](../../Definitions/IA-000022/ia_definition.md)として新設する。読取り・評価を所有するIA-000004へ統合せず、作成側の試行、公開状態、衝突および再観測を独立した情報責務として保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「記録の成否と不明状態を見分け、重複記録や別実行の上書きを起こさず次の処置を選べる」の成立条件、「未記録と推定して再発行し、重複または上書きを起こす」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
