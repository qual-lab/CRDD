# IA分析: 実行事実を安全に記録して結果を確かめる

成果物種別: IA分析
分析対象: [UX-000032](../../../02_UX/Definitions/UX-000032/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行基盤・TypeScriptアプリの組込み担当者 |
| 場面 | 観測した実行事実を後から比較できる形で残す時 |
| 目的 | 同じ意味で取得できる記録を安全に一度だけ公開する |
| 得たい結果 | 記録済み・未記録・結果不明を見分け、重複や上書きなく次の処置を選べる |
| 重要場面 | 保存要求後に結果確認が途切れる時 |
| 避ける失敗 | 未記録と推定して再発行し、重複または別実行の上書きを起こす |
| 守る品質 | 同じ識別情報で再観測し、結果不明を保つ |

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 実行 | 事実が属する一回の実行 | 実行識別子で記録と取得を結ぶ |
| 情報源 | どの実行基盤・アプリが観測したか | 情報源の識別子と改訂版を実行へ結ぶ |
| 観測 | 値、未観測理由、観測時点 | 実行・情報源・測定項目へ結ぶ |
| 記録試行 | 一回の記録依頼と再観測の単位 | 実行と作成側が発行した試行識別子で結ぶ |
| 公開結果 | 記録済み、未記録、結果不明 | 記録試行と完成記録または回復先へ結ぶ |

```text
[O: 実行] --観測元--> [O: 情報源]
[O: 実行] --持つ--> [O: 観測]
[O: 実行] --記録を試みる--> [O: 記録試行]
[O: 記録試行] --返す--> [O: 公開結果]
[O: 公開結果] --確認する--> [O: 完成記録／回復先]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 準備中（prepared）／公開中（publishing）／記録済み（recorded）／未記録（not_recorded）／結果不明（unknown） |
| 可視性 | 作成側には記録状態、同じ実行・情報源・試行、衝突先または再観測先を返す。秘密情報や許可外内容は表示・診断へ複製しない。 |
| 導線 | 観測→記録依頼→結果。結果不明では再発行せず、同じ実行と試行→再観測→確定状態へ進む。 |
| 責任 | 作成側は許可された最小事実と識別情報を渡す。システムは検査、不変公開、衝突再読取り、状態返却および終了後資源回収を担う。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行記録Writerと不変Storeは存在するが、Canonical設計の根拠ではなく後続Reality Auditの照合対象とする。 |
| 採用境界 | 現行名や状態値はUXから必要性を導けた範囲だけ採用し、実装都合の項目を逆流させない。 |

## 5. IA処置

[IA-000022](../../Definitions/IA-000022/ia_definition.md)として新設する。読取り・評価を所有するIA-000004へ統合せず、作成側の試行、公開状態、衝突および再観測を独立した情報責務として保持する。
