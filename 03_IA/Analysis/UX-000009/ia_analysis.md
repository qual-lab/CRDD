# IA分析: プロジェクトの現在地を根拠と不完全性付きで理解する

成果物種別: IA分析
分析対象: [UX-000009](../../../02_UX/Definitions/UX-000009/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | プロジェクト状況を確認する時 |
| 目的 | プロジェクトの現在地を根拠と不完全性付きで理解する |
| 得たい結果 | 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる |
| 重要場面 | 現在の表示を信じる直前 |
| 避ける失敗 | 欠測や古い値を完全な現在値と誤認する |
| 守る品質 | 根拠、不完全性、観測時点を同時に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | プロジェクト（Project）、プロジェクト項目、読取り投影（Projection）、情報源（Source）、改訂版（Revision）、観測時点（Observed At）、対象範囲（Coverage）、競合 | 対象を同一視せず、「プロジェクト→現在投影→不足・競合→情報源→次の判断」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | Project→現在投影→不足・競合→情報源（Source）→次の判断 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: プロジェクト（Project）]
[O: プロジェクト（Project）] --根拠と次の行動を辿る--> [O: 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | complete／partial／開示制限（restricted）／stale／競合あり（conflicting）／不明（unknown） |
| 可視性 | 現在の表示を信じる直前では、根拠、不完全性、観測時点を同時に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | Project→現在投影→不足・競合→情報源（Source）→次の判断。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「プロジェクトの現在地を根拠と不完全性付きで理解する」ために必要な判断を行う。システムは「物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる」を支える対象・状態・根拠を示し、「欠測や古い値を完全な現在値と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト運営（project-operation）とCROSの設計に候補がある。読取り投影（Projection）を正本へ昇格しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |
