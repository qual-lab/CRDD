# IA分析: 必要な情報を渡し結果を同じ仕事へ戻す

成果物種別: IA分析
分析対象: [UX-000019](../../../02_UX/Definitions/UX-000019/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 外部へ渡す情報の所有者 |
| 場面 | 別Agentやツールへ仕事を渡す時、または結果を受け取る時 |
| 目的 | 必要な情報だけを出所付きで渡す |
| 得たい結果 | 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる |
| 重要場面 | 外部境界へ情報を出す直前 |
| 避ける失敗 | 全量投入・秘密情報混入・古い仮説の現在値化 |
| 守る品質 | 情報源・改訂版・選択理由を保持する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 仕事用情報一式 | 選択した仕事用情報一式 | 情報一式の識別子（Package ID） |
| 情報源 | 出所と改訂版（Revision） | 情報源の識別子（Source Identity）＋改訂版（Revision） |
| 作業 | 受け渡し先の仕事 | 作業識別子（Task Identity） |
| 結果 | Taskから戻る成果と状態 | Taskへ結合 |
| 選択理由 | 情報を仕事用情報一式へ含めた理由 | Package Itemへ結合 |
| 引き渡し | 役割間の移送 | 情報源（Source）／Target Role |
| 判断 | 結果とともに元の仕事へ戻す判断・未解決事項 | 責任者（Owner）と決定権限（判断を確定する権限主体）へ結ぶ |


```text
[O: 情報源]
      │ 選択される
      ▼
[O: 仕事用情報一式] ◀──引き渡す── [O: 引き渡し]
      │ 作業を支える
      ▼
[O: 作業]
      │ 生む
      ▼
[O: 結果]          [O: 選択理由] ──含めた理由を示す──▶ [O: 仕事用情報一式]
      │ 判断とともに戻す
      ▼
[O: 判断]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000014 | 仕事用情報一式 | 仕事用情報一式 | Same | 委譲に必要なContextを一式として保持する |
| IA-000014 | 情報源 | 情報源参照 | Rename | 本文複製ではなくSource Referenceとして表示を明確にする |
| IA-000014 | 作業 | 作業 | Same | 引き渡す仕事の同一性を保持する |
| IA-000014 | 結果 | 結果 | Same | 元の仕事へ戻すResultとして保持する |
| IA-000014 | 選択理由 | 選択理由 | Same | 委譲先や方法を選んだ理由を保持する |
| IA-000014 | 引き渡し | 引き渡し | Same | 境界をまたぐ情報と責任の移動単位を保持する |
| IA-000014 | 判断 | 判断 | Same | 結果や候補の採否を元の権限へ戻す |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 準備済み（prepared）／送信済み（sent）／受領済み（received）／返却済み（returned）／停止（blocked） |
| 可視性 | 「外部境界へ情報を出す直前」では、情報源・改訂版・選択理由を保持するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 仕事用情報一式→情報源→作業→結果→根拠→引き渡し→判断。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 送信元の仕事用情報一式・情報源参照・引渡しを作る責任がContext Package・Source Reference・Handoffを作成し、実行担当がTask Resultを返す。 |
| 時間的な意味 | 準備済み（prepared）／送信済み（sent）／受領済み（received）／返却済み（returned）／停止（blocked）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「必要な情報だけを出所付きで渡す」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 外部へ渡す情報の所有者が「別Agentやツールへ仕事を渡す時、または結果を受け取る時」に「必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 委譲元のHuman／委譲元のAgent決定権限が送信範囲・委譲先・結果採用を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 全量投入・秘密情報混入・古い仮説の現在値化 |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は外部へ渡す情報の所有者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「外部境界へ情報を出す直前」に、全量投入・秘密情報混入・古い仮説の現在値化ことを避け、情報源・改訂版・選択理由を保持することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000017: 外部へ渡す情報の所有者が「必要な情報だけを出所付きで渡す」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000024: プロジェクト運営者／PMが「境界を越えた結果を同じタスクへ受け取る」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000027: 外部へ渡す情報の所有者が「送信範囲を理解し帰還結果を候補として扱う」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 外部へ渡す情報の所有者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | CROSの引き渡し（handoff）設計と実行編成（Coordinator）の搬送がある。会話全文や未選択情報（Context）を無条件に複製しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000014](../../Definitions/IA-000014/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる」の成立条件、「全量投入・秘密情報混入・古い仮説の現在値化」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
