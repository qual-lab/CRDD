# IA分析: 必要な情報を渡し結果を同じ仕事へ戻す

成果物種別: IA分析
分析対象: [UX-000019](../../../02_UX/Definitions/UX-000019/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 外部へ渡す情報の所有者 |
| 場面 | 別Agentやツールへ仕事を渡す時、または結果を受け取る時 |
| 目的 | 必要な情報だけを出所付きで渡す |
| 得たい結果 | 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる |
| 重要場面 | 外部境界へ情報を出す直前 |
| 避ける失敗 | 全量投入・秘密情報混入・古い仮説の現在値化 |
| 守る品質 | 情報源・改訂版・選択理由を保持する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 仕事用情報一式（Context Package）、情報源（Source）、改訂版（Revision）、選択理由（Selection Reason）、作業（Task）、引き渡し（Handoff）、結果（Result）、判断（Decision） | 対象を同一視せず、「情報源→選択→仕事用情報一式（Context Package）→Task→結果（Result）→元の仕事」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 情報源→選択→仕事用情報一式（Context Package）→Task→結果（Result）→元の仕事 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 外部へ渡す情報の所有者の判断] --確認する--> [O: 仕事用情報一式（Context Package）]
[O: 仕事用情報一式（Context Package）] --根拠と次の行動を辿る--> [O: 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 準備済み（prepared）／送信済み（sent）／受領済み（received）／返却済み（returned）／停止（blocked） |
| 可視性 | 外部境界へ情報を出す直前では、情報源・改訂版・選択理由を保持するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 情報源→選択→仕事用情報一式（Context Package）→Task→結果（Result）→元の仕事。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 外部へ渡す情報の所有者は「必要な情報だけを出所付きで渡す」ために必要な判断を行う。システムは「必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる」を支える対象・状態・根拠を示し、「全量投入・秘密情報混入・古い仮説の現在値化」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | CROSの引き渡し（handoff）設計と実行編成（Coordinator）の搬送がある。会話全文や未選択情報（Context）を無条件に複製しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |
