# IA分析: AIモデル構成を安全に更新・選択する

成果物種別: IA分析
分析対象: [UX-000018](../../../02_UX/Definitions/UX-000018/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 利用モデルやAI提供元条件を変更する時 |
| 目的 | AIモデル選択を検証可能な構成として更新する |
| 得たい結果 | 新モデルへ追随してもコード改修を繰り返さずに済む |
| 重要場面 | AI提供元で実行する前のモデル確定 |
| 避ける失敗 | 未知または非対応のモデルを実行可能と表示する |
| 守る品質 | 構成変更を検証し実効選択を観測可能にする |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| AIモデル | 利用候補のAIモデル | Provider＋Model ID |
| モデル構成 | 許可候補と制約 | 構成の改訂版（Config Revision） |
| 利用可否 | 現在利用可能か | Model＋Environment |
| 選択結果 | 今回の実効選択 | Task＋Model |
| 選択理由 | AIモデル選択を検証可能な構成として更新する際に、「選択理由」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 支える対象、情報源、改訂版または観測時点へ結ぶ |
| 再選定条件 | 再選定する条件 | 選択結果（Selection）へ結合 |
| 作業上の役割 | AIモデルを選ぶ時のExecutor／Reviewer等の役割 | Task Roleで識別する |

```text
[O: モデル構成]
      ├── 候補を宣言する ──▶ [O: AIモデル] ──現在状態を持つ──▶ [O: 利用可否]
      │                              ▲
      │                              │ 選ぶ
      └── 選択条件を与える ─▶ [O: 作業上の役割] ──選択を制約する──▶ [O: 選択結果]
                                                                              ▲
                              [O: 選択理由] ──説明する──────────────┤
                              [O: 再選定条件] ──再選定を発火する────┘
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000013 | AIモデル | AIモデル | Same | 選択対象となるModelを保持する |
| IA-000013 | モデル構成 | 構成 | Rename | コード外で更新できるConfigurationとして保持する |
| IA-000013 | 利用可否 | 利用可否 | Same | 現在利用できるかを構成と分ける |
| IA-000013 | 選択結果 | 選択結果 | Same | 選んだModelを表す判断結果を保持する |
| ― | 選択理由 | ― | Not Applicable | IA-000013の選択結果とAIモデルを結ぶ理由として保持し、独立Objectへ変換しない |
| IA-000013 | 再選定条件 | 再選定条件 | Same | Availability等が変わった時の切替条件を保持する |
| IA-000013 | 作業上の役割 | 作業上の役割 | Same | Executor／Reviewer等の選択文脈を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 有効（valid）／無効（invalid）／利用可能（available）／利用不能（unavailable）／選択済み（selected） |
| 可視性 | 「AI提供元で実行する前のモデル確定」では、構成変更を検証し実効選択を観測可能にするために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | AIモデル→モデル構成→利用可否→選択結果→選択理由→再選定条件。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | AIモデル構成を管理する主体がModel・Configuration・Task Roleを保ち、利用可否と選択結果を記録する責任がAvailabilityとSelectionを記録する。 |
| 時間的な意味 | 有効（valid）／無効（invalid）／利用可能（available）／利用不能（unavailable）／選択済み（selected）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「AIモデル選択を検証可能な構成として更新する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 実行環境の導入・運用者が「利用モデルやAI提供元条件を変更する時」に「新モデルへ追随してもコード改修を繰り返さずに済む」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 導入環境の信頼方針を決める主体が許可Model集合を、許可範囲内でモデルを選択・再選定する責任が許可範囲内の選択・再選定を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 未知または非対応のモデルを実行可能と表示する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は実行環境の導入・運用者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「AI提供元で実行する前のモデル確定」に、未知または非対応のモデルを実行可能と表示することを避け、構成変更を検証し実効選択を観測可能にすることを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000016: 実行環境の導入・運用者が「AIモデル選択を検証可能な構成として更新する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 実行環境の導入・運用者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行編成（Coordinator）に選択実装がある。コード上のモデル名や暗黙の代替選択（fallback）を正本にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000013](../../Definitions/IA-000013/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「新モデルへ追随してもコード改修を繰り返さずに済む」の成立条件、「未知または非対応のモデルを実行可能と表示する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
