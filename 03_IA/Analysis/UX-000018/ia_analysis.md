# IA分析: AIモデル構成を安全に更新・選択する

成果物種別: IA分析
分析対象: [UX-000018](../../../02_UX/Definitions/UX-000018/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 利用モデルやAI提供元条件を変更する時 |
| 目的 | AIモデル選択を検証可能な構成として更新する |
| 得たい結果 | 新モデルへ追随してもコード改修を繰り返さずに済む |
| 重要場面 | AI提供元で実行する前のモデル確定 |
| 避ける失敗 | 未知または非対応のモデルを実行可能と表示する |
| 守る品質 | 構成変更を検証し実効選択を観測可能にする |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | AIモデル（Model）、構成（Configuration）、作業上の役割（Task Role）、利用可否（Availability）、選択結果（Selection）、Reason、再選定条件（Fallback Condition） | 対象を同一視せず、「設定→検証→利用可能候補→選択→理由・再選定条件」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 設定→検証→利用可能候補→選択→理由・再選定条件 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 実行環境の導入・運用者の判断] --確認する--> [O: AIモデル（Model）]
[O: AIモデル（Model）] --根拠と次の行動を辿る--> [O: 新モデルへ追随してもコード改修を繰り返さずに済む]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 有効（valid）／無効（invalid）／利用可能（available）／利用不能（unavailable）／選択済み（selected） |
| 可視性 | AI提供元で実行する前のモデル確定では、構成変更を検証し実効選択を観測可能にするために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 設定→検証→利用可能候補→選択→理由・再選定条件。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行環境の導入・運用者は「AIモデル選択を検証可能な構成として更新する」ために必要な判断を行う。システムは「新モデルへ追随してもコード改修を繰り返さずに済む」を支える対象・状態・根拠を示し、「未知または非対応のモデルを実行可能と表示する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行編成（Coordinator）に選択実装がある。コード上のモデル名や暗黙の代替選択（fallback）を正本にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000013](../../Definitions/IA-000013/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
