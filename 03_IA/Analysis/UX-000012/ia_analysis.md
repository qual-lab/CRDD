# IA分析: 入口を変えても同じ仕事を続ける

成果物種別: IA分析
分析対象: [UX-000012](../../../02_UX/Definitions/UX-000012/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 開発者 |
| 場面 | ローカルMCPの通信方式を選ぶ時 |
| 目的 | 通信方式を変えても同じ公開契約・入力・権限判断で操作する |
| 得たい結果 | stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる |
| 重要場面 | 入口を切り替えて同じ仕事を開始・継続する場面 |
| 避ける失敗 | 通信方式によって入力・権限判断・状態・結果の意味が変わる |
| 守る品質 | 公開契約・入力・権限判断・状態・結果を通信方式間で一致させる |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 公開要求、公開契約、通信手段（Transport）、作用発行状態、結果 | 対象を同一視せず、「入口→同じ公開要求→Runtime→同じ結果」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 入口→同じ公開要求→Runtime→同じ結果 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 開発者の判断] --確認する--> [O: 公開要求]
[O: 公開要求] --根拠と次の行動を辿る--> [O: stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 受付前／受付済み／作用前失敗／作用後失敗／結果あり |
| 可視性 | 入口を切り替えて同じ仕事を開始・継続する場面では、公開契約・入力・権限判断・状態・結果を通信方式間で一致させるために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 入口→同じ公開要求→Runtime→同じ結果。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 開発者は「通信方式を変えても同じ公開契約・入力・権限判断で操作する」ために必要な判断を行う。システムは「stdio MCPとlocalhost HTTPのどちらでも、同じ入力・権限・状態・結果で仕事を続けられる」を支える対象・状態・根拠を示し、「通信方式によって入力・権限判断・状態・結果の意味が変わる」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | MCP stdioとlocalhost HTTPは通信方式の接続部（Transport adapter）である。通信エラーと業務結果を分ける。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000008](../../Definitions/IA-000008/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
