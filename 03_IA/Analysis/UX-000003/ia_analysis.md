# IA分析: 委任中の状態と判断要否を理解する

成果物種別: IA分析
分析対象: [UX-000003](../../../02_UX/Definitions/UX-000003/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 委任した仕事の応答を待つ時 |
| 目的 | 現在の実行状態と必要な判断を確認する |
| 得たい結果 | 内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる |
| 重要場面 | 応答がなく待機か停止かを判断する場面 |
| 避ける失敗 | 古い観測や一律表示を進捗・完了と誤認する |
| 守る品質 | 観測時点・停止理由・必要な判断を行動可能に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 作業 | 実行可能な仕事単位 | Objectiveと作業識別子（Task Identity） |
| 試行 | 一回ごとの実行 | 依頼識別子と試行番号で識別する |
| 依頼 | 再開・追跡する元の依頼 | 依頼識別子（Request Identity）で識別する |
| 決定権限 | 誰が実行継続・停止・受入を決められるか | 対象・主体・有効時点へ結ぶ |
| 作業状態 | 実行可能な仕事単位 | Objectiveと作業識別子（Task Identity） |
| AI提供元状態 | 現在の実行状態と必要な判断を確認する際に、「AI提供元状態」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 対象、判定時点、情報源で識別し、不明を正常へ丸めない |
| 判断 | 現在の実行状態と必要な判断を確認する際に、「判断」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 元の依頼・対象・改訂版へ結び、別の結果と混同しない |
| 入力 | 現在の実行状態と必要な判断を確認する際に、「入力」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 取消 | 現在の実行状態と必要な判断を確認する際に、「取消」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 所有する文脈、安定した識別情報、関連対象で同じものと別のものを区別する |
| 次の行動 | 現在許される行動 | 状態と権限（Authority）から導く |


```text
                        [O: AI提供元状態]
                               │ 実行可能性へ影響する
                               ▼
[O: 依頼] ──開始する──▶ [O: 試行] ──実行する──▶ [O: 作業]

[O: 入力] ──再開を支える──▶ [O: 作業状態] ──次の行動を制約する──▶ [O: 次の行動]
                               ▲    ▲                                  ▲
                               │    │                                  │ 選択する
                    停止させる │    │                              [O: 判断]
                           [O: 取消]

[O: 決定権限] ──選択を許す──▶ [O: 次の行動]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000002 | 作業 | 作業 | Same | 状態を持つ実行対象を保持する |
| IA-000003 | 試行 | 試行 | Same | 一回ごとの実行を保持する |
| IA-000003 | 依頼 | 依頼 | Same | 同じ依頼を再開・追跡する識別単位を保持する |
| IA-000002 | 決定権限 | 決定権限 | Same | 委任時と実行中の判断主体を保持する |
| ― | 作業状態 | ― | Not Applicable | IA-000002とIA-000003の「状態・可視性・時間的な意味」節へ状態として保持し、作業や試行そのものへ変換しない |
| ― | AI提供元状態 | ― | Not Applicable | IA-000002の「状態・可視性・時間的な意味」節へ、AI提供元状態を独立Objectではなく状態・可視条件として保持する |
| ― | 判断 | ― | Not Applicable | IA-000002の決定権限が選ぶ行動として関係に保持し、権限そのものへ変換しない |
| ― | 入力 | ― | Not Applicable | IA-000003の依頼へ渡される内容として関係に保持し、依頼そのものへ変換しない |
| ― | 取消 | ― | Not Applicable | IA-000002の「情報の優先度・まとまり・見つけ方・責任」節へ、取消を独立Objectではなく次行動への導線として保持する |
| IA-000003 | 次の行動 | 次の行動 | Same | 観測結果に基づく安全な選択を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 開始可能（ready）／実行中（running）／入力・判断待ち（waiting）／停止（blocked）／完了（completed）／失敗（failed） |
| 可視性 | 「応答がなく待機か停止かを判断する場面」では、観測時点・停止理由・必要な判断を行動可能に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 作業状態→AI提供元状態→判断→入力→取消→次の行動。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMが目的・判断・入力を保ち、実行状態を記録する責任が作業状態・取消・回復状態を提供する。 |
| 時間的な意味 | 開始可能（ready）／実行中（running）／入力・判断待ち（waiting）／停止（blocked）／完了（completed）／失敗（failed）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「現在の実行状態と必要な判断を確認する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | プロジェクト運営者／PMが「委任した仕事の応答を待つ時」に「内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 人間の決定権限者が委任範囲・取消・候補結果の採否を確定する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 古い観測や一律表示を進捗・完了と誤認する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はプロジェクト運営者／PMを代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「応答がなく待機か停止かを判断する場面」に、古い観測や一律表示を進捗・完了と誤認することを避け、観測時点・停止理由・必要な判断を行動可能に示すことを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000002: プロジェクト運営者／PMが「複数AIへ任せる範囲と権限を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000003: プロジェクト運営者／PMが「目的と受入条件で節目を委ねる」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | プロジェクト運営者／PMを代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト実行状態の管理（Project Runtime）が提供する状態投影を利用できる。内部の待ち行列（Queue）状態は利用者状態の正本にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000002](../../Definitions/IA-000002/ia_definition.md)および[IA-000003](../../Definitions/IA-000003/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる」の成立条件、「古い観測や一律表示を進捗・完了と誤認する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
