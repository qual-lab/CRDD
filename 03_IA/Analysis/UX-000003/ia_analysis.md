# IA分析: 委任中の状態と判断要否を理解する

成果物種別: IA分析
分析対象: [UX-000003](../../../02_UX/Definitions/UX-000003/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 委任した仕事の応答を待つ時 |
| 目的 | 現在の実行状態と必要な判断を確認する |
| 得たい結果 | 内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる |
| 重要場面 | 応答がなく待機か停止かを判断する場面 |
| 避ける失敗 | 古い観測や一律表示を進捗・完了と誤認する |
| 守る品質 | 観測時点・停止理由・必要な判断を行動可能に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 作業（Task）、実行主体、現在状態、判断、入力、次の行動 | 対象を同一視せず、「Task→現在状態→判断要否→待機・入力・取消・回復」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | Task→現在状態→判断要否→待機・入力・取消・回復 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: 作業（Task）]
[O: 作業（Task）] --根拠と次の行動を辿る--> [O: 内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 開始可能（ready）／実行中（running）／入力・判断待ち（waiting）／停止（blocked）／完了（completed）／失敗（failed） |
| 可視性 | 応答がなく待機か停止かを判断する場面では、観測時点・停止理由・必要な判断を行動可能に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | Task→現在状態→判断要否→待機・入力・取消・回復。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「現在の実行状態と必要な判断を確認する」ために必要な判断を行う。システムは「内部ログを読まず、実行中・待機・停止と現在必要な判断を理解できる」を支える対象・状態・根拠を示し、「古い観測や一律表示を進捗・完了と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト実行状態の管理（Project Runtime）が提供する状態投影を利用できる。内部の待ち行列（Queue）状態は利用者状態の正本にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |
