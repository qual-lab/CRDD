# IA分析: 故障した境界と影響範囲を理解する

成果物種別: IA分析
分析対象: [UX-000008](../../../02_UX/Definitions/UX-000008/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | AI実行環境の導入または利用が止まった時 |
| 目的 | 故障した境界と影響する能力を特定する |
| 得たい結果 | AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる |
| 重要場面 | 一つの失敗を全体障害と判断する直前 |
| 避ける失敗 | 一律の失敗表示で無関係な能力まで停止する |
| 守る品質 | 失敗した場所・影響範囲・利用可能性を分ける |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 実行基盤、認証、起動、取消、結果取得、回復、利用可能能力 | 対象を同一視せず、「故障→境界→影響する能力→継続可能範囲→回復」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 故障→境界→影響する能力→継続可能範囲→回復 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 実行環境の導入・運用者の判断] --確認する--> [O: 実行基盤]
[O: 実行基盤] --根拠と次の行動を辿る--> [O: AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 各境界の利用可能（available）／停止（blocked）／不明（unknown）。全体停止と分ける |
| 可視性 | 一つの失敗を全体障害と判断する直前では、失敗した場所・影響範囲・利用可能性を分けるために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 故障→境界→影響する能力→継続可能範囲→回復。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行環境の導入・運用者は「故障した境界と影響する能力を特定する」ために必要な判断を行う。システムは「AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる」を支える対象・状態・根拠を示し、「一律の失敗表示で無関係な能力まで停止する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | AI提供元の接続部（Provider adapter）とOS境界の共通部品（platform-access）が境界を分離。Process内部状態は診断時だけ辿る。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000020](../../Definitions/IA-000020/ia_definition.md)へ接続する。依頼単位の実行・回復ではなく、実行基盤の境界ごとの故障と利用可能能力を独立して判断するため、IA-000003へ統合しない。試作上の理解しやすさは未確認として下流へ渡す。
