# IA分析: 公式の識別と保証を混同せず見分ける

成果物種別: IA分析
分析対象: [UX-000031](../../../02_UX/Definitions/UX-000031/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD閲覧者 |
| 場面 | 公式らしい入口や視覚素材を見つけた時 |
| 目的 | 識別表示と保証の根拠を分けて確認する |
| 得たい結果 | 見た目だけを信頼根拠にせず適切な入口を選べる |
| 重要場面 | 公式表示を信頼判断へ用いる直前 |
| 避ける失敗 | アイコンや見た目を署名・準拠・品質保証と誤認する |
| 守る品質 | 識別表示と検証可能な信頼根拠を別に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 公式識別（Official Identity）、配布者（Publisher）、署名（Signature）、準拠（Conformance）、品質主張（Quality Claim） | 対象を同一視せず、「公式表示→配布者（Publisher）→完全性→準拠→品質主張→利用判断」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 公式表示→配布者（Publisher）→完全性→準拠→品質主張→利用判断 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: CRDD閲覧者の判断] --確認する--> [O: 公式識別（Official Identity）]
[O: 公式識別（Official Identity）] --根拠と次の行動を辿る--> [O: 見た目だけを信頼根拠にせず適切な入口を選べる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 識別済み（identified）／確認済み（verified）／信頼済み（trusted）／品質確認済み（quality_assured）を別軸にする |
| 可視性 | 公式表示を信頼判断へ用いる直前では、識別表示と検証可能な信頼根拠を別に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 公式表示→配布者（Publisher）→完全性→準拠→品質主張→利用判断。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | CRDD閲覧者は「識別表示と保証の根拠を分けて確認する」ために必要な判断を行う。システムは「見た目だけを信頼根拠にせず適切な入口を選べる」を支える対象・状態・根拠を示し、「アイコンや見た目を署名・準拠・品質保証と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 署名・公開文書が根拠を持つ。公式表示だけで全保証を成立させない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000015](../../Definitions/IA-000015/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
