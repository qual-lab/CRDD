# IA分析: Meeting内容を候補化し採否を判断する

成果物種別: IA分析
分析対象: [UX-000014](../../../02_UX/Definitions/UX-000014/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | Meeting後に決定・Topic・Actionを整理する時 |
| 目的 | 会議の内容を候補として整理し正本へつなぐ |
| 得たい結果 | 会話と採用判断を混同せず仕事を継続できる |
| 重要場面 | 候補を採用または却下する場面 |
| 避ける失敗 | 会議記録が自動的に正本へ昇格する |
| 守る品質 | 候補・判断・反映結果を区別する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 会議（Meeting）、会議項目（Meeting Item）、候補（Candidate）、論点（Topic）、関係（Relation）、判断（Decision）、責任者（Owner） | 対象を同一視せず、「Meeting→Item→候補→既存Topic比較→採否→所有正本」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | Meeting→Item→候補→既存Topic比較→採否→所有正本 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: 会議（Meeting）]
[O: 会議（Meeting）] --根拠と次の行動を辿る--> [O: 会話と採用判断を混同せず仕事を継続できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 観測済み（observed）／候補（candidate）／採用（adopted）／却下（rejected）。会話と正本を分ける |
| 可視性 | 候補を採用または却下する場面では、候補・判断・反映結果を区別するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | Meeting→Item→候補→既存Topic比較→採否→所有正本。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「会議の内容を候補として整理し正本へつなぐ」ために必要な判断を行う。システムは「会話と採用判断を混同せず仕事を継続できる」を支える対象・状態・根拠を示し、「会議記録が自動的に正本へ昇格する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト運営（project-operation）設計に作成から終了までの流れ（Lifecycle）がある。媒体名で分類せず目的と継続性で分類する。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000010](../../Definitions/IA-000010/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
