# IA分析: プロジェクト・リポジトリ・基点フォルダを区別して対象を選ぶ

成果物種別: IA分析
分析対象: [UX-000011](../../../02_UX/Definitions/UX-000011/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 参照または操作対象を選ぶ時 |
| 目的 | プロジェクト・リポジトリ・基点フォルダを区別して対象を確認する |
| 得たい結果 | 論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる |
| 重要場面 | 外部作用（Effect）対象を確定する直前 |
| 避ける失敗 | 同名や近いパスを同じ対象と誤認する |
| 守る品質 | 各識別情報と物理基点フォルダの結合を明示する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | プロジェクト（Project）、リポジトリ（Repository）、リポジトリの基点フォルダ（Repository Root）、結合情報（Binding） | 対象を同一視せず、「Project→Repository→Binding→検証済みRoot」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | Project→Repository→Binding→検証済みRoot | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: プロジェクト（Project）]
[O: プロジェクト（Project）] --根拠と次の行動を辿る--> [O: 論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 確認済み（verified）／未確認（unverified）／曖昧（ambiguous）／利用不能（unavailable） |
| 可視性 | 外部作用（Effect）対象を確定する直前では、各識別情報と物理基点フォルダの結合を明示するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | Project→Repository→Binding→検証済みRoot。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「プロジェクト・リポジトリ・基点フォルダを区別して対象を確認する」ために必要な判断を行う。システムは「論理プロジェクトを一つに見ながら、参照・実行・回復の対象リポジトリと基点フォルダを取り違えずに選べる」を支える対象・状態・根拠を示し、「同名や近いパスを同じ対象と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | リポジトリの構成宣言（repository manifest）と履歴管理（Version Control）の境界が識別を支える。Path文字列だけを権限（Authority）にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |
