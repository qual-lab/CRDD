# IA分析: リポジトリ単独で日常作業を続ける

成果物種別: IA分析
分析対象: [UX-000010](../../../02_UX/Definitions/UX-000010/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 開発者 |
| 場面 | リポジトリで作業を始める時 |
| 目的 | 現在リポジトリだけで日常作業を完結する |
| 得たい結果 | 横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる |
| 重要場面 | 横断利用へ切り替える判断 |
| 避ける失敗 | CROS未設定で手元作業まで止まる |
| 守る品質 | 手元を既定にし横断を任意に保つ |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 手元の情報 | 現在Repositoryが所有する正本 | 検証済みリポジトリの基点フォルダ（Repository Root） |
| 日常作業 | 現在リポジトリで完結する作業 | 対象Repositoryへ結ぶ |
| 履歴管理能力 | 履歴を扱う差替可能な能力 | 接続口（Port）／利用能力（Capability）で識別 |
| リポジトリ横断情報源 | 手元の情報だけでは足りない時に、許可された別Repositoryの情報へ進むための情報源 | 情報源Identityと許可範囲で識別する |

```text
[O: 手元の情報]
      │ 支える
      ▼
[O: 日常作業]
      ├── 必要時に利用する ───────▶ [O: 履歴管理能力]
      └── 手元で不足する時だけ参照する ─▶ [O: リポジトリ横断情報源]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000007 | 手元の情報 | 手元の情報 | Same | Repository内で直接利用できるContextを保持する |
| IA-000007 | 日常作業 | 手元の作業 | Rename | Repository内で完結する作業として保持する |
| IA-000007 | 履歴管理能力 | 履歴管理能力 | Same | Git等へ交換可能な履歴境界として保持する |
| IA-000007 | リポジトリ横断情報源 | リポジトリ横断情報源 | Same | 手元の情報で不足するときだけ参照する別情報源を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 手元で利用可能（local available）／横断情報源を利用不能（cross-source unavailable）でも継続可能 |
| 可視性 | 「横断利用へ切り替える判断」では、手元を既定にし横断を任意に保つために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 手元の情報→日常作業→履歴管理能力。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | Repository正本を管理する主体が手元の正本を保ち、許可された横断情報源を提供する責任が許可された横断情報源を提供し、履歴を運ぶ責任が履歴を運ぶ。 |
| 時間的な意味 | 手元で利用可能（local available）／横断情報源を利用不能（cross-source unavailable）でも継続可能の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「現在リポジトリだけで日常作業を完結する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 開発者が「リポジトリで作業を始める時」に「横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 利用者が横断参照の要否を選び、Repository正本を管理する主体が外部公開可能範囲を決める。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | CROS未設定で手元作業まで止まる |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は開発者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「横断利用へ切り替える判断」に、CROS未設定で手元作業まで止まることを避け、手元を既定にし横断を任意に保つことを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000008: 開発者が「現在リポジトリだけで日常作業を完結する」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000036: 開発者が「日常作業をCommit SHAや特定Git実装から切り離す」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 開発者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 全Toolはリポジトリ内で完結する経路（Repository-local）を維持する。CROSや履歴確定済み（Commit）の状態を日常作業の必須条件にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000007](../../Definitions/IA-000007/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「横断機能、Commit済み状態または特定の履歴実装を前提にせず、現在リポジトリで日常作業を開始・継続できる」の成立条件、「CROS未設定で手元作業まで止まる」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
