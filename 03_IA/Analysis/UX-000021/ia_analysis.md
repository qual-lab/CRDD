# IA分析: 切断後も同じ依頼へ戻る

成果物種別: IA分析
分析対象: [UX-000021](../../../02_UX/Definitions/UX-000021/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | プロジェクト運営者／PM |
| 場面 | 応答喪失後に再接続する時 |
| 目的 | 切断後に同じ依頼へ戻る |
| 得たい結果 | 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる |
| 重要場面 | 再実行するか判断する直前 |
| 避ける失敗 | Timeoutを未実行とみなし新規外部作用（Effect）を起こす |
| 守る品質 | 同一識別情報の照会を再実行より先に示す |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 依頼識別子（Request Identity）、試行（Attempt）、接続中の作業単位（Session）、現在有効な利用許可（Current Grant）、結果（Result）、回復義務（Recovery Obligation） | 対象を同一視せず、「再接続→同じ依頼（Request）→現在権限→状態・結果→回復義務」の順に関係付ける。回復義務の有無と回復処置の実行を同一視しない。 |
| 根拠と次の行動 | 再接続→同じ依頼（Request）→現在権限→状態・結果→回復義務 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: プロジェクト運営者／PMの判断] --確認する--> [O: 依頼識別子（Request Identity）]
[O: 依頼識別子（Request Identity）] --根拠と次の行動を辿る--> [O: 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 進行中（active）／切断（disconnected）／結果取得可能（result_available）／回復必要（recovery_required）／確定済み（settled） |
| 可視性 | 再実行するか判断する直前では、同一識別情報の照会を再実行より先に示すために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 再接続→同じ依頼（Request）→現在権限→状態・結果→回復義務。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | プロジェクト運営者／PMは「切断後に同じ依頼へ戻る」ために必要な判断を行う。システムは「応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる」を支える対象・状態・根拠を示し、「Timeoutを未実行とみなし新規外部作用（Effect）を起こす」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | プロジェクト実行状態の管理（Project Runtime）は同じ依頼の再取得を持つ。時間切れ（Timeout）から未実行を推定しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000003](../../Definitions/IA-000003/ia_definition.md)および[IA-000014](../../Definitions/IA-000014/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
