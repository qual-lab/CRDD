# IA分析: 仕事に必要な標準ツールを迷わず選ぶ

成果物種別: IA分析
分析対象: [UX-000016](../../../02_UX/Definitions/UX-000016/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 開発者 |
| 場面 | ツールで処理を始める時 |
| 目的 | 固定Commitに対応するツール／実行基盤と利用可能性を知る |
| 得たい結果 | 現在リポジトリと目的に対応する標準ツールを見つけ、利用可能性・外部作用の権限・開発実行・公式実行を区別して選べる |
| 重要場面 | 発見したツール／実行基盤を起動する直前 |
| 避ける失敗 | 版不一致・欠落実行基盤・改ざん配布目録（Manifest）を対応版と誤認する |
| 守る品質 | Commit・配布集合・配布目録（Manifest）・実行基盤の対応を検証する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 利用能力（Capability）、利用可否、実行権限（Authority）、Repository 改訂版（Revision）、配布物（Distribution）、配布目録（Manifest）、実行環境との結合（Runtime Binding） | 対象を同一視せず、「仕事→必要能力→登録Tool→配布根拠→起動」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 仕事→必要能力→登録Tool→配布根拠→起動 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 開発者の判断] --確認する--> [O: 利用能力（Capability）]
[O: 利用能力（Capability）] --根拠と次の行動を辿る--> [O: 現在リポジトリと目的に対応する標準ツールを見つけ、利用可能性・外部作用の権限・開発実行・公式実行を区別して選べる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 利用可能（available）／利用不能（unavailable）／未確認（unverified）／停止（blocked） |
| 可視性 | 発見したツール／実行基盤を起動する直前では、Commit・配布集合・配布目録（Manifest）・実行基盤の対応を検証するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 仕事→必要能力→登録Tool→配布根拠→起動。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 開発者は「固定Commitに対応するツール／実行基盤と利用可能性を知る」ために必要な判断を行う。システムは「現在リポジトリと目的に対応する標準ツールを見つけ、利用可能性・外部作用の権限・開発実行・公式実行を区別して選べる」を支える対象・状態・根拠を示し、「版不一致・欠落実行基盤・改ざん配布目録（Manifest）を対応版と誤認する」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 配布目録（package manifest）と起動処理（launcher）が実装済み。一覧表示を実行権限の発行にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000011](../../Definitions/IA-000011/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
