# IA分析: 仕事に必要な標準ツールを迷わず選ぶ

成果物種別: IA分析
分析対象: [UX-000016](../../../02_UX/Definitions/UX-000016/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 開発者 |
| 場面 | ツールで処理を始める時 |
| 目的 | 固定Commitに対応するツール／実行基盤と利用可能性を知る |
| 得たい結果 | 現在リポジトリと目的に対応する標準ツールを見つけ、利用可能性・外部作用の権限・開発実行・公式実行を区別して選べる |
| 重要場面 | 発見したツール／実行基盤を起動する直前 |
| 避ける失敗 | 版不一致・欠落実行基盤・改ざんManifestを対応版と誤認する |
| 守る品質 | Commit・配布集合・Manifest・実行基盤の対応を検証する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 利用能力 | Toolが提供する仕事上の能力 | 利用能力（Capability） ID |
| 利用可否 | 現在利用可能か | 利用能力（Capability）＋環境 |
| 決定権限 | 固定Commitに対応するツール／実行基盤と利用可能性を知る際に、「決定権限」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 主体、対象範囲、有効時点で識別する |
| リポジトリ改訂版 | 固定Commitに対応するツール／実行基盤と利用可能性を知る際に、「リポジトリ改訂版」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 安定した識別情報と所属関係で同じ対象を追跡する |
| 配布物 | 配布単位 | 配布内容の基点（Content Root） |
| 配布目録 | 配布内容と根拠 | 配布目録のハッシュ（Manifest Hash） |
| 実行環境との結合 | 配布と実行環境の結合 | 結合識別子（Binding Identity） |


```text
[O: リポジトリ改訂版]
      │ 宣言する
      ▼
[O: 利用能力] ◀──利用を許す── [O: 決定権限]
      │ 現在状態を持つ
      ▼
[O: 利用可否]

[O: 配布物]
      ├── 説明される ────▶ [O: 配布目録]
      └── 実行環境へ結ぶ ─▶ [O: 実行環境との結合]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000011 | 利用能力 | 利用能力 | Same | Repositoryで必要な仕事能力を保持する |
| IA-000011 | 利用可否 | 利用可否 | Same | 現在利用できるかを能力と分けて保持する |
| IA-000011 | 決定権限 | 実行権限 | Rename | 能力を実行できるAuthorityとして保持する |
| ― | リポジトリ改訂版 | ― | Not Applicable | IA-000011のCanonical Object表にある対応対象の「識別・関係」へ、リポジトリ改訂版を独立Objectではなく識別条件または関係として保持する |
| IA-000011 | 配布物 | 配布物 | Same | Toolを届ける単位として保持する |
| IA-000011 | 配布目録 | 配布目録 | Same | 配布物の内容とIdentityを保持する |
| IA-000011 | 実行環境との結合 | 実行環境との結合 | Same | ToolとRuntimeのBindingを保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 利用可能（available）／利用不能（unavailable）／未確認（unverified）／停止（blocked） |
| 可視性 | 「発見したツール／実行基盤を起動する直前」では、Commit・配布集合・Manifest・実行基盤の対応を検証するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 利用能力→利用可否→決定権限→リポジトリ改訂版→配布物→配布目録→実行環境との結合。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | Tool配布情報を管理する主体がCapability・Distribution・Manifestを保ち、利用可否と実行環境との結合を観測する責任がAvailabilityとBindingを観測する。 |
| 時間的な意味 | 利用可能（available）／利用不能（unavailable）／未確認（unverified）／停止（blocked）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「固定Commitに対応するツール／実行基盤と利用可能性を知る」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | 開発者が「ツールで処理を始める時」に「現在リポジトリと目的に対応する標準ツールを見つけ、利用可能性・外部作用の権限・開発実行・公式実行を区別して選べる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | Repository正本を管理する主体または導入環境の信頼方針を決める主体がTool利用と実行Authorityを許可する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 版不一致・欠落実行基盤・改ざんManifestを対応版と誤認する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項は開発者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「発見したツール／実行基盤を起動する直前」に、版不一致・欠落実行基盤・改ざんManifestを対応版と誤認することを避け、Commit・配布集合・Manifest・実行基盤の対応を検証することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000014: 開発者が「現在リポジトリで利用可能な機能を知る」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000034: 開発者が「リポジトリに対応する標準ツールを迷わず使う」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | 開発者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 配布目録（package manifest）と起動処理（launcher）が実装済み。一覧表示を実行権限の発行にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000011](../../Definitions/IA-000011/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「現在リポジトリと目的に対応する標準ツールを見つけ、利用可能性・外部作用の権限・開発実行・公式実行を区別して選べる」の成立条件、「版不一致・欠落実行基盤・改ざんManifestを対応版と誤認する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
