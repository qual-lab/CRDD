# IA分析: 物語と構造から文書の意味を理解する

成果物種別: IA分析
分析対象: [UX-000027](../../../02_UX/Definitions/UX-000027/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD閲覧者 |
| 場面 | 工程成果物を初めて読む時 |
| 目的 | 課題と判断の物語から構造化詳細へ進む |
| 得たい結果 | 情報量を失わず短時間で意味と次の行動を理解できる |
| 重要場面 | 判断理由と条件を結び付ける場面 |
| 避ける失敗 | 確認項目順と専門語だけで文書を埋める |
| 守る品質 | 物語と構造化した情報を両立する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 物語（Narrative）、構造化した詳細（Structured Detail）、判断（Decision）、検証根拠（Evidence）、正本（Canonical Source） | 対象を同一視せず、「問題と目的→判断→構造化詳細→根拠→次工程」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 問題と目的→判断→構造化詳細→根拠→次工程 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: CRDD閲覧者の判断] --確認する--> [O: 物語（Narrative）]
[O: 物語（Narrative）] --根拠と次の行動を辿る--> [O: 情報量を失わず短時間で意味と次の行動を理解できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 下書き（draft）／レビュー済み（reviewed）／現在有効（current）／履歴（historical）を必要時に区別 |
| 可視性 | 判断理由と条件を結び付ける場面では、物語と構造化した情報を両立するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 問題と目的→判断→構造化詳細→根拠→次工程。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | CRDD閲覧者は「課題と判断の物語から構造化詳細へ進む」ために必要な判断を行う。システムは「情報量を失わず短時間で意味と次の行動を理解できる」を支える対象・状態・根拠を示し、「確認項目順と専門語だけで文書を埋める」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | Documentation規則が支える。見出し検査を読者理解の証明にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000018](../../Definitions/IA-000018/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
