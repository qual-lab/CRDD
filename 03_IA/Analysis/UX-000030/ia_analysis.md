# IA分析: 公式素材を権利と用途を確認して使う

成果物種別: IA分析
分析対象: [UX-000030](../../../02_UX/Definitions/UX-000030/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | ブランド素材を追加または利用する時 |
| 目的 | 視覚素材の出所・権利・用途を確認する |
| 得たい結果 | 公式識別へ安心して収載・派生利用できる |
| 重要場面 | 公式用途へ採用する直前 |
| 避ける失敗 | 見た目だけで権利や信頼保証を推定する |
| 守る品質 | 由来・権利・用途を追跡する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 素材 | 利用候補の視覚・文章素材 | 素材識別子（Asset Identity） |
| 由来 | 生成・取得・編集の由来 | 情報源（Source）と履歴 |
| 権利確認 | 収載・公開・再配布の権利根拠 | 権限（Authority）と記録 |
| 許可用途 | 許可された用途 | 素材（Asset）＋Scope |
| 派生物 | 素材を加工して作られ、元の由来と権利を引き継ぐ成果物 | 派生物Identityと元素材Identityで識別する |

```text
[O: 派生物] ──元を辿る──▶ [O: 素材]
                                    ├── 由来を持つ ───────▶ [O: 由来]
                                    └── 利用可否を確認される ─▶ [O: 権利確認]
                                                                      │ 用途を許す
                                                                      ▼
                                                               [O: 許可用途]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000019 | 素材 | 素材 | Same | 利用対象となるAssetを保持する |
| IA-000019 | 由来 | 由来 | Same | 作成元と取得経路を保持する |
| IA-000019 | 権利確認 | 権利確認 | Same | 利用権限の確認結果を保持する |
| IA-000019 | 許可用途 | 許可用途 | Same | 利用できる範囲を保持する |
| IA-000019 | 派生物 | 派生物 | Same | 加工後も由来と権利を追跡する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 候補（candidate）／採用済み（approved）／開示制限（restricted）／取下げ済み（withdrawn） |
| 可視性 | 「公式用途へ採用する直前」では、由来・権利・用途を追跡するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 素材→由来→権利確認→許可用途。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 素材情報を管理する主体が素材・由来・権利確認・派生関係を記録する。 |
| 時間的な意味 | 候補（candidate）／採用済み（approved）／開示制限（restricted）／取下げ済み（withdrawn）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「視覚素材の出所・権利・用途を確認する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD作成者・保守者が「ブランド素材を追加または利用する時」に「公式識別へ安心して収載・派生利用できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 権利保有者またはRepositoryの利用許可責任者がAllowed Useを確定する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 見た目だけで権利や信頼保証を推定する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD作成者・保守者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「公式用途へ採用する直前」に、見た目だけで権利や信頼保証を推定することを避け、由来・権利・用途を追跡することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000035: 識別表示が入口発見を助けながら信頼誤認を増やさないか、権利情報の許容確認負担 |
| 判断者 | CRDD作成者・保守者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | CommunicationとReleaseに記録がある。見た目の公式性を権利根拠にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000019](../../Definitions/IA-000019/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「公式識別へ安心して収載・派生利用できる」の成立条件、「見た目だけで権利や信頼保証を推定する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
