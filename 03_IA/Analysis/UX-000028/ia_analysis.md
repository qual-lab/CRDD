# IA分析: 工程固有の図から意図を引き継ぐ

成果物種別: IA分析
分析対象: [UX-000028](../../../02_UX/Definitions/UX-000028/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD閲覧者 |
| 場面 | 工程の入口・出口で成果物を渡す時 |
| 目的 | 工程固有の図から状態・関係・未接続を理解する |
| 得たい結果 | 後工程で意図を再発明せず漏れを発見できる |
| 重要場面 | 下流義務へ変換する場面 |
| 避ける失敗 | 必要な図を黙って省略しAIごとに記法が変わる |
| 守る品質 | 図の意味・凡例・正本関係を固定する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 図の要素 | 図中の対象・関係 | 凡例に従う文書内識別子（Local Identity） |
| 図 | 複数の要素と関係をまとめて意味を示す図 | 文書内の図識別子（Diagram Identity） |
| 情報源が持つ意味 | 工程固有の図から状態・関係・未接続を理解する際に、「情報源が持つ意味」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 情報源の識別情報と改訂版または観測時点で識別する |
| 引継ぎ義務 | 次工程が失ってはならない意味 | 情報源（Source） Contextへ結合 |


```text
[O: 図] ──含む──▶ [O: 情報源が持つ意味]
      │ 図中へ投影される
      ▼
[O: 図の要素]
      │ 次工程へ意味を渡す
      ▼
[O: 引継ぎ義務]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000018 | 図 | 図 | Same | 複数要素と関係を持つ図全体を保持する |
| IA-000018 | 図の要素 | 図の要素 | Same | 凡例で識別する要素を保持する |
| ― | 情報源が持つ意味 | ― | Not Applicable | IA-000018のCanonical Object表にある対応対象の「識別・関係」へ、情報源が持つ意味を独立Objectではなく識別条件または関係として保持する |
| IA-000018 | 引継ぎ義務 | 引継ぎ義務 | Same | 後工程が図から失ってはならない意味を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 作成済み（created）／参照（referenced）／理由付き非該当（not_applicable with reason） |
| 可視性 | 「下流義務へ変換する場面」では、図の意味・凡例・正本関係を固定するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 図の要素→情報源が持つ意味→引継ぎ義務。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 成果物AuthorがNarrative・Structured Detail・Diagramを作成し、工程OwnerがHandoff Obligationを更新する。 |
| 時間的な意味 | 作成済み（created）／参照（referenced）／理由付き非該当（not_applicable with reason）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「工程固有の図から状態・関係・未接続を理解する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD閲覧者が「工程の入口・出口で成果物を渡す時」に「後工程で意図を再発明せず漏れを発見できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 対象Contextの対象の判断を確定する主体が意味と判断を確定し、図の見た目だけで契約を変更しない。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 必要な図を黙って省略しAIごとに記法が変わる |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD閲覧者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「下流義務へ変換する場面」に、必要な図を黙って省略しAIごとに記法が変わることを避け、図の意味・凡例・正本関係を固定することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000032: CRDD作成者・保守者が「工程固有の図から状態・関係・未接続を理解する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | CRDD閲覧者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | テキスト図記法と基本図処置がある。図を独立正本や装飾にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000018](../../Definitions/IA-000018/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「後工程で意図を再発明せず漏れを発見できる」の成立条件、「必要な図を黙って省略しAIごとに記法が変わる」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
