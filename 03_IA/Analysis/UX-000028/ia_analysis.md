# IA分析: 工程固有の図から意図を引き継ぐ

成果物種別: IA分析
分析対象: [UX-000028](../../../02_UX/Definitions/UX-000028/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD閲覧者 |
| 場面 | 工程の入口・出口で成果物を渡す時 |
| 目的 | 工程固有の図から状態・関係・未接続を理解する |
| 得たい結果 | 後工程で意図を再発明せず漏れを発見できる |
| 重要場面 | 下流義務へ変換する場面 |
| 避ける失敗 | 必要な図を黙って省略しAIごとに記法が変わる |
| 守る品質 | 図の意味・凡例・正本関係を固定する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 図（Diagram）、図の要素（Diagram Element）、上流での意味（Source Meaning）、引継ぎ義務（Handoff Obligation）、処置（Disposition） | 対象を同一視せず、「上流意図→工程図→要素の意味→下流義務」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 上流意図→工程図→要素の意味→下流義務 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: CRDD閲覧者の判断] --確認する--> [O: 図（Diagram）]
[O: 図（Diagram）] --根拠と次の行動を辿る--> [O: 後工程で意図を再発明せず漏れを発見できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 作成済み（created）／参照（referenced）／理由付き非該当（not_applicable with reason） |
| 可視性 | 下流義務へ変換する場面では、図の意味・凡例・正本関係を固定するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 上流意図→工程図→要素の意味→下流義務。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | CRDD閲覧者は「工程固有の図から状態・関係・未接続を理解する」ために必要な判断を行う。システムは「後工程で意図を再発明せず漏れを発見できる」を支える対象・状態・根拠を示し、「必要な図を黙って省略しAIごとに記法が変わる」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | テキスト図記法と基本図処置がある。図を独立正本や装飾にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000018](../../Definitions/IA-000018/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
