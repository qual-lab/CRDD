# IA分析: 監査・是正・判断を一つの改訂版で閉じる

成果物種別: IA分析
分析対象: [UX-000023](../../../02_UX/Definitions/UX-000023/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 複数指摘を是正する時 |
| 目的 | 監査合意から是正・反証までを一つの改訂版で閉じる |
| 得たい結果 | 小出しの指摘と局所PatchのLoopを減らせる |
| 重要場面 | 再レビューへ固定候補を渡す直前 |
| 避ける失敗 | 一部是正や監査回数を完成と誤認する |
| 守る品質 | 合意事項と試験を全数対応させる |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 指摘 | レビュー・監査の指摘 | 指摘の識別子（Finding Identity） |
| 是正 | 指摘への構造是正 | ChangeとFindingへ結合 |
| 検証 | 実行条件と観測結果 | 改訂版（Revision）へ結合 |
| 判断要求 | 監査合意から是正・反証までを一つの改訂版で閉じる際に、「判断要求」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 元の依頼・対象・改訂版へ結び、別の結果と混同しない |
| 現在の改訂版 | 確認対象の固定版 | 改訂版の識別子（Revision Identity） |


```text
[O: 現在の改訂版]
      │ レビューで生む
      ▼
[O: 指摘]
      │ 処置される
      ▼
[O: 是正]
      │ 反証される
      ▼
[O: 検証]
      │ 残る判断を抽出する
      ▼
[O: 判断要求]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000016 | 指摘 | 指摘 | Same | 独立確認のFindingを保持する |
| IA-000016 | 是正 | 是正 | Same | Findingを閉じる構造修正を保持する |
| IA-000016 | 検証 | 検証根拠 | Rename | 何を確認したかと結果を持つ根拠として表示を明確にする |
| ― | 判断要求 | ― | Not Applicable | IA-000016の「情報の優先度・まとまり・見つけ方・責任」節へ、判断要求を独立Objectではなく次行動への導線として保持する |
| IA-000016 | 現在の改訂版 | 改訂版 | Rename | 同じRevisionをCanonical表示へ揃える |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 固定済み（fixed）／レビュー中（under_review）／是正必要（changes_required）／確認済み（verified）／判断必要（decision_required） |
| 可視性 | 「再レビューへ固定候補を渡す直前」では、合意事項と試験を全数対応させるために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 指摘→是正→検証→判断要求→現在の改訂版。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 変更担当がRoadmap Item・Change・Changed File・Remediationを更新し、Reviewer／Quality担当がFinding・Evidence・Quality Stateを記録する。 |
| 時間的な意味 | 固定済み（fixed）／レビュー中（under_review）／是正必要（changes_required）／確認済み（verified）／判断必要（decision_required）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「監査合意から是正・反証までを一つの改訂版で閉じる」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD作成者・保守者が「複数指摘を是正する時」に「小出しの指摘と局所PatchのLoopを減らせる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 変更Ownerが是正案を、独立ReviewerがFinding解消を、公開可否を決める主体が公開可否をそれぞれ確定する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 一部是正や監査回数を完成と誤認する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD作成者・保守者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「再レビューへ固定候補を渡す直前」に、一部是正や監査回数を完成と誤認することを避け、合意事項と試験を全数対応させることを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000026: CRDD作成者・保守者が「監査合意から是正・反証までを一つの改訂版で閉じる」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | CRDD作成者・保守者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | CHGとQualityが根拠を保持する。別改訂版の結果を混在させない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000016](../../Definitions/IA-000016/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「小出しの指摘と局所PatchのLoopを減らせる」の成立条件、「一部是正や監査回数を完成と誤認する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
