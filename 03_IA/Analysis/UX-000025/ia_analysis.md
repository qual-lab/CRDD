# IA分析: 過去の推論情報と現在値を区別する

成果物種別: IA分析
分析対象: [UX-000025](../../../02_UX/Definitions/UX-000025/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 過去判断を再利用または更新する時 |
| 目的 | 当時の仮説と現在有効な意図を区別する |
| 得たい結果 | 判断理由を追跡しつつ古い前提を現在値にしない |
| 重要場面 | 判断理由をAIへ渡す場面 |
| 避ける失敗 | 履歴を上書きし競合する理由を勝手に統合する |
| 守る品質 | 現行性・選択範囲・使用改訂版を追跡する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 過去の情報 | 当時の仮説と現在有効な意図を区別する際に、過去の値と、その判断に至った背景を取り違えないための情報 | 過去値は対象・値が有効だった時点・改訂版で識別する。推論の背景は判断対象・判断時点・根拠に用いた情報源の組合せで識別する。同じ記録に含まれていても、この二つを同一の情報として扱わない。 |
| 過去値 | 現在値と比較する履歴値 | 対象＋値が有効だった時点＋改訂版で識別する |
| 推論の背景 | 当時の判断材料と前提 | 判断対象＋判断時点＋根拠に用いた情報源で識別する |
| 現在有効な意図 | 現在の仕事で有効な判断・方針 | 現行の正本と改訂版へ結ぶ |
| 選択根拠 | 当時の仮説と現在有効な意図を区別する際に、「選択根拠」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 支える対象、情報源、改訂版または観測時点へ結ぶ |
| 有効性 | 過去の情報が現在有効か、履歴か、置換済みかを示す状態 | 対象Identityと評価時点で識別する |

```text
[O: 選択根拠]
      │ 採用理由を示す
      ▼
[O: 現在有効な意図] ◀──現在有効か比較する── [O: 過去の情報]
      │                                           │
      └──────────判定される──────────┬───────────┘
                                      ▼
                                [O: 有効性]

[O: 過去値] ──判断時の前提へ結ぶ──▶ [O: 推論の背景]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| ― | 過去の情報 | ― | Not Applicable | 過去値と推論の背景をまとめた利用者向け概念として保持し、別Objectへ変換しない |
| IA-000021 | 過去値 | 過去値 | Same | 現在値と比較する履歴値を保持する |
| IA-000021 | 推論の背景 | 推論の背景 | Same | 当時の判断材料と前提を保持する |
| IA-000021 | 現在有効な意図 | 現在有効な意図 | Same | 現在の判断基準をCanonicalに保持する |
| IA-000021 | 選択根拠 | 選択理由 | Rename | 現在の選択を支える理由として保持する |
| IA-000021 | 有効性 | 有効性 | Same | current／historical／superseded／unknownを保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 現在有効（current）／履歴（historical）／置換済み（superseded）／不明（unknown） |
| 可視性 | 「判断理由をAIへ渡す場面」では、現行性・選択範囲・使用改訂版を追跡するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 過去の情報→現在有効な意図→選択根拠。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 判断の背景・過去値・選択理由を記録する責任と、対象正本の現在有効な意図を更新する責任を分ける。 |
| 時間的な意味 | 現在有効（current）／履歴（historical）／置換済み（superseded）／不明（unknown）の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「当時の仮説と現在有効な意図を区別する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD作成者・保守者が「過去判断を再利用または更新する時」に「判断理由を追跡しつつ古い前提を現在値にしない」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 対象の判断を確定する主体が現在有効な意図と置換関係を確定する。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 履歴を上書きし競合する理由を勝手に統合する |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD作成者・保守者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「判断理由をAIへ渡す場面」に、履歴を上書きし競合する理由を勝手に統合することを避け、現行性・選択範囲・使用改訂版を追跡することを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000029: CRDD作成者・保守者が「当時の仮説と現在有効な意図を区別する」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | CRDD作成者・保守者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 文書・履歴境界を利用できる。履歴確定識別子（Commit SHA）を唯一の成立条件にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000021](../../Definitions/IA-000021/ia_definition.md)へ接続する。情報の引き渡しではなく、過去の判断と現在有効な意図を区別するため、IA-000014へ統合しない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「判断理由を追跡しつつ古い前提を現在値にしない」の成立条件、「履歴を上書きし競合する理由を勝手に統合する」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
