# IA分析: 内部変更後も成立済み能力を安全に使う

成果物種別: IA分析
分析対象: [UX-000007](../../../02_UX/Definitions/UX-000007/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 責務・契約・接続部または実行環境の構成を変更する時 |
| 目的 | 維持・変更・廃止された能力と利用側を確認する |
| 得たい結果 | 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる |
| 重要場面 | 変更を完了・公開可能と判断する直前 |
| 避ける失敗 | 主経路だけ移行し副次利用側を取り残す |
| 守る品質 | 旧能力・全利用側・置換根拠を閉じる |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 情報Object | 利用者にとっての意味 | 同一性と関係の基準 |
|---|---|---|
| 変更前の能力 | 利用者が失ってはならない成立済み能力 | 名称と基準版の根拠（Baseline Evidence）で識別する |
| 公開契約 | 維持・変更・廃止された能力と利用側を確認する際に、「公開契約」の意味・状態・対象範囲を他の情報と取り違えないための情報 | 適用対象、所有者、改訂版で識別する |
| 利用側 | 契約を利用する入口・派生・配布経路 | 公開入口または責任で識別 |
| 置換後の実装 | 能力の新しい所有先 | 正式契約（Contract）へ結ぶ |
| 維持根拠 | 置換後も利用能力が成立する証拠 | 利用側（Consumer）ごとに結ぶ |


```text
[O: 変更前の能力]
      │ 意味を保持される
      ▼
[O: 公開契約]
      ├── 利用される ──▶ [O: 利用側] ───────┐
      └── 実装される ──▶ [O: 置換後の実装] ─┤
                                               │ 維持・置換を検証される
                                               ▼
                                        [O: 維持根拠]
```

図中の`[O:]`は情報Objectだけを表す。利用者、判断行為、利用者成果はObjectへ置き換えない。関係名と向きは、同じ対象を追跡し、誤った統合を避けるための情報上の関係であり、画面遷移や実装依存を表さない。

### Canonical化候補

| 接続先 | 分析Object | Canonical Object | 処置 | 判断理由 |
|---|---|---|---|---|
| IA-000005 | 変更前の能力 | 利用能力 | Rename | 利用者が失ってはならない成立済み能力として保持する |
| IA-000005 | 公開契約 | 正式契約 | Rename | 能力を利用側へ約束するCanonical Contractとする |
| IA-000005 | 利用側 | 利用側 | Same | 契約を消費する主体を保持する |
| IA-000005 | 置換後の実装 | 置換先 | Rename | 能力の新しい所有先として保持する |
| IA-000005 | 維持根拠 | 能力維持の根拠 | Rename | 置換後も能力が成立する証拠を保持する |

この対応は分析結果からCanonical定義を再構築するための候補である。`Split`または`Merge`でも元の利用者向け意味を失わず、正式入力にないObjectを追加しない。

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 維持／変更／廃止／未確認 |
| 可視性 | 「変更を完了・公開可能と判断する直前」では、旧能力・全利用側・置換根拠を閉じるために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 変更前の能力→公開契約→利用側→置換後の実装→維持根拠。結果なし、判断待ち、失敗または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 変更担当が能力・契約・利用側・置換先・検証根拠を追跡する。 |
| 時間的な意味 | 維持／変更／廃止／未確認の区別を保持する。現在値、古い値、履歴または不明を同じ正常状態へ丸めない。 |
| 情報の優先度 | まず「維持・変更・廃止された能力と利用側を確認する」の判断に必要な対象・状態・判断要否を示し、識別情報と根拠は必要時に辿れるようにする。 |
| 情報のまとまり | CRDD作成者・保守者が「責務・契約・接続部または実行環境の構成を変更する時」に「責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる」を得るための対象・状態・根拠・次の行動を同じ文脈で扱う。 |
| 判断権限 | 能力維持の責任主体が置換完了を確定し、Evidence不足の能力を削除済みと扱わない。利用者は提示された情報から次の行動を選ぶが、正本の意味・状態を無断で変更しない。 |
| 重要な失敗 | 主経路だけ移行し副次利用側を取り残す |
| 制約・対象外 | 画面、UI部品、API、DB、Class、保存形式および具体的な振る舞いをIAで確定しない。 |
| 人間判断 | UXから継承した未確認事項はCRDD作成者・保守者を代表する利用者とQual-Labが判断する。IA固有の追加判断はない。正式入力にないObject、状態または責任を追加する必要が生じた場合は人間の決定権限者へ戻す。 |
| IAへ戻す条件 | UI／SPEC分析またはQuality Analysis / IAで、Object・同一性・関係・状態・可視性・時間的な意味が不足または競合すると判明した場合。 |
| 検証意図 | 「変更を完了・公開可能と判断する直前」に、主経路だけ移行し副次利用側を取り残すことを避け、旧能力・全利用側・置換根拠を閉じることを確認できる必要がある。 |

ここで示す主体は、情報契約上必要な機能責任を表し、特定の人物・組織・Componentへの割当を確定しない。後続工程は、この責任境界を保ったまま実際の主体へ割り当てる。

### 未確認事項と判断

| 区分 | 内容 |
|---|---|
| UXから継承する確認事項 | REQ-000005: 実行環境の導入・運用者が「責務分離後も成立済み機能を使う」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000019: CRDD作成者・保守者が「責務移動後の全利用側を閉じる」を行う際の判断基準、許容負担、利用環境および失敗後の選択／REQ-000023: 実行環境の導入・運用者が「AI提供元固有の一連の状態変化を接続部越しに正確に扱う」を行う際の判断基準、許容負担、利用環境および失敗後の選択 |
| 判断者 | CRDD作成者・保守者を代表する利用者とQual-Lab。 |
| 現在判定 | 後続の実利用確認が必要。現在のUX定義をCanonical化する判断を止める事項ではない。 |
| 未確認時の影響 | 利用者成果、重要場面、失敗および品質期待を仮説として保持し、定量条件や実現方式を確定しない。 |
| IAで追加した未確認事項 | なし。正式入力にない定量条件、状態値または実現方式を追加しない。 |
| IA固有の追加人間判断 | なし。UXから継承した判断をIAで確定済みにしない。 |
| Discoveryへ戻す条件 | 想定した利用者、問題、望ましい変化または制約が誤っていると判明した場合。 |

## 4. 現実照合の参考情報（正式入力ではない）

この節は後続のReality Auditへ引き継ぐ参考情報であり、IA Candidateを導く正式入力ではない。前節までをUX Definitionから再導出した結果として優先する。


| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | ArchitectureとCHGに利用側までの閉包（Consumer Closure）がある。ファイル取込み（file import）一覧を利用者情報の主役にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000005](../../Definitions/IA-000005/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。UXから継承する未確認事項を、判断者と影響を含めて接続先へ保持する。

## 6. 後続工程が保持する意味

| 接続先 | 保持する意味 |
|---|---|
| UI（UX＋IAの正式入力） | 情報の優先度、可視性、状態差、まとまり、見つけ方および関係の理解を保持する。 |
| SPEC（UX＋IAの正式入力） | 対象の識別、関係、状態、可視条件、責任および時間的な意味を保持する。 |
| Quality Analysis / IA（伴走） | 「責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる」の成立条件、「主経路だけ移行し副次利用側を取り残す」という失敗および前章の検証意図を保持する。 |

ArchitectureやSourceへ直接引き渡さない。UI／SPECは、UX DefinitionとIA Definitionの双方を正式入力として分析する。

## 7. 補足分析

なし。必須情報は第1章から第7章に保持する。現行文書・実装との比較は第4章の参考情報として分離し、Canonical IAの根拠には用いない。
