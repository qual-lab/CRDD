# IA分析: 内部変更後も成立済み能力を安全に使う

成果物種別: IA分析
分析対象: [UX-000007](../../../02_UX/Definitions/UX-000007/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | CRDD作成者・保守者 |
| 場面 | 責務・契約・接続部または実行環境の構成を変更する時 |
| 目的 | 維持・変更・廃止された能力と利用側を確認する |
| 得たい結果 | 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる |
| 重要場面 | 変更を完了・公開可能と判断する直前 |
| 避ける失敗 | 主経路だけ移行し副次利用側を取り残す |
| 守る品質 | 旧能力・全利用側・置換根拠を閉じる |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 変更前の能力、公開契約、利用側、置換実装、検証根拠 | 対象を同一視せず、「変更→能力→全利用側→置換→反証根拠」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 変更→能力→全利用側→置換→反証根拠 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: CRDD作成者・保守者の判断] --確認する--> [O: 変更前の能力]
[O: 変更前の能力] --根拠と次の行動を辿る--> [O: 責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 維持／変更／廃止／未確認 |
| 可視性 | 変更を完了・公開可能と判断する直前では、旧能力・全利用側・置換根拠を閉じるために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 変更→能力→全利用側→置換→反証根拠。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | CRDD作成者・保守者は「維持・変更・廃止された能力と利用側を確認する」ために必要な判断を行う。システムは「責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる」を支える対象・状態・根拠を示し、「主経路だけ移行し副次利用側を取り残す」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | ArchitectureとCHGに利用側までの閉包（Consumer Closure）がある。ファイル取込み（file import）一覧を利用者情報の主役にしない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000005](../../Definitions/IA-000005/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
