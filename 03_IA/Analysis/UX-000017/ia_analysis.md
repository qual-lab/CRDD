# IA分析: 実行時データを安全に保持・清掃する

成果物種別: IA分析
分析対象: [UX-000017](../../../02_UX/Definitions/UX-000017/ux_definition.md)
状態: 分析済み

## 1. UXから受け取る意味

| 観点 | この分析で受け取る内容 |
|---|---|
| 利用者 | 実行環境の導入・運用者 |
| 場面 | 実行時データを作成または清掃する時 |
| 目的 | 実行時データの所有場所と一連の状態変化を理解する |
| 得たい結果 | 保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる |
| 重要場面 | 永続化または削除の直前 |
| 避ける失敗 | subdirectoryや別基点フォルダへ同名データを作る |
| 守る品質 | 用途別領域とcleanup条件を明示する |

画面、API、保存形式は決めず、上記の利用者成果を情報の単位と関係へ変換する。

## 2. 情報候補と関係

| 候補 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| 見分ける対象 | 実行データの基点（Runtime Root）、実行データ（Data Item）、目的（Purpose）、責任者（Owner）、永続性（Durability）、保持条件（Retention）、Cleanup | 対象を同一視せず、「作業→データ用途→保持判断→清掃→不存在確認」の順に関係付ける。識別できない対象は既知の対象へ推定統合しない。 |
| 根拠と次の行動 | 作業→データ用途→保持判断→清掃→不存在確認 | 起点、判断対象、根拠、戻り先を同じ流れとして辿れるようにする。 |

```text
[O: 実行環境の導入・運用者の判断] --確認する--> [O: 実行データの基点（Runtime Root）]
[O: 実行データの基点（Runtime Root）] --根拠と次の行動を辿る--> [O: 保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる]
```

## 3. 状態・可視性・導線・責任

| 観点 | 分析結果 |
|---|---|
| 状態 | 一時（temporary）／保持必要（durable）／回復必要（recovery_required）／清掃可能（eligible_for_cleanup）／不明（unknown） |
| 可視性 | 永続化または削除の直前では、用途別領域とcleanup条件を明示するために必要な状態と不足を判断対象と同じ文脈で示す。詳細な識別情報と根拠は必要時に辿れるようにし、非開示対象は存在自体を推測表示しない。 |
| 導線 | 作業→データ用途→保持判断→清掃→不存在確認。結果がない、判断待ち、または状態不明の場合も、根拠か安全な戻り先を失わない。 |
| 責任 | 実行環境の導入・運用者は「実行時データの所有場所と一連の状態変化を理解する」ために必要な判断を行う。システムは「保存場所の内部構造を推測せず、保持すべき状態と一時物を区別して安全に作業を継続・終了できる」を支える対象・状態・根拠を示し、「subdirectoryや別基点フォルダへ同名データを作る」という誤認を生まない責任を持つ。 |

## 4. 現行文書・実装との照合

| 照合対象 | 結果 |
|---|---|
| UXから導いた意味 | 対象・状態・導線は前節までを正とする。 |
| 現行構造 | 実行時データ部品（runtime-data package）と`.crdd`規則がある。名前や経過時間だけで削除しない。 |
| 採用境界 | 現行の名称や状態値は、UX由来の意味と一致する範囲だけを照合根拠にする。実装にだけ存在する区分はIA定義へ逆流させない。 |

## 5. IA処置

[IA-000012](../../Definitions/IA-000012/ia_definition.md)へ接続する。上記7軸を接続先へ保持し、複数UXを統合する場合も対象固有の状態、失敗、導線を消さない。試作上の理解しやすさは未確認として下流へ渡す。
