# 作業の現在地と証拠を、置き場所から迷わない

成果物種別: Discovery分析
探索ID: `EXP-000018`
状態: 要求採用
主な情報源: CHG-000069、CHG-000070
判断する人: Qual-Lab
記録の性質: v0.20公開状態の伝播漏れとRoadmap／Change／根拠再編から再構成
時系列根拠: CHG-000069とCHG-000070を起点とする。
下流の主要CHG: CHG-000069、CHG-000070

## きっかけ

変更を追う人とリリース・品質を判断する人が、現在の状態とその根拠を複数の置き場所から探し、候補と公開済みを取り違える余地があった。

v0.20.0ではリリース自体が成立しても、Overview、CHANGELOG、品質、Roadmap等に候補表示が残った。また根拠が品質配下とCHG配下へ分散し、何を直接証明する記録かより、ファイル種別で置き場所が決まっていた。

## 問題を分けた

| 問題 | 必要だったこと |
|---|---|
| リリース状態の取り残し | 状態変更の全利用側を閉じる |
| RoadmapとChangeの混在 | 未完了作業と変更履歴を別入口にする |
| 根拠の分散 | 直接証明する対象が責任者になる |
| Quality Centerの巨大化 | 根拠倉庫でなく現在品質の投影にする |

```text
Roadmap = 未完了作業の現在入口
Change  = 何を変えたか
リリース = 何を公開したか
根拠 = 直接証明するChangeまたはリリースが所有
品質 = 根拠を読んだ現在評価
```

## 採用した要求

`REQ-000033`: Roadmap、Change、リリース、根拠および品質は、未完了状態、変更差分、公開判断、直接証明対象および現在品質の責務を分け、状態遷移時は全利用側へ伝播しなければならない。

## 反証条件

同じ根拠を複数箇所へ複製する、公開済みと候補が同じ表示になる、またはパス名だけで現在性・責任者を判定する場合は、この責務分離が機能していない。

## 現在地と次への引き渡し

未完了作業、変更、公開、直接の根拠、現在品質を別の責務として扱い、状態変更時に全利用側へ伝える方向を採用している。UXには、作業やリリースを追う人が、現在地と根拠へ置き場所から迷わず到達できる体験として渡す。責務分離後も同じ状態を複数箇所で手動更新する必要が残る場合は、伝播境界を見直す。
