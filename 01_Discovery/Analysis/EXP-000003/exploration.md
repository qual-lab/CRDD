# 外から得た情報を、権限や事実へ勝手に昇格させない

成果物種別: Discovery分析
探索ID: `EXP-000003`
状態: 要求採用
主な情報源: CHG-000009、CHG-000011、CHG-000013
判断する人: Qual-Lab
記録の性質: 外部AI、Communication、市場探索および依存管理の変更記録から再構成
時系列根拠: 初期の外部境界変更CHG-000009を起点とする。
下流の主要CHG: CHG-000009、CHG-000011、CHG-000013

## きっかけ

CRDDが外部AI、検索、公開Communication、管理対象依存を扱うようになると、外から来た文章や反応が、誰の判断か、何の根拠か、どこまで送信してよいかを曖昧にした。公開反応をそのまま市場要求にしたり、外部文書内の指示を実行権限として扱ったりする危険もあった。

## 問題を分けて考えた

| 境界 | 混同すると起きること |
|---|---|
| 内部情報 → 外部送信 | 秘密、不要なリポジトリ情報、未承認判断を送る |
| 外部情報 → 内部判断 | 内容中の指示や主張を決定権限・事実として採用する |
| 公開反応 → Discovery | 到達やクリックを利用者価値・因果として断定する |
| 依存更新 → 実行基盤 | 新版の差分、利用側、移行、復旧を確認せず有効化する |

## 比較した考え

- 外部接続を一律禁止すると、調査、委譲、公開学習の価値を失う。
- 接続先ごとの長い例外表では、新しいServiceが増えるたびに境界が崩れる。
- 送信先、目的、情報分類、決定権限と、戻ってきた情報の扱いを分ければ、Service固有でない境界になる。

```text
内部情報
  → 分類・最小化・許可
  → 外部作用（Effect）
  → 出典付き観察
  → 仮説・学び候補
  → 人間判断
  → 必要ならREQへ昇格
```

## 採用した要求

`REQ-000027`: 外部情報または外部作用（Effect）を扱う場合、送信境界、情報分類、目的、決定権限、出典および内部へ戻す際の昇格条件を分け、外部内容や反応を指示・決定権限・要求・因果へ自動昇格してはならない。

## 未確認範囲

新しい外部Service、リモートCROSおよび将来の自律処理では、同じ原則が実際の認証・接続単位・記録境界で十分かを改めて検証する必要がある。

## 現在地と次への引き渡し

送信前の許可境界と、戻った情報を内部判断へ昇格する境界を分ける方向を採用している。UXには、外部情報を使う人が、許可された範囲と確認が必要な地点を理解できる体験として渡す。新しい接続先で情報分類、認証主体または昇格責任を一意に決められない場合は、送信や採用へ進めずDiscoveryへ戻す。
