# 別の端末から、安全にプロジェクト情報へ届く

成果物種別: Discovery分析
探索ID: `EXP-000022`
状態: 要求採用
主な情報源: リモートMCP、想定利用者／共有CROS構想
判断する人: Qual-Lab
記録の性質: リモートMCP、想定利用者／共有CROSおよび接続資格情報による利用範囲の対話から再構成
時系列根拠: 2026-09-13に固定したv0.21構想群で、手元入口の後に扱う依存順とした。

## きっかけ

ChatGPTなど別Hostの利用側から、CROSが扱うプロジェクト情報へ接続したいという要求が出た。Localhostで動くMCP／HTTPは既にあるため、listen先を広げれば済むようにも見えた。

リモート化すると、手元では同一利用者とHostの内側に隠れていた境界が表へ出る。接続した主体、利用できる作業領域、作業領域へ公開されたリポジトリ、各リポジトリの実アクセス可能性は別々に変化し得る。また、Network切断により「Serverでは完了したが利用側は結果を受け取れない」状態が生じる。

```text
接続できた
  ≠ 作業領域を使える
  ≠ リポジトリを読める
  ≠ 結果を外へ返してよい

要求を送れた
  ≠ 未実行
  ≠ 実行中
  ≠ 完了結果を受信済み
```

## 本当の問題

Network接続だけでは、誰がどのプロジェクトを読めるか、途中で応答を失った時に同じ処理をどう確認するかが決まらない。Serverが読める情報と、接続した利用者へ返してよい情報も同じではない。

## 置いた仮説

接続接続資格情報に利用可能な作業領域を結び、接続単位ではその範囲だけを使う。作業領域に公開されたリポジトリだけを解決し、応答が途切れても同じ依頼 IDで結果を取り直せる形を考えた。

```text
接続資格情報
    ↓
接続単位で使える作業領域
    ↓
作業領域に公開されたリポジトリ
    ↓
許可されたプロジェクト情報だけを返す
```

独自の利用者役割やリポジトリごとの細かなACLは、CROSがIAM製品になるため初期範囲から外した。

| 方向 | 評価 | 採否 |
|---|---|---|
| 手元 HTTPのlisten先だけを広げる | 接続はできるが、内容 Grantと再取得がない | 不採用 |
| CROS独自の利用者役割とACLを作る | 細かい制御は可能だが、IAM責務が膨張する | 不採用 |
| 接続資格情報から作業領域 Grantを作り、リポジトリ Exposureを解決する | 小さな権限モデルで利用範囲を表現できる | 採用 |
| Timeout時に同じ要求を再実行する | 実装は単純だが、外部への変更を重複し得る | 不採用。依頼の識別情報で結果を照会する |

## 守ること

- TLSなどの暗号化と認証を前提にする。
- 認証成功と、内容を読めることを同一視しない。
- 読めない情報源の名前や件数を漏らさない。
- Timeoutを取消完了とみなさず、結果を再取得できるようにする。

## 現在の判断

リモート利用はv0.21で代表経路を設計する。目的はHTTP公開ではなく、プロジェクト情報へ安全に到達することである。

## 次工程で確かめること

認証失敗、作業領域範囲外、部分的に読めるプロジェクト、応答喪失、同じ依頼の再取得を含める。手元利用へリモート Serverを強制しないことも確認する。

<a id="remote-context-actor-process"></a>

```text
利用側          CROS Server           リポジトリ
  │                 │                     │
  ├─ 認証・要求 ───>│                     │
  │                 ├─ 利用範囲を確認     │
  │                 ├─ 許可済み取得 ─────>│
  │                 │<─ 状態と改訂版 ─────┤
  │<─ 結果または不足 ┤                     │
  └─ 応答喪失時は同じ依頼を照会する
```

## 採用した要求

`REQ-000011`: リモート利用者へプロジェクト情報を提供する場合、接続認証、接続単位の作業領域 Grant、リポジトリ Exposureおよび各リポジトリの実アクセス可能性を別々に検証し、許可された内容だけを返さなければならない。

`REQ-000021`: リモート要求の応答を失った場合、Timeoutを取消完了または未実行と推定せず、同じ依頼の識別情報で状態と完了結果を安全に再取得できなければならない。
