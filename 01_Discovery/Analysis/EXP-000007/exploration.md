# 「今どうなっているか」を毎回組み立て直さない

成果物種別: Discovery分析
探索ID: `EXP-000007`
状態: 要求採用
主な情報源: CRDDの自己適用、CHG-000055、v0.20のプロジェクト State
判断する人: Qual-Lab
記録の性質: v0.20までの自己適用対話、CHG-000055およびプロジェクト State実装から再構成
時系列根拠: CHG-000055とv0.20までの自己適用観測を起点とする。

## 何度も起きていたこと

「今どこまで進んだ？」「何が止まっている？」という単純な確認に、Markdown、Git、AIとの会話、Checkerの結果、実行記録を順番に調べる必要があった。一つずつの情報が間違っているわけではない。役割ごとに正しく分かれているため、最後に人かAIが現在地を組み立て直していた。

## 問題は文書の多さではなかった

文書を一つにまとめると、今度は正本の役割が崩れる。本当の問題は、必要な情報を集めた時に「どこから得たか」「いつの状態か」「読めなかった情報があるか」を保ったまま見せる共通の方法がなかったことだった。

<a id="problem-evidence-opportunity"></a>

```text
分かれた正本は保つ
        │
        ├─ 状態
        ├─ 品質
        ├─ 判断
        └─ Git・実行記録
        ↓
出典と不足を失わず、現在地として見せる
```

## 置いた仮説

同じ情報を別の場所へコピーせず、必要な時に読み取り用のプロジェクト全体の表示を作ればよいと考えた。人は薄いWorkbenchから、AIはMCPから同じ表示を利用する。どちらも元の正本へ戻れることを条件にする。

比較対象は、AIへ質問するだけの方法、静的報告、薄いWorkbenchである。Workbenchが最も良いとはまだ分かっていない。

| 仮説 | 強み | 未確認または弱み |
|---|---|---|
| 必要な都度AIへ質問する | 新しいUIが不要 | 毎回情報解決が必要で、回答差と出典確認負担が残る |
| 静的報告を生成する | 配布・閲覧が容易 | 更新間隔により古くなり、定型外の問いへ進みにくい |
| 薄いWorkbenchで同じRead Modelを投影する | 状態と正本導線を反復利用できる | UI維持費に見合う利用価値は未実証 |

したがって採用したのはWorkbenchそのものではなく、出典と不足を保つプロジェクト全体の表示である。Workbenchの採否は、この共通表示を使った比較実測で判断する。

## 守ること

- 情報がない、読めない、古い、競合している、を正常な値に丸めない。
- AIの要約だけでプロジェクトの健全性やリリース可否を決めない。
- プロジェクト全体の表示を直接編集せず、変更は元の正本へ戻す。

## 現在の判断

出典と観測時点を持つプロジェクト全体の表示は採用した。Workbenchの価値は、同じ課題をAI、静的報告、Workbenchで試してから判断する。

## 次工程で確かめること

UXでは、利用者が現在地と不足を理解し、迷わず元の正本や判断対象へ進めるかを確かめる。検証では、探索時間、追加質問、出典確認、誤った完全視が減るかを比較する。

<a id="project-operation-actor-process"></a>

```text
利用者             CRDDの正本             AI／ツール
  │                    │                     │
  ├─ 現在地を確認 ─────────────────────────>│
  │                    ├─ 状態と出典 ───────>│
  │<─ 現在地・不足・正本への導線 ───────────┤
  └─ 判断または元の正本へ進む
```

<a id="project-operation-sipoc"></a>

| 入力元 | 入力 | 処理 | 出力 | 利用者 |
|---|---|---|---|---|
| リポジトリ、実行基盤、品質、Git | 状態、出典、観測時点 | 必要な情報を解決し、不足を保ってまとめる | プロジェクト全体の表示、判断待ち、正本への導線 | 開発者、プロジェクト運営者、PM |

<a id="project-operation-value-stream"></a>

```text
プロジェクトを選ぶ → 情報源を確認する → 現在地をまとめる → 判断または正本へ進む
                       └─ 不足あり → 不足を表示する
```

<a id="project-operation-as-is-to-be"></a>

```text
現在: 個別に探す → 自分で組み立てる → 不足を追加確認する
候補: プロジェクトを選ぶ → 出典付きの現在地を見る → 次の判断へ進む
```

## 採用した要求

`REQ-000007`: プロジェクト全体の表示は、現在状態とともに項目ごとの出典、改訂版または観測時点、欠測、制限、競合および古さを保持し、所有する正本へ戻れるようにしなければならない。
