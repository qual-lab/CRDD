# REQ-000022 Runtime Dataの保持・清掃・回復

成果物種別: Discovery Definition
要求ID: `REQ-000022`
Discovery判断: 要求採用
判断する人: Qual-Lab

## 要求

Runtime Dataは保持期限、清掃条件、Recovery要否および終了後状態を持ち、由来不明、参照中または回復途中の残存物を正常状態へ混ぜたり、推測で削除したりしてはならない。

## 対象と利用状況

Runtime運用者が、成功、失敗、取消後に`.crdd`やOS管理Rootへ残った状態、候補、回復資源、一時物を扱う場面。

## 解く問題と望ましい変化

```text
現在: 保持期限とRecovery参照を持たない残存は、消せず蓄積するか、必要資源を推測で削除して回復不能にする。
    ↓
望ましい変化: 各Runtime Dataが保持期限、清掃条件、Recovery要否、終了後状態を持ち、安全に再開または不存在確認できる。
```

## 採用理由と比較

名前や経過時間による一括削除を避け、exact IdentityとLifecycleに基づく保持・清掃契約を採る。

## 成立条件

- 作成時にOwner、用途、保持、清掃、Recovery条件を記録する
- 成功、失敗、取消の全終了経路で残存と削除可否を判定する
- 参照中、由来不明、観測不能、回復途中を削除せず明示状態で返す

## 制約

- Evidence記録と物理残存を同一視しない
- `tmp`へRecoveryに必要な資源を置かない

## 検証意図

全終了経路、Process crash、清掃再入場、参照中、由来不明、期限超過を作り、残存、回復、最終不存在を観測する。
