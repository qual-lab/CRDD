# REQ-000009 プロジェクト・リポジトリ・基点フォルダの識別情報分離

成果物種別: Discovery定義
要求ID: `REQ-000009`
Discoveryでの判断: 要求採用
判断する人: Qual-Lab

## 要求

論理プロジェクト、各リポジトリおよび検証済み実行基点フォルダは、相互に代用しない独立した識別情報として結び付けられなければならない。

## 対象と利用状況

一つの論理プロジェクトが開発、管理、Commercial等の複数リポジトリに分かれる、または一リポジトリだけで成立する場面。

## 解く問題と望ましい変化

```text
現在: プロジェクト、リポジトリ、実行基点フォルダを同一視すると、所属、正本、アクセス境界、実行対象を名前やパスから誤推定する。
    ↓
望ましい変化: Project ID、Repository ID、検証済み基点フォルダを独立識別情報として結び、同居と分離を同じモデルで扱える。
```

## 採用理由と比較

基準リポジトリ配下への集約は所有と障害を集中し、プロジェクト情報の複製は同期を壊すため、明示Bindingを採る。

## 成立条件

- 一プロジェクト一リポジトリと一プロジェクト複数リポジトリを同じ識別情報規則で表せる
- リポジトリ名や配置ではなく検証済みBindingからプロジェクト所属と基点フォルダを解決する
- 同じProject IDでもリポジトリごとの責務とアクセス境界を保持する

## 制約

- 全リポジトリへ20_プロジェクトの複製を要求しない
- Project IDをRepository IDまたはファイルシステム上のパスとして利用しない

## 検証意図

単一、複数、移動後基点フォルダ、偽装パス、重複識別情報を与え、Binding解決と拒否を観測する。
