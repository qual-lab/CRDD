# REQ-000003 目的から完了・再開までプロジェクトを進める

成果物種別: Discovery定義
要求ID: `REQ-000003`
Discoveryでの判断: 要求採用
判断する人: Qual-Lab

## 要求

Project Runtimeは、人間が目的、受入条件、人間へ戻す判断点を示して節目を委ねられるようにしなければならない。そのうえで、目的、節目、タスク同士の関係、判断待ち、再計画、統合結果を、停止後も失われない一続きの状態として管理しなければならない。一部のタスクが成功しただけで、プロジェクト全体を達成済みにしてはならない。

## 対象と利用状況

プロジェクト運営者が、目的と受入条件を渡して一つの節目を委ね、複数のタスク、人間の判断、再計画、結果の統合を通して進める場面。

## 解く問題と望ましい変化

```text
現在: 個別タスクの成功だけでは、競合や判断待ちを含む上位目的の達成と、停止後の再開点を説明できない。
    ↓
望ましい変化: 目的と受入条件で節目を委ね、タスク同士の関係、判断待ち、再計画、統合、受入を一続きの状態として管理し、判断が必要な時は人間へ戻し、停止後も同じ仕事へ戻れる。
```

## 採用理由と比較

Coordinatorへの機能追加ではプロジェクトの意味がAI提供元実行へ従属し、外部管理ツールではCRDDの候補・判断・回復と意味がずれるため、独立アプリケーションの中核（Application Core）を採る。

## 成立条件

- 目的から導いたタスクと関係、節目を同じプロジェクトの識別情報で追跡する
- 目的、受入条件、人間へ戻す判断点から、委ねる範囲と節目の完了条件を説明できる
- 判断待ちや競合を成功へ丸めず、人間判断を同じ一連の状態変化へ戻す
- 全タスクの成功だけでなく、統合結果と受入条件が成立した時だけ上位達成を表示する

## 制約

- Project Runtimeへ一般的なプロジェクト管理製品の全責務を持たせない
- 人間が決める内容を実行基盤が補完しない

## 検証意図

分岐タスク、部分成功、競合、判断待ち、再計画、統合拒否、停止後再開を与え、上位状態と再入場点を観測する。
