# REQ-000016 AIモデル設定内容の検証可能な外部構成

成果物種別: Discovery定義
要求ID: `REQ-000016`
Discoveryでの判断: 要求採用
判断する人: Qual-Lab
探索元: [EXP-000026](../../Analysis/EXP-000026/exploration.md)

## 要求

既存AI提供元との接続部の意味を変えないモデル、設定内容、仕事Profileへの割当およびCLI配置は、中核の改修を伴わず、検証可能な設定として更新できなければならない。導入環境は安定したProfileを追加し、登録済みProvider Adapter、許可Modelおよび推論設定へ割り当てられなければならない。

## 対象と利用状況

AI実行基盤を設定する運用者が、既存接続部で使えるProfile、Provider Adapter、モデル、推論設定およびCLI配置を更新する場面。Repository単体ではローカル設定、CROSではAdministratorが管理するServer設定を使う。

## 解く問題と望ましい変化

```text
現在: 利用可能なモデル一覧（Catalog）の変化と、実行環境の開始から終了・回復までの手順変更が同じ中核コードに結び付き、単純更新にもBuild／配布が必要になる。
    ↓
望ましい変化: 既存接続部の意味を変えない構成は、検証可能な設定として更新し、Host可用性と処理許可を確認して選択できる。
```

## 採用理由と比較

中核への全列挙は更新が重く、任意Executable設定は信頼を失うため、検証済み接続部の範囲内だけ外部構成する。

## 成立条件

- モデル、設定内容、仕事Profileへの割当、CLI配置をSchemaと接続部対応で検証する
- Profileは仕事の目的を表す安定IDを持ち、導入環境が追加できる
- Profileは登録済みProvider Adapter、Adapterが許すModelおよび検証可能な推論設定へ接続する
- Claude Code等の実行環境とgpt-6-astra等のModelを別の設定要素として扱う
- Repository単体とCROSで同じProfile Schemaを使い、設定Ownerと保存先を分ける
- 登録、Host可用、認証、処理許可を別々に判定する
- 構成変更後も既存接続部の起動、取消、結果意味が変わらない

## 制約

- 設定へ秘密情報、任意Executableまたは未検証引数を書かない
- 費用だけでモデルを自動選択しない
- v0.22ではProvider間の自動Fallbackまたは自己最適化を行わない

## 検証意図

Profile追加、Claude Code AdapterまたはCodex Adapterへの割当、gpt-6-astra等のModel追加、設定内容変更、CLI移動、未知Adapter、未知Model、Host不可および認証不足を与え、外部変更の前の選択と拒否を観測する。同じProfileが同じ有効設定から決定論的に一つの構成へ解決されることも確認する。
