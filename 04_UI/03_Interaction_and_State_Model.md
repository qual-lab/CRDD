## 1. 共通操作Flow

UI-000008の現行操作は[UI定義](Definitions/UI-000008/ui_definition.md#操作とfeedback)を正本とする。画面詳細は最新判断へ未追従である。指定ユーザー交換／全員交換×通常／Host入口の全4組で対象・失効範囲・既存発行先・保持情報を事前表示し、Host入口または全員交換の3組だけ明示確認する。独立失効は新発行なし。対象不明・必要な管理者不存在・必要状態の観測不能・認可破損は新Effect前停止とし、発行自体または結果記録が不明なら元発行Identityで現在再観測へ戻し、交換由来だけ同じexact Recoveryを保持する。発行・記録確定で受け渡しだけ未確認なら、確定事実を保持し現在認可の下で別の明示交換を選ぶ。完了・rollback・旧鍵有効・開始済み取消済みを推測表示せず、Secretを再表示しない。鍵の発行・独立失効・交換はadministrator専用固定で、Role詳細権限のON／OFF設定を設けない。通常鍵操作は同一Process Workbench backendだけで提供し、MCPには秘密値の有無を問わず鍵操作の一覧・Schema・登録・dispatchを公開しない。通常Host回復はログイン済みローカル操作者を信頼する対話CLIで交換2操作だけを扱い、追加認証・専用資格・承認コード・OS管理者昇格を要求しない。既存Root／Path検証を維持する。manager／administratorはユーザー登録・表示名変更、developer／managerの割当て・詳細権限、Repository登録・登録解除・公開範囲を管理する。administratorの付与・解除・降格を含むRole変更、administrator詳細権限と鍵3操作はadministratorだけが管理する。developerへ管理操作、managerへ管理者専用操作を設定で委譲しない。

```text
[対象を選ぶ]
      │
      ▼
[現在状態と利用範囲を確認]
      │
      ├─ 不明 / 欠測 / 制限 ─→ [根拠・Coverageを確認]
      │
      ├─ 人間判断が必要 ─────→ [判断内容と影響を確認]
      │
      └─ 操作可能 ───────────→ [操作内容とEffectを確認]
                                      │
                                      ▼
                                  [実行する]
                                      │
                   ┌──────────────────┼──────────────────┐
                   ▼                  ▼                  ▼
                完了               停止               結果不明
                   │                  │                  │
                   ▼                  ▼                  ▼
              次の行動へ      理由別の処置へ      回復義務を保持
```

登録解除・鍵の受け渡し未確認の現在の限定投影：登録解除は対象の登録と対応Exposureを同じ受理操作で除去する。事前の別操作による公開解除を必須にせず、以後の対象CROSアクセスを停止する。他Repositoryの登録／Exposureと対象Repository本体・Product Dataは保持する。発行自体または結果記録が不明なら、Credential IDとは別の非秘密な元発行Identityで現在再観測し、新交換を開始しない。交換由来だけ元のsame exact Recoveryを保持し、通常発行へ交換Recoveryを新設しない。発行・結果記録が確定し配送／受領だけ未確認なら、「発行済み・受け渡し未確認」と示し、確定事実を維持する。Secretの保存・再表示・自動再発行はしない。現在認可されたadministratorが人間の明示した既存交換を新しく開始でき、そのOperation／Recoveryは元処理とは別にする。現在の管理認証を失った場合は、Workbench認可を迂回せず既存Host交換入口へ案内する。Detail候補へ伝播中・今回の契約／品質限定独立再レビュー済み（残指摘0）。Visual／Architecture／Quality／Sourceへは今回未伝播であり、以前のDetail限定レビューを今回へ流用しない。

## 2. 取消・回復Flow

```text
実行中
  │ action: 取消
  ▼
取消要求済み ── 完了通知待ち
  │
  ├─ cleanup確認済み ─→ 停止結果 / 次の行動
  └─ cleanup不明 ─────→ 回復義務あり
                              │
                              ▼
                         回復処置中
                              │
                              ├─ 終了後確認済み ─→ 義務解消
                              └─ 観測不能 ───────→ 義務維持
```

取消要求、Process終了、資源回収、回復処置、回復義務解消を同じ状態へ畳まない。

## 3. 表示状態の共通Variant

| Variant | 利用者へ示す内容 | 主な操作 |
|---|---|---|
| 初期／未選択 | 選択対象と利用可能範囲 | 対象を選ぶ |
| 読み込み中 | 何をいつから取得中か | 待機、必要時だけ取消 |
| 空 | 0件なのか未取得なのか | 作成、再取得、情報源確認 |
| 一部取得 | 取得済み範囲、欠測、制限 | 利用可能範囲で続行、根拠確認 |
| 判断待ち | 判断主体、選択肢、影響、保留時 | 判断する、保留する |
| 操作中 | 対象、操作、取消可否 | 待機、許可時のみ取消 |
| 完了 | 結果、Effect、根拠、次行動 | 結果確認、次工程へ進む |
| 停止 | 理由、Effect有無、cleanup、再開条件 | 是正、回復、担当者へ渡す |
| 結果不明 | 不明な範囲、再実行禁止、回復参照 | 状態確認、専用回復 |
| 権限なし | 開示可能な範囲だけの理由 | Credential切替または終了 |
| 競合／古い情報 | 競合対象、観測時点、再読込み条件 | 正本確認、再取得 |

## 4. 操作の表示原則

- 主要操作は現在の利用者目的に直接進む一つを優先する。
- 不可逆操作、外部送信、Authority発行、再試行は対象・影響・境界を実行前に示す。
- 利用不能な操作は隠すか無効化するだけでなく、存在開示が許可される場合に理由と代替を示す。
- 成功表示はSystemの完了条件を満たした時だけ使い、受付、開始、要求発行または候補生成を完了と表示しない。
