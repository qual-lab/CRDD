# UX-000005のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000005`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000005 目的と受入条件で節目を委ねる](../../../02_UX/Definitions/UX-000005/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「プロジェクト運営者／PM」 |
| 利用のきっかけ | プロジェクトの成果をまとめて任せる時 |
| 目的 | 目的と受入条件で節目を委ねる |
| 得たい結果 | 内部タスクを追わず統合済みの完成を判断できる |
| 独立した利用者成果 | 内部タスクを逐次操作せず、目的・受入条件・統合状態から節目の完成と必要な判断を理解できる |
| 重要な場面 | タスク成功と節目完成を区別する |
| 避ける失敗 | タスク件数を完成と誤認する |
| 守る品質 | 統合・品質・判断待ちを分けて示す |

## 3. 必要な認識・操作・Feedback

```text
プロジェクトの成果をまとめて任せる時
        ↓
確認すること: 目的、受入条件、節目、タスク、統合状態、品質、および同じ節目へ戻るための再開条件を関連付ける
        ↓
利用者の目的: 目的と受入条件で節目を委ねる
        │
        ├─ ★ 判断点: タスク成功と節目完成を区別する
        ├─ ⚠ 避ける失敗: タスク件数を完成と誤認する
        └─ ✓ 必要なFeedback: 統合・品質・判断待ちを分けて示す
        ↓
内部タスクを追わず統合済みの完成を判断できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「タスク成功と節目完成を区別する」で利用者が「内部タスクを追わず統合済みの完成を判断できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「プロジェクトの成果をまとめて任せる時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「内部タスクを追わず統合済みの完成を判断できる」を、統合・品質・判断待ちを分けて示すという条件で確認できる |
| 成果不成立 | 「タスク件数を完成と誤認する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 回復／再開 | 同じ対象へ戻る条件と、未解消の義務を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「目的、受入条件、節目、タスク、統合状態、品質、および同じ節目へ戻るための再開条件を関連付ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「タスク数や部分成功を完成へ畳む表示と、停止後に目的・受入条件・判断点を失った別の節目として再開する挙動を反証する」を確かめられる形を保ち、下流へ「IAは目的、節目、タスク、統合状態、品質および判断の関係を分ける。SPECとArchitectureは同じ目的・節目・判断点へ戻る再開契約を具体化し、Verificationはタスク数でなく一連の委任体験を確認する。」を渡す。必要情報をここで推測して先取りしない。
