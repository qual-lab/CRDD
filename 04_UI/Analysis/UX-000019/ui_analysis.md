## 1. 正式入力

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「外部へ渡す情報の所有者」／「プロジェクト運営者／PM」 |
| 利用のきっかけ | 別Agentやツールへ仕事を渡す時、または結果を受け取る時 |
| 目的 | 必要な情報だけを出所付きで渡す |
| 得たい結果 | 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる |
| 独立した利用者成果 | 必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる |
| 重要な場面 | 外部境界へ情報を出す直前 |
| 避ける失敗 | 全量投入・秘密情報混入・古い仮説の現在値化 |
| 守る品質 | 情報源・改訂版・選択理由を保持する |

## 3. 必要な認識・操作・Feedback

```text
別Agentやツールへ仕事を渡す時、または結果を受け取る時
        ↓
確認すること: 受け渡す情報一式、情報源、タスク、結果、根拠、引き渡し、判断を関連付ける
        ↓
利用者の目的: 必要な情報だけを出所付きで渡す
        │
        ├─ ★ 判断点: 外部境界へ情報を出す直前
        ├─ ⚠ 避ける失敗: 全量投入・秘密情報混入・古い仮説の現在値化
        └─ ✓ 必要なFeedback: 情報源・改訂版・選択理由を保持する
        ↓
必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「外部境界へ情報を出す直前」で利用者が「必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「別Agentやツールへ仕事を渡す時、または結果を受け取る時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「必要最小限の情報を出所・現行性・許可付きで渡し、相関・完全性付きの結果を同じタスクへ戻せる」を、情報源・改訂版・選択理由を保持するという条件で確認できる |
| 成果不成立 | 「全量投入・秘密情報混入・古い仮説の現在値化」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 判断・許可 | 誰が何を決めるかと、許可前後の状態を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「受け渡す情報一式、情報源、タスク、結果、根拠、引き渡し、判断を関連付ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「全量投入、秘密情報混入、情報捏造、別タスク結果混入およびAgent完了の自動採用を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
