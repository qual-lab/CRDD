## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | Project運営者、Meeting参加者、Topic責任者が論点や会議記録を日常的に扱う |
| 利用のきっかけ | 登録、確認、更新、終了、訂正または誤登録削除を行う時 |
| 目的 | Topicの継続状態とMeetingの時点記録を経緯・関係ごと維持する |
| 得たい結果 | 入口を変えても同じ記録へ到達し、正当な履歴を残して誤登録だけを安全に除ける |
| 重要な場面 | 物理削除を確定する直前 |
| 避ける失敗 | 正当な履歴、関連対象または関係整合性を失う |
| 守る品質 | 影響と復旧可能性を示し、明示確認後も関係を整合させる |

## 3. 必要な認識・操作・Feedback

```text
Topic／Meetingを扱う
        ↓
現在状態・記録時点・関係・経緯を認識する
        ↓
作成／取得／更新／終了／訂正／削除 ──→ 結果・競合・残存関係・回復可能性
        ↓
正当な履歴を保って次の判断へ進む
```

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | Topicの継続状態とMeetingの時点記録を見分けられる |
| 成果成立 | 対象、関係、処置および終了後状態を確認できる |
| 成果不成立 | 競合、部分成功、権限不足と安全な戻り先を理解できる |
| 判断不能 | 影響または復旧可能性が不明な削除を確定できない |

## 5. UI処置

| UI候補 | 処置 | 保持する利用者成果 | 判断理由 |
|---|---|---|---|
| [UI-000009](../../Definitions/UI-000009/ui_definition.md) | Same | 論点と会議記録を安全に維持する | Meeting・Topicの判断と処置を担う既存UI責務を、登録・更新・終了・訂正・安全な削除まで拡張する |

## 6. IA観点との統合時に確認すること

Topic、Meeting、記録時点、関係、Lifecycle処置、削除影響および操作結果を見分け、削除前後の関係整合と回復可能性を判断できるかを確認する。
