| 観点 | UX定義から受け取る内容 |

| 目的 | 故障した境界と影響する能力を特定する |
| 得たい結果 | AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる |
| 独立した利用者成果 | AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる |
| 重要な場面 | 一つの失敗を全体障害と判断する直前 |
| 避ける失敗 | 一律の失敗表示で無関係な能力まで停止する |
| 守る品質 | 失敗した場所・影響範囲・利用可能性を分ける |

## 3. 必要な認識・操作・Feedback

```text
AI実行環境の導入または利用が止まった時
        ↓
確認すること: AI実行環境ごとの認証、起動、取消、結果取得、回復、利用可能な機能を関連付ける
        ↓
利用者の目的: 故障した境界と影響する能力を特定する
        │
        ├─ ★ 判断点: 一つの失敗を全体障害と判断する直前
        ├─ ⚠ 避ける失敗: 一律の失敗表示で無関係な能力まで停止する
        └─ ✓ 必要なFeedback: 失敗した場所・影響範囲・利用可能性を分ける
        ↓
AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「一つの失敗を全体障害と判断する直前」で利用者が「AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「AI実行環境の導入または利用が止まった時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「AI実行環境の認証・起動・取消・結果取得・回復のどこに違いがあり、故障時に何が利用可能かを理解できる」を、失敗した場所・影響範囲・利用可能性を分けるという条件で確認できる |
| 成果不成立 | 「一律の失敗表示で無関係な能力まで停止する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 取消 | 取消要求と実際の停止・後始末完了を同じ結果として扱わない |
| 回復／再開 | 同じ対象へ戻る条件と、未解消の義務を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「AI実行環境ごとの認証、起動、取消、結果取得、回復、利用可能な機能を関連付ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「認証・起動・取消・結果取得・回復の違いを同じ失敗へ畳む表示と、利用可能な機能まで停止する判断を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
