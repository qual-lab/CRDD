## 1. 正式入力

- UX定義: [UX-000021 切断後も同じ依頼へ戻る](../../../02_UX/Definitions/UX-000021/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「プロジェクト運営者／PM」 |
| 利用のきっかけ | 応答喪失後に再接続する時 |
| 目的 | 切断後に同じ依頼へ戻る |
| 得たい結果 | 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる |
| 独立した利用者成果 | 応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる |
| 重要な場面 | 再実行するか判断する直前 |
| 避ける失敗 | Timeoutを未実行とみなし新規外部作用（Effect）を起こす |
| 守る品質 | 同一識別情報の照会を再実行より先に示す |

## 3. 必要な認識・操作・Feedback

```text
応答喪失後に再接続する時
        ↓
確認すること: 依頼の識別情報、接続単位、現在の利用権限、結果、回復を結ぶ
        ↓
利用者の目的: 切断後に同じ依頼へ戻る
        │
        ├─ ★ 判断点: 再実行するか判断する直前
        ├─ ⚠ 避ける失敗: Timeoutを未実行とみなし新規外部作用（Effect）を起こす
        └─ ✓ 必要なFeedback: 同一識別情報の照会を再実行より先に示す
        ↓
応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「再実行するか判断する直前」で利用者が「応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「応答喪失後に再接続する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「応答喪失後に新規実行せず、現在の利用権限で同じ依頼の状態・結果・回復義務へ戻れる」を、同一識別情報の照会を再実行より先に示すという条件で確認できる |
| 成果不成立 | 「Timeoutを未実行とみなし新規外部作用（Effect）を起こす」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 回復／再開 | 同じ対象へ戻る条件と、未解消の義務を区別する |
| 判断・許可 | 誰が何を決めるかと、許可前後の状態を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「依頼の識別情報、接続単位、現在の利用権限、結果、回復を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「再接続時の外部作用（Effect）の二重実行、古いセッションの決定権限および別依頼への誤結合を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
