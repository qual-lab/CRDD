# UX-000018のUI分析

## 1. 正式入力

- UX定義: [UX-000018 AIモデル構成を安全に更新・選択する](../../../02_UX/Definitions/UX-000018/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「実行環境の導入・運用者」 |
| 利用のきっかけ | 利用モデルやAI提供元条件を変更する時 |
| 目的 | AIモデル選択を検証可能な構成として更新する |
| 得たい結果 | 新モデルへ追随してもコード改修を繰り返さずに済む |
| 独立した利用者成果 | 新しいモデルへ追随するとき、コード改修を待たず検証済み構成を更新し、実効選択と再選定理由を理解できる |
| 重要な場面 | AI提供元で実行する前のモデル確定 |
| 避ける失敗 | 未知または非対応のモデルを実行可能と表示する |
| 守る品質 | 構成変更を検証し実効選択を観測可能にする |

## 3. 必要な認識・操作・Feedback

```text
利用モデルやAI提供元条件を変更する時
        ↓
確認すること: Model 設定内容、利用可否、Selection、理由、Fallback Conditionを結ぶ
        ↓
利用者の目的: AIモデル選択を検証可能な構成として更新する
        │
        ├─ ★ 判断点: AI提供元で実行する前のモデル確定
        ├─ ⚠ 避ける失敗: 未知または非対応のモデルを実行可能と表示する
        └─ ✓ 必要なFeedback: 構成変更を検証し実効選択を観測可能にする
        ↓
新モデルへ追随してもコード改修を繰り返さずに済む
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「AI提供元で実行する前のモデル確定」で利用者が「新モデルへ追随してもコード改修を繰り返さずに済む」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「利用モデルやAI提供元条件を変更する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「新モデルへ追随してもコード改修を繰り返さずに済む」を、構成変更を検証し実効選択を観測可能にするという条件で確認できる |
| 成果不成立 | 「未知または非対応のモデルを実行可能と表示する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「Model 設定内容、利用可否、Selection、理由、Fallback Conditionを結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「未知設定の黙示代替、非対応モデルの実行可能表示および無説明選択を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
