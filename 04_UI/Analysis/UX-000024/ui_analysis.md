# UX-000024のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000024`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000024 外部利用の送信・持帰り・昇格を制御する](../../../02_UX/Definitions/UX-000024/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「外部へ渡す情報の所有者」 |
| 利用のきっかけ | 外部AI・検索・公開Communication・管理対象依存を利用する時 |
| 目的 | 送信範囲と内部へ戻す際の昇格条件を理解する |
| 得たい結果 | 不要情報を漏らさず人間判断を保って外部連携できる |
| 独立した利用者成果 | 外部作用（Effect）の前に送信先・目的・操作・情報分類・許可範囲を理解し、外部情報・反応・依存新版を出典付き候補として扱える |
| 重要な場面 | 外部作用（Effect）の前と結果昇格時 |
| 避ける失敗 | 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する |
| 守る品質 | 同意・投影・採用を分離する |

## 3. 必要な認識・操作・Feedback

```text
外部AI・検索・公開Communication・管理対象依存を利用する時
        ↓
確認すること: 送信先、目的、情報分類、同意、候補を結ぶ
        ↓
利用者の目的: 送信範囲と内部へ戻す際の昇格条件を理解する
        │
        ├─ ★ 判断点: 外部作用（Effect）の前と結果昇格時
        ├─ ⚠ 避ける失敗: 接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する
        └─ ✓ 必要なFeedback: 同意・投影・採用を分離する
        ↓
不要情報を漏らさず人間判断を保って外部連携できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「外部作用（Effect）の前と結果昇格時」で利用者が「不要情報を漏らさず人間判断を保って外部連携できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「外部AI・検索・公開Communication・管理対象依存を利用する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「不要情報を漏らさず人間判断を保って外部連携できる」を、同意・投影・採用を分離するという条件で確認できる |
| 成果不成立 | 「接続済みを包括許可とし、外部反応や依存新版を要求・因果・方針へ自動昇格する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 判断・許可 | 誰が何を決めるかと、許可前後の状態を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「送信先、目的、情報分類、同意、候補を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「接続済み・過去同意からの包括許可、不要情報送信、外部反応・依存新版の要求／因果／方針への自動昇格を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
