# UX-000009のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000009`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000009 プロジェクトの現在地を根拠と不完全性付きで理解する](../../../02_UX/Definitions/UX-000009/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「プロジェクト運営者／PM」 |
| 利用のきっかけ | プロジェクト状況を確認する時 |
| 目的 | プロジェクトの現在地を根拠と不完全性付きで理解する |
| 得たい結果 | 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる |
| 独立した利用者成果 | 物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる |
| 重要な場面 | 現在の表示を信じる直前 |
| 避ける失敗 | 欠測や古い値を完全な現在値と誤認する |
| 守る品質 | 根拠、不完全性、観測時点を同時に示す |

## 3. 必要な認識・操作・Feedback

```text
プロジェクト状況を確認する時
        ↓
確認すること: プロジェクト、項目、情報源、改訂版、観測時点、網羅範囲および次の判断を関連付ける
        ↓
利用者の目的: プロジェクトの現在地を根拠と不完全性付きで理解する
        │
        ├─ ★ 判断点: 現在の表示を信じる直前
        ├─ ⚠ 避ける失敗: 欠測や古い値を完全な現在値と誤認する
        └─ ✓ 必要なFeedback: 根拠、不完全性、観測時点を同時に示す
        ↓
物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「現在の表示を信じる直前」で利用者が「物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「プロジェクト状況を確認する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「物理構成を意識せずプロジェクトの現在地を理解し、欠測・制限・競合・古さと情報源へ戻れる」を、根拠、不完全性、観測時点を同時に示すという条件で確認できる |
| 成果不成立 | 「欠測や古い値を完全な現在値と誤認する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「プロジェクト、項目、情報源、改訂版、観測時点、網羅範囲および次の判断を関連付ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「partial、stale、restricted、conflictingおよび未観測値の誤認を反証する」を確かめられる形を保ち、下流へ「IAは項目ごとの情報源、現行性、網羅範囲、競合および不足を踏まえた次の判断を表現する。UIは不完全性を0件や正常状態と同じ見た目にせず、Verificationは完全性を崩す反例を使う。」を渡す。必要情報をここで推測して先取りしない。
