| 避ける失敗 | 主経路だけ移行し副次利用側を取り残す |
| 守る品質 | 旧能力・全利用側・置換根拠を閉じる |

## 3. 必要な認識・操作・Feedback

```text
責務・契約・接続部または実行環境の構成を変更する時
        ↓
確認すること: 変更前の機能、公開契約、利用側、置換後の実装、根拠を結ぶ
        ↓
利用者の目的: 維持・変更・廃止された能力と利用側を確認する
        │
        ├─ ★ 判断点: 変更を完了・公開可能と判断する直前
        ├─ ⚠ 避ける失敗: 主経路だけ移行し副次利用側を取り残す
        └─ ✓ 必要なFeedback: 旧能力・全利用側・置換根拠を閉じる
        ↓
責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「変更を完了・公開可能と判断する直前」で利用者が「責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「責務・契約・接続部または実行環境の構成を変更する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「責務・契約・接続部の変更後も、維持・変更・廃止された能力を理解し、取り残しのない結果を安全に利用・公開できる」を、旧能力・全利用側・置換根拠を閉じるという条件で確認できる |
| 成果不成立 | 「主経路だけ移行し副次利用側を取り残す」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 回復／再開 | 同じ対象へ戻る条件と、未解消の義務を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「変更前の機能、公開契約、利用側、置換後の実装、根拠を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「主経路だけの移行、旧契約残存および根拠のない旧処理削除を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
