# UX-000022のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000022`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000022 残存資源を安全に回復・清掃する](../../../02_UX/Definitions/UX-000022/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「実行環境の導入・運用者」 |
| 利用のきっかけ | 失敗後または保守時に残存を見つけた時 |
| 目的 | 残存資源の由来・保持・清掃・回復を理解する |
| 得たい結果 | 必要な根拠を残し不要物を安全に片付けられる |
| 独立した利用者成果 | 失敗後に残存の由来・影響・再入場先を理解し、必要な回復を行って不存在まで確認できる |
| 重要な場面 | 削除または回復を選ぶ場面 |
| 避ける失敗 | 名前や経過時間だけで由来不明物を削除する |
| 守る品質 | 残存・観測不能・不存在を区別する |

## 3. 必要な認識・操作・Feedback

```text
失敗後または保守時に残存を見つけた時
        ↓
確認すること: 残存物、回復対象の識別情報、処置、不存在の根拠を結ぶ
        ↓
利用者の目的: 残存資源の由来・保持・清掃・回復を理解する
        │
        ├─ ★ 判断点: 削除または回復を選ぶ場面
        ├─ ⚠ 避ける失敗: 名前や経過時間だけで由来不明物を削除する
        └─ ✓ 必要なFeedback: 残存・観測不能・不存在を区別する
        ↓
必要な根拠を残し不要物を安全に片付けられる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「削除または回復を選ぶ場面」で利用者が「必要な根拠を残し不要物を安全に片付けられる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「失敗後または保守時に残存を見つけた時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「必要な根拠を残し不要物を安全に片付けられる」を、残存・観測不能・不存在を区別するという条件で確認できる |
| 成果不成立 | 「名前や経過時間だけで由来不明物を削除する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 回復／再開 | 同じ対象へ戻る条件と、未解消の義務を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「残存物、回復対象の識別情報、処置、不存在の根拠を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「清掃要求だけの完了表示、別処理の巻込みおよび不明状態での削除を反証する」を確かめられる形を保ち、下流へ「IAは残存物、保持期間、回復、清掃を分け、ArchitectureとVerificationは一連の状態変化全体を実境界で確認する。」を渡す。必要情報をここで推測して先取りしない。
