## 2. 正式入力から保持する情報構造

| 対象 | 保持する意味・関係 |
|---|---|
| ユーザー | 安定userId、表示専用名、一つの現行Role。同名・改名はIdentity／Authority変更ではない |
| 接続資格 | Credential ID→userId。生Secretを含めず、古いRole権限を固定しない |
| Role／Role詳細権限 | administrator／manager／developer。詳細権限はRoleが所有し、ユーザー・資格への個別追加権限なし |
| Repository Exposure | Repository IDと公開対象範囲。Role権限・実アクセスとは別 |
| 実アクセス可能性 | Repository IDと現在の取得可能性。不明・取得不能を利用可能にしない |
| 接続中の作業単位 | Session ID、Credential ID、userId。認可は現行Roleへ結び直す |
| Repository情報範囲／リポジトリ | Repository IDと情報責務・内容正本。利用者Roleや公開設定ではない |
| 管理能力 | 現行Roleの管理許可。内容閲覧を自動的に得ない |
| Secret表示境界 | 発行／鍵交換後だけ一度表示。永続Identityを作らない |
| 接続資格状態 | 有効／期限切れ／失効／不明。リセット専用の永続状態は作らない |
| Access Recovery | 同じRecovery ID、操作種別（指定ユーザー交換／全員交換）と入口・Authority属性 |
| Recovery対象／保持対象／結果 | 対象userId・失効資格集合・既存発行先、保持するユーザー情報・Role権限・Repository登録・Product Data、失効確定範囲と発行結果・結果改訂・再入場先 |

userIdは正式入力の採用済みUUID制約を継承する。版・Schema・生成方式をここで決めない。
ユーザー／Credential／Role権限→Repository Exposure→実アクセス→Repository内容の関係を保持する。管理能力はRoleの別の許可であり、Repository情報責務はこの許可連鎖とは別にRepositoryが所有する。

## 3. 利用場面・状態・導線

| 利用場面 | 対象と状態 | 保持する導線 |
|---|---|---|
| Remote利用 | 自身、資格、現行Role、公開／実アクセス、利用可能／資格要求／制限／利用不能／不明と複数対象の部分成立 | 資格→ユーザー→現行Role権限→公開対象→実アクセス→情報源 |
| 通常管理 | 管理対象ID・表示名・現行Role・資格の有効／期限切れ／失効／不明 | 対象→現行値→変更またはリセットの影響→結果 |
| 鍵交換 | 2操作の範囲・発行先・保持情報、2入口のAuthority、確認待ち／進行中／blocked／completed、失効確定／発行不明 | 入口確認→操作範囲・既存対象／発行先・保持情報→同じRecovery→現在再観測→新資格で再入場 |

認証済み利用者の自身表示、非認証入口へのユーザー情報0、非管理者への他ユーザー一覧・存在・件数0を別々に保持する。Repository非開示対象の存在・名前・件数も漏らさない。
部分成立を全体利用可能にせず、未観測・古い値・競合を正常や不存在へ畳まない。鍵交換のID／Role保持、旧資格拒否と開始済み取消の分離、Role変更の次認可反映を保持する。

指定ユーザー交換／全員交換は操作範囲、通常管理／Hostは入口・Authorityとして別軸にする。両入口で同じ2操作を扱い、ユーザーID・表示名・Role・詳細権限・Repository登録・Product Dataを保持する。対象は表示名ではなく既存userIdで固定する。特別ユーザー・追加権限・回復専用Bootstrapを作らず、認可設定破損の修復を鍵交換に含めない。初回Server設定方式は変更しない。

| 操作 | 失効範囲 | 新資格の発行先 | 保持する違い |
|---|---|---|---|
| 指定ユーザー交換 | 対象userIdの全旧有効資格 | 同じ既存userId | 他ユーザーの鍵を保持 |
| 全員交換 | 全ユーザーの全旧有効資格 | 指定した既存administrator userId | 他ユーザーはその管理者による通常の再発行・再配布まで旧資格利用不能 |

通常入口は現行管理認可、Host入口はHost OS Authorityを確認する。Host入口と全員交換は人間の明示確認を必要とする。

処置前に対象ID・表示名、失効範囲、既存発行先、保持情報を示す。全員交換では操作中の管理者自身の旧鍵も失効し、新Secretは一度だけ受け取ることを明示する。失効後の発行失敗・応答喪失・Process喪失では、失効確定範囲と新資格発行結果の不明を別に示し、同じRecoveryへ戻る確認先を示す。現在再観測前に完了・rollback・旧資格利用可能・開始済み操作取消済みと表示せず、Secretを再表示しない。対象不明・管理者不存在・必要状態を安全に確認不能・認可設定破損では処置前停止を示す。

## 4. 表示優先度・責任

自身と現在利用できる対象を先に示し、管理者には対象ID・表示名・Role・資格状態・処置影響を示す。緊急時は種別・対象・保持範囲と現在地を優先する。色だけで状態を伝えず、名前・状態語と意味順を保つ。

情報契約上の管理責任、Host回復責任、Repository内容責任を保持し、Component配置や物理保存方式は決めない。
