# UX-000032のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000032`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000032 実行事実を安全に記録して結果を確かめる](../../../02_UX/Definitions/UX-000032/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析は作成側の利用者成果、操作、Feedbackと体験差だけを導く。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 実行基盤・TypeScriptアプリの組込み担当者 |
| 利用のきっかけ | 観測した実行事実を共有可能にする時 |
| 目的 | 同じ意味で取得できる記録を安全に一度だけ公開する |
| 得たい結果 | 記録済み・未記録・結果不明を見分け、重複や上書きなく次の処置を選べる |
| 重要な場面 | 保存要求後に結果確認が途切れる時 |
| 避ける失敗 | 未記録と推定して再発行し、重複または別実行の上書きを起こす |
| 守る品質 | 同じ識別情報で再観測し、結果不明を保つ |

## 3. 必要な認識・操作・Feedback

```text
観測した事実を残す
        ↓
記録対象と許可範囲を確認
        ↓
記録を依頼 ──→ 記録済み／未記録／結果不明
        │                         │
        └──────── 結果不明 ──────┘
                         ↓
                 同じ試行を再観測
```

作成側は「記録を依頼する」と「同じ試行を再観測する」を見分ける。結果不明時に再発行を既定操作として見せない。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 記録対象、情報源、観測時点、許可範囲を確認できる |
| 成果成立 | 完成記録と同じ実行・試行を対応付けて確認できる |
| 成果不成立 | Effect 0を確認した未記録と、修正して再依頼できる理由を受け取る |
| 判断不能 | 結果不明を保持し、同じ実行・試行の再観測へ進める |

## 5. UI処置

| UI候補 | 処置 | 保持する利用者成果 | 判断理由 |
|---|---|---|---|
| [UI-000020 実行記録の依頼と結果確認](../../Definitions/UI-000020/ui_definition.md) | New | 実行事実を安全に記録して結果を確かめる | 記録Effectを発行する操作と結果不明時の再観測は、読取り診断とは異なる利用者操作・Authority境界を持つ |

## 6. IA観点との統合時に確認すること

記録対象、作成側、記録試行、公開状態、衝突先および回復先を、利用者が同じ実行へ対応付けられるかを確認する。具体的なAPI、保存形式、Lock方式は先取りしない。
