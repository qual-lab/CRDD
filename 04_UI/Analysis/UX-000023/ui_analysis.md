# UX-000023のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000023`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000023 監査・是正・判断を一つの改訂版で閉じる](../../../02_UX/Definitions/UX-000023/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「CRDD作成者・保守者」 |
| 利用のきっかけ | 複数指摘を是正する時 |
| 目的 | 監査合意から是正・反証までを一つの改訂版で閉じる |
| 得たい結果 | 小出しの指摘と局所PatchのLoopを減らせる |
| 独立した利用者成果 | 合意した条件、適用先、反証、未処置および現在必要な人間判断を一つの改訂版で理解して収束できる |
| 重要な場面 | 再レビューへ固定候補を渡す直前 |
| 避ける失敗 | 一部是正や監査回数を完成と誤認する |
| 守る品質 | 合意事項と試験を全数対応させる |

## 3. 必要な認識・操作・Feedback

```text
複数指摘を是正する時
        ↓
確認すること: 指摘、是正、Verification、判断要求、現在の改訂版を結ぶ
        ↓
利用者の目的: 監査合意から是正・反証までを一つの改訂版で閉じる
        │
        ├─ ★ 判断点: 再レビューへ固定候補を渡す直前
        ├─ ⚠ 避ける失敗: 一部是正や監査回数を完成と誤認する
        └─ ✓ 必要なFeedback: 合意事項と試験を全数対応させる
        ↓
小出しの指摘と局所PatchのLoopを減らせる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「再レビューへ固定候補を渡す直前」で利用者が「小出しの指摘と局所PatchのLoopを減らせる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「複数指摘を是正する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「小出しの指摘と局所PatchのLoopを減らせる」を、合意事項と試験を全数対応させるという条件で確認できる |
| 成果不成立 | 「一部是正や監査回数を完成と誤認する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「指摘、是正、Verification、判断要求、現在の改訂版を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「指摘の小出し適用、解消済み判断の再要求および一部是正の完成表示を反証する」を確かめられる形を保ち、下流へ「IAは指摘、判断、是正、根拠を分け、WorkflowとVerificationは収束完了条件を具体化する。」を渡す。必要情報をここで推測して先取りしない。
