# IA-000013のUI分析

成果物種別: UI分析（IA観点）
分析単位: `IA-000013`
状態: 分析済み

## 1. 正式入力

- IA定義: [IA-000013 AIモデル構成・選択・再選定](../../../03_IA/Definitions/IA-000013/ia_definition.md)

UXやREQを直接読んで不足を補完しない。この分析はIA定義から情報設計観点だけを導き、利用者成果と操作体験はUX観点の分析に委ねる。

## 2. UIへ引き継ぐ情報構造

コード改修なしに検証済み構成を更新し、実効選択と理由を理解する。

| 対象 | 利用者にとっての意味 | 識別・関係 |
|---|---|---|
| AIモデル（Model） | 利用候補のAIモデル | Provider＋Model ID |
| 構成（Configuration） | 許可候補と制約 | 構成の改訂版（Config Revision） |
| 作業上の役割（Task Role） | 実行・確認等の必要役割 | Taskへ結合 |
| 利用可否（Availability） | 現在利用可能か | Model＋Environment |
| 選択結果（Selection） | 今回の実効選択 | Task＋Model |
| 再選定条件（Fallback Condition） | 再選定する条件 | 選択結果（Selection）へ結合 |

UIでは「AIモデル（Model）、構成（Configuration）、作業上の役割（Task Role）、利用可否（Availability）、選択結果（Selection）、再選定条件（Fallback Condition）」の識別と関係を維持する。同名・近似値、未観測・不存在、現在値・古い値を表示都合でまとめない。

## 3. 表示の優先順位とNavigation

| 利用場面 | 最初に見分ける対象 | 区別する状態 | 次の導線 |
|---|---|---|---|
| `UX-000018`／実行環境の導入・運用者／利用モデルやAI提供元条件を変更する時 | AIモデル（Model）、構成（Configuration）、作業上の役割（Task Role）、利用可否（Availability）、選択結果（Selection）、Reason、再選定条件（Fallback Condition） | 有効（valid）／無効（invalid）／利用可能（available）／利用不能（unavailable）／選択済み（selected） | 設定→検証→利用可能候補→選択→理由・再選定条件 |

```text
AIモデル構成・選択・再選定
        ↓
対象と現在状態
        ↓
不足・制限・競合
        ↓
関係・根拠
        ↓
判断／回復／次の対象
```

内部ID、生Log、実装詳細は最初の結論へ混在させず、根拠を掘り下げる段階で示す。

## 4. 表示差と開示境界

IA定義が要求する状態区分:

- `UX-000018`: 有効（valid）／無効（invalid）／利用可能（available）／利用不能（unavailable）／選択済み（selected）

IA定義が要求する導線と責任:

- 実行環境の導入・運用者: 利用モデルやAI提供元条件を変更する時に「AIモデル選択を検証可能な構成として更新する」ために必要な判断を行う。システムは「未知または非対応のモデルを実行可能と表示する」を避けられるよう、構成変更を検証し実効選択を観測可能にする。

値なし、未観測、古い値、競合、部分取得、開示制限および結果不明は、それぞれ利用者の次の判断が異なる場合に別の表示状態として扱う。開示できない対象は、その存在自体を示せるかも決定権限に従う。

## 6. UX観点との統合時に確認すること

UX観点の分析が求める利用者成果、重要場面、操作およびFeedbackに対し、「AIモデル構成・選択・再選定」の対象・状態・関係・導線が過不足なく判断材料を提供するかをUI定義で確認する。IAからUIへ引き渡す固有の意図は「UIは実効値と理由を、SPECは選定規則を、Architectureは構成読取りとProvider照会を定める。」であり、利用者の目的をここで推測して先取りしない。
