# UX-000031のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000031`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000031 公式の識別と保証を混同せず見分ける](../../../02_UX/Definitions/UX-000031/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「CRDD閲覧者」 |
| 利用のきっかけ | 公式らしい入口や視覚素材を見つけた時 |
| 目的 | 識別表示と保証の根拠を分けて確認する |
| 得たい結果 | 見た目だけを信頼根拠にせず適切な入口を選べる |
| 独立した利用者成果 | CRDDの公式入口や素材を視覚的に見分けながら、その表示だけを署名・準拠・品質または発行元への信頼の証明と誤認せず利用できる |
| 重要な場面 | 公式表示を信頼判断へ用いる直前 |
| 避ける失敗 | アイコンや見た目を署名・準拠・品質保証と誤認する |
| 守る品質 | 識別表示と検証可能な信頼根拠を別に示す |

## 3. 必要な認識・操作・Feedback

```text
公式らしい入口や視覚素材を見つけた時
        ↓
確認すること: 公式識別、配布者、署名、準拠状況、品質上の主張を分ける
        ↓
利用者の目的: 識別表示と保証の根拠を分けて確認する
        │
        ├─ ★ 判断点: 公式表示を信頼判断へ用いる直前
        ├─ ⚠ 避ける失敗: アイコンや見た目を署名・準拠・品質保証と誤認する
        └─ ✓ 必要なFeedback: 識別表示と検証可能な信頼根拠を別に示す
        ↓
見た目だけを信頼根拠にせず適切な入口を選べる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「公式表示を信頼判断へ用いる直前」で利用者が「見た目だけを信頼根拠にせず適切な入口を選べる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「公式らしい入口や視覚素材を見つけた時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「見た目だけを信頼根拠にせず適切な入口を選べる」を、識別表示と検証可能な信頼根拠を別に示すという条件で確認できる |
| 成果不成立 | 「アイコンや見た目を署名・準拠・品質保証と誤認する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 判断・許可 | 誰が何を決めるかと、許可前後の状態を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「公式識別、配布者、署名、準拠状況、品質上の主張を分ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「公式／非公式表示、保証根拠の欠落、見た目だけの信頼推定および識別不能な入口を反証する」を確かめられる形を保ち、下流へ「IAは識別表示と保証根拠を別Informationとして扱う。UI／Communicationは両者を誤認させず、SPECとVerificationは公式表示だけから信頼を成立させない。」を渡す。必要情報をここで推測して先取りしない。
