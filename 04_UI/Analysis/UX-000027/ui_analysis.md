# UX-000027のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000027`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000027 物語と構造から文書の意味を理解する](../../../02_UX/Definitions/UX-000027/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「CRDD閲覧者」。初めて読む人と後工程担当者を含む |
| 利用のきっかけ | 工程成果物を初めて読む時 |
| 目的 | 課題と判断の物語から構造化詳細へ進む |
| 得たい結果 | 情報量を失わず短時間で意味と次の行動を理解できる |
| 独立した利用者成果 | 課題と判断の物語を理解してから、表・図で条件と関係を確認し、次の行動へ進める |
| 重要な場面 | 判断理由と条件を結び付ける場面 |
| 避ける失敗 | 確認項目順と専門語だけで文書を埋める |
| 守る品質 | 物語と構造化した情報を両立する |

## 3. 必要な認識・操作・Feedback

```text
工程成果物を初めて読む時
        ↓
確認すること: 物語、構造化した詳細、判断、根拠を結ぶ
        ↓
利用者の目的: 課題と判断の物語から構造化詳細へ進む
        │
        ├─ ★ 判断点: 判断理由と条件を結び付ける場面
        ├─ ⚠ 避ける失敗: 確認項目順と専門語だけで文書を埋める
        └─ ✓ 必要なFeedback: 物語と構造化した情報を両立する
        ↓
情報量を失わず短時間で意味と次の行動を理解できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「判断理由と条件を結び付ける場面」で利用者が「情報量を失わず短時間で意味と次の行動を理解できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「工程成果物を初めて読む時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「情報量を失わず短時間で意味と次の行動を理解できる」を、物語と構造化した情報を両立するという条件で確認できる |
| 成果不成立 | 「確認項目順と専門語だけで文書を埋める」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「物語、構造化した詳細、判断、根拠を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「確認項目順、専門語だけの説明および情報削減による見せかけの可読性を反証する」を確かめられる形を保ち、下流へ「文書化規則は物語を先に示す構成と構造化を優先する構成を両立し、各工程は読者理解と機械追跡を確認する。」を渡す。必要情報をここで推測して先取りしない。
