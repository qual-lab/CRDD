# UX-000013のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000013`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000013 許可された作業領域だけをリモート利用する](../../../02_UX/Definitions/UX-000013/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「プロジェクト運営者／PM」 |
| 利用のきっかけ | リモート接続を開始・再接続する時 |
| 目的 | 許可された作業領域だけへ接続する |
| 得たい結果 | 場所が変わっても開示範囲を理解して安全に使える |
| 独立した利用者成果 | 接続元や接続資格情報が変わっても、現在許可された作業領域だけを利用し、利用不能理由と管理能力を内容閲覧から区別できる |
| 重要な場面 | 利用可能情報を表示する時 |
| 避ける失敗 | 利用不能なリポジトリの存在や内容を推測表示する |
| 守る品質 | 現在の利用許可範囲（Grant）だけを開示し不足を補完しない |

## 3. 必要な認識・操作・Feedback

```text
リモート接続を開始・再接続する時
        ↓
確認すること: 接続資格情報、接続単位、作業領域の利用許可範囲、システム管理能力、開示範囲を分ける
        ↓
利用者の目的: 許可された作業領域だけへ接続する
        │
        ├─ ★ 判断点: 利用可能情報を表示する時
        ├─ ⚠ 避ける失敗: 利用不能なリポジトリの存在や内容を推測表示する
        └─ ✓ 必要なFeedback: 現在の利用許可範囲（Grant）だけを開示し不足を補完しない
        ↓
場所が変わっても開示範囲を理解して安全に使える
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「利用可能情報を表示する時」で利用者が「場所が変わっても開示範囲を理解して安全に使える」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「リモート接続を開始・再接続する時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「場所が変わっても開示範囲を理解して安全に使える」を、現在の利用許可範囲（Grant）だけを開示し不足を補完しないという条件で確認できる |
| 成果不成立 | 「利用不能なリポジトリの存在や内容を推測表示する」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |
| 回復／再開 | 同じ対象へ戻る条件と、未解消の義務を区別する |
| 判断・許可 | 誰が何を決めるかと、許可前後の状態を区別する |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「接続資格情報、接続単位、作業領域の利用許可範囲、システム管理能力、開示範囲を分ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「存在漏えい、一律の追加許可による解錠、古い利用許可範囲および管理能力からの閲覧権限推定を反証する」を確かめられる形を保ち、下流へ「IAは接続資格情報、接続単位、作業領域、公開範囲設定（Exposure）および情報源可用性を区別する。Threat／SPEC／Architectureは開示可否と外部変更の決定権限を別契約として具体化する。」を渡す。必要情報をここで推測して先取りしない。
