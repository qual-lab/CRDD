## 1. 正式入力

- UX定義: [UX-000006 実行事実を根拠付きで振り返る](../../../02_UX/Definitions/UX-000006/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「実行環境の導入・運用者」 |
| 利用のきっかけ | 実行結果を振り返る時 |
| 目的 | 実行事実を出所と観測時点付きで比較する |
| 得たい結果 | 推測と事実を混ぜず改善候補を判断できる |
| 独立した利用者成果 | 実行主体が異なっても、観測事実・未観測・評価・改善候補を出所と時点付きで区別して振り返れる |
| 重要な場面 | 未観測値を含む実行事実の取得 |
| 避ける失敗 | 未観測を0や正常へ畳む |
| 守る品質 | 出所・時点・観測状態を保持する |

## 3. 必要な認識・操作・Feedback

```text
実行結果を振り返る時
        ↓
確認すること: 実行記録（Execution）、観測状態（Observation State）、情報源、評価（Assessment）、候補を分ける
        ↓
利用者の目的: 実行事実を出所と観測時点付きで比較する
        │
        ├─ ★ 判断点: 未観測値を含む実行事実の取得
        ├─ ⚠ 避ける失敗: 未観測を0や正常へ畳む
        └─ ✓ 必要なFeedback: 出所・時点・観測状態を保持する
        ↓
推測と事実を混ぜず改善候補を判断できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「未観測値を含む実行事実の取得」で利用者が「推測と事実を混ぜず改善候補を判断できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「実行結果を振り返る時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「推測と事実を混ぜず改善候補を判断できる」を、出所・時点・観測状態を保持するという条件で確認できる |
| 成果不成立 | 「未観測を0や正常へ畳む」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「実行記録（Execution）、観測状態（Observation State）、情報源、評価（Assessment）、候補を分ける」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「空値の正常化、評価の事実化および出所のない比較を反証する」を確かめられる形を保つ。必要情報をここで推測して先取りしない。
