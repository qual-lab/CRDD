# UX-000028のUI分析

成果物種別: UI分析（UX観点）
分析単位: `UX-000028`
状態: 分析済み

## 1. 正式入力

- UX定義: [UX-000028 工程固有の図から意図を引き継ぐ](../../../02_UX/Definitions/UX-000028/ux_definition.md)

IAやREQを直接読んで不足を補完しない。この分析はUX定義から利用者観点だけを導き、情報構造はIA観点の分析に委ねる。

## 2. UIへ引き継ぐ利用者成果

| 観点 | UX定義から受け取る内容 |
|---|---|
| 利用者／利用状況 | 製品全体の利用者像にある「CRDD閲覧者」。設計・実装・検証を引き継ぐ後工程担当者を含む |
| 利用のきっかけ | 工程の入口・出口で成果物を渡す時 |
| 目的 | 工程固有の図から状態・関係・未接続を理解する |
| 得たい結果 | 後工程で意図を再発明せず漏れを発見できる |
| 独立した利用者成果 | 工程固有の図から全体像・関係・状態差・未接続を理解し、後工程で意図を再発明せずに引き継げる |
| 重要な場面 | 下流義務へ変換する場面 |
| 避ける失敗 | 必要な図を黙って省略しAIごとに記法が変わる |
| 守る品質 | 図の意味・凡例・正本関係を固定する |

## 3. 必要な認識・操作・Feedback

```text
工程の入口・出口で成果物を渡す時
        ↓
確認すること: Diagram Element、情報源が持つ意味、引き渡す義務を結ぶ
        ↓
利用者の目的: 工程固有の図から状態・関係・未接続を理解する
        │
        ├─ ★ 判断点: 下流義務へ変換する場面
        ├─ ⚠ 避ける失敗: 必要な図を黙って省略しAIごとに記法が変わる
        └─ ✓ 必要なFeedback: 図の意味・凡例・正本関係を固定する
        ↓
後工程で意図を再発明せず漏れを発見できる
```

このUXからUIへ渡す中心は、特定の部品や内部処理ではなく、「下流義務へ変換する場面」で利用者が「後工程で意図を再発明せず漏れを発見できる」へ進める認識・判断・Feedbackである。

## 4. 状況による体験差

| 状況 | この利用者成果で必要な体験 |
|---|---|
| 利用開始 | 「工程の入口・出口で成果物を渡す時」で、対象と判断に必要な前提を理解できる |
| 成果成立 | 「後工程で意図を再発明せず漏れを発見できる」を、図の意味・凡例・正本関係を固定するという条件で確認できる |
| 成果不成立 | 「必要な図を黙って省略しAIごとに記法が変わる」を避け、理由と安全な戻り先を理解できる |
| 判断不能 | 不明な事実を補完せず、何を確認しなければ判断できないか分かる |

上表にない処理中、取消、回復その他の状態を、共通テンプレートだけを根拠に追加しない。必要性はこのUXの意味とIA観点の情報構造をUI定義で統合して判断する。

## 6. IA観点との統合時に確認すること

IA観点の分析が「Diagram Element、情報源が持つ意味、引き渡す義務を結ぶ」を識別・状態・関係・可視性・導線として表現できるかを確認する。UI定義では「図の黙示省略、機械的で読めない記法および図と試験の断絶を反証する」を確かめられる形を保ち、下流へ「各工程は図の意味と処置を所有し、Checkerは欠落を、レビューは意味の正しさを確認する。」を渡す。必要情報をここで推測して先取りしない。
