# SCR-000008 ユーザー・Role権限・接続資格と利用可能範囲

成果物種別: Logical Screen Detail
Screen ID: `SCR-000008`
状態: Canonical
確認状態: 最新鍵管理判断を再伝播・限定独立レビュー済み・残指摘0。実画面・実装・E2E成立は未主張。
維持責任者: Qual-Lab

## 1. Screenの目的と入口・終了条件

- 利用者の作業・認識目的: 自身と許可内Repositoryを確認し、現在許可された通常管理と固定administratorの鍵操作を見分ける。鍵交換の対象、影響と結果を認識する。
- 対象UI Definition: [UI-000008](../../../../Definitions/UI-000008/ui_definition.md)
- Area: [configuration-trust](../area.md)
- 入口: 接続・自身確認、現在許可された通常管理、Workbenchの固定administrator鍵操作、またはログイン済みローカル操作者のHost交換が必要な時。通常とHostの条件を別々に確認する。
- 終了条件: 接続結果と許可・公開・実アクセスの範囲、管理処置の結果、または未確定範囲と同じ回復への確認先を認識し、次の安全な行動を選べる。
- Route／Surface候補: 接続・許可内情報利用のSurfaceと鍵操作入口を分ける。通常鍵操作は同一Process Workbench backend、Hostの交換2操作は対話CLIで提供する。MCPに鍵操作を出さない。具体Layout・表示案内は未確定で、Remote入口からHost回復を実行しない。

鍵の発行・独立失効・交換はadministrator専用固定で、RoleのON／OFF設定を設けない。通常鍵操作は同一Process Workbench backendだけで扱い、MCPへ鍵操作の一覧・Schema・登録・dispatchを公開しない。Hostはログイン済みローカル操作者を信頼する対話CLIで交換2操作だけを扱う。追加認証・専用資格・承認コード・OS管理者昇格は要求せず、既存Root／Path検証を維持し、検証済み範囲外へ越境しない。他4管理群（ユーザー管理・Role設定・Repository登録・公開範囲管理）の担当Role・設定可否はOPENである。

|---|---|---|---|---|
| `PRT-000008` | 接続・許可された最小管理・鍵操作の認識を扱う | userId、表示専用名、一つの現行Role、鍵操作の固定administratorと他4管理群の未確定割当、資格状態、Repository公開／取得範囲、秘密表示境界、回復の現在地 | 接続／現在許可されたユーザー・Role管理／Workbenchの発行・独立失効・交換／Hostの交換2操作のみ | 利用可能／資格要求／制限／利用不能／不明、部分成立、確認待ち／進行中／blocked／completed |

## 3. InteractionとBHV対応

| Interaction Key | PRT | 利用者の意図 | Feedback | BHV | Coverage |
|---|---|---|---|---|---|
| `PRT-000008.spec-000012` | PRT-000008 | 自身と利用範囲を確認し、許可された通常管理・独立失効・鍵交換2操作を行う | 対象と影響、新Secret一度表示、旧資格失効、保持情報、失効確定／発行不明、同じRecovery IDと確認先を区別する | [BHV-000012](../../../../../05_SPEC/Details/BHV-000012/behavior.md) | 限定レビュー済み・残指摘0 |

PRT内の操作は次のように区別する。新しい全体IDや画面を発行せず、同じInteractionの操作種別として保持する。

| 操作 | 処置前に示す対象と影響 | 結果と次の行動 |
|---|---|---|
| 登録・名前／Role変更・Role権限変更 | 対象userId・表示名・現行値・変更影響 | 名前はIdentity／Authorityではない。Role権限の次認可への反映を確認する |
| 新規資格発行 | Workbenchの固定administrator、既存対象userId・現行Role | 新Secret一度表示と発行結果。旧資格の失効・交換処理とは区別する |
| 接続 | 自身と現行Role・許可内Repository | 認証と内容アクセス、部分成立を分ける。新発行を伴わない |
| 独立した資格失効 | Workbenchの固定administrator、対象資格と以後の要求への影響 | 失効結果または既知状態・確認先。新資格・Secret・交換再入場を伴わず、開始済み操作の取消完了としない |
| 指定ユーザー交換 | 対象既存userId・表示名、その全旧有効資格、同じ発行先、保持情報 | 対象の旧鍵を失効し同じユーザーへ新鍵を一度表示。他ユーザーの鍵を保持する |
| 全員交換 | 全ユーザーの全旧有効資格、指定した既存administrator userId、保持情報。操作中管理者自身の旧鍵も失効する | 指定管理者へ新鍵を一度表示。他ユーザーは管理者の通常再発行・再配布まで旧鍵を使えない |

鍵交換はユーザーID・表示名・Role・詳細権限・Repository登録・Product Dataを変えない。秘密値は一覧・履歴・会話・Evidence・Repositoryへ保存／再表示しない。

```text
交換入口を確認（Workbench固定administrator または Hostログイン済み操作者）
  → 対象・失効範囲・既存発行先・保持情報を事前表示
  → Host入口または全員交換のみ人間の明示確認
  → 処置の現在地と結果を表示
      ├ 確定 → 一度表示した新資格で再入場
      └ 失効確定／発行不明 → 同じRecoveryへ戻り現在再観測
```

通常入口の指定ユーザー交換へ追加の明示確認Gateを課さない。対象不明・管理者不存在・必要状態を安全に確認不能・認可設定破損では処置前停止を示す。特別ユーザー、追加権限、回復専用Bootstrapは作らない。初回Server設定方式は変更しない。

| 交換の入口と操作 | 事前表示 | 明示確認 |
|---|---|---|
| 通常Workbench × 指定ユーザー | 対象ID・表示名、失効範囲、発行先、保持情報 | 追加確認なし |
| 通常Workbench × 全員 | 同上 | 必須 |
| Host CLI × 指定ユーザー | 同上 | 必須 |
| Host CLI × 全員 | 同上 | 必須 |

## 4. State／Variant

| 状態の軸 | 発生条件 | 表示する意味 | 次の行動／禁止 |
|---|---|---|---|
| 利用状態 | 接続と要求毎の認可・公開・取得判定 | 利用可能／資格要求／制限／利用不能／不明。複数対象の一部成立は別表示 | 許可範囲だけ選択し、不明や非開示を利用可能／不存在へ丸めない |
| 資格状態 | 現在の資格情報 | 有効／期限切れ／失効／不明 | 永続resetting／rotating状態を追加しない |
| 確認待ち／進行中 | 必要な確認または処置が未完了 | 操作種別、入口、対象、現在地 | 受付や要求発行を完了にしない |
| blocked | 処置前条件不足、または処置後の未解決状態 | 不足と既知処置を分離する | 新Effect前停止。開始済み取消完了を推定しない |
| 失効確定／発行不明 | 発行失敗・応答喪失・Process喪失 | 確定失効範囲、未確定発行、同じRecovery IDと確認先 | 現在再観測前に完了・rollback・旧資格利用可能と表示せず、Secret再表示もしない |
| completed | 必要な処置結果を確認した | 操作ごとの確定結果。独立失効は失効結果（新発行なし）、鍵交換は失効と発行の確定・新資格での再入場先、その他は当該操作の結果 | 過去Effect 0や開始済み取消の証明にしない |

回復参照の表示は許可された利用側に限定し、参照から操作Authorityを推定しない。

## 5. VisualとAccessibility

- Visual Baseline参照: [v0.21 UI Visual Baseline](../../../Visual/visual_baseline.md)
- Area Design Guide参照: [configuration-trust](../area.md)
- Screen固有の視覚判断: 自身／管理対象、現在状態、重大な不足、操作と影響、結果、根拠の順を保つ。失効確定と発行不明は別の見出し・状態語で示す。
- Reading Order／Focus Order: 対象→現行状態→操作と影響→必要な確認→結果→確認先。色だけに依存せずKeyboardとTextで到達可能にする。

- Workbench／Host CLIの入口分担は採用済み。Product固有のLayout・表示案内は未確定で、新Visual Direction、CMPや画面実装を固定しない。

## 8. 検証意図

検証では固定administrator以外の通常鍵操作、MCP鍵操作の一覧・Schema・登録・dispatch、Hostの新規発行・独立失効、追加認証要求、検証済みRoot／Path範囲外への操作を反証する。他4管理群の未決割当を暗黙に許可しない。発行・失効・交換を結果表示でも分け、交換は旧失効前から同じRecoveryへ結合し、結果搬送・受領を完了へ丸めない。

## 補足分析

UI-000008の現在の意味を既存SCR／PRTへ具体化する。新しい権限、状態Store、ユーザー成果は追加しない。限定した詳細契約の更新であり、Visual実装・工程Exit・実E2E成立ではない。
