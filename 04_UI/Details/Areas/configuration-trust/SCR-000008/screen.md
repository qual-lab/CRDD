## 1. Screenの目的と入口・終了条件

- 利用者の作業・認識目的: 自身と許可内Repositoryを確認し、現在許可された通常管理と固定administratorの鍵操作を見分ける。鍵交換の対象、影響と結果を認識する。初回設定では未初期化確認から最初の管理者・Host端末一度提示・exact同鍵の初回確認用限定接続成功による受領・接続確認までを認識する。
- 対象UI Definition: [UI-000008](../../../../Definitions/UI-000008/ui_definition.md)
- Area: [configuration-trust](../area.md)
- 入口: 接続・自身確認、現在許可された通常管理、Workbenchの固定administrator鍵操作、またはログイン済みローカル操作者のHost交換が必要な時。通常とHostの条件を別々に確認する。初回Host設定の明示開始も別場面として扱う。
- 終了条件: 接続結果と許可・公開・実アクセスの範囲、管理処置の結果、または発行・受け渡しの未確認範囲と状態別の次行動を認識し、次の安全な行動を選べる。
- Route／Surface候補: 接続・許可内情報利用のSurfaceと鍵操作入口を分ける。通常鍵操作は同一Process Workbench backend、初回Host設定と通常Host回復の交換2操作は別操作として対話CLIで提供する。MCPに鍵操作を出さない。具体Layout・表示案内は未確定で、Remote入口からHost回復を実行しない。

鍵の発行・独立失効・交換はadministrator専用固定で、RoleのON／OFF設定を設けない。通常鍵操作は同一Process Workbench backendだけで扱い、MCPへ鍵操作の一覧・Schema・登録・dispatchを公開しない。通常Host回復はログイン済みローカル操作者を信頼する対話CLIで交換2操作だけを扱う。追加認証・専用資格・承認コード・OS管理者昇格は要求せず、既存Root／Path検証を維持し、検証済み範囲外へ越境しない。manager／administratorがユーザー登録・表示名変更、developer／managerの割当て・詳細権限、Repository登録・登録解除・公開範囲を管理する。administratorの付与・解除・降格を含むRole変更、administrator詳細権限と鍵3操作はadministrator専用固定であり、Role内容設定で委譲しない。

| 管理操作 | developer | manager | administrator |
|---|---|---|---|
| ユーザー登録・表示名変更 | 不許可 | 許可 | 許可 |
| developer／managerの割当て・変更 | 不許可 | 許可 | 許可 |
| administratorの付与・解除・降格を含むRole変更 | 不許可 | 不許可 | 許可 |
| developer／managerの詳細権限設定 | 不許可 | 許可 | 許可 |
| administratorの詳細権限設定 | 不許可 | 不許可 | 許可 |
| 鍵の発行・独立失効・交換 | 不許可 | 不許可 | 許可 |
| Repository登録・登録解除 | 不許可 | 許可 | 許可 |
| Repository公開範囲設定 | 不許可 | 許可 | 許可 |

固定管理能力は現行Roleと上表の割当てから判定し、Role詳細権限の内容設定から派生させない。managerによるadministratorの表示名変更は許可するが、そのRoleの付与・解除・降格・詳細権限・鍵操作は許可しない。developerの管理拒否を自身表示・許可内利用の拒否へ広げない。

manager自身の内容範囲も、変更前の現在の管理認可→明示的なRole内容範囲／Exposure更新→次要求で現行Role・Exposure・実アクセスの再評価、と分ける。管理能力から内容閲覧を自動付与せず、更新受理を内容取得・開始済み取消完了と表示しない。表示の非表示／無効化だけで認可を代替せず、BHVの処置前判定で拒否・不明を扱う。

| 独立した資格失効 | Workbenchの固定administrator、対象資格と以後の要求への影響 | 失効結果または既知状態・確認先。新資格・Secret・交換再入場を伴わず、開始済み操作の取消完了としない |
| 指定ユーザー交換 | 対象既存userId・表示名、その全旧有効資格、同じ発行先、保持情報 | 対象の旧鍵を失効し同じユーザーへ新鍵を一度表示。他ユーザーの鍵を保持する |

| 通常Workbench × 全員 | 同上 | 必須 |
| Host CLI × 指定ユーザー | 同上 | 必須 |

### 一度提示の接点と状態表示

通常は操作administratorのWorkbench画面に秘密を一度だけ提示し、提示後の受領確認ボタンは置かない。対象本人への製品外引渡しは画面の受領済み状態にしない。初回とHost交換は端末に一度だけ提示する。初回は端末提示と同鍵の最初の接続確認を別の状態語で示し、確認の保存・読戻し・清掃確認後だけ通常管理へ案内する。接続未確認・保存等の不明では完了表示をせず、既存の明示交換か元試行再観測の既知条件を示す。確認方式・実画面・端末文言は未成立である。

### 初回Host設定の端末導線

[UI-000008の初回設定](../../../../Definitions/UI-000008/ui_definition.md#初回host設定の認識操作結果)を、同じPRT／Interaction内の別操作として具体化する。通常管理のユーザー登録（鍵を発行しない）および既存ユーザーの鍵交換とは分離する。ログイン済みHost操作者を信頼し、既存OSユーザーの管理Root／Pathを確認する。既存Credential・追加認証・専用資格・承認コード・OS管理者昇格は要求しない。Remote画面・MCP・自動起動へ実行入口を公開しない。

```text
初回CROS設定を明示開始 → 管理状態・途中の初期化記録を確認
  ├ 双方未初期化 → 管理用表示名 → 最初のadministrator UUID作成
  │                 → 同じuserIdへ発行 → 結果記録 → Host端末一度提示 → exact同鍵の初回確認用限定接続成功を受領・接続確認 → 確認の保存・読戻し・清掃確認 → 初回完了／通常Authority
  初回確認のいずれか未確認・失敗・観測不能 → 初回完了表示0／通常Authority0
  ├ 既存状態 → 初回設定拒否
  ├ 確認済み途中 → 元初期化試行の個別事実を表示・再観測
  └ 観測不能／不明 → 開始不可・不足と確認先（試行／UUIDを推定しない）
```

| 状態・条件 | 認識する結果と次の行動 |
|---|---|
| 双方未初期化を確認・明示開始 | 管理状態と途中の初期化記録の双方を確認した後だけ、表示専用の管理用名入力→最初のadministrator UUID作成→同じuserIdへ鍵発行・結果記録→Host端末へのSecret一度提示→exact同鍵の初回確認用限定接続成功による受領・接続確認→確認の保存・読戻し・清掃確認→初回完了／通常Authorityへの接続と進む。 |
| 既存管理状態・ユーザー・管理者あり | 初回設定を拒否する。鍵喪失は既存Host交換へ。管理者不存在・Role／認可破損を再初期化で修復しない |
| 確認済み途中 | 非秘密の元初期化試行と、作成UUID・発行・結果記録・Host提示・exact同鍵の初回確認用限定接続確認を別事実として保持・再観測する。作成済み・発行済みを未初期化へ戻さない。 |
| 発行または結果記録が未確認 | 確認済み元試行の再観測だけ。新交換・再初期化・自動再発行なし |
| 発行・記録確定、Host提示未確認 | 確定発行とHost提示不明を分離。作成済みadministratorを対象とする既存Host指定ユーザー交換を別明示操作として案内する |
| 発行・記録・Host提示確定、同鍵初回接続未確認 | 提示済みと接続確認不明を分離。同じ別明示交換を案内し、旧Secret受領済みとは示さない |
| 観測不能・不明 | 新Effect前に停止し、確認先を示す。単一ファイル不存在・別Root・読取り失敗・破損・Lock使用中・未解決回復を未初期化にしない。未試行と不明を区別し、存在未確認の試行・UUIDを推定しない |
| 必要な結果を確認 | Host一度提示、exact同鍵の初回確認用限定接続成功、確認の保存・読戻し・清掃確認がすべて成立した場合だけ初回完了と通常管理への接続を示す。個別の途中結果から全体完了を推定しない。 |
| 初回確認の失敗・未確認・観測不能 | 初回完了や通常利用可能を表示しない。元試行の既知事実と未確認段階を示し、発行／記録不明の再観測と、確定発行後の提示・接続未確認に対する既存明示交換を区別する。保存・清掃の処置はArchitectureで確定する。 |

表示名は識別補助でありAuthorityではない。秘密は結果の一度だけの表示に分離し、一覧・診断・履歴へ保存せず、戻る操作で再表示しない。途中再入場で別UUID・追加鍵・自動再初期化を作らない。初期化試行は交換Recoveryではない。Repository登録・Exposure・内容閲覧を自動付与せず、Product Dataを変更しない。

端末の読み順は「初回設定の目的→現在状態→表示名入力→確認済み結果→次行動」。状態を色だけで表さず、文字とKeyboard操作で認識可能にする。具体的な引数・表示文言・端末実測は未確定で、既存Visual BaselineやG1〜G5の完了を再主張しない。

回復参照の表示は許可された利用側に限定し、参照から操作Authorityを推定しない。

### 登録解除と鍵の状態別案内

登録解除は同じ受理済み操作で対象の登録と対応Exposureを除去する。別の先行公開解除を必須にせず、他登録・Exposure、対象Repository本体・Product Dataを保持する。両除去を確認した場合だけ解除完了とし、片側残存・観測不能を完了にしない。解除完了と開始済み操作終了未観測は別に保持し、取消成功・過去Effect 0・実資源終了を推定しない。新しい取消処置は追加しない。

発行または結果記録が不明なら、Credential IDとは別の非秘密の元発行Identityと既知事実で現在再観測する。交換由来だけ元のexact Recoveryを保持し、通常発行へ交換Recoveryを作らない。発行・結果記録が確定し提示・引渡し（初回は同鍵の接続確認）だけ未確認なら「発行済み・受け渡し未確認」とし、確定発行を不明へ戻さない。秘密再表示・保存・自動再発行をせず、現在許可されたadministratorが別の明示交換を選ぶ。管理認証を失った場合は既存Host交換入口へ案内し、Workbench認可を迂回しない。

別交換は別Operation／Recoveryとし、旧処理の事実・元発行Identityと分離する。各交換内は旧失効前から同じexact Recoveryへ結合する。指定交換は先の発行鍵を含む対象ユーザーの全旧有効資格を失効して同じ既存userIdへ発行し、他ユーザーの鍵を保持する。全員交換は先の発行鍵を含む全旧有効資格を失効して指定既存administratorへ発行し、他ユーザーは通常再発行・再配布へ戻る。4組の事前表示・3組の明示確認と保持情報を再適用する。遅延した旧応答で失効鍵を利用可能と表示しない。新交換成功を旧Secret受領・rollback・開始済み取消完了へ読み替えない。

## 8. 検証意図

検証では固定administrator以外の通常鍵操作、MCP鍵操作の一覧・Schema・登録・dispatch、通常Host回復からの新規発行・独立失効、追加認証要求、検証済みRoot／Path範囲外への操作を反証する。9 Role分担行のRole別肯否、managerによるadministrator表示名変更許可とRole付与・解除・降格・詳細権限・鍵拒否、developer管理拒否、現在認可不明のEffect前停止を検証する。通常発行の旧失効なし、独立失効の指定Credential–userId一致・指定外失効なし・新資格／Secretなし、交換範囲逸脱なしを反証する。発行・失効・交換を結果表示でも分け、交換は旧失効前から同じRecoveryへ結合し、発行・結果記録・提示結果を別事実とし、通常の対象本人受領は観測外、初回だけ同鍵接続確認として保持する。登録解除の両除去確認／片側残存、両除去済み・既存操作終了未観測、発行／記録不明、発行済み・受け渡し未確認、管理認証喪失、失効後の遅延応答を反証する。新交換成功から旧Secret受領を推定しない。

初回設定の検証は、双方未初期化・明示開始後の一度作成／発行／Host提示とexact同鍵の初回確認用限定接続成功による受領・接続確認と、その確認の保存・読戻し・清掃成立後の通常管理への接続、既存・不明での初期化Effect 0、途中再入場の別UUID・追加鍵・自動再初期化0、Host提示とexact同鍵の初回確認用限定接続確認の別、Secret保存／再表示・MCP公開0を個別に観測する。検証義務の導出入力であり、実行Passではない。各段階の未確認・失敗・観測不能を注入し、初回完了表示と通常Authorityの発行がともに0となる反例をQualityへ渡す。
